知識庫計畫的範圍界定與整體遠景

  • 主要讀者：決策層、產品與開發團隊、潛在合作夥伴

  • 建立日期：2026/06/08
  • 最後更新：2026/07/05
  • 編碼：UTF-8（繁體中文，含 BOM）

本文是 docs/strategy/ 策略文件集的總綱。商業價值與行銷見 02-商業價值與行銷策略、架構建議見 03-知識庫架構研究與建議、路線圖見 04-開發建議與路線圖。

一、一句話定位

將分散的資訊轉換成可搜尋、可理解、可運用的企業智慧資產，並透過 AI 與 Agent 持續創造更大的商業價值。

整個計畫是一個完整閉環：

資料匯入  →  資料清洗  →  建立知識庫  →  附加應用
  (收集整合)   (結構化/去蕪存菁)  (可搜尋可推理)   (轉成商業價值)
      ▲                                                │
      └──────────────  價值回饋、持續擴充  ◀───────────┘

本專案（KnowledgeExtraction.AI）是實踐此計畫的第一個步驟：先把「匯入」與「清洗」的基礎能力做穩，再往「知識庫」與「附加應用」延伸。

二、四階段範圍定義

下表逐段定義每個階段「做什麼、產出什麼、本計畫近期納入/不納入」。近期＝未來 3–6 個月（見 04 路線圖）。

階段一：資料匯入（收集與整合知識來源）

  • 目標：把企業內外部各種資料匯入系統。
  • 資料來源（願景全集）：Word、Excel、PowerPoint、PDF、電子郵件、影片、音訊、會議錄音、網頁內容、檔案伺服器、資料庫、聊天記錄（Teams、LINE、Slack 等）、OCR 圖片文字辨識。
  • 產出：標準化的原始內容與中繼資料（來源、時間、權屬、格式）。
  • 近期納入：延續並穩固現有的音訊/影片（上傳、YouTube、抖音、yt-dlp）與文件（PDF/Word/PPT/Excel）匯入。
  • 近期不納入：Email/IM 聊天記錄、檔案伺服器/資料庫直連、OCR 圖片辨識（列為後續擴充，已在願景內預留）。

階段二：資料清洗（轉換成可被 AI 理解的知識）

  • 目標：產出高品質、結構化的知識內容，並過濾或移除沒有價值的資料。
  • 能力（願景全集）：重複內容移除、敏感資訊遮罩、分類、標籤、摘要產生、重點/實體擷取、格式正規化、上下文補足、知識頁審核（distillation，把原始內容蒸餾為精煉、真實可用的知識）。
  • 產出：乾淨、分段、可索引的知識單元，以及蒸餾後的精煉知識（含分類/標籤/摘要與遮罩後內容）。
  • 近期納入：摘要與關鍵資訊擷取、分類與標籤自動化、敏感資訊遮罩、去重與品質過濾，外加知識頁審核——萃取出真實可用的知識而非僅原文搬運。
  • 現況：上述清洗能力（去重、遮罩、分類/標籤、摘要、品質過濾）均已實作（CleaningEnhancer，0.2.60–0.2.68），並已完成知識頁審核（蒸餾為互連 Wiki 實體頁，0.2.117）；不再只是「語音轉文字／文件轉 Markdown」的格式轉換。

階段三：建立知識庫（讓知識可被快速搜尋與理解）

  • 目標：產出可搜尋、可推理、可擴充的企業知識庫。
  • 關鍵待研究：採單一架構或混合式架構（純向量檢索 / 關鍵字 / 混合檢索 / 圖譜）——詳見 03 架構研究。
  • 企業環境必備：權控、遮罩、存取日誌（稽核）。
  • 產出：知識庫索引（向量＋關鍵字）、權控檢索 API、稽核紀錄。
  • 近期納入：切塊、Embedding、向量索引、延續團隊權控的檢索 API（中型規模：數萬文件、數百使用者）。
  • 現況：切塊（Chunker）、Embedding（雲端 text-embedding-3-large／地端 bge-m3）、向量索引、混合檢索（向量＋關鍵字加權融合）、團隊層權控檢索（檢索層即過濾）與 檢索品質評測均已實作（階段三，0.2.123–0.2.128 起）。向量目前存於關聯式 DB 並於應用層計算 cosine；pgvector/sqlite-vec 為 IVectorStore 之未來抽換點。

階段四：附加應用（將知識轉換成實際商業價值）

  • 目標：基於知識庫發展各種應用，提升附加價值。
  • 應用（願景全集）：AI 智慧問答、企業知識助理、文件自動摘要、SOP 查詢助手、客服問答系統、專案管理助理、專家知識傳承系統、AI Agent 自動化工作流。
  • 本計畫旗艦應用（聚焦兩個）：
  • AI 智慧問答／企業知識助理——最通用、最容易展示價值的入口。
  • AI Agent 自動化工作流——長期願景，價值最高。
  • 近期納入：旗艦應用一的 MVP（KB 問答助理）；旗艦應用二先做雛形與可行性驗證。
  • 現況：旗艦應用一「AI 知識問答助理」已實作（跨來源問答、串流回答、Query Rewrite、出處鑽取、兩段式相似度門檻、回答詳簡切換），另有「知識來源 AI 對話」。旗艦應用二「Agent 自動化工作流」的內建工作流引擎尚未實作，仍屬長期願景。

三、終局遠景

  • 企業日常營運不斷產生的資訊（文件、會議、影音、信件、聊天、系統資料）都能被自動收斂為知識資產。
  • 員工以自然語言提問即可取得帶出處、帶權限、可稽核的答案，而非靠人工翻找或詢問特定人員。
  • 知識資產驅動一層層應用：問答 → 助理 → SOP/客服 → 專案管理 → 專家傳承 → Agent 自動化工作流。
  • 最終效益：提升效率、降低人力成本、加速知識傳承與決策品質。

四、雙路線定位

本計畫同時走兩條路線（兩者皆是）：

路線對象價值主張成功衡量
內部自用開發人員自身開發人員自己使用這些功能，把自身蒐集的資料/知識資產化；同時作為最佳 dogfooding，邊用邊驗證產品自身查找效率、功能可用性、缺陷發現速度
對外商品化其他企業／通路夥伴可私有部署、企業級權控與遮罩的知識庫方案客戶數、營收、續約率

「內部自用」指開發人員自己要用的功能（非泛指公司全員）：開發者天天使用，最能驗證價值、最快發現問題，再對外商品化。

兩條路線共用同一套核心系統；差異主要在部署模式、計費與行銷包裝，詳見 02-商業價值與行銷策略。

部署上地端與雲端皆須支援：地端/私有部署是面對「資料不可外流」企業的關鍵賣點，雲端則以速度與功能為先。

近期進場楔子假設（office-hours 2026/06/08，待驗證）：對外商品化的最尖銳切入點假設為知識傳承（老手流失/新人接不起來），先以人工 concierge 試點驗證真實需求再決定是否全面收斂定位。詳見 05 §〇 需求驗證。

五、與現有系統的關係

KnowledgeExtraction.AI 目前是成熟的 .NET 10 / Blazor Server 平台（v0.3.14、約 340+ 個 C# 檔，不含 migrations），匯入 → 清洗 → 知識庫 → 附加應用的四階段閉環已大致貫通。

階段現況待補
匯入✅ 音訊/影片、文件、圖片辨識（OCR/LLM 視覺）已可用Email/IM、檔案伺服器/DB 直連
清洗✅ 格式轉換＋去重、遮罩、分類/標籤、摘要、品質過濾，並含知識頁審核—
知識庫✅ 向量庫、切塊、Embedding、索引、混合檢索、問答 RAG（含 Query Rewrite）、檢索品質評測、團隊層權控檢索（檢索層過濾）、知識型態版本化/時效性（版本狀態機＋as-of 時點檢索）結構化 PDF 專屬 RAG
附加應用✅ AI 知識問答助理、知識來源 AI 對話內建 Agent 自動化工作流引擎
權控基礎✅ 團隊權控、角色、Category/Team 標籤，檢索層即過濾（越權不外洩）—

可重用的既有元件與改造切入點（背景佇列服務、文件轉文字處理器、TagStringHelper 權控等）詳見 04 開發建議與路線圖的「初步技術驗證」。

六、範圍邊界（避免誤解）

  • 本策略文件集只界定範圍與方向，不含程式碼變更。
  • 「近期」聚焦在把匯入 → 清洗 → 知識庫三能力補齊並產出高品質知識庫；附加應用以旗艦問答助理 MVP 為主。
  • 願景全集（全資料來源、全應用）為長期方向，逐步擴充，不在近期一次到位。
