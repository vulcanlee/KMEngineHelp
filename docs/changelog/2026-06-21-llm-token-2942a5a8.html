2026-06-21 LLM 提示詞盤點文件 ＋ 完整 token 用量日誌

版本：0.2.108 → 0.2.109

需求

(A) 一份文件說明每次呼叫 LLM 會送出哪些提示詞、如何組合、哪些是硬編碼、能否搬到 appsettings、可行性/影響與多種彈性/透明化建議。 (B) 稽核所有 LLM API 呼叫，把回傳的 token 用量（輸入/輸出/推理及任何其他欄位）全部寫入日誌。

變更

Part A：文件（不改程式）

  • 新增 [docs/architecture/LLM 提示詞與用量透明化.md]：LLM 互動全景表、硬編碼預設提示詞完整清單、既有客製機制與優先序、搬 appsettings 的可行性/影響、四個方案與取捨、透明化建議與 roadmap。
  • docs/README.md 架構區加入連結。

Part B：完整 token 用量日誌（改程式）

  • 新增 TokenUsageFormatter（Business/Services/Transcription）：static Format(JToken? usage) 遞迴攤平 usage 所有數值欄位為 key=value，涵蓋 prompt_tokens_details.cached_tokens、*.audio_tokens、completion_tokens_details.reasoning_tokens 等任意子欄位。
  • OpenAIChatCompletionClient：LogUsage 與 LogStreamUsage 在友善欄位（送出/接收/理解/合計）外，額外記 完整明細=。
  • OpenAITranscriptionClient：response_format 由 text 改 json，逐字稿取 text（防禦性 fallback），新增 OpenAI 轉錄用量…完整明細=（gpt-4o-transcribe 有 usage；whisper-1 記「不可用」）。
  • 遵守鐵則：只記 token 數字，不記金鑰與請求/回應本文。

影響範圍

  • 變更：TokenUsageFormatter.cs（新）、OpenAIChatCompletionClient.cs、OpenAITranscriptionClient.cs、TokenUsageFormatterTests.cs（新）、docs/architecture/LLM 提示詞與用量透明化.md（新）、docs/README.md、docs/architecture/開發慣例與限制速查.md、appsettings.json（版本號）。
  • 轉錄回應格式由 text 改 json，逐字稿內容不變（取 .text）。無資料庫變更，不需 migration。

驗證

  1. dotnet test 全綠（276 通過，含 3 筆新 TokenUsageFormatterTests）。
  2. 設好金鑰：清洗/對話日誌每筆含 完整明細=；語音轉錄日誌出現「OpenAI 轉錄用量…完整明細=」。
  3. scripts/Test-DocsEncoding.ps1 全綠。
