Markdown 表格渲染成純文字：啟用 Markdig 的 UsePipeTables（1.0.102）

  • 日期：2026-07-29
  • 版本：1.0.101 → 1.0.102
  • 類型：Bug 修正（共用 Markdown 渲染器；影響 12 個呼叫端，其中多數是既有問題而非本次造成）

症狀

頁面說明對話窗（1.0.101 新增）裡的表格顯示成字面文字，而不是表格：

| | 一般（精準檢索） | 全域（社群摘要） |
|---|---|---|
| 適合問 | 具體的事實、條款、步驟、數字 | 整體風險有哪些 |

根因

Components/Commons/MarkdownRenderer.cs 的 Markdig pipeline 只有兩個擴充：

new MarkdownPipelineBuilder()
    .DisableHtml()
    .UseSoftlineBreakAsHardlineBreak()
    .Build();

Markdig 預設是純 CommonMark，不認得 pipe table 語法——表格必須明確加 UsePipeTables()（或整包 UseAdvancedExtensions()）才會啟用。全 repo 從未啟用過（UsePipeTables|UseAdvancedExtensions|UseGridTables 零命中）。沒有表格擴充時，Markdig 把那幾行當成普通段落原樣輸出，於是畫面上出現字面的 |。

這是靜默失敗的典型：建置成功、沒有例外、沒有警告、既有測試全綠，只有人眼看得出來。

影響範圍比表面更大

該 renderer 有 12 個呼叫端（11 個檔案）。除了頁面說明，最關鍵的是 Components/Commons/ContentEditDialog.razor:81——它被知識來源、文件轉文字、影音轉逐字稿、圖片解讀、Wiki 頁、會議編輯與檢視共 8 個視圖重用，渲染的是抽取／清洗後的內容。

而系統自己的提示詞就要求 LLM 輸出表格（KnowledgeExtraction.Business/Services/Prompts/LlmPromptDefaults.cs 的 DocumentPdfToMarkdown）：

  • 「表格一律轉為 Markdown 表格語法並保留每一格內容；跨欄跨列的儲存格請另以文字補述。」
  • 「圖表若可還原為數據，請額外以 Markdown 表格呈現該數據。」

也就是說，PDF 文件抽取結果裡的表格在 1.0.101 之前就已經渲染壞了——只要原始 PDF 有表格。同樣受影響的還有 Wiki 頁（知識百科）、AI 知識問答與知識來源對話的回答、會議紀錄摘要與決議事項、聊天紀錄稽核。1.0.101 的 40 份說明檔（共 260 個表格，平均每頁 6.5 個）只是把這個既有問題放大到每一頁都看得見。

變更

1. 啟用表格擴充（Components/Commons/MarkdownRenderer.cs）

new MarkdownPipelineBuilder()
    .DisableHtml()            // 保留：MarkupString 的 XSS 防線
    .UsePipeTables()          // 新增
    .UseSoftlineBreakAsHardlineBreak()
    .Build();

UsePipeTables() 內建於 Markdig 主套件（本專案 1.3.2），不需要新增任何 NuGet 參考。它也不開放任何原始 HTML 透傳——DisableHtml() 這條 XSS 防線完全未動。

類別上補了 <remarks>，明寫這兩個擴充都不可移除、以及移除後的具體後果。

刻意不用 UseAdvancedExtensions()：它一次啟用約 15 個擴充，其中 Mathematics 會把 $ 當數學公式起始——知識庫文件常出現「$100 到 $200」這種金額，會被吃成公式而顯示錯亂；MediaLinks 還可能輸出 <iframe>。範圍遠超「修表格」所需。也不加 UseGridTables()（沒有內容使用 grid table）。

2. 補上表格樣式（wwwroot/app.css）

只修渲染還不夠，有兩個都會讓使用者看到壞畫面的問題：

  • .markdown-preview 全專案沒有任何 CSS（9 個呼叫端共用這個 class），app.css 也沒有任何 table/th/td 規則。只啟用擴充，那 9 處會變成瀏覽器預設的無框線、無底色表格。
  • .page-help-content 是 overflow: hidden auto（水平隱藏），寬表格會被裁掉且無法捲動。

新增一組同時涵蓋兩個容器的樣式。關鍵是 display: block + overflow-x: auto：Markdig 產生的是裸 <table>、沒有外層 wrapper 可以掛捲動容器，所以讓表格自己成為捲動容器——寬表格橫向捲動，既不會被裁切，也不會讓整頁冒出水平捲軸。

3. 移除重複定義（Components/Commons/PageHelpDialog.razor）

1.0.101 在該元件的 <style> 內寫了一份 .page-help-content table 樣式。現在統一由 app.css 定義（app.css 是全域檔，對 AntDesign Modal 的 portal 內容有效——.change-password-modal、.member-manage-modal 已是先例），元件內那三塊刪除，只留一行註解指向 app.css。

測試

新增 KnowledgeExtraction.Tests/MarkdownRendererTests.cs（9 條）

MarkdownRenderer 被 12 個呼叫端共用，卻長期零測試覆蓋——這正是這個 bug 能一直存在的原因。補上守門：

測試釘住什麼
pipe table → 輸出含 <table>／<th>／<td>本次 bug 的回歸釘
表格內中文儲存格內容完整保留中文不被吃掉
<script> 與 <img onerror=...> 都被轉義DisableHtml() 這條 XSS 防線沒被這次改動弄掉
單一換行仍輸出 <br>UseSoftlineBreakAsHardlineBreak() 沒被表格擴充影響
圍欄程式碼區塊仍輸出 <pre><code>說明檔用它畫 ASCII 流程圖
$100／$200 字面保留、輸出不含 math刻意不開 UseAdvancedExtensions() 的決定
null／空字串 → string.Empty既有行為

新增 PageHelpCatalogTests.EveryHelpDocumentWithATable_RendersAnHtmlTable（1 條）

掃 Datas/Help/*.md，凡含表格分隔列（^\|[-:\s|]+\|$）的檔案，整份經 MarkdownRenderer.ToHtml() 渲染後必須含 <table>。

40 份檔案全部匹配到表格分隔列（合計 260 個），所以這一條不是空過的斷言——它以真實內容涵蓋全部說明檔。日後若有人移除 UsePipeTables()，這一條會連同 MarkdownRendererTests 一起紅。
