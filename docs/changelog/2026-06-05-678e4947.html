發行說明：團隊清單（Team）管理功能（0.2.35）

期間：2026/06/05。本輪新增「團隊清單」CRUD 管理頁面，供未來建立其他紀錄時指定「特定或所有團隊」可使用之用。與「分類清單」功能高度同構，差異在於團隊多一個「團隊代號」欄位。版本來源為 appsettings.json 的 SystemVersion。需求與規格見 團隊清單 PRD。

重點摘要

  • 新增團隊清單管理頁面（路由 /teams），提供新增、查詢、編輯、刪除。
  • 團隊名稱為唯一值；團隊代號為選填，但有填寫時亦須唯一。兩者比對皆忽略大小寫並去除頭尾空白，新增與編輯皆生效（編輯排除自身）。
  • 列表預設依更新時間由新到舊排序。
  • 側邊選單於既有「資料定義」主功能表下，在「分類清單」之後新增「團隊清單」，並納入角色權限控制。

功能與變更

0.2.35 — 新增團隊清單 CRUD

  • 資料模型：新增 Team 實體（Id、Name、Code、Description、IsEnabled、CreatedAt、UpdatedAt）；

BackendDBContext 新增 DbSet<Team>；產生 Sqlite 與 SqlServer 雙 migration（AddTeam）。

  • 後端分層（比照 Category）：TeamRepository、TeamService、TeamController，

以及 TeamDto／TeamCreateUpdateDto／TeamSearchRequestDto／TeamAdapterModel。

  • 名稱唯一性：UI 路徑由 TeamService.BeforeAddCheckAsync／BeforeUpdateCheckAsync 驗證；

API 路徑由 TeamRepository.ExistsByNameAsync 驗證，重複時回 409 Conflict。

  • 代號唯一性：僅在代號非空白時檢查（ExistsByCodeAsync），允許多筆代號為空；同樣回 409 Conflict。
  • 預設排序：TeamRepository.GetPagedAsync 與 TeamService.GetAsync 預設 OrderByDescending(UpdatedAt)。
  • UI（Blazor Server + Ant Design）：TeamPage（/teams）與 TeamViewView；

表格欄位為名稱、團隊代號、描述、啟用狀態、更新時間、操作；新增／編輯 Modal 含團隊代號與啟用狀態切換。

  • 選單與權限：Datas/Menu.json 於「資料定義」下、「分類清單」之後新增「團隊清單」(id 42)；

MagicObjectHelper 新增 角色_團隊清單；RolePermissionService 於「資料定義」群組加入對應權限（位置索引對齊）。

  • 接線：AutoMapping 新增 Team 對應；ServiceCollectionExtensions 註冊 TeamService／TeamRepository；

_Imports.razor 加入 Teams 命名空間。

  • 測試：新增 TeamServiceTests，涵蓋名稱／代號唯一性（忽略大小寫＋去空白、空代號可並存、編輯排除自身）與預設排序；全套測試 103 筆通過。
  • 文件：新增 團隊清單 PRD；appsettings.json 版本號 0.2.34 → 0.2.35。

使用方式

  1. 既有角色需先到「系統管理 → 角色管理」勾選「資料定義 / 團隊清單」權限。
  2. 部署前對資料庫套用 AddTeam migration（Update-Database）。
  3. 進入「資料定義 → 團隊清單」即可新增、編輯、刪除團隊；名稱重複（含僅大小寫或頭尾空白差異）會被擋下；團隊代號有填且重複時亦會被擋下。

未來延伸（Out of Scope）

  • 其他紀錄（專案、會議、轉錄等）指定「特定團隊」或「所有團隊」可使用之關聯機制（屆時可依 IsEnabled 僅顯示啟用中的團隊）。
  • 團隊的批次匯入／匯出、團隊成員／負責人、階層（父子）結構。
