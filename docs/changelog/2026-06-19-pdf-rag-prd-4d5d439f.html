新增「PDF 型 RAG 處理」PRD（規劃中，0.2.91）

  • 日期：2026-06-19
  • 版本：0.2.90 → 0.2.91
  • 類型：文件新增（PRD，規劃中）

需求

依據「PDF 型 RAG 處理思路」的內容，建立一份 PRD 作為日後系統改善依據：PDF 做 RAG 不能只「轉文字→切片→丟向量庫」，重點在辨識類型、保留結構、語意切分、可追溯引用、多工具協作與評測閉環。

變更

新增 docs/prd/PDF型RAG處理-prd.md（狀態：規劃中）

聚焦「讀懂・切分・引用」，涵蓋：

  • PDF 類型判斷（原生文字/掃描/圖文混排）與對應解析策略。
  • 文件結構還原（頁碼、標題層級、章節、段落、表格位置、圖片說明、註腳、頁眉頁腳標記避免重複召回）。
  • 語意切片與 chunk metadata（非固定字數；標題不離正文、條款完整、表格獨立、圖表摘要；metadata 含頁碼/章節/編號/Teams，繼承來源權控；可選 contextual note）。
  • 表格/圖片/圖表專門處理（沿用既有多模態 API）。
  • Agent 工具鏈（Search PDF / Read Page / Extract Table / Chart Analysis / Citation Source）。
  • 可追溯引用與評測閉環（檢索/頁碼/表格/OCR/圖表/引用支撐度等細指標，延伸黃金評測精神）。
  • 技術選型建議（具體＋替代）：PyMuPDF/pdfplumber、Docling/Unstructured、PaddleOCR/Tesseract、沿用 OpenAI vision、pgvector（屬路線圖階段三）。
  • 資料模型草案、相依與風險、容量限制、與現有架構整合、分階段落地、驗收條件。

明確界定範圍：embedding/向量庫/混合檢索＋rerank/問答 UI 屬路線圖「階段三建立知識庫」，本 PRD 不重複規格，只負責產出可被階段三索引的結構化 chunk。
