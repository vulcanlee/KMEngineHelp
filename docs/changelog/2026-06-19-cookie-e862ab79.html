修正抖音下載 UNDERRSOCKET：改用瀏覽器 context 帶 cookie 下載（0.2.87）

  • 日期：2026-06-19
  • 版本：0.2.86 → 0.2.87
  • 類型：缺陷修正

問題

0.2.85 為抖音下載加了「逾時＋3 次重試」後，實測仍失敗：三次重試全部 UND_ERR_SOCKET （other side closed）後放棄（log Id=67）。證明這不是偶發抖動，而是 Node fetch 對抖音 CDN 網址系統性被斷線，重試無法解決。

根因

get-douyin-audio.mjs 原本先 context.close() 關閉瀏覽器，再以 Node undici fetch 下載已 攔截的 CDN 網址。undici 是純 Node HTTP 客戶端、僅送極簡標頭、且不帶任何 cookie。0.2.85 註解假設「URL 已預簽章、不需 cookie」並不成立：抖音 TOS CDN 的防盜鏈會把「沒有瀏覽器 session cookie／瀏覽器標頭」的請求直接斷線。瀏覽器當初能載入串流，正是因為它自動帶上 context 內的 cookie（ttwid 等）與完整標頭。

修正

tools/douyin-audio/get-douyin-audio.mjs 下載區塊：

  • 改為在關閉瀏覽器前，用 Playwright context.request.get(chosen, { headers: { Referer, User-Agent }, timeout, maxRedirects }) 下載，再 await resp.body() 取得位元組。context.request

會自動沿用瀏覽器 context 的 cookie 與近似瀏覽器標頭，繞過 CDN 防盜鏈斷線。

  • 保留 3 次重試 + 退避以防真正的偶發抖動；下載成功或耗盡後於 finally 關閉瀏覽器。
  • 頁內 fetch 因 CDN 跨網域受 CORS 阻擋、無法讀取位元組，故不採用。

不改 C#（DouyinAudioDownloader 仍以 exit code 包裝，150 秒總逾時足夠）。

影響範圍

  • 變更檔案：tools/douyin-audio/get-douyin-audio.mjs、tools/douyin-audio/README.md、

appsettings.json（版本號）。無模型／資料庫變更，不需 migration。

驗證

  1. node --check tools/douyin-audio/get-douyin-audio.mjs 語法正確。
  2. node tools/douyin-audio/get-douyin-audio.mjs "<抖音連結>" --out <暫存.mp3> 應成功產出 mp3、

無 UND_ERR_SOCKET。

  1. 系統「音訊轉錄」貼抖音連結，背景下載成功並完成轉錄。
