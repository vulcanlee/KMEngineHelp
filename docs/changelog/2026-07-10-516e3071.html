資料一致性強化：刪素材清孤兒＋編修標記過時＋一致性巡檢頁（0.3.19→0.3.20）

  • 日期：2026-07-10
  • 版本：0.3.19 → 0.3.20
  • 類型：新增功能／資料一致性修正（依 docs/architecture/資料生命週期與維護.md §6 backlog）

需求

KnowledgeSourceItem 以 ItemType＋ItemId 軟參照素材、無硬 FK，導致三個維護缺口：

  • 刪素材留孤兒（P1-A）：刪 MediaTranscription/DocumentExtraction/ImageRecognition 不會清除引用它的成員，下游清洗/蒸餾/向量默默過時，只在顯示時標「（來源已不存在）」。
  • 編修素材文字不標記過時（P2）：就地改逐字稿/Markdown/解讀文字後，下游不知情、連 ContentStale 都不設。
  • 無孤兒／一致性一覽（P1-B）：既有孤兒與過時來源只能人工逐筆找、逐筆重跑。

變更

商業層

  • 新增 KnowledgeSourceMaintenanceHelper.MarkOwningSourcesStaleAsync(context, itemType, itemId, removeOrphanItems)（Business/Helpers）：查引用該素材的 KnowledgeSourceItem，將所屬來源設 ContentStale=true＋UpdatedAt；removeOrphanItems=true 時 RemoveRange 孤兒成員。不自行 SaveChanges，與呼叫端同一交易原子提交。
  • P1-A：三個素材 DeleteAsync 在 Remove(item) 前呼叫 helper（removeOrphanItems: true）。
  • P2：MediaTranscriptionService.UpdateTranscriptContentAsync、DocumentExtractionService.UpdateMarkdownContentAsync、ImageRecognitionService.UpdateRecognitionTextContentAsync 落檔後呼叫 helper（removeOrphanItems: false；成員保留）。
  • P1-B：新增 DataConsistencyService（GetReportAsync 偵測孤兒成員與過時來源；CleanupOrphansAsync 清孤兒；admin 看全庫、非 admin 依 TagStringHelper 權控）。

模型

  • 新增 DataConsistencyReportAdapterModel（OrphanMemberAdapterModel／StaleSourceAdapterModel）與 DataConsistencyCleanupResult。

UI 層

  • 新增 admin 頁 /data-consistency（DataConsistencyPage + DataConsistencyView，Flavor B）：兩張唯讀表（孤兒成員、過時來源）＋工具列「清除所有孤兒成員」「重新清洗所有過時來源」（逐筆重用帶權控的 KnowledgeSourceService.TriggerCleaningAsync）＋逐列「重新清洗」。
  • Menu.json 於「系統管理」群組（id 4）新增 adminOnly 子項（id 45，icon fact_check）；因掛既有 admin 群組，免動 RolePermissionService/MagicObjectHelper 三方同步。
  • DI：ServiceCollectionExtensions 註冊 DataConsistencyService（Scoped）。

測試

  • 新增 DataConsistencyTests（6 筆）：helper 刪除清孤兒＋標記過時、僅標記過時（成員保留）、多來源皆標記、不相關成員不受影響；DataConsistencyService 偵測孤兒／過時、CleanupOrphansAsync 只清孤兒且標記來源過時。
  • MenuIconTests／CrudActionIconTests 維持綠（新頁圖示 fact_check 已在允許清單；View 未用工具列 emoji）。

範圍決策（誠實記錄）

  • 無 schema 變更 → 無 migration（純服務／UI／查詢）。
  • 巡檢頁為 admin-only、看全庫（與 /rag-diagnostics 一致）；重跑動作各自再檢查團隊權控。
  • 刪素材/編修僅標記過時、不自動重跑下游（避免非預期運算成本）；重跑由使用者或巡檢頁批次觸發。
  • 未納入：素材版本鏈（P3，需雙資料庫 migration），維持選配 backlog。

驗證

  1. dotnet build 成功；dotnet test 綠燈（含新增 DataConsistencyTests、MenuIconTests、CrudActionIconTests）。
  2. 手動：admin 於「系統管理 → 資料一致性巡檢」可見、非 admin 不可見。
  3. 造孤兒：來源加入某素材 → 刪該素材 → 該來源死成員自動移除、來源標記過時。
  4. 編修某素材逐字稿 → 所屬來源標記過時。
  5. 巡檢頁對 legacy 孤兒/過時來源顯示並可一鍵清除/重新清洗。
  6. scripts/Test-DocsEncoding.ps1 全綠。
