圖片清單新增「批次上傳壓縮檔（.zip）自動建立記錄」（0.3.1）

  • 日期：2026-07-08
  • 版本：0.3.0 → 0.3.1
  • 類型：新增功能

需求

圖片清單原本只能單張上傳。使用者手上常有一整批圖片，逐張上傳效率低。需求是：比照文件萃取近期新增的「批次上傳壓縮檔」，提供一個壓縮檔上傳入口，上傳一個 .zip，系統自動為裡面每張圖片各建立一筆記錄。

決策（與需求方確認）

  • 入口：新增獨立「批次上傳壓縮檔」按鈕／Modal，原單張上傳不變。
  • 不自動解讀：批次建立的記錄維持「未解讀」狀態，AI 視覺解讀仍由使用者之後手動觸發（與圖片單張上傳行為一致；圖片 AddAsync 本就不排解讀佇列）。
  • 標題取自完整原始檔名（含副檔名），非去副檔名。
  • 分類／團隊：上傳時選一組共用標籤，套用到本次所有記錄；團隊預設帶入使用者所屬團隊。
  • 子資料夾：遞迴所有層級，忽略資料夾結構（僅用檔名）。
  • 不支援檔（非圖片格式）：略過並回報清單。
  • 嵌套 .zip：略過並列入清單（不遞迴解壓）。
  • 安全上限（防 zip bomb）：檔數 500、解壓總量 2GB，超過整批拒絕、不建立任何記錄。
  • 不改資料模型、不需 migration。

變更

Business 層

  • ImageRecognitionService.AddBatchFromZipAsync(zipStream, categories, teams, maxFileCount, maxUncompressedBytes, ct)：以 System.IO.Compression.ZipArchive（.NET 內建，無需 NuGet）走訪 entries，前置安全檢查（檔數／解壓總量）後，對每張支援的圖片複用既有 AddAsync（存檔＋建記錄）。單一 entry 失敗記入清單、不中斷其餘。不排解讀佇列，記錄狀態為「未解讀」。
  • 新常數 MaxBatchFileCount = 500、MaxBatchUncompressedBytes = 2GB。
  • 複用既有結果型別 BatchZipImportResult（KnowledgeExtraction.Models/Systems/BatchZipImportResult.cs）與圖片格式驗證 ImageFormatValidator（.jpg／.jpeg／.png／.webp／.gif）。

UI 層

  • ImageRecognitionView：工具列新增「批次上傳壓縮檔」按鈕（Icon drive_folder_upload）；新增批次上傳 Modal（共用分類／團隊 ＋ <InputFile accept=".zip">）與「批次匯入結果」Modal（成功筆數＋略過／失敗清單）。輪詢守衛加入批次視窗狀態，避免 Modal 開啟時被 5 秒自動刷新干擾。

測試

  • 新增 ImageRecognitionBatchZipTests（8 個）：建記錄／標題取完整原始檔名／不排解讀佇列且狀態為未解讀／遞迴子資料夾／略過不支援檔並回報／略過嵌套 zip 並回報／共用分類團隊套用全部／超檔數上限整批拒絕／超解壓總量整批拒絕／損毀 zip 不拋例外／png ContentType 推得。
  • drive_folder_upload 已在 CrudActionIconTests 允許清單（文件萃取先前已加入），本次沿用同圖示，允許清單無需變更。

影響範圍

  • 不動現行單張上傳與 LLM 視覺解讀邏輯。
  • 已同步更新 docs/operations/容量邊界與限制.md（批次上限）。
  • appsettings.json SystemVersion 0.3.0 → 0.3.1。無資料庫變更，不需 migration。

驗證

  1. dotnet test --filter ImageRecognitionBatchZipTests 綠燈（8 通過）。
  2. 全專案 dotnet build 成功（僅既有無關警告）。
  3. /image-recognition 批次上傳混合內容 zip（含非圖片檔、嵌套 zip）：每張支援圖片各建一筆「未解讀」記錄、略過清單正確；分類／團隊正確套用；非管理員只看得到自己團隊（或公開）的記錄。
  4. scripts/Test-DocsEncoding.ps1 全綠。
