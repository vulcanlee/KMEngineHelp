變更紀錄

知識庫問答稽核紀錄持久化（EVAL-2）（0.3.1→0.3.2）

  • 日期：2026-07-08
  • 版本：0.3.1 → 0.3.2
  • 類型：新增功能（RAG 補強清單第一項）

需求

RAG 補強總彙整清單挑選最有槓桿的資料地基項目 EVAL-2：把每輪問答的稽核資訊（最高分 topScore、信心、命中明細、問句長度）從「只寫 NLog」改為持久化到資料庫，以支撐後續 topScore 分佈統計（EVAL-3）與兩段式門檻校準（RQ-1）。

變更

資料層

  • 新增實體 KnowledgeBaseQueryAudit（KnowledgeExtraction.AccessDatas/Models/）：CreatedAt、IsAdmin、Teams、OriginalQueryLength、EffectiveQueryLength、WasRewritten、HitCount、TopScore、Confidence、RejectThreshold、LowConfidenceThreshold、HitDetailsJson。
  • BackendDBContext 註冊 DbSet + CreatedAt 索引。
  • 雙 migration AddKnowledgeBaseQueryAudit（Sqlite AccessDatas + SqlServer AccessDatas.SqlServerMigrations）。

商業層

  • KnowledgeBaseChatService.RetrieveAsync 三分支（0 命中／低於 RejectThreshold／正常回答）各呼叫新私有 WriteQueryAuditAsync 寫入一列稽核。
  • 隱私邊界（不變量）：只存長度與分數，命中明細只含 id/layer/score，不存問句本文、context 本文、chunk 文字——延續既有 NLog 稽核的隱私設計。
  • 韌性：稽核寫入全段 try/catch，失敗只 LogWarning，不影響問答回答。

測試

  • KnowledgeBaseChatServiceTests 新增 3 個測試：正常回答／低於 Reject／0 命中 各驗證寫入一列且欄位正確、命中明細不含本文。共 15 個測試全綠。

文件

  • 更新 docs/planning/12-RAG系統補強總彙整與優先序.md：新增「§〇 完成進度追蹤」單一狀態入口，標記 EVAL-2 ✅ 已完成；修正統計為 39 項。
  • 更新 docs/architecture/知識庫RAG設計與執行.md §七：把「問答稽核紀錄持久化」移至已實作，說明新表與隱私邊界。
  • 新增 docs/guides/RAG補強修正測試指南.md：EVAL-2 測試專節 + 通用模板。

影響範圍

  • 無 UI 變更、無新權限、無 Menu.json（純後端持久化；UI 由日後 EVAL-3/EVAL-4 消費）。
  • appsettings.json SystemVersion 0.3.1 → 0.3.2。需套用雙 migration（dotnet ef database update）。

驗證

  1. dotnet test --filter KnowledgeBaseChatServiceTests 綠燈（15 通過）。
  2. dotnet build 成功。
  3. 手動：/knowledge-base 問一題 → KnowledgeBaseQueryAudit 新增一列、無本文外洩。
  4. scripts/Test-DocsEncoding.ps1 全綠。
