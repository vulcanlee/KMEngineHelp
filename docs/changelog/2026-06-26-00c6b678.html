階段三步驟 4：混合檢索（IRetrievalService）（0.2.126）

  • 日期：2026/06/26
  • 版本：0.2.125 → 0.2.126
  • 對應設計：階段三：知識庫與 RAG 設計規格 §7、§8；路線圖步驟：strategy/12 §12.2 步驟 4

摘要

階段三第四步驟：建立混合檢索服務。對使用者問句同時做向量（語意）+ 全文（關鍵字）檢索、加權分數融合取 topK，並在檢索層即套團隊權控——越權內容永不進入候選與結果（規格 §8.3）。作為步驟 5 跨來源問答取數的底座。

設計重點

  • provider 無關：沿用步驟 2 方向。向量路徑走既有 IVectorStore.SearchAsync（cosine + 權控）；全文路徑以 VectorEmbedding.ChunkText.Contains（EF→LIKE，SQLite/SQL Server 皆通）。
  • 權控即過濾（資安關鍵）：兩路皆套 TagStringHelper.BuildTeamAccessPredicate（非管理員只見公開或交集團隊；管理員不限）。越權 0 命中。
  • 分數融合：fused = VectorWeight×cosine + KeywordWeight×(命中詞數/總詞數)，缺一方以 0 計；過 MinScore 門檻、遞減取 TopK。權重/topK/門檻為可調參數（規格 T3）。
  • 降級：未設定嵌入端點時向量路徑略過，退化為關鍵字檢索（不擲例外）。
  • 雙層：RetrievalQuery.SourceLayer 可只取 Wiki 或 Cleaned，或 null 雙層皆檢索。

變更內容

  • 設定：SystemSettings 新增 Retrieval 群組（TopK/CandidateTopK/VectorWeight/KeywordWeight/MinScore）；appsettings.json 同步新增區段。
  • 檢索服務（KnowledgeExtraction.Business/Services/Embeddings/）：IRetrievalService + RetrievalQuery/RetrievalHit；RetrievalService（向量路徑 + 全文路徑〔含私有 ChunkText OR 述詞建構器〕+ 切詞 + 融合）。
  • DI：ServiceCollectionExtensions 註冊 AddScoped<IRetrievalService, RetrievalService>()。
  • 測試：RetrievalServiceTests（越權 0 命中、管理員全得、無團隊只得公開、融合分項分數、未設定嵌入退化關鍵字檢索、TopK、SourceLayer 過濾）。全套 346 個測試綠燈。本步驟無模型變更、不需 migration。

後續

依 strategy/12 §12.2，下一步為步驟 5：跨來源問答 KnowledgeBaseChatService（取 scope → 檢索 → 組 context〔Wiki 導引在前、Cleaned 佐證在後〕→ 四層提示詞 + RAG 槽位 → 串流）＋ 知識庫問答頁（出處面板與鑽取下載）＋ 權限三處同步。
