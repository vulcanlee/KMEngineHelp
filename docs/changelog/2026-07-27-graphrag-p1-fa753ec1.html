Graph RAG P1：概念連結邊 + 圖檢索融合（1.0.82 → 1.0.83）

  • 日期：2026-07-27
  • 版本：1.0.82 → 1.0.83
  • 類型：新增功能（Graph RAG 第一階段）

背景

延續《Graph RAG 導入分析與實作藍圖》(docs/strategy/2026-07-27-Graph-RAG導入分析與實作藍圖.md) 的 P1：把蒸餾階段既有的概念連結 WikiPage.LinkTitles（[[標題]]）具體化為可遍歷的邊，並在現有混合檢索加上第三路「圖檢索」，讓「跨文件關聯 / 多跳」問題答得更好。低風險、沿用既有資產、無 LLM 抽取、無審核 UI。

變更

  1. 新增邊表 GraphEdge（AccessDatas/Models/GraphEdge.cs）：來源頁→目標頁（SourceWikiPageId/TargetWikiPageId 純索引整數、不設 WikiPage FK 以避免 SQL Server 多重串聯路徑）、Relation、Teams（權控，由來源頁複製）、KnowledgeSourceId（Cascade FK＋重建批次鍵）。BackendDBContext 加 DbSet 與三個索引。
  2. 新增 GraphEdgeService.RebuildForSourceAsync（Business/Services/Embeddings/）：解析 LinkTitles（TagStringHelper.ToList）→ 以標題對應到「已完成且現行」的 WikiPage（先同來源、再全域）→ 整批刪除/重建該來源的邊（冪等）。無 LLM。
  3. 建邊觸發：於既有重索引時機順帶重建——DistillationProcessor（蒸餾完成後）、WikiPageService.ApproveAsync/UpdateContentAsync（TryEnqueueSourceReindexAsync 之後）。失敗只記警告、不影響主流程。
  4. 圖檢索融合（RetrievalService.SearchGraphAsync）：以 vector∪keyword 命中中的「Wiki 層」頁為種子（強度＝該頁最佳 chunk 的 Vw*v+Kw*k）→ 沿 GraphEdge 1 跳取鄰居頁 → 把鄰居頁的「現行 Wiki 層」chunk 以種子強度加分。融合式改為 Vw*v + Kw*k + GraphWeight*g；RetrievalHit 加 GraphScore。問答端 KnowledgeBaseChatService 只讀 hit.Entity/hit.Score，不需改動。
  5. GraphWeight 熱調參數（貫穿 SystemSettings.Retrieval、RetrievalParamOverride、EffectiveRetrievalParams、RetrievalSettingsProvider、RagDiagnosticsService、/rag-diagnostics 頁）。預設 0.2（啟用），管理員可於檢索診斷頁熱調或設 0 關閉；試檢索面板新增「圖分」欄。appsettings.json 補 GraphWeight: 0.2。
  6. 雙庫 migration AddGraphEdge（AccessDatas Sqlite 與 AccessDatas.SqlServerMigrations 各一；含 GraphEdge 表與 RetrievalParamOverride.GraphWeight 欄）。
  7. appsettings.json：SystemVersion 1.0.82 → 1.0.83。
  8. 文件：本 changelog、開發慣例與限制速查.md 新增 Graph RAG 不變量、藍圖 §9 標記 P1 已實作。

安全與相容（leak=0 紅線）

  • 圖遍歷全程套團隊權控：邊查詢（e.Teams）與鄰居 chunk 查詢（x.Teams）皆用 TagStringHelper.BuildTeamAccessPredicate，並對齊 as-of 版本與查詢期 SourceIds/Categories/Teams 篩選——非管理員不會被加分到越權 chunk（已由 GraphPath_DoesNotLeakOtherTeamNeighbor_ZeroLeak 測試釘住）。
  • 設計為「新表＋旁掛管線＋不動既有檢索預設」：GraphWeight 設 0 即回到純混合檢索（GraphWeightZero_DisablesGraphPath 測試）。
