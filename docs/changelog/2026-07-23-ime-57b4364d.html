修正聊天輸入框注音（IME）組字被中斷（1.0.35）

  • 日期：2026-07-23
  • 版本：1.0.34 → 1.0.35

摘要

修正「知識庫問答」與「知識來源 AI 對話」兩個聊天頁的提問輸入框：使用注音（或其他 IME）輸入法時，組字尚未完成即被中斷、殘缺注音符號被當文字吞入，導致中文無法正常輸入。

根因

聊天輸入框用 AntDesign <TextArea> 但採「單向 Value="@userInput" ＋ OnInput 逐鍵更新」。每按一鍵即更新 userInput，Blazor 事件結束後自動 re-render，因 Value 為受控屬性，重繪會把值寫回 <textarea> DOM；在 Blazor Server（SignalR 非同步往返）下，此寫回落在 IME 組字進行中時會取消／提交 composition，打斷輸入。標題等欄位用 <Input @bind-Value>（onchange、失焦才更新）則不受影響。

當初改用 OnInput 是為了讓「送出」鈕即時啟用，代價即為 IME 中斷。

修正

  • 兩頁 <TextArea> 由 Value + OnInput 改回 @bind-Value="userInput"（走 onchange，組字期間不回寫 DOM），與正常標題欄位一致，IME 安全。
  • 「送出」鈕移除 Disabled（空白判斷），改為永遠可點；SendAsync 開頭已擋 isStreaming 與空白，點空白不動作。使用者打完字點送出時，滑鼠按下先使輸入框失焦提交值，SendAsync 讀到的即為完整內容。
  • 移除不再引用的 OnUserInput 方法。

檔案：Components/Views/KnowledgeBase/KnowledgeBaseChatView.razor（＋.razor.cs）、Components/Views/KnowledgeSources/KnowledgeSourceChatView.razor（＋.razor.cs）。

備註

  • 無資料模型變更，不需要資料庫 migration。
  • ContentEditDialog（清洗結果編修對話窗）有相同成因，但因需即時 Markdown 預覽，不適合單純 @bind-Value，本次不處理；日後如要修需採「組字守衛（composition guard）」技法。
