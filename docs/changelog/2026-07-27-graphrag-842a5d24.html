背景

Graph RAG P1～P6 在 2026-07-27 單日連續交付六個版本（1.0.83 → 1.0.88），程式與 migration 都完整，但文件層落後。盤點後確認四類落差：

  1. 索引沒跟上：docs/README.md 的 changelog 分區最新只到 1.0.80——GraphRAG 六篇＋分析報告篇＋ 1.0.81／1.0.82 共九筆完全沒有索引條目；docs/changelog/README.md 反而是齊的。docs/guides/EFCore.md 的 migration 清單只有 P5／P6 兩筆，缺 P1／P2／P3 三筆。
  2. 索引描述過時：三處都寫「P1～P3 實作藍圖」，但該藍圖實際已寫到 P6。
  3. 策略文件敘述已被實作推翻：四份文件仍寫著「GraphRAG 為未來選配／非近期範圍」「待補關聯查詢／知識圖譜」「唯一缺口是跨文件多跳推理」「非目標（YAGNI）」；docs/planning/12 的 DIS-3 連結圖資料表 仍標 ⬜，但該項實質已由 P1 的 GraphEdge 完成。
  4. 核心技術文件零覆蓋：docs/architecture/知識庫RAG設計與執行.md 完全未提圖檢索，但 RetrievalService 的融合式早已改為三路；根 README.md 除一條文件連結外沒有任何 Graph RAG 功能介紹；docs/features/知識百科與WikiLink.md 未說明 LinkTitles 的下游用途。

這類落差的風險是「讀者會相信文件而不去核對程式」——例如照 EFCore.md 的清單盤點 migration 會漏掉三筆、看 03-知識庫架構研究與建議 會以為圖譜還沒做。
