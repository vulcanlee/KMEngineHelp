管理者日誌下載頁：依時間區間打包 zip 下載（1.0.11 → 1.0.12）

  • 日期：2026-07-18
  • 版本：1.0.11 → 1.0.12
  • 類型：新功能（管理員維運：網頁打包下載系統日誌）
  • 對應 commit：e17727f（本篇為補建之功能紀錄）

需求

出問題時支援人員常需要「事發時段的系統日誌」；先前只能登入伺服器翻 C:\temp\Logs\ 資料夾人工挑檔。本次新增管理員專用頁面：選「起始時間～結束時間」，系統把該區間的 NLog 日誌逐筆過濾、合併打包成 zip 直接下載。

變更

  • 服務層：新增 LogArchiveService——讀取 NLog 應用程式日誌（每日輪替、保留 30 天），逐筆（entry）依時間戳過濾（含起訖端點）、例外堆疊等多行內容完整保留，依時間排序合併為單一 .log 後封裝 zip；zip 檔名 logs_{yyyyMMddHHmm}-{yyyyMMddHHmm}.zip。區間無資料仍產出（空日誌檔）。
  • API：新增 LogArchiveController（GET /api/LogArchive/download?from&to）：伺服器端驗證管理員身分（非管理員 403）、參數與區間檢核，回傳 zip 串流。
  • 頁面：新增 /log-download（LogDownloadPage ＋ LogDownloadView）：起始／結束時間選擇器（預設最近一小時）＋「下載」鈕，以整頁導航呼叫下載 API（Cookie 帶入）；非管理員進頁顯示「您沒有權限下載系統日誌。」
  • 驗證與限制：未選時間→「請選擇起始與結束時間。」；起始晚於結束→「起始時間不可晚於結束時間。」；區間上限 31 天；合併後未壓縮超過 200 MB →「選取範圍的日誌量過大，請縮小時間區間。」
  • 選單：Menu.json 系統管理群組新增「日誌下載」（id 410、icon download、adminOnly）；MenuIconTests 允許清單同步。
  • DI：ServiceCollectionExtensions 註冊 LogArchiveService。
  • 文件：operations/日誌與設定檔說明.md 補日誌下載段落；architecture/開發慣例與限制速查.md 同步。
  • appsettings.json 版本標記 1.0.11 → 1.0.12。

已知限制

  • 日誌檔保留 30 天（每日輪替），超過保留期的區間拿不到已清除的日誌。
  • 200 MB 為合併後未壓縮上限，超限請縮小時間區間分次下載。

驗證

  • LogArchiveServiceTests 涵蓋：時間戳過濾（含端點）、多行例外堆疊保留、排序合併、區間/大小上限、zip 檔名與空區間行為。
  • 端到端：管理員可下載並解壓對照操作紀錄；非管理員頁面與 API 皆被擋（403）。
  • 操作說明已於 1.0.12 文件同步（見 三大操作手冊同步）納入三份操作指南。
