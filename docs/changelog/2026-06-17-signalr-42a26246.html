提高 SignalR 訊息上限，修復編修長逐字稿時畫面閃爍（0.2.81）

  • 日期：2026-06-17
  • 版本：0.2.80 → 0.2.81
  • 類型：缺陷修正 / 基礎設定

問題

於「編修逐字稿」對話窗點選文字仍造成畫面不斷閃爍，瀏覽器主控台持續出現： Error: Cannot send data if the connection is not in the 'Connected' State. （堆疊顯示 ant-design-blazor.js → invokeMethodAsync → beginInvokeDotNetFromJS）

0.2.80 移除右側 Markdown 預覽後，問題仍在 —— 證明預覽並非閃爍主因。

真正根因

本系統為 Blazor Server（Interactive Server，SignalR circuit）。Program.cs 未設定 MaximumReceiveMessageSize，沿用 SignalR 預設 32KB 上限。

當很長的逐字稿載入 AntDesign <TextArea> 後，元件把整段大字串由用戶端同步回伺服器（AntDesign JS interop 於輸入／焦點事件回呼 .NET，挾帶整段文字）。訊息超過 32KB → SignalR hub 中斷 circuit → Blazor 進入重連迴圈（畫面閃爍），用戶端後續送出即拋 Cannot send data ... 'Connected' State。

失敗方向是 client → server 的接收上限，因此移除 server→client 的預覽渲染無法解決。

修正

Program.cs：於 AddInteractiveServerComponents() 後鏈接 AddHubOptions，提高接收訊息上限至 10MB：

builder.Services.AddRazorComponents()
.AddInteractiveServerComponents()
.AddHubOptions(options =>
{
    options.MaximumReceiveMessageSize = 10 * 1024 * 1024;
});
  • 10MB 足以容納數小時逐字稿（一般數十～數百 KB），仍為有限上限（非無限），內部系統安全寬裕。
  • 同時涵蓋其他長內容情境（編修產生結果、文件 Markdown 等可能 >32KB）。

與 0.2.80 的關係

0.2.80 的 ShowPreview 參數（逐字稿不顯示 Markdown 預覽）維持不變，定位為純文字 UX 改善，而非閃爍修正；本次方為閃爍／斷線的真正解法。

影響範圍

  • 變更檔案：Program.cs（SignalR Hub 設定）。
  • 無模型／資料庫變更，不需 migration。

驗證

  1. 對逐字稿很長（明顯 >32KB）的紀錄點「編修逐字稿」：點選／捲動／連續輸入不再閃爍，主控台無 Cannot send data ...、無 circuit 重連；儲存正確寫回。
  2. 回歸：長的「編修產生結果」內容可正常編修、預覽、儲存，不閃爍。
