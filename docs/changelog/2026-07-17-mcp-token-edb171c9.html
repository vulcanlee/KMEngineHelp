變更紀錄

MCP 問答寫入聊天紀錄並補 Token 用量歸屬（1.0.6 → 1.0.8）

  • 日期：2026-07-17
  • 版本：1.0.6 → 1.0.8（1.0.7 未獨立發布，於本次一併升至 1.0.8）
  • 類型：新功能（MCP Server 可觀測性補齊：聊天紀錄與 Token 歸屬）

需求

透過 MCP Server 進來的知識庫問答，先前在 /chat-logs 看不到、/token-usage 報表也認不出是 MCP 來源，形成可觀測性缺口。本次補齊：讓 MCP 問答比照 Blazor 問答一樣被完整記錄與計量，並正確歸屬到呼叫者與作業。設計與使用說明見 MCP Server 整合設計與使用指南、MCP 服務使用說明書 §6.6。

變更

  • 聊天紀錄：knowledge_ask 每次呼叫寫入 LlmChatLog（Origin=Mcp，標示「MCP Server 問答」），全文含呼叫端 API Key 名稱、問題、回傳給 Agent 的檢索參考資料 context 與出處；明確標註「伺服器端未生成 AI 答案」（答案由 MCP 用戶端 LLM 生成）。
  • 身分解析：新增 Web/Mcp/McpIdentityResolver.cs——由 HttpContext 的 ClaimTypes.Sid 反查使用者、填入 CurrentUserService，修正 MCP 情境下稽核／紀錄 user=null 的缺口。
  • Token 歸屬：knowledge_ask / knowledge_search 在工具方法自身範圍 OperationContext.Push（Operation=McpKnowledgeAsk / McpKnowledgeSearch），讓檢索的 Embedding／QueryRewrite token 正確歸屬到呼叫者與作業（AsyncLocal 必須與 await 同一 scope 才會流到底層 client）。
  • 顯示端：/chat-logs 新增來源標籤與篩選、/token-usage 作業標籤新增 MCP 選項。
  • 文件：MCP服務使用說明書 §6.6 補「MCP 聊天紀錄與 Token 歸屬」，說明生成 token 在用戶端、不在本系統計量。

主要異動檔案

  • AccessDatas/Models/LlmChatLog.cs、LlmTokenUsage.cs（新增 MCP 來源／作業常數）
  • Business/Services/DataAccess/ChatLogService.cs
  • Web/Mcp/McpIdentityResolver.cs（新增）、KnowledgeAskTool.cs、KnowledgeSearchTool.cs
  • Web/Components/Views/ChatLogs/ChatLogsView.razor(.cs)、Views/TokenUsage/TokenUsageView.razor.cs

已知限制

  • 生成 token 不在本系統計量：MCP 用戶端 LLM 產生的答案 token 由用戶端計量，本系統只計檢索期（Embedding／QueryRewrite）token。
  • 稽核 account：KnowledgeBaseQueryAudit 的 account/name 仍以工具日誌 user= 補足；IsAdmin/Teams 正確。

驗證

  • 無資料庫 migration（Origin/Operation 皆為字串常數，未新增 Entity 欄位）。
  • dotnet test 通過（含權控不變量、四工具、LoggingConventionTests）。
  • appsettings.json 版本標記 1.0.6 → 1.0.8。
