Toast 通知全站改右下角＋工作項目可靠追溯來源會議（1.0.24）

  • 日期：2026/07/21
  • 版本：1.0.23 → 1.0.24
  • 類型：體驗一致化修正 ＋ 資料追溯強化
  • 觸發來源：使用者回報兩問題——(1) 上傳錄音後背景轉錄的逐則進度 toast 出現在螢幕中間偏上，與系統其他右下角通知不一致；且尾端多則會「一次大量冒出」。(2) 由會議待辦建立的工作項目，其描述內「（來源會議：111）」在會議標題改名（111→222）後仍顯示舊名，日後無法回溯來源會議。
  • 相關：背景管線處理過程逐則 toast 通知（1.0.23）、會議 AI 自動化、會議欄位擴充與進度統計

一、問題一：toast 位置不一致

根因

系統用兩套 AntDesign 服務：NotificationService（可設 Placement = BottomRight，右下角卡片，全站結果通知都用它）與 MessageService（固定置中頂部、無位置選項）。少數路徑走 MessageService，就是那些置中的 toast。背景管線進度（PipelineProgressToaster）正是其一。

另發現一個放大不一致的樣板：不少 CRUD 檢視同一動作同時彈兩次——先一則右下角 NotificationService 卡片，緊接著又一則置中 MessageService（多為「新增成功」），屬純重複。

做法：全站掃描，一律改右下角

以 messageService.*Async() 為線索全站清點約 90 處，分三類處理：

類別情形處理
A（重複雙彈）已有相鄰右下角通知，另有一則重複的置中訊息刪除該置中訊息；若 MessageService 因此不再被使用，一併移除其注入
B（唯一回饋）該處只有置中訊息、無相鄰通知改為 notificationService.Open(new NotificationConfig{ …, Placement = BottomRight })；5 個原本未注入 NotificationService 的檔案補上注入
C（管線進度）PipelineProgressToaster 逐則進度改走 NotificationService 右下角，並加短存留 Duration = 3 避免堆疊

樣式採逐處內嵌 NotificationConfig，吻合程式庫既有約 137 處內嵌寫法，不另建 helper。跳過未註冊的範例檔 RoleViewViewSample.razor.cs。轉換過程另修好 6 處「半遷移殘留」（Media/Doc/Image 檢視中，同一動作已有右下角通知卻又留一則置中訊息）——刪掉多餘那則，避免兩則相同卡片連彈。

進度流暢度：錯開依序淡入

管線進度是「每 5 秒輪詢、一次撈齊該批新事件」的機制，尾端幾則（段完成→簡繁轉換→存逐字稿→轉錄完成）在伺服器端幾秒內接連發生，於是同批一次爆出。改為 PumpAsync 內每則間隔 StaggerDelayMs = 600（毫秒）依序彈出，卡片從右下角順勢級聯淡入。保持 5 秒輪詢不變（不增伺服器負載）。

cursor 在彈出前已推進，延遲期間下一輪不會重撈；各檢視 PollTickAsync 的 isPolling 旗標保證不重疊；8 則 × 600ms ≈ 4.8 秒 < 5 秒間隔，收斂安全。

二、問題二：工作項目可靠追溯來源會議

根因

MeetingActionItemService.BuildDescription 把 meeting.Title 以字串內插成「（來源會議：{標題}）」寫進 MyTask.Description——這是建立當下的標題快照。MyTask 與 Meeting 之間沒有任何 Id 關聯，會議改名後快照不會更新，也無從回溯。

做法：軟參照 ＋ 即時解析

  • MyTask 新增 int? SourceMeetingId，軟參照、不做硬 FK——比照既有 Meeting.SourceTranscriptionId 慣例，避免全域 Restrict 刪除政策讓「有工作掛著的會議」刪不掉，讀取端容忍孤兒 Id。
  • 建立工作項目時寫入 SourceMeetingId = meeting.Id，並停止把標題快照寫進描述（描述只留草稿本文）。
  • MyTasService.GetAsync 依 SourceMeetingId 即時查出會議的目前標題填入 SourceMeetingTitle（不落地），並套團隊權控：會議已刪或無權時不外洩標題／連結。
  • 工作項目編輯視窗新增唯讀「來源會議」欄位，顯示目前標題並可點擊跳轉（帶 ?openMeetingId= 導向 /meeting，由會議頁自動開啟該筆編輯視窗）。標題改名 111→222 後，欄位自動顯示 222。

已知限制

  • 不回填：既有工作項目仍保留舊的「（來源會議：…）」描述文字且 SourceMeetingId 為 null，不會出現新欄位。
  • 軟參照：來源會議被刪或無團隊權限時，欄位顯示灰字後備、無連結。

三、變更檔案

Fix 1（toast）

  • Web/Components/Views/Commons/PipelineProgressToaster.cs：改注入 NotificationService、右下角、Duration = 3、StaggerDelayMs = 600 錯開淡入。
  • 約 28 個檢視檔：類別 A 刪除重複置中訊息＋孤兒清理；類別 B 改右下角通知（MainLayout、LogSettingsView、LogDownloadView、KnowledgeSourceChatView、KnowledgeBaseChatView 另補注入 NotificationService）。

Fix 2（來源會議）

  • AccessDatas/Models/MyTask.cs：新增 SourceMeetingId（軟參照）。
  • Business/Services/DataAccess/MeetingActionItemService.cs：寫入 SourceMeetingId、移除標題快照與 BuildDescription。
  • Business/Services/DataAccess/MyTasService.cs：GetAsync 即時解析會議目前標題（套權控）。
  • Models/AdapterModel/MyTasAdapterModel.cs：新增 SourceMeetingId／SourceMeetingTitle。
  • Business/Models/AutoMapping.cs：SourceMeetingTitle 標記 Ignore（由服務填入）。
  • Web/Components/Views/Projects/MyTasEditModal.razor(.cs)：唯讀可點「來源會議」欄位＋OpenSourceMeeting。
  • Web/Components/Views/Projects/MeetingViewView.razor.cs：處理 ?openMeetingId= 深連結自動開啟。

Migration：AddMyTaskSourceMeeting，Sqlite 與 SqlServer 雙 provider，各只新增 SourceMeetingId 單欄。

四、驗證

  • dotnet build 0 錯誤；dotnet test 629 項全通過，零迴歸。
  • 兩份 migration 產出乾淨，只有對 MyTas 表的單欄 AddColumn，未夾帶 MyTas/MyTask 非預期 rename。
  • 全站僅剩未註冊的 RoleViewViewSample.razor.cs 一處 MessageService（刻意略過）。

待實機驗證：上傳錄音後進度 toast 於右下角依序淡入；工作項目「來源會議」欄位在會議改名後顯示新名並可跳轉；來源會議刪除／無權時顯示灰字後備。
