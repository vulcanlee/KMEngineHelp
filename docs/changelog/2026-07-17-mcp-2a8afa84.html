變更紀錄

系統健康監控新增 MCP Server 與 4 項基礎設施檢查（1.0.10 → 1.0.11）

  • 日期：2026-07-17
  • 版本：1.0.10 → 1.0.11
  • 類型：新功能（/system-health 儀表板新增 5 個健康檢查項）

需求

/system-health 原本 16 個檢查項未涵蓋「對外整合與 AI 基礎設施」的就緒狀態。本次新增 MCP Server 檢查，並補上 4 個現有未監控的缺口，讓管理員在一頁看出這些依賴是否就緒。檢查項數量 16 → 21。設計與現況見 系統健康監控 PRD、系統健康監控功能說明、系統監控與健康檢查指南。

變更

新增 5 個檢查方法於 Web/Health/SystemHealthService.cs（沿用既有 CreateItem 工廠，燈號/分數/頁面自動生效）：

檢查項權重綠 / 黃 / 紅
MCP Server8綠＝McpAccess policy＋McpApiKey scheme＋/mcp 端點＋≥1 把啟用金鑰；黃＝0 把啟用金鑰（JWT/Cookie 仍可入，X-API-Key 無法）；紅＝policy/scheme/端點缺失
分散式快取8Memory→綠；Redis 以 IDistributedCache 寫入/回讀 ping 實測，成功綠、失敗紅
AI 生成/嵌入 Provider10複用 OpenAISettings.IsChatLlmConfigured/IsEmbeddingConfigured 依 Cloud/Local 分流；未就緒紅
RAG 檢索設定6沿用 RetrievalSettingsProvider 規則；門檻越界紅、權重和非 1 黃
背景管線8七條匯入/處理背景服務都註冊→綠、缺任一→紅（僅檢查註冊，未偵測卡死/積壓）
  • SystemHealthService 建構子新增注入：IOptions<CacheSettings>、IDistributedCache、IAuthorizationPolicyProvider、IAuthenticationSchemeProvider、IEnumerable<EndpointDataSource>、IEnumerable<IHostedService>（皆框架既有服務，不需改 DI 註冊）。總權重 160 → 200。
  • appsettings.json SystemVersion 1.0.10 → 1.0.11。

已知限制

  • 背景管線僅檢查「是否註冊/實例化」；BackgroundService 無公開心跳、佇列介面無 Count，偵測卡死/佇列積壓需另改介面，本次不做。
  • 分散式快取因未註冊 IConnectionMultiplexer，Redis 只能以 IDistributedCache 探測（非直連 multiplexer 狀態）。
  • RAG 檢索設定檢查的是 appsettings 靜態值；使用者於 DB override 的生效值可能不同（evidence 已註明）。

驗證

  1. dotnet build（Web）0 錯誤。
  2. dotnet test 全數通過（既有 558 + 新增 1 個整合測試 SystemHealthReportTests：以測試 host 解析 ISystemHealthService 執行 GetReportAsync，斷言 5 個新 Category 均出現、背景管線與快取為健康、MCP 項存在且不擲例外）。
  3. 實跑：Web 啟動正常（SystemVersion=1.0.11、七條背景服務啟動、無 DI/啟動例外）。
  4. scripts/Test-DocsEncoding.ps1 全綠。
