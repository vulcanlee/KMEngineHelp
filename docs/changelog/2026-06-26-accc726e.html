階段三步驟 3：Chunker + 嵌入索引管線（0.2.125）

  • 日期：2026/06/26
  • 版本：0.2.124 → 0.2.125
  • 對應設計：階段三：知識庫與 RAG 設計規格 §5、§6；路線圖步驟：strategy/12 §12.2 步驟 3

摘要

階段三第三步驟：把嵌入用戶端（步驟 1）與向量存取層（步驟 2）接成自動化索引管線。知識來源蒸餾完成後，自動把「清洗內容」與「已核准 Wiki 頁」切塊、嵌入、寫入 VectorEmbedding，支援重啟回復、取消、增量重建與孤兒清除。完全仿照既有「知識蒸餾」三件套的結構與慣例。

設計重點

  • 切塊器 Chunker：段落/語意感知（以空行切段落、追蹤最近 Markdown 標題作為 AnchorRef、累積至目標長度才切、保留少量重疊、超長段落硬切）。切塊參數為類別常數（待 PoC 調整，規格 T2）。
  • 三件套（仿 Distillations）：IEmbeddingIndexQueue/EmbeddingIndexQueue（Channel、Singleton）、EmbeddingIndexBackgroundService（消費迴圈 + RecoverPendingAsync 重啟回復 + 取消標記）、EmbeddingIndexProcessor（重試/取消/狀態機 + 增量 + 孤兒清除）。
  • 增量重建：以 (SourceLayer, WikiPageId, ContentHash) 比對既有向量，僅對新增/變更 chunk 呼叫 IEmbeddingClient.EmbedAsync（批次），不變者不重嵌；移除的 chunk 即孤兒清除。向量寫入前 VectorMath.Normalize（L2 正規化，規格 §4.4）。
  • 觸發：DistillationProcessor 蒸餾成功後，若 IsEmbeddingConfigured() 即設來源 EmbeddingIndexStatus=等待中 並入列；未設定則略過（問答退回單一來源模式，規格 §4.3）。
  • FK 孤兒清除（關鍵正確性）：VectorEmbedding.WikiPageId 為 Restrict FK；重蒸餾刪除 Wiki 頁前、以及 WikiPageService.DeleteAsync 刪單頁前，皆先清除對應 Wiki 層向量，避免外鍵違規。Cleaned 層向量保留，交由增量 diff 處理。

變更內容

  • 狀態欄位：KnowledgeSource 新增 EmbeddingIndexStatus/EmbeddingIndexProgressPercentage/EmbeddingIndexErrorMessage/IndexedAt；KnowledgeSourceAdapterModel 新增對應狀態常數（待索引/等待中/處理中/已索引/失敗/已取消）。雙 migration AddEmbeddingIndexStatus。
  • 管線（KnowledgeExtraction.Business/Services/Embeddings/）：Chunker、IEmbeddingIndexQueue/EmbeddingIndexQueue、EmbeddingIndexProcessor；VectorMath 新增 Normalize；PipelineNames.EmbeddingIndex。
  • 背景服務：KnowledgeExtraction.Web/BackgroundServices/EmbeddingIndexBackgroundService.cs。
  • 觸發與清理：DistillationProcessor 注入 IEmbeddingIndexQueue＋IOptions<OpenAISettings>、成功後入列、重蒸餾清 Wiki 層向量；WikiPageService.DeleteAsync 清對應向量。
  • DI：ServiceCollectionExtensions 註冊 Chunker/IEmbeddingIndexQueue/EmbeddingIndexProcessor；Program.cs 加 AddHostedService<EmbeddingIndexBackgroundService>()。
  • 測試：ChunkerTests（切塊/標題錨點/長文切多塊/超長硬切/空輸入）、VectorMathTests 補 Normalize、EmbeddingIndexProcessorTests（索引兩層、增量不重嵌、內容變更孤兒清除、未核准頁不索引、退回頁向量被清、未設定略過、已取消不動作）。全套 339 個測試綠燈。

後續

依 strategy/12 §12.2，下一步為步驟 4：混合檢索（IRetrievalService：向量 + 全文並行、分數融合、檢索層即套團隊權控、雙層取用），驗收越權洩漏 0 命中。
