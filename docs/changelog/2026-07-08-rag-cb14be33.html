需求

/rag-diagnostics 已有分佈/門檻/近期稽核紀錄。診斷手冊 §四 另規劃三塊未做：索引健康、症狀自檢、試檢索。補完後 /rag-diagnostics 成為完整「RAG 維運中心」。

變更（服務集中、View 薄）

商業層（RagDiagnosticsService 擴充，注入 IRetrievalService／IRecordAccessScopeProvider／IOptions<OpenAISettings>）

  • GetIndexHealthAsync()：每知識來源一列——清洗/蒸餾/索引狀態、已核准 Wiki 數、Cleaned/Wiki chunk 數（VectorEmbedding.GroupBy）、最後索引時間（Max(UpdatedAt)）、紅黃綠燈（已清洗但無 chunk→red；已清洗未索引或內容過期→yellow；否則 green）+ 是否已設定嵌入（OpenAISettings.IsEmbeddingConfigured()）。
  • RunSelfCheckAsync()：自動列出當前問題與建議（未設嵌入、已清洗但索引為空、部分未索引、內容過期、樣本不足）。
  • TryRetrieveAsync(query)：跑混合檢索 + 兩段式信心判定，回候選 chunk 的向量/關鍵字/融合分、層別、AnchorRef、片段。不呼叫 LLM、不寫稽核；以目前使用者 scope（管理員→看全部）執行。
  • 新 POCO：IndexHealthReport/Row、SelfCheckFinding、TrialRetrievalResult/Hit。

UI 層

  • RagDiagnosticsView 新增三區：索引健康（燈號表 + 未設嵌入提示）、症狀自檢（findings 清單 + 重新自檢）、試檢索（問句輸入 + 候選 chunk 分數表 + 信心徽章 + 退化提示）。沿用頁面 CheckIsAdmin 守門與選單 adminOnly。

測試

  • RagDiagnosticsTests 新增 4：索引健康紅/綠燈與計數、症狀自檢回報、試檢索命中映射與信心、空問句→Insufficient（用 fake IRetrievalService）。相關 12 個測試全綠。

影響範圍

  • 進度：EVAL-4 ✅ 完成（/rag-diagnostics 成維運中心）。
  • 無資料表／欄位／migration（複用既有表）；無新權限（沿用 adminOnly + CheckIsAdmin）。
