變更紀錄

RAG 診斷頁：topScore 分佈統計、門檻建議與可套用門檻（EVAL-3 + RQ-1 + EVAL-5 門檻切片）（0.3.2→0.3.3）

  • 日期：2026-07-08
  • 版本：0.3.2 → 0.3.3
  • 類型：新增功能（RAG 補強清單）

需求

EVAL-2 已把問答稽核持久化但無讀取端。本次一次交付相扣三項：EVAL-3（topScore 分佈統計）、RQ-1（依分佈建議門檻 + 效果模擬）、EVAL-5 門檻切片（在頁面上直接套用兩段式門檻、熱生效）。

變更

資料層

  • 新增實體 RetrievalSettingOverride（單列覆蓋表：RejectThreshold?／LowConfidenceThreshold?／UpdatedAt／UpdatedBy）+ DbSet；雙 migration AddRetrievalSettingOverride。

商業層

  • IRetrievalSettingsProvider + RetrievalSettingsProvider：解析「有效門檻」（DB 覆蓋 → appsettings → 預設），提供 Set／Clear（驗證 0 ≤ reject ≤ lowConf ≤ 1）。
  • KnowledgeBaseChatService.RetrieveAsync 改為每輪取有效門檻用於兩段式判定與稽核記錄 → 頁面套用後下一則問答即熱生效。移除建構式對 IOptions<SystemSettings> 的直接門檻讀取（改由 provider，最小爆炸半徑，不動 RetrievalService 的 TopK/權重）。
  • 純函式 TopScoreStatsCalculator + POCO TopScoreStatsReport：直方圖、Min/P10/P25/Median/P75/P90/Max/Mean（僅計有命中）、各信心佔比、啟發式建議（P10/P35，樣本 ≥20 才給）、門檻效果模擬。
  • RagDiagnosticsService：聚合報告 + ApplyThresholdsAsync／ResetThresholdsAsync。

UI 層

  • 管理員頁 /rag-diagnostics（RagDiagnosticsPage + RagDiagnosticsView）：CheckIsAdmin() 擋人、由網址進入（不進 Menu.json、不動權限樹三處同步，比照 /system-health）。呈現分佈卡片、百分位表、直方圖、目前 vs 建議門檻、效果模擬表，及「套用／套用建議值／回復預設」。

測試

  • 新增 TopScoreStatsCalculatorTests（6）、RagDiagnosticsTests（provider 4 + service 2）、KnowledgeBaseChatServiceTests 熱套用測試（1）。相關 28 個測試全綠。

校準誠實原則

  • 建議門檻為啟發式起點（P10/P35），非以「庫內/庫外」標註校準；嚴謹校準仍需 RAG 評測黃金集（EVAL-1）。頁面與文件均明示此限制。

影響範圍

  • 進度：EVAL-3 ✅、RQ-1 ✅ 完成；EVAL-4／EVAL-5 部分完成（門檻切片）。詳見 docs/planning/12-... §〇。
  • 同步更新 docs/operations/RAG問題診斷手冊.md、docs/architecture/知識庫RAG設計與執行.md、docs/guides/RAG補強修正測試指南.md。
  • appsettings.json SystemVersion 0.3.2 → 0.3.3；需套用雙 migration。

已知落差（記錄備查）

  • 稽核 Teams 為逗號分隔（非 TagStringHelper 換行格式），故本頁為管理員全庫統計；未來要做「非管理員看自家團隊統計」需先統一格式。

驗證

  1. dotnet test --filter "KnowledgeBaseChatServiceTests|TopScoreStatsCalculatorTests|RagDiagnosticsTests" 綠燈（28 通過）。
  2. dotnet build 成功。
  3. 手動：問數題 → /rag-diagnostics 看分佈/建議/模擬 → 套用門檻 → 再問確認改判 → 回復預設；非管理員被擋。
  4. scripts/Test-DocsEncoding.ps1 全綠。
