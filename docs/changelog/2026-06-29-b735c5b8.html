變更紀錄

所屬專案改為選填、可清除（0.2.149–0.2.151）

  • 日期：2026/06/29
  • 版本：0.2.148 → 0.2.151

摘要

修正「工作項目」與「會議記錄」兩個維護頁的「所屬專案」欄位：

  • 工作項目：編輯時雖已設 AllowClear，但 AntDesign 1.6.0 的單選 Select（DataSource + @bind-Value 為 int?）清除 (x) 圖示不會穩定出現，導致選了專案後無法還原為「未指定」。
  • 會議記錄：所屬專案被強制必填（資料註解、FormItem、新增自動帶入第一個專案、服務端驗證共四層），新增時被迫輸入、編輯時無法取消。

兩頁改為選填且可清除：下拉清單最前面加入值為 null 的「（不指定專案）」選項，不再依賴不可靠的 AllowClear 圖示，並與表單既有的優先級/狀態欄位（皆用 SelectOption 子元素）一致。

變更內容

  • 移除 [Required]：MeetingAdapterModel.ProjectId、Meeting.ProjectId、MeetingCreateUpdateDto.ProjectId、MyTaskCreateUpdateDto.ProjectId。
  • MeetingViewView.razor / MyTasViewView.razor：所屬專案 Select 由 DataSource 改為 SelectOption 子元素，最前面加「（不指定專案）」（Value 為 null）；會議頁 FormItem 移除 Required。
  • MeetingViewView.razor.cs：OnAddAsync 移除「自動帶入第一個專案」邏輯。
  • MeetingService：移除「請選擇所屬專案」必填驗證；專案存在性檢查改為僅在有指定專案時才執行；AddAsync/UpdateAsync 加入 ProjectId <= 0 → null 正規化（與 MyTasService 一致）。
  • 新增雙 provider migration MakeMeetingProjectOptional：將 Meeting.ProjectId 由 NOT NULL 改為可空（SQLite 於 KnowledgeExtraction.AccessDatas、SQL Server 於 KnowledgeExtraction.AccessDatas.SqlServerMigrations）。
  • SystemVersion 升至 0.2.151 (2026/06/29)（0.2.149 完成程式碼/文件，0.2.150 補上 migration 修正啟動，0.2.151 修正「（不指定專案）」選取凍結）。
  • 修正選取凍結：「（不指定專案）」選項的 Value 由 null 改為哨兵值 0（AntDesign 1.6.0 無法處理 Value=null 的 SelectOption，選取會凍結 circuit）；編輯/新增載入時把 null 正規化為 0，存檔仍由服務端 <=0→null 還原為 NULL。

注意事項

  • EF Core 行為：[Required] 套在 int? 上會把欄位對映為 NOT NULL。MyTask.ProjectId 早已於前一提交以 MakeMyTaskProjectOptional 改為可空；Meeting.ProjectId 原本因 [Required] 為 NOT NULL，本次移除後須補產 MakeMeetingProjectOptional（雙 provider）才可空，否則啟動 Migrate() 會拋 PendingModelChangesWarning。
  • 子工作仍沿用父工作專案、編輯視窗不顯示所屬專案欄位，本次未更動。
  • 團隊權控（IRecordAccessScopeProvider / TagStringHelper）完全不受影響。
