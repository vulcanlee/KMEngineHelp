階段三步驟 1：嵌入用戶端與雲端/地端切換（0.2.123）

  • 日期：2026/06/26
  • 版本：0.2.122 → 0.2.123
  • 對應設計：階段三：知識庫與 RAG 設計規格 §4；路線圖步驟：strategy/12 §12.2 步驟 1

摘要

啟動知識庫五階段願景的階段三「知識庫與 RAG」第一個小步驟：建立嵌入（embedding）用戶端與雲端/地端切換設定，作為後續向量索引（步驟 2）、混合檢索（步驟 4）的基礎。完全沿用既有 OpenAIChatCompletionClient／ResolveChatLlm() 慣例（AddHttpClient + IOptions<OpenAISettings> + Bearer + 靜態方法便於測試 + TokenUsageFormatter 用量日誌 + 介面以 DI 綁定具體型別）。

設計重點

  • 對稱密集檢索：文件與查詢用同一模型、同一維度嵌入；維度固定 1024（schema 硬承諾 VECTOR(1024)）。
  • 雲端/地端可互換：雲端 text-embedding-3-large 帶 dimensions=1024；地端 bge-m3 原生 1024，不送 dimensions 參數。兩者皆 1024，切換不動 schema。
  • 供應者解析：EmbeddingProvider 留空時沿用 GenerationProvider，可獨立覆寫。
  • 無金鑰降級基礎：IsEmbeddingConfigured() 供後續索引管線判斷是否略過索引（步驟 3 接用）。

變更內容

  • 設定 OpenAISettings（KnowledgeExtraction.Models/Systems/OpenAISettings.cs）：新增 EmbeddingProvider、EmbeddingModel（預設 text-embedding-3-large）、EmbeddingDimensions（預設 1024）、EmbeddingTimeoutSeconds（預設 120）、LocalEmbeddingModel（預設 bge-m3）；新增 GetEmbeddingProvider()／ResolveEmbeddingLlm()／IsEmbeddingConfigured() 與 EmbeddingLlmConfig record（Dimensions 為可空，地端為 null）。appsettings.json 同步新增欄位。
  • 嵌入用戶端 IEmbeddingClient + OpenAIEmbeddingClient（KnowledgeExtraction.Business/Services/Embeddings/）：POST embeddings、Bearer、批次嵌入（一次多筆 text、回傳依 data[].index 排序）；靜態 BuildRequestBody／ParseEmbeddings 便於單測；輸入為空時不呼叫遠端；無金鑰擲出明確例外；用量走 TokenUsageFormatter。
  • DI：Program.cs 新增 AddHttpClient<OpenAIEmbeddingClient>（BaseAddress/逾時取自 ResolveEmbeddingLlm()）；ServiceCollectionExtensions 以 AddScoped<IEmbeddingClient>(sp => sp.GetRequiredService<OpenAIEmbeddingClient>()) 綁定。
  • 測試：新增 OpenAIEmbeddingClientTests（請求建構含/不含 dimensions、回應解析維度正確、依 index 排序、空 data 擲例外）；OpenAISettingsTests 補嵌入供應者解析與 IsEmbeddingConfigured。全套 310 個測試綠燈。

後續

依 strategy/12 §12.2，下一步為步驟 2：VectorEmbedding 實體 + 雙 migration（SQLite sqlite-vec／SQL Server VECTOR）+ IVectorStore/DualDbVectorStore（單測：upsert/search round-trip）。
