知識庫問答：查詢期依「知識來源／分類」篩選（0.3.21→0.3.22）

  • 日期：2026-07-11
  • 版本：0.3.21 → 0.3.22
  • 類型：新增功能（多客戶／多系統精準問答；無 migration）

需求

跨庫問答（/knowledge-base-chat）原本只靠「登入者團隊自動權控＋語意相似度」，無法在提問時把範圍縮到某幾個知識來源或某些分類（＝某客戶的某套系統）。本次加入查詢期範圍篩選與問答頁多選 UI，補足新手指南 §二十/§19.8 標示的「規劃中增強」。

變更

檢索層（向量＋關鍵字兩路徑皆套，疊加在團隊權控之上）

  • RetrievalQuery（IRetrievalService.cs）、VectorQuery（IVectorStore.cs）新增可選 IReadOnlyList<int>? SourceIds、IReadOnlyList<string>? Categories（預設 null＝不限）。
  • RetrievalService.SearchKeywordAsync（關鍵字路徑）與 DualDbVectorStore.SearchAsync（向量路徑）在既有 team／SourceLayer／ApplyEffective 之後加入：SourceIds → Where(x => SourceIds.Contains(x.KnowledgeSourceId))；Categories → 重用 TagStringHelper.BuildContainsAnyPredicate<VectorEmbedding>(x => x.Categories, ...)（精確成員、空集合回 _ => true）。SearchVectorAsync 建 VectorQuery 時帶入兩欄。
  • KnowledgeBaseChatService.RetrieveAsync 簽章新增 sourceIds/categories（相容預設）並帶入 RetrievalQuery。

UI 層

  • KnowledgeBaseChatView：設定面板新增「限定知識來源」（多選，DataSource 為使用者可存取的知識來源，值＝Id）與「限定分類」（多選）兩個 AntDesign Select；載入 CategoryService.GetAllEnabledNamesAsync() 與 KnowledgeSourceService.GetAsync（團隊權控內建）；SendAsync 帶入所選。留空＝在有權限的整個知識庫問答。

測試

  • 新增 RetrievalFilterTests（3 筆）：DualDbVectorStore.SearchAsync 依 SourceIds／Categories 正確縮小、留空回全部。
  • 全測試 496 通過、0 失敗。

範圍決策（誠實記錄）

  • 團隊權控永遠先套用，本篩選只在可見集合內再縮小、無法擴權；篩選留空＝現狀、完全相容。
  • 兩條檢索路徑都套（避免關鍵字路徑漏濾）。
  • 查詢期參數、無 schema 變更 → 無 migration（VectorEmbedding.KnowledgeSourceId/.Categories 欄位已存在）。

影響範圍

  • docs/guides/新手完整操作指南.md §19.8、§20.2/§20.3/§20.4。
  • docs/guides/AI知識問答使用指南.md §三設定面板。
  • docs/architecture/知識庫RAG設計與執行.md（查詢期範圍篩選段）。
  • appsettings.json SystemVersion 0.3.21 → 0.3.22。

驗證

  1. dotnet build 成功、dotnet test 綠（496 通過，含 RetrievalFilterTests）。
  2. 手動：/knowledge-base-chat 展開設定，不選＝跨可見庫；選知識來源→答案與出處只來自該來源；選分類→只來自該分類；併用取交集。
  3. 非管理員：選了無權限來源也不外洩（團隊權控先行）。
  4. scripts/Test-DocsEncoding.ps1 全綠。
