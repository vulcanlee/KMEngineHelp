選單舊名補漏與會議紀錄型素材修正（1.0.70）

  • 日期：2026-07-26
  • 版本：1.0.69 → 1.0.70
  • 類型：顯示標籤補漏（無邏輯變更）＋資料損毀修正＋過時標記補漏＋腳手架腳本修正

起因

盤點 docs/guides/ 22 份文件與程式碼的落差時，發現兩組「加了新東西卻沒補齊所有相關處」的漏改，且都會實際影響使用者：

  1. 1.0.58「畫面標籤與選單名稱統一」其實沒改完，但該份 changelog 的驗證段落卻寫「grep 確認程式中已無舊選單名作為顯示標籤（0 筆殘留）」。
  2. 1.0.25 新增第四種素材型別「會議紀錄」時只補了兩處，漏掉的其中一處會造成真實資料損毀。

一、更正 1.0.58 的不實驗證宣稱

2026-07-25 畫面標籤與選單名稱統一 的「驗證」第 2 點宣稱 0 筆殘留，這個結論是錯的。原因是該次採用的規則是「只改目前值剛好等於舊選單名」的標籤，於是下列同樣是使用者可見舊名的字串全被排除在 grep 之外：

  • 複合字串：新增文件萃取／修改文件萃取／新增音訊轉錄／修改音訊轉錄（值不等於 文件萃取，而是包含它）
  • 被引號包住的指路字串：請至『知識來源管理清單』按『建立索引』
  • 從來不是選單名、但同樣過時的字串：圖片辨識（作業別／儀表板標籤）、系統健康檢查（此頁名從未存在，選單一直是「系統健康監控」）

另外 KnowledgeSourceView.razor 的「素材型別」下拉被列在該次的問題清單裡，但 git log -L 確認它從未被修改過 —— 一直是 音訊轉錄／文件萃取／圖片清單。

沿用 1.0.57 Menu.json 的權威改名對照：音訊轉錄→影音轉逐字稿、文件萃取→文件轉文字、圖片清單/圖片辨識→圖片解讀、知識庫問答→AI 知識問答、知識來源管理清單→知識來源加工、AI 聊天紀錄→問答稽核明細、對話總覽→完整對話紀錄、清洗設定檔→清洗規則設定、系統健康檢查→系統健康監控。

三、資料一致性巡檢會刪掉正常的會議紀錄成員（資料損毀）

DataConsistencyService.GetReportAsync 的 existing 字典只列了三種素材型別（註解也自承「比對三個素材表」），沒有 TypeMeeting。因此 ItemType == "Meeting" 時 TryGetValue 直接回 false → 每一筆正常的會議紀錄成員都被判定為孤兒；而 CleanupOrphansAsync 會把報表上的孤兒全部 RemoveRange。

後果：管理員在「系統管理 → 系統監控與日誌 → 資料一致性巡檢」按一下「清除孤兒」，就會刪掉所有正常的會議紀錄成員，並把所屬知識來源標記為過時。

同時 GetSummaryAsync 的 OR 條件也漏了 Meeting，造成儀表板顯示 0 筆孤兒、巡檢頁顯示 N 筆，兩邊互相矛盾。

修正：existing 補 TypeMeeting、GetSummaryAsync 補對應 OR 條件、修正註解「三個」→「四個」。

四、編修／刪除會議紀錄不會標記所屬來源過時

音訊／文件／圖片三型在「編修素材文字」與「刪除素材」時都會呼叫 KnowledgeSourceMaintenanceHelper.MarkOwningSourcesStaleAsync，會議紀錄型漏了：

  • MeetingService.UpdateGeneratedContentAsync：補 removeOrphanItems: false（成員保留，只標記過時）
  • MeetingService.DeleteAsync：補 removeOrphanItems: true（清孤兒成員＋標記過時）
  • 順帶補上該方法缺少的 Directory.CreateDirectory（原本目錄不存在時會丟 DirectoryNotFoundException，被 catch 吞掉只回「會議紀錄寫入失敗」）

判定依據是「有沒有寫回被 KnowledgeSourceContentAggregator 讀取的那個檔案」，也就是 GeneratedContentRelativePath 指向的 .md 全文；Summary／Decisions／Participants 不進聚合內容，因此 UpdateAsync（只改中介資料）與 ApplyGeneratedFieldsAsync 刻意不標記過時，與另三型一致。

五、腳手架密碼清洗失效（安全）

scripts/New-StarterProject.ps1 的清洗與安全檢查都比對固定字串 '"SupportPassword": "support"'，但 appsettings.json 的實際值早已不是 support → 取代永遠不命中、安全檢查永遠不警告。而 Program.cs 每次啟動都會用 BootstrapSettings.SupportPassword 重設 support 帳號的密碼雜湊，等於每個 scaffold 出來的專案都內建一組已知管理帳密。

修正內容：

  • 清洗改為以鍵名為準的 regex（("Key"\s*:\s*)"…"），用 MatchEvaluator 而非取代字串（避免密碼含 $ 被當成 $1）；涵蓋 SupportPassword、SupportEmail、SigningKey（取代值 ≥32 字元，因 JwtSettings.SigningKey 有 [MinLength(32)]）。
  • 安全檢查改為「讀回值是否等於預期佔位值」，清洗沒生效就會警告。
  • 檔名比對放寬為 appsettings*.json。
  • 修掉 BOM 副作用：原本 Set-Content -Encoding UTF8 在 PowerShell 7 是「無 BOM」，會剝掉 docs/ 下所有 .md 的 BOM，導致 scaffold 出來的專案第一次跑 Test-DocsEncoding.ps1 就整批 FAILED。改用 File.ReadAllBytes／WriteAllText 逐檔保留原本的 BOM 有無。
  • 修掉巢狀排除目錄未生效：$excludedDirectories 原本只過濾最上層，巢狀的 src/<方案>/.vs 會被一併複製，而 .vsidx 在 Visual Studio 開著時是鎖定的 → 腳本在複製階段就崩潰，根本走不到密碼清洗。改為逐檔複製並過濾任何層級。
