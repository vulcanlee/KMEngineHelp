側邊選單名稱全面調整（1.0.57）

  • 日期：2026-07-25
  • 版本：1.0.56 → 1.0.57
  • 類型：使用體驗調整（僅顯示名稱，無功能變更）

問題

側邊選單多處名稱無法讓一般使用者判斷該畫面用途，三類問題：

  1. 名不符實：「圖片清單」實際是用視覺 LLM 把圖片讀成文字；「知識蒸餾」實際是知識頁的審核／編修／版本治理，蒸餾動作其實在知識來源頁觸發，該頁連「新增」按鈕都沒有。
  2. 內部術語外洩：「黃金評測」「RAG評測」「清洗設定檔」「文件萃取」「資料定義」對非開發者無意義。
  3. 難以區分的配對：「分類清單」vs「專案分類」、「AI 聊天紀錄」vs「對話總覽」、「Token 用量」vs「Token 用量分析」。

既有角色權限完全不受影響

角色權限存於 RoleView.TabViewJson，內容是 MagicObjectHelper.角色_xxx 的值，不是選單顯示名。選單顯示名只在 Menu.json；執行期的權限判定由 SidebarMenuService 以位置索引注入 PermissionName，與顯示名無關。

因此本次只改顯示名，MagicObjectHelper 與 RolePermissionService 完全未異動，不需要資料庫 migration，既有角色的可見選單與頁面授權一如既往。

⚠️ 承上：MagicObjectHelper.角色_xxx 的字面值永遠不可更動。一旦更動，所有既有 RoleView.TabViewJson 的字串會失配（RolePermissionService 以 Ordinal 比對），所有非管理員角色瞬間掉權限，而且沒有任何測試抓得到（測試皆透過常數引用，會跟著一起變綠）。

顯示名與權限名的對應表

改名後兩者大量分離，MenuPermissionAlignmentTests.DisplayNameToPermissionName 由 1 筆擴充為 16 筆，並從「既有例外」重新定位為顯示名 ↔ 權限名的正式對應表。日後更名選單只需在此補一筆，測試仍能守住「選單子項 ↔ 權限」的位置索引不變量。

影響範圍

  • Menu.json：只改 name，順序／id／icon／adminOnly 一律未動（順序一動就會觸發位置索引不變量）。
  • 23 個頁面的 <PageTitle> 同步更新，順帶消除既有的不一致（選單「專案項目」vs 標題「專案管理」、RAG評測 vs RAG 評測 等）。
  • 畫面上方標題列讀 Menu.json 的 name，會一併顯示新名稱。
  • 無資料庫 migration、無邏輯變更、無 API 變更。
  • PRD 與歷史 changelog 屬歷史紀錄，維持原用語未追改。

驗證

  1. 守護測試先紅後綠：只改 Menu.json、未補白名單時 EverySubMenuItem_PairsWith_ItsOwnPermissionName 如期失敗並列出 16 項待對應；補上後轉綠。
  2. dotnet test 通過：643 個測試全數通過。
  3. git diff 確認 MagicObjectHelper.cs 與 RolePermissionService.cs 零變更；Menu.json 的 diff 只有 name 行。
  4. 實機（需重啟站台，選單有 sidebar:menu:raw 快取）：管理員逐一點開 8 個群組確認名稱與頁面皆可進入；另以非管理員角色登入，確認可見選單與改名前完全相同。
