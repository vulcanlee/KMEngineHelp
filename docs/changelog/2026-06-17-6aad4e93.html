清洗結果對話窗可複製、預覽與線上編修（0.2.83）

  • 日期：2026-06-17
  • 版本：0.2.82 → 0.2.83
  • 類型：功能強化 / UI

需求

/knowledge-sources「檢視清洗結果」原為唯讀檢視，需比照音訊轉錄頁「編修產生結果」對話窗：

  1. 對話窗要有複製按鈕（複製清洗結果內容）。
  2. 右方要有 Markdown 預覽。
  3. 對話窗邊界與做法比照「編修產生結果」（共用 ContentEditDialog：90vw、top:3vh、90vh、左編輯／右預覽）。
  4. 要有修改內容＋儲存功能。
  5. 確認清洗結果不存資料庫、而是存到 appsettings.json 指定目錄下的檔案。

變更

ContentEditDialog（共用元件）

  • 新增 ShowCopy（預設 false）：為真時於編輯區標題列顯示「複製」鈕，呼叫 navigator.clipboard.writeText 複製目前編輯內容（含成功/失敗訊息）。
  • 新增 Note（可選）：於編輯區上方顯示一行備註（此處用於審核者資訊）。
  • 注入 IJSRuntime 與 AntDesign MessageService。現有三處使用點（逐字稿、產生結果、文件萃取、圖片辨識）預設不顯示複製鈕、無備註，行為不變。

KnowledgeSourceView

  • 「檢視清洗結果」由唯讀 <pre> Modal 改為 <ContentEditDialog ShowPreview="true" ShowCopy="true" Note="@cleanedReviewInfo" OnSave="OnSaveCleanedAsync" />。
  • 新增 OnSaveCleanedAsync：呼叫 UpdateCleanedContentAsync，成功關窗＋提示、失敗顯示錯誤（比照 MediaTranscriptionView.OnSaveEditAsync）。

KnowledgeSourceService

  • 新增 UpdateCleanedContentAsync(int id, string content)，比照 MediaTranscriptionService.UpdateGeneratedContentAsync 不變量：CleanTrackingHelper.Clean<KnowledgeSource> → 追蹤查詢 → 團隊權控（IsTeamAccessible）→ 原地覆寫同一相對路徑（Encoding.UTF8，與 CleaningProcessor 寫入一致）→ 僅更新 UpdatedAt。
  • 狀態維持不變（不因編修而重新送審）。

儲存機制確認（需求 5）

清洗結果只存檔案、不存資料庫：CleaningProcessor 以 Encoding.UTF8 寫入 ExternalFileSystem.CleanedSourcePath（appsettings.json，預設 C:\temp\KnowledgeExtraction\CleanedSource）下 {年}/{guid}.md；DB KnowledgeSource 僅存相對路徑 CleanedContentRelativePath，無內容欄位。本次編修亦覆寫同一檔案，未新增任何內容欄位 → 不需 migration。

影響範圍

  • 變更檔案：Components/Commons/ContentEditDialog.razor、Components/Views/KnowledgeSources/KnowledgeSourceView.razor(+.razor.cs)、Business/Services/DataAccess/KnowledgeSourceService.cs。
  • 無模型／資料庫變更。

驗證

  1. 對「已清洗／待審核」紀錄點「檢視清洗結果」：寬版對話窗、左編輯／右預覽、上方審核者資訊、複製鈕可用。
  2. 修改後儲存：成功提示、關窗、重開為新內容、來源狀態不變、UpdatedAt 更新；CleanedSourcePath 下對應檔案已更新。
  3. 權控：非管理員且無團隊交集無法讀/寫。
  4. 回歸：其他 ContentEditDialog 使用點行為不變。
