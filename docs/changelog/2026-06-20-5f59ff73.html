變更紀錄

表單／內容對話窗放大版樣式全域化，修正六頁對話窗超出螢幕（0.2.101）

  • 日期：2026-06-20
  • 版本：0.2.100 → 0.2.101
  • 類型：使用體驗修正（CSS）

問題

部分頁面的對話窗（如音訊轉錄「依提示詞產生內容」「產生結果」）下緣緊貼／超出螢幕底部，正上方卻留有大片空白，視覺不佳；而「編修產生結果」（ContentEditDialog）等則正常呈現寬版滿版。

根因

表單／內容對話窗的放大版樣式（width:90vw、height:90vh、內容區可捲動）原本只寫在 Components/Commons/FormModalHelper.razor 的 <style>，只有在頁面實際渲染 <FormModalHelper /> 時才載入。下列六頁的對話窗標了 Class="project-view-modal" 但未渲染 <FormModalHelper />，導致樣式未載入而退回 AntDesign 預設（窄、固定 top:100px、高度隨內容增長 → 下緣超出、上方留白）：音訊轉錄、圖片辨識、技能、黃金樣本、文件萃取、知識來源。

變更

  • wwwroot/app.css（全域、必載）：新增 .role-view-modal / .my-user-modal / .project-view-modal / .my-tas-modal / .meeting-view-modal 的放大版樣式（90vw×90vh、top:5vh、.ant-modal-body flex 內捲），以及 .change-password-modal 緊湊版。內容與原 FormModalHelper 相同，僅改為全域，使所有頁面一致生效，從根本消除「忘了放 <FormModalHelper />」的問題。
  • FormModalHelper.razor：移除已移至 app.css 的對話窗尺寸樣式，僅保留 .role-view-table-wrap 表格列樣式。對話窗樣式單一來源在 app.css。
  • KnowledgeSourceView.razor：兩個小型確認窗（「確認清洗」「退回」）移除 Class="project-view-modal"，避免全域化後被放大成 90vw×90vh，維持 AntDesign 預設小尺寸。
  • appsettings.json SystemVersion 0.2.100 → 0.2.101。

影響範圍

  • 純 CSS／class 調整，無邏輯與資料異動。
  • 六頁的新增/編輯、產生、結果、預覽、明細等內容型對話窗放大至接近滿版（比照圖片四）。Width="700/720/800" 等明確寬度會被全域 90vw !important 覆蓋（屬內容型放大版，符合需求）。
  • 既有正常頁面（專案、使用者、角色、分類、團隊、會議、任務、提示詞、清洗設定）對話窗行為不變；「管理成員」對話窗（member-manage-modal，92vw/1400px）選擇器更具體，仍優先生效、不受影響。

驗證

  1. dotnet build 通過。
  2. 逐一開啟六頁對話窗：寬約 90vw、貼齊上方、整體在視窗內、內容過長於內容區捲動、下緣不超出螢幕。
  3. 知識來源頁「確認清洗」「退回」維持小尺寸、未被放大。
  4. 既有正常頁面與「管理成員」對話窗回歸不變。
