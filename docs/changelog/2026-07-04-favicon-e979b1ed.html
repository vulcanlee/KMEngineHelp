favicon 去白邊與透明化紀錄

⚠️ 勘誤（1.0.79 補記）：本篇的成果宣稱並未達成，緊裁基準取錯了。

第 3 步的「依非透明像素 bbox 緊裁（裁切後約 304×341）」用的是 alpha bbox。但來源圖的白色圓角卡片外圍有一層淺灰柔邊（幽靈環），它既不夠透明（alpha > 32）也不夠白（min RGB < 235），四角 flood fill 會停在那裡 —— 於是緊裁到的是卡片，不是標誌。1.0.79 在記憶體中重跑本篇演算法完整重現：alpha bbox = 328×367（比例 0.894，與本篇自述的「約 304×341」比例 0.891 是同一個東西），而標誌本體的墨色 bbox 是 230×277（比例 0.830）。

結果是本篇產出的 favicon.png 中，標誌只佔畫布 57.8% × 70.3%，「讓 logo 貼齊放大」的目的沒有達到，分頁圖示依然明顯小於其他網站。

已於 1.0.79 改以墨色 bbox（alpha > 128 且 (R+G+B)/3 < 200）為緊裁基準並改由版控腳本 scripts/Build-Favicons.py 產生，詳見 favicon 多尺寸重生。本篇以下內容保留原貌，僅供追溯。

變更目的

瀏覽器分頁的 favicon 圖示偏小（原為圓角白色底磚 + 約 28% 留白，縮到 16–32px 時 logo 佔比太小）。本次將 favicon 去除白色留白、改透明背景，讓 logo 貼齊放大。

處理方式

以 Python + PIL 重新處理來源圖：

  1. 轉 RGBA。
  2. 從四個角落 ImageDraw.floodfill 去背（threshold 40）：外圍連通的近白區域填為透明；深藍六邊形形成邊界，內部白色（盾牌、鑰匙孔、節點中心）完好保留（未用「全部白→透明」以免挖空內部）。
  3. 依非透明像素 bbox 緊裁（裁切後約 304×341），四周加約 4% 透明 padding、置中於正方形透明畫布。
  4. 縮放為 128×128（LANCZOS），輸出覆蓋 wwwroot/favicon.png（RGBA、透明底）。
