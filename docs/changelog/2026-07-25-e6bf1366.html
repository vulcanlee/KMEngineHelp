清洗設定檔新增預設範本按鈕與欄位說明圖示、分類上限提高至 10（1.0.48→1.0.49）

  • 日期：2026-07-25
  • 版本：1.0.48 → 1.0.49
  • 類型：功能新增（清洗設定檔畫面）＋常數調整

本篇為事後補寫。 1.0.49 當時未留下 changelog，於 1.0.71 盤點 docs/changelog/README.md 索引時發現缺漏，依 commit 7cbe235 的實際 diff（8 檔 +228/-28）補寫。內容一律以該 commit 的程式碼為準，未加入事後推測。

需求

「清洗規則設定」/cleaning-profiles 有三個讓人卡住的地方：

  1. 只能從空白開始寫。五段提示詞（去重／遮罩／分類／摘要／信心自評）沒有任何範例，使用者不知道「怎麼寫會保留多少內容」，只能自己摸索；而留空又會落到系統全域內建預設——那組預設其實相當積極刪減，常造成「清洗後內容少太多」的抱怨。
  2. 欄位沒有說明。每一欄的用途、留空會發生什麼、寫壞了會有什麼後果，畫面上完全看不到。
  3. 分類保留上限硬編為 5。即使設定檔的分類提示詞要求更多、更細的分類，超過 5 個一律被截掉，且這個數字寫在程式裡、沒有任何提示。

變更

三顆預設範本按鈕

工具列（新增／重新整理 旁）新增三顆按鈕：最大保留範本、低度清洗範本、中度清洗範本。

  • 按下不會直接寫入資料，而是開啟「新增」表單並帶入整組內容（OnApplyPresetAsync），視窗標題變成 新增清洗設定檔（範本：{範本名稱}），使用者可先檢視、微調（例如改名、依產業補上要保留的關鍵詞）再按確定儲存。名稱唯一性仍由 BeforeAddCheckAsync 把關。
  • 除了快速上手，也讓使用者能藉範本內容學習提示詞的寫法。
  • 新增 Components/Views/CleaningProfiles/CleaningProfilePresets.cs 範本工廠（MaxRetention()／LowCleaning()／MediumCleaning()），每個方法回傳一個已填好五段提示詞的 CleaningProfileAdapterModel。
  • 保留程度由高到低：最大保留 > 低度清洗 > 中度清洗 >（系統全域預設）。三個範本的每一段都明確填寫，用意是覆蓋 LlmPromptDefaults 的激進內建預設。
  • 三個範本的遮罩段一律要求「原樣輸出其餘內容」——這不是文字風格問題：清洗流程的遮罩步驟若回傳空白會丟例外導致整筆不寫檔，所以範本刻意把這句寫進去，避免使用者照抄後踩到。

欄位說明圖示

表單全部欄位加上說明圖示（LabelTemplate ＋ Tooltip ＋ MaterialIcon），游標移上顯示該欄位的用法與注意事項。

分類保留上限 5 → 10

Business/Services/Cleanings/CleaningEnhancer.cs 原本是硬編的 .Take(5)，改為新增常數並改用它：

/// <summary>分類步驟保留的標籤數量上限（供清洗設定檔要求更多分類時使用）。</summary>
private const int MaxCategories = 10;

影響與相容性

  • 未指定設定檔的行為完全不變：全域內建預設仍要求 1–5 個分類，上限放寬只是讓「設定檔要求更多分類」時不會被截在 5。
  • 超過上限的分類是直接截掉、不報錯，且這個上限仍寫在程式裡、畫面上改不了。
  • 三顆範本按鈕只是帶入表單內容，不會直接建立資料，也不影響既有設定檔。
  • 無資料庫 migration、無 API 合約變更、無破壞性變更。

已知缺口（由後續版本補）

本次新增的兩個圖示 bolt、tune 漏同步 CrudActionIconTests.AllowedCrudActionIcons 白名單，導致該測試自本版起持續失敗，直到 1.0.53 才順帶修好。
