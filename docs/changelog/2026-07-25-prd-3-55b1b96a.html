三、文件宣稱已實作、實際沒有

紀錄分類與團隊權控-prd.md §六宣稱「對外 API 的 *SearchRequestDto 亦新增 CategoryFilters、TeamFilters」。實際上這兩欄只存在於 Models/Systems/DataRequest，Dtos/Commons/ 的 8 個 *SearchRequestDto、基底 SearchRequestBaseDto 與各 Controller 皆無。

已移入新的 §15.4「未依原設計落地的項目」，並明確註明這只影響 API 層的過濾能力、不影響權控——Controller 的可見性仍由 Service／Repository 的 IRecordAccessScopeProvider 強制。不寫明的話，下次稽核容易把它誤判為資安缺口。

同表另記錄 5 項設計與實作的落差：介面實際命名為 IRecordAccessScopeProvider 且實作在 Web/Auth（因需 IHttpContextAccessor）、非管理員團隊下拉未限縮、專案／工作／會議改用 WorkCategoryService、Modal 已抽為獨立元件、GetAllEnabledNamesAsync 早已實作。

四、權控涵蓋清單補齊

紀錄分類與團隊權控-prd.md 的權控落點清單停在首次實作，補進 7 個後續新增的落點：DashboardService、DataConsistencyService、RagDiagnosticsService、ContentInventoryReportService、MeetingActionItemService、Web/Mcp/KnowledgeSearchTool、LogArchiveController；紀錄型別也由「五種」更新為六種（含 ImageRecognition）。

另新增 §15.3 記錄刻意不套團隊權控的例外：PipelineProgressQueryService 改以 UserAccount 精確相等過濾（只回報自己送出的管線進度）。程式內已有註記，文件同步記載以免日後誤報成漏洞。
