變更紀錄

將「清洗設定檔」選單從「清洗與蒸餾」移至「資料定義」（0.2.103）

  • 日期：2026-06-20
  • 版本：0.2.102 → 0.2.103
  • 類型：選單/權限結構調整

需求

將「清洗設定檔」(/cleaning-profiles) 在側邊功能表上的位置，從「清洗與蒸餾」子功能表移至「資料定義」子功能表（放在最後，提示詞清單之後）。

變更（選單與權限三處同步）

選單與權限以位置索引對應（SidebarMenuService.ApplyPermissionStructure/ApplyChildPermissionStructure），三處同步調整：

  • Datas/Menu.json：
  • 「清洗與蒸餾」(id 3) 移除「清洗設定檔」(原 id 33)；其後「AI技能產生器」id 34 → 33（補回連號，維持 群組×10+序 慣例）。
  • 「資料定義」(id 5) 末端新增「清洗設定檔」(id 54，icon tune，/cleaning-profiles)。
  • RolePermissionService.GetRoleListPermissionAllName()：
  • 清洗與蒸餾群組（外層索引 2）移除 角色_清洗設定檔；動作型 角色_知識審核 仍排在所有頁面型權限之後，索引對齊不變。
  • 資料定義群組（外層索引 4）於 角色_提示詞清單 之後加入 角色_清洗設定檔。
  • MagicObjectHelper：角色_清洗設定檔 常數值不變（"清洗設定檔"），僅將定義位置移至 角色_提示詞清單 之後以對齊新順序。

影響範圍與相容性

  • 權限以字串值 "清洗設定檔" 儲存於角色（RoleView.TabViewJson），值未變更 → 既有角色授權不受影響，無需資料庫 migration（選單/權限非 DB 實體）。
  • Menu.json 的 id 為裝飾性欄位（程式以陣列位置對應，未當鍵使用）。
  • MenuIconTests：「清洗設定檔」沿用 tune（已在允許清單），移動後仍通過。

文件同步更新

  • docs/prd/清洗設定檔-prd.md：管理頁歸屬由「清洗與蒸餾」群組改為「資料定義」群組。
  • docs/security/認證授權與權限機制.md：「資料定義」表新增 角色_清洗設定檔 列並更正既存錯誤 id（4/41/42/43 → 5/51/52/53/54）；「清洗與蒸餾」表補列 角色_AI技能產生器、加註清洗設定檔已移出。
  • docs/architecture/開發慣例與限制速查.md：位置索引陷阱範例改寫為仍正確的敘述。

驗證

  1. dotnet build 通過；dotnet test 全綠（含 MenuIconTests）。
  2. scripts/Test-DocsEncoding.ps1 通過（UTF-8 含 BOM、無亂碼）。
  3. 登入後側邊選單：「清洗與蒸餾」不再有「清洗設定檔」；「資料定義」最後一項為「清洗設定檔」，點擊進入 /cleaning-profiles。
  4. 既有角色仍可正常存取 /cleaning-profiles。
