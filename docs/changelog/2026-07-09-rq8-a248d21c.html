一鍵全量重建索引（RQ-8）（0.3.9→0.3.10）

  • 日期：2026-07-09
  • 版本：0.3.9 → 0.3.10
  • 類型：新增功能（RAG 補強清單）

需求

補強清單 RQ-8（P1）：目前只能在「知識來源管理清單」逐來源手動按「建立索引／重建索引」，缺少「對所有符合條件來源一次全量重建」的入口。在調整切塊參數（EVAL-5 已排除、因需重建索引才生效）、換嵌入模型或大量來源需重索引時特別麻煩。

變更

商業層

  • KnowledgeSourceService.TriggerEmbeddingIndexAllAsync()：查詢使用者可存取（非管理員依 TagStringHelper.BuildTeamAccessPredicate 團隊權控）的所有「已清洗」來源，逐一重用既有 TriggerEmbeddingIndexAsync（含權控＋in-flight 守衛＋入列）；回傳入列摘要（成功數＋略過清單與原因）。索引處理器為增量冪等（(SourceLayer, WikiPageId, ContentHash) 差集，內容未變不重嵌），故對已索引來源重跑很便宜、可安全重入。

模型

  • 新增 BatchEmbeddingIndexResult（EnqueuedCount + List<BatchEmbeddingIndexSkip>；BatchEmbeddingIndexSkip(Title, Reason)），仿 BatchZipImportResult 的「成功數＋逐項原因」形狀。

UI 層

  • 知識來源管理清單（KnowledgeSourceView）工具列新增「全量重建索引」按鈕（CrudActionButton Icon="replay"，允許清單內圖示）：確認框 → 呼叫服務 → 訊息顯示「已排入 N 筆／略過 M 筆」→ 有略過時開 Modal 列出來源與原因。
  • 逐來源進度與失敗沿用該頁現有 5 秒輪詢 + 每列索引狀態/進度% + NotifyPipelineTransitions 完成/失敗通知，無需新增輪詢基礎設施。

測試

  • KnowledgeSourceServiceTests：
  • TriggerEmbeddingIndexAllAsync_EnqueuesEligible_AndReportsInFlightSkips（已清洗×2 入列、草稿排除、索引中略過並附原因、佇列恰收 2 個 id）。
  • TriggerEmbeddingIndexAllAsync_NonAdmin_OnlyRebuildsAccessibleSources（非管理員只重建公開＋自隊，他隊不入列）。
  • 全測試 463 通過、0 失敗（含 CrudActionIconTests/MenuIconTests 圖示允許清單）。

範圍決策（誠實記錄）

  • 入口放知識來源管理清單工具列（非 RagDiagnostics 維運中心）：該頁已具備觸發服務、進度輪詢與逐筆失敗通知，重用成本最低。
  • 範圍＝使用者可存取的「已清洗」來源（非管理員依團隊權控）；非「已清洗」來源不納入（查詢即排除）。
  • 無 schema 變更 → 無 migration。
  • 多實例部署競態（SCALE-2，P2）仍為已知待辦；單實例下佇列為 SingleReader Channel，天然序列化。

驗證

  1. dotnet build 成功、dotnet test 綠燈（463 通過）。
  2. 手動：/knowledge-source 工具列按「全量重建索引」→ 確認框 → 摘要顯示已排入/略過（草稿、索引中被略過並附原因）→ 表格每列索引狀態轉 等待中→處理中→已索引，進度%更新，完成/失敗 toast。
  3. 冪等：對已索引且內容未變來源重跑，差集為空不重嵌。
  4. 權控：非管理員只重建自身可存取來源。
  5. scripts/Test-DocsEncoding.ps1 全綠。
