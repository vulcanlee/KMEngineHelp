音訊轉錄：下載來源影片自動轉碼為 H.264（0.2.116）

  • 日期：2026-06-23
  • 版本：0.2.115 → 0.2.116

摘要

「音訊轉錄」頁面的「下載來源檔案」按鈕（0.2.115）會提供 yt-dlp／抖音助手保留的原始影片下載。但小紅書、抖音等平台的影片常以 HEVC/H.265（或 VP9、AV1）編碼，Windows 內建播放器需另購「HEVC 視訊延伸模組」才能播放。本次新增：下載並保留原始影片後，自動將非「H.264 + MP4」的影片重新編碼為 H.264（libx264）+ AAC、MP4 容器，下載到的來源影片即可在一般 Windows 播放器直接播放。

內容

  • 轉碼範圍：只要不是「H.264 編碼且 MP4 容器」就轉（涵蓋 HEVC、VP9、AV1，以及 mkv／webm 等容器）；

已是 H.264 MP4 則跳過、不重編，避免畫質損失與多餘耗時。

  • 原檔處理：轉碼成功後取代原檔（不保留未轉碼版本），OriginalMediaRelativePath 改指向轉碼後的 .mp4；

下載檔名與 MIME 由副檔名推斷（.mp4 → video/mp4），下載服務無需改動。

  • 適用來源：於背景下載完成後在單一中央接點處理，同時涵蓋 yt-dlp（YouTube／小紅書）與抖音兩條路徑。
  • 失敗策略：轉碼屬加值，沿用「原始影片保留失敗不中斷」哲學——任何例外只記 LogWarning 並保留原檔，

轉錄主流程照常完成。

實作

  • 新增 VideoTranscoder（Business/Services/Transcription/VideoTranscoder.cs）：

以 ffmpeg -i 解析 stderr 探測視訊編碼（不依賴 ffprobe），需轉碼時以 -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -c:a aac -b:a 192k -movflags +faststart 輸出 MP4； 抽出純函式 NeedsTranscode(extension, videoCodec) 供單元測試。

  • TranscriptionProcessor.DownloadFromUrlAsync：取得下載結果後、寫入紀錄前，若有保留原始影片即呼叫

VideoTranscoder.EnsurePlayableAsync，並以轉碼後路徑回算 OriginalMediaRelativePath。

  • 測試：VideoTranscoderTests 驗證 NeedsTranscode 的容器／編碼判斷（h264 mp4 跳過、HEVC／VP9／非 mp4 轉碼、無視訊串流不轉）。
