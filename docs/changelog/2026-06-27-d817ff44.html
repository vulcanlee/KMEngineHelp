側邊欄父選單圖示依語意顯示（0.2.134）

  • 日期：2026-06-27
  • 版本：0.2.133 → 0.2.134
  • 類型：Bug 修正

症狀

側邊欄的 4 個父功能表（專案管理、清洗與蒸餾、系統管理、資料定義）圖示完全相同 （都是資料夾 folder_open），無法一眼看出各群組用途；收合側邊欄時尤其明顯。

根本原因

Menu.json 其實已為每個父選單設定不同的 icon，但 SidebarMenuNode／NavMenu 的 GetMaterialIconKind 內有一條攔截所有父選單的 catch-all：

_ when Item.HasChildren => "folder_open",
_ => icon

凡是不在明確 switch 名單中的父選單圖示，一律被覆寫為 folder_open，因此 4 個父選單顯示同一個 資料夾。子選單（葉節點）走 _ => icon 直通，故本來就各自正確。此為早期刻意設計 （見 docs/changelog/2026-06-11-修正側邊欄圖示.md），現調整為父選單也依語意顯示圖示。

另外，原「專案管理」圖示 folder_managed 屬 Material Symbols-only，本應用程式 （Components/App.razor）載入的是 classic Material Icons，移除 catch-all 後若直通會破圖。

修正

  • SidebarMenuNode.razor.cs／NavMenu.razor.cs：移除 _ when HasChildren => "folder_open" 這條，

讓父選單圖示經 _ => icon 直通；保留空字串 fallback 與既有別名（含 shield_person => security）。

  • Menu.json：「專案管理」圖示 folder_managed → assignment（合法 classic Material Icons，語意為任務/專案）。
  • 其餘父圖示維持 cleaning_services／manage_accounts／dataset（皆為合法 classic 名稱）。
  • MenuIconTests：新增父選單圖示允許清單 AllowedParentIcons 與回歸測試

MenuJson_ParentIcons_AreAllowedClassicMaterialIcons，並更新類別 doc comment。

備註

本次只動圖示，未新增頁面或權限，故不需動 MagicObjectHelper／RolePermissionService／權限樹三處同步， 亦不需資料庫 migration。新增父選單時，請使用 classic Material Icons 名稱並加入 MenuIconTests.AllowedParentIcons。
