抖音下載保留原始影片（0.2.89）

  • 日期：2026-06-19
  • 版本：0.2.88 → 0.2.89
  • 類型：功能新增

需求

抖音下載原本只保留轉錄用的 mp3，不保留原始影片。助手腳本攔截音訊串流轉 mp3 後即刪除中介檔，DouyinAudioDownloader 回傳的 OriginalMediaRelativePath 恆為 null。需求是讓抖音下載也能保留原始影片（與 yt-dlp 路徑一致，落地於 OriginalMediaPath）。

變更

助手腳本 tools/douyin-audio/get-douyin-audio.mjs

  • 新增 --out-video <mp4完整路徑> 參數。
  • 下載重試迴圈抽成可重用的 downloadBuffer(url, label)；在關閉瀏覽器前一併取得影片所需位元組（下載需 context cookie）。
  • 影片來源優先序與組裝：
  • 合併式來源（含影音）→ 直接落地為 mp4（與 mp3 來源同網址時重用已下載位元組，不重複下載）。
  • DASH 分流 → 下載純視訊軌，並在有純音訊軌時以 ffmpeg -c:v copy -c:a aac 合流為單一 mp4。
  • 僅音訊無視訊 → 不產生影片。
  • 成功時於 stdout 印出 VIDEO_PATH=。影片保留為加值功能，任何失敗只記錄於 stderr，不影響 mp3 與離開碼。

C# DouyinAudioDownloader.cs / TranscriptionProcessor.cs

  • DownloadAudioAsync 新增 originalMediaRootPath 參數；非空時以 --out-video 指向 OriginalMediaPath/{yyyy}/{guid}.mp4，並解析 VIDEO_PATH=、檔案存在則回填 OriginalMediaRelativePath（否則 null）。
  • TranscriptionProcessor 抖音分支改傳 originalMediaRootPath；既有第 184 行已會將 OriginalMediaRelativePath 寫入紀錄並存檔。

影響範圍

  • 變更檔案：tools/douyin-audio/get-douyin-audio.mjs、tools/douyin-audio/README.md、DouyinAudioDownloader.cs、TranscriptionProcessor.cs、docs/operations/外部工具安裝與路徑設定.md、docs/operations/日誌與設定檔說明.md、docs/prd/音訊影片轉錄服務PRD.md、appsettings.json（版本號）。
  • OriginalMediaRelativePath 欄位早已存在，不需 migration。
  • 不改動 mp3／轉錄主流程行為。

重要前提

appsettings.json 的 OpenAISettings:DouyinHelperScript 必須指向更新後的 get-douyin-audio.mjs，否則行為不變。

驗證

  1. node --check tools/douyin-audio/get-douyin-audio.mjs 語法正確；dotnet build 通過。
  2. node tools/douyin-audio/get-douyin-audio.mjs "<抖音連結>" --out <暫存.mp3> --out-video <暫存.mp4> 同時產出 mp3 與可播放（有聲）的 mp4，stdout 含 MP3_PATH= 與 VIDEO_PATH=。
  3. 系統「音訊轉錄」貼抖音連結，轉錄完成後確認 mp3 在 MediaUpload、原始 mp4 在 OriginalMedia、該筆 OriginalMediaRelativePath 已填值。
  4. 僅音訊／攔不到視訊的情境，mp3 仍成功、未產出影片、流程不中斷。
