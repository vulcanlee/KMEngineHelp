變更紀錄

檔案上傳進度對話窗 ＋ 全站重複「關閉」按鈕修正（1.0.50）

  • 日期：2026-07-25
  • 版本：1.0.49 → 1.0.50
  • 類型：使用體驗強化（UI／上傳流程）

問題

  1. 大檔上傳無進度、無法取消：音訊轉錄／文件萃取／圖片清單／會議錄音的上傳皆走 Blazor <InputFile> + IBrowserFile.OpenReadStream()（SignalR circuit），實際瓶頸是 stream.CopyToAsync(memory) 把整包檔案讀進伺服器記憶體。主「新增」對話窗按下確定即關窗，CopyToAsync 在背景繼續跑——使用者看不到百分比、不知是否完成，也無法中止。全專案先前沒有任何上傳進度回報。
  2. 多處對話窗有兩顆同名「關閉」按鈕：如右上角使用者選單的「關於」窗，OkText 與 CancelText 都設為「關閉」，使 AntDesign 預設 footer 的 OK/Cancel 兩顆都顯示「關閉」，重複多餘。

變更

一、上傳進度對話窗 ＋ 取消

  • 新增共用元件 Components/Commons/UploadProgressModal.razor：對外提供 ReadWithProgressAsync(IBrowserFile file, long maxSize)，以分塊讀取取代單一 CopyToAsync，回報 已讀 / 總大小 百分比並支援 CancellationToken；完成或取消後自動關窗。回傳緩衝好的 MemoryStream（Position=0），使用者取消則回傳 null。
  • 各上傳點改用此元件（把原本三行 OpenReadStream＋CopyToAsync 樣板替換為 ReadWithProgressAsync）：
  • MediaTranscriptions/MediaTranscriptionView（新增、上傳新版本）
  • DocumentExtractions/DocumentExtractionView（新增、上傳新版本、批次 zip）
  • ImageRecognitions/ImageRecognitionView（新增、上傳新版本、批次 zip）
  • Projects/MeetingRecordingUploadModal（原本 Content = stream 直送，改為先緩衝再送）
  • 取消語意：中止「瀏覽器→伺服器」這段傳輸；因服務端存檔只在傳輸完成後才呼叫，取消＝不會有任何檔案被寫入。

二、修正重複「關閉／取消」按鈕

  • 七個「兩顆都叫『關閉』」的純確認窗改為單顆「關閉」（沿用專案既有 Footer="null" + 內容右對齊單顆按鈕的慣例）：
  • Layout/MainLayout.razor（關於）
  • Views/GoldenSamples/GoldenSampleView.razor
  • Views/DocumentExtractions/DocumentExtractionView.razor（批次匯入結果、預覽）
  • Views/KnowledgeSources/KnowledgeSourceView.razor（全量重建索引：略過清單）
  • Views/RagEvaluations/RagEvaluationView.razor
  • Views/ImageRecognitions/ImageRecognitionView.razor（批次匯入結果）
  • 範例檔 Views/Admins/RoleViewViewSample.razor：Modal 加 Footer="null"，移除與內容自放「儲存／取消」重複的預設 footer。

影響範圍

  • 上傳成功後的服務端寫檔流程與佇列排入不變（仍先緩衝到記憶體，與原行為一致，無記憶體用量回歸）。
  • 確認窗改為單顆按鈕，關閉行為與 ×／Esc 不變。
  • 無資料庫 migration（純前端行為與 UI）。appsettings.json SystemVersion 1.0.49 → 1.0.50。

驗證

  1. dotnet build 通過、無亂碼、我方檔案無新警告。
  2. 四種匯入各上傳一個大檔：按確定後出現進度窗、百分比遞增、完成自動關閉、佇列有排入；上傳中按「取消」→ 立即中止、無檔案寫入。批次 zip 與「上傳新版本」同樣有進度窗。
  3. 「關於」及其餘確認窗底部只剩單顆「關閉」；範例檔無重複「取消」。
