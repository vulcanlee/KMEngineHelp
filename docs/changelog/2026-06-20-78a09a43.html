變更紀錄

文件萃取限制可上傳副檔名並於畫面顯示（0.2.92）

  • 日期：2026-06-20
  • 版本：0.2.91 → 0.2.92
  • 類型：功能調整

需求

文件萃取原本不限制上傳副檔名（任何檔案直接交 MarkItDown，不支援者轉換時才失敗），畫面也只有模糊說明。需求是：限制只能上傳支援清單內的副檔名（含 .txt），並在畫面顯示讓使用者知道可上傳哪些格式。

變更

新增 DocumentFormatValidator

  • src/KnowledgeExtraction/KnowledgeExtraction.Business/Helpers/DocumentFormatValidator.cs：比照 ImageFormatValidator／MediaFormatValidator。
  • AllowedExtensions（MarkItDown 常見可處理格式，含 .txt）：.pdf .docx .doc .pptx .ppt .xlsx .xls .csv .txt .md .json .xml .html .htm .epub .zip .jpg .jpeg .png .gif .bmp .tiff .webp。
  • IsSupported(fileName)、AllowedExtensionsText（「、」串接，顯示用）、AcceptAttribute（逗號串接，供 <InputFile accept>）。

後端驗證

  • DocumentExtractionService.BeforeAddCheckAsync：檔案大小檢查後新增副檔名驗證，不支援者回「不支援的檔案格式，僅接受：…」。

前端 UI

  • DocumentExtractionView.razor：<InputFile> 加 accept（檔案選取對話框預設只顯示允許格式）；說明文字改為「支援格式：{完整清單}，單檔上限 1GB。」。

測試

  • 新增 DocumentFormatValidatorTests（.txt/.pdf/Office 為 true、.exe/無副檔名為 false、清單含 .txt、accept 為逗號串接），全部通過。

影響範圍

  • 推翻文件萃取 PRD 原「不限制」決策，已同步更新 docs/prd/文件萃取-markitdown-prd.md 與 docs/operations/容量邊界與限制.md。
  • 不改 MarkItDown 轉換邏輯本身；不動圖片/音訊上傳（各有驗證）。
  • appsettings.json SystemVersion 0.2.91 → 0.2.92。無資料庫變更，不需 migration。

驗證

  1. dotnet test --filter DocumentFormatValidator 綠燈（15 通過）。
  2. /document-extraction 新增：.txt 可建立並轉換；.exe 等被擋下並提示「僅接受：…」；表單顯示完整支援清單。
  3. scripts/Test-DocsEncoding.ps1 全綠。
