SEC-3 權控標籤傳播修正 + SEC-5 稽核補使用者身分（0.3.10→0.3.11）

  • 日期：2026-07-09
  • 版本：0.3.10 → 0.3.11
  • 類型：資安補強（RAG 補強清單 SEC 系列）

需求

補強清單兩項 P1 資安待辦：

  • SEC-3（chunk 層 ACL 細緻度）：VectorEmbedding.Teams 本就是 per-chunk、檢索/評測已 per-chunk 過濾且守門 leak=0，但探索發現一個實際權控一致性 bug——KnowledgeSourceService.UpdateAsync 變更來源 Teams 時不同步 WikiPage.Teams／VectorEmbedding.Teams。由於檢索權控過濾的是向量的 Teams（舊值），把來源改嚴後舊向量仍帶舊（較寬鬆）團隊 → 過度曝露，且 RagEval 越權檢查用同一舊值、內部一致故抓不到。
  • SEC-5（稽核鏈路補全，資安視角）：EVAL-2 已把問答稽核落表，但 KnowledgeBaseQueryAudit 只記 IsAdmin＋Teams、無使用者身分，無法回答 §十⑤「誰問了什麼」。

變更

SEC-3：來源團隊變更即時傳播（無 migration）

  • KnowledgeSourceService.UpdateAsync：團隊變更時以 ExecuteUpdateAsync 直接把新標籤傳播到該來源的 WikiPage.Teams 與 VectorEmbedding.Teams（免重嵌，只改 ACL 標籤），關閉過度曝露窗。
  • 決策：完整「段落層」差異化標記待具體 JTBD 再導入，現階段維持來源/團隊層並以 leak=0 守底線。見 docs/architecture/知識庫RAG設計與執行.md §六之三。

SEC-5：問答稽核補提問者身分（雙 migration AddUserIdentityToQueryAudit）

  • KnowledgeBaseQueryAudit 新增 UserAccount／UserName（nullable）。
  • KnowledgeBaseChatService 注入既有 CurrentUserService，WriteQueryAuditAsync 寫入提問者帳號/姓名（null 安全；未登入/API 為 null）。
  • RagDiagnosticsService.GetAuditRecordsAsync 投影 + KnowledgeBaseQueryAuditRow 加欄；/rag-diagnostics 近期稽核表新增「帳號」欄。
  • 隱私邊界：僅放寬到「身分」（帳號/姓名），仍不存問句本文/context/chunk 文字。

測試

  • KnowledgeSourceServiceTests.UpdateAsync_TeamsChanged_PropagatesToWikiAndVectors。
  • KnowledgeBaseChatServiceTests.RetrieveAsync_PersistsAudit_RecordsAskerIdentity。
  • 全測試 465 通過、0 失敗。

範圍決策（誠實記錄）

  • SEC-3 = 修權控傳播落差 + 決策註記；不做完整 per-chunk 段落標記 UI。
  • SEC-5 = 稽核補使用者身分；匯出(CSV)、不可竄改(immutable)、保留期(retention)、越權/被拒事件稽核列後續。
  • 兩者皆維持不變量「RagEval 越權洩漏 = 0」。

影響範圍

  • 進度：SEC-3 ✅、SEC-5 ✅ 完成。詳見 docs/planning/12-... §〇。
  • 同步更新 docs/architecture/知識庫RAG設計與執行.md（§六之三）、docs/operations/RAG問題診斷手冊.md、docs/planning/12-...。
  • appsettings.json SystemVersion 0.3.10 → 0.3.11；SEC-5 需套用雙 migration。

  3. SEC-5：以某帳號問一題 → /rag-diagnostics 近期稽核「帳號」欄顯示該帳號；未登入為「—」不報錯。
