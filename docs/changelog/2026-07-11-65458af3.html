變更紀錄

日誌可診斷化強化：分級生效＋執行環境情境＋例外快照＋守則測試（0.3.22→0.3.23）

  • 日期：2026-07-11
  • 版本：0.3.22 → 0.3.23
  • 類型：可觀測性強化（延伸既有日誌標準，非重寫；無 migration）

需求

讓日誌能判斷系統是否如預期運作、問題發生時看到重要資訊與例外堆疊、把「當時程式運作環境」按等級寫入，且日後新程式碼一律遵循。系統已有成熟日誌標準（開發慣例速查 §1.1 三鐵則＋0.2.104 覆蓋），故本次補關鍵缺口而非機械式全面補日誌。

變更

分級真正生效（Debug/Trace）＋臨時切換

  • 修正先前 LogDebug 被 NLog 二次過濾丟棄、Trace 全然不可見的問題：把「效果等級」的唯一有效開關集中到 NLog * 規則。
  • nlog.config：應用層 * 規則加 ruleName="AppCatchAll"、minlevel 維持 info（＝預設效果等級）；因 autoReload="true"，改該行 minlevel 存檔即免重啟生效，改回 info 即恢復。
  • appsettings.json／appsettings.Development.json：Logging:LogLevel:Default → Trace（MEL 放行，把實際等級交給上述 NLog 規則；保留 Microsoft.AspNetCore=Warning）。
  • 管理員執行期切換畫面：新增 Web/Diagnostics/ILogLevelController＋NLogLevelController（以 FindRuleByName("AppCatchAll")＋SetLoggingLevels＋ReconfigExistingLoggers 執行期改等級，註冊為 Singleton）；新增頁 /log-settings（LogSettingsPage＋LogSettingsView，admin-only，下拉 Trace/Debug/Information/Warning/Error＋套用，立即生效）；Menu.json 群組「系統管理」新增子項（id 46「日誌等級」，icon=tune）。此切換為執行期暫時覆蓋——nlog.config 存檔（autoReload）或重啟後回到檔案預設（info）。

執行環境情境（scope）＋系統環境

  • 新增 KnowledgeExtraction.Share.Helpers.LogScope（建立 BeginScope 情境字典）與 RuntimeEnvironmentInfo（StartupSummary／Snapshot）。
  • nlog.config layout（file/console）新增 user=/op=/id= 情境欄位（渲染 MEL scope 屬性；TraceId 既有）。
  • 請求層 UseHttpRequestLogging 以 BeginScope 帶登入者＋操作；七條背景管線各帶 Operation＋RecordId（涵蓋其 Processor/Enhancer 日誌）。
  • Program.cs 啟動記一行系統環境摘要（OS/Framework/機器/環境/版本/DB/LLM 提供者）。

例外堆疊＋系統快照

  • ApiExceptionFilterAttribute、/Error 頁：例外日誌加 RuntimeEnvironmentInfo.Snapshot()（機器/程序/記憶體/執行緒）。
  • 新增 LoggingErrorBoundary（繼承 ErrorBoundary），於 MainLayout 包住內容區——Blazor 元件未處理例外now會 LogError＋快照並顯示友善畫面（先前無 ErrorBoundary、元件例外不落日誌）。

補靜默 catch 與無日誌檔

  • LlmGenerationService／DocumentLlmGenerationService 舊檔刪除的空 catch (IOException) {} → 補 LogDebug。
  • SystemHealthService 新增 ILogger 並於目錄可寫探測失敗記 LogDebug（原全檔無日誌）。
  • 誠實記錄：OpenAIChatCompletionClient.TryParseChunk、PipelineCancellationRegistry.TryCancel、兩個 View 的 ParseMetrics 為 static／已加註解的非空 fallback，屬低價值高頻或已文件化，維持現狀（非空 catch、不觸犯守則）。

守則測試

  • 新增 LoggingConventionTests：掃 src 產品碼（排除 Tests/Migrations/自動產生/obj/bin），禁止空 catch {}，違反即失敗並列 file:line。

文件

  • 擴充 docs/architecture/開發慣例與限制速查.md §1.1（Trace 語意、分級與臨時切換兩法、情境 scope＋啟動摘要＋例外快照、ErrorBoundary、守則測試）。
  • 更新 docs/operations/日誌與設定檔說明.md（§2.1 預設 info＋兩種臨時開 Trace 方式、新增 §2.2 情境欄位與快照）。

範圍決策（誠實記錄）

  • 不做全面機械式補日誌：既有覆蓋已廣（Warning 355/Info 317/Error 195/Debug 184），全面補會重複並違反「view 層不重複記錄」原則。
  • 沿用三鐵則：不記金鑰/密碼/token/請求本文；情境 scope 僅放帳號/團隊名/操作/Id。
  • 無 schema 變更 → 無 migration。
