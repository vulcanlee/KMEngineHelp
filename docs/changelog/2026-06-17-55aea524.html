逐字稿編修對話窗移除右側預覽並修復畫面閃爍（0.2.80）

  • 日期：2026-06-17
  • 版本：0.2.79 → 0.2.80
  • 類型：缺陷修正 / UI

問題

於「編修逐字稿」對話窗中：

  1. 逐字稿內容一定是純文字，右半部 Markdown 即時預覽沒有意義、只佔版面。
  2. 當逐字稿內容很長時，於左側編輯區點選任一區域會造成畫面不斷閃爍，並於瀏覽器主控台出現：

Error: Cannot send data if the connection is not in the 'Connected' State.

根因

ContentEditDialog.razor 右側預覽 @((MarkupString)MarkdownRenderer.ToHtml(editingText)) 會在每次重繪時，把整份（很長的）逐字稿重新轉成 HTML，並透過 Blazor Server 的 SignalR 線路送出。內容過長時 render batch／interop 週期過重，導致線路不穩、反覆重連（畫面閃爍），客戶端送出資料時即拋出上述錯誤。

修正

  • ContentEditDialog 新增 ShowPreview 參數（預設 true）；ShowPreview="false" 時右側預覽區塊完全不進入 render tree，左側編輯區自然撐滿寬度。
  • MediaTranscriptionView 的 <ContentEditDialog> 改傳 ShowPreview="@(!editIsTranscript)"：
  • 「編修逐字稿」→ ShowPreview=false：無預覽、滿版、消除過重渲染與閃爍。
  • 「編修產生結果」→ ShowPreview=true：維持 Markdown 即時預覽。
  • 文件萃取（DocumentExtractionView）、圖片辨識（ImageRecognitionView）沿用預設 true，行為不變。

影響範圍

  • 變更檔案：
  • Components/Commons/ContentEditDialog.razor
  • Components/Views/MediaTranscriptions/MediaTranscriptionView.razor
  • 無模型／資料庫變更，不需 migration。

後續修正（重要）

本次將閃爍歸因於「預覽即時轉 HTML」判斷有誤：移除預覽後閃爍仍在。真正根因為 Blazor Server SignalR 預設 MaximumReceiveMessageSize（32KB）被長逐字稿超過，已於 0.2.81 修正（見 2026-06-17-提高SignalR訊息上限修復長逐字稿閃爍.md）。本次的 ShowPreview 參數定位修正為純文字 UX 改善（逐字稿不需 Markdown 預覽），予以保留。

驗證

  1. 對有產生結果的紀錄點「編修產生結果」：維持左編輯／右 Markdown 預覽、即時更新、儲存正常。
  2. 文件萃取／圖片辨識編修對話窗仍顯示預覽、行為不變。
  3. （閃爍之最終驗證見 0.2.81 changelog。）
