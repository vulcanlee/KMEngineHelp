二、原本的計畫是錯的，先說結論

批次 5 原訂為「大合併」：以 guides/新手完整操作指南.md 為唯一權威，把其餘手冊與 7 份小指南轉成短指標。逐份比對內容後推翻了這個方向：

  • docs/guides/ 的 9,826 行不是重複膨脹，而是一組刻意分層的文件，各自服務不同讀者：安裝人員（使用者安裝與操作手冊，含 .NET Runtime、appsettings 逐鍵、抖音工具鏈、--urls／HTTPS 等別處找不到的內容）、一般使用者（AI知識問答使用指南，103 行、最常被單獨轉發）、管理員故障速查（系統監控與健康檢查指南，88 行，故障當下要能一次捲完）、知識維護者的參考卡（兩份評測指南、清洗規則設定指南——做事時攤在旁邊照著填）。
  • 大合併只能減少約 280 行（2.9%），卻會摧毀「整份單獨發給某個角色」這個屬性。
  • 兩份評測指南經查證是兩個不同功能，不可合併：/golden-samples 重跑清洗五段 LLM、打的是樣本自己的輸入文字、必須有 LLM 金鑰；/rag-evaluation 只跑混合檢索完全不經 LLM、打的是整個已索引知識庫、必須有嵌入端點。

真正的問題是分層漏水——本該在權威文件裡的內容只存在於某一份專題文件，導致該讀者查不到。本批修的是這個。

五、清理保護式替換刻意跳過的區域

批次 3 遮蔽了圍欄程式碼與圖表，導致舊選單名殘留在 mermaid／ASCII 流程圖內。已修 新手完整操作指南、完整操作手冊、實作練習手冊、從匯入到知識的操作流程、知識來源加工與清洗規則設定、使用者安裝與操作手冊 共 14 處。

ASCII 圖是對齊敏感的（┐├┘─► 連接線），改名造成字寬變化會讓圖形歪掉，因此逐塊改寫並重新對齊，不是單純字串替換。

另修兩處批次 3 的重複詞：日誌等級切換切換（完整操作手冊、security/認證授權與權限機制）。

權限常數（角色_黃金評測 等）與資料實體名（「黃金樣本」）刻意保留未動。
