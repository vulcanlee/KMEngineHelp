清洗 QA-3：人工審核關卡（核准/退回）（0.2.65）

  • 日期：2026-06-12
  • 版本：0.2.64 → 0.2.65
  • 對應路線圖：資料清洗開發代辦清單 第四階段 QA-3、設計 strategy/08

摘要

QA-2 會把低信心清洗結果路由為「待審核」。QA-3 加入人工審核關卡：審核者可把「待審核」 核准為「已清洗」，或退回為「已退回」，並記錄審核者與時間。

內容

  • 資料模型：KnowledgeSource 新增 ReviewedBy/ReviewedAt；新增狀態「已退回」

（KnowledgeSourceAdapterModel.StatusRejected）。雙 provider migration AddKnowledgeSourceReview（皆可空、免回填）。

  • 權限：新增專屬動作權限「知識審核」（MagicObjectHelper.角色_知識審核、RolePermissionService

之「清洗與蒸餾」群組）。這是動作權限非選單頁，故不加 Menu.json（角色管理勾選樹仍可勾選）。

  • 服務：KnowledgeSourceService.ApproveAsync／RejectAsync(id, reason)，注入 CurrentUserService

取審核者帳號；強制檢查：團隊權控（IsTeamAccessible）＋ 審核權限（IsAdmin 或具「知識審核」角色）＋ 狀態須為「待審核」。核准 → 已清洗並清空 ErrorMessage；退回 → 已退回，理由（選填）寫入 ErrorMessage。

  • UI：「待審核」列在具審核權時顯示 核准（✅）／退回（↩️）；退回開啟理由輸入 Modal；

「已退回」仍可檢視清洗結果與重新清洗；清洗結果 Modal 顯示審核者與時間。

  • 測試：KnowledgeSourceServiceTests 新增 5 筆（核准成功並記錄審核者、退回含理由、無審核權失敗、

非待審核狀態失敗、越權團隊失敗）；全測試 199 筆綠燈。

  • 不影響既有安全不變量（遮罩失敗仍整筆失敗、Teams 不被 LLM/審核改動）。

備註

  • 既有角色需於「角色管理」勾選「知識審核」才能審核（管理員不受限）。
  • 「校正」（核准前編輯清洗內容）與 QA-4 黃金評測不在本次範圍。
