2026-06-10 三條匯入管線：圖片佇列化、自動重試、取消機制（0.2.56–0.2.58）

摘要

完成資料清洗前置工作（strategy/08 Part A 的 A1/A2/A3，對應 planning/07 第〇階段）：圖片識別改為佇列化處理並補齊狀態機，與文件萃取／媒體轉錄三管線一致；三條管線一併加入自動重試、手動重試、取消機制與重啟回復。系統版本 0.2.55 → 0.2.58（每階段 +1）。

異動內容

A1 圖片識別佇列化（0.2.56）

  • 資料模型：ImageRecognition 新增 Status（未解讀／等待中／處理中／已完成／失敗／已取消，上傳預設「未解讀」）、ProgressPercentage、ErrorMessage、RecognitionPrompt（最近一次解讀提示詞，供重試重新入列）；雙 provider migration AddImageRecognitionStatus，Up() 內回填既有資料（已有解讀文字者標「已完成」）。
  • 管線：新增 IImageRecognitionQueue／ImageRecognitionQueue（Channel<int>）、ImageRecognitionProcessor、ImageRecognitionBackgroundService，完全比照文件萃取模式；移除 ImageRecognitionGenerationService，LLM 呼叫與檔案寫入併入 Processor（圖片改由 Processor 自磁碟讀取；入列動作於 UI scope 通過團隊權控）。
  • 服務：ImageRecognitionService 新增 EnqueueRecognitionAsync(id, prompt)（權控、提示詞必填、等待中/處理中拒絕重複入列）。
  • UI：解讀對話窗按「解讀」改為入列（移除 Task.Run 與 recognizingIds）；列表新增「狀態」「進度」欄（狀態可排序）；解讀中停用 ✨；輪詢改依 Status 判斷。觸發時機維持手動選提示詞。

A3 取消機制（0.2.57）

  • 取消註冊表：新增 IPipelineCancellationRegistry／PipelineCancellationRegistry（Singleton，(管線, Id) → linked CancellationTokenSource；Dispose 以 KeyValuePair 精確移除避免誤刪同 Id 新註冊）；PipelineNames 常數。
  • 背景服務：三個 BackgroundService 處理每筆時註冊取消權杖；單筆取消（非主機關機）時 MarkCancelledAsync 標記「已取消」（僅當狀態仍為等待中/處理中，不覆蓋已完成；紀錄已刪除則略過）。
  • 狀態：三個 AdapterModel 新增 StatusCancelled = "已取消"；Processor 出列時跳過已取消紀錄。
  • 服務：三個 Service 的 DeleteAsync 先發取消再刪除；新增 CancelAsync（等待中直接標記；處理中發取消、註冊表未命中的重啟孤兒直接標記）；TryDeleteRelative 改容錯（檔案被佔用記 log 不中斷）。

A2 自動重試與重啟回復（0.2.58）

  • 重試規則：新增 PipelineRetryHelper（MaxAttempts = 3，即首次＋自動重試 2 次；退避 10s×N）。暫時性錯誤（HttpRequestException、IOException、TaskCanceledException 逾時、未知例外）可重試；真取消、檔案不存在、設定/參數錯誤不重試。
  • Processor：三個 Processor 核心抽出 ProcessCoreAsync，ProcessAsync 套重試迴圈；重試期間 ErrorMessage 註記「第 N 次嘗試失敗，自動重試中」。
  • 手動重試：三個 Service 新增 RetryAsync（僅失敗/已取消；圖片另需留有 RecognitionPrompt）。
  • 重啟回復：三個 BackgroundService 啟動時 RecoverPendingAsync——「處理中」重設為「等待中」（註記系統重啟）並連同原「等待中」依 Id 升冪重新入列；圖片「未解讀」不入列（維持手動觸發）。
  • UI：三個清單頁操作區新增 重試（🔁，失敗/已取消）與 取消（⏹️，等待中/處理中）按鈕；圖片頁新增 檢視錯誤訊息（⚠️）；刪除確認文案註明會一併取消進行中工作。

測試

  • 新增 PipelineCancellationRegistryTests（7）、PipelineRetryHelperTests（3）、ImageRecognitionQueueFlowTests（9，SQLite in-memory 驗證入列/重試/取消狀態流與權控）；全部測試 164 綠。

注意事項

  • 套用本版需執行資料庫 migration（SQLite 與 SQL Server 各有 AddImageRecognitionStatus），啟動時自動套用。
  • 既有圖片紀錄經回填後：已有解讀文字者顯示「已完成」，其餘顯示「未解讀」。
  • 既有「失敗」紀錄沒有 RecognitionPrompt（佇列化前產生），不能用 🔁 重試，需以 ✨ 重新選提示詞解讀。

範圍外

  • A4 容量邊界文件化（前端事前提示、各工具上限說明）仍在 planning/07 待辦。
  • 多實例部署的入列競態防護（目前單實例 read-then-write 可接受）。
