Graph RAG P2：LLM 三元組抽取 + 人工審核 + 接進檢索（1.0.83 → 1.0.84）

  • 日期：2026-07-27
  • 版本：1.0.83 → 1.0.84
  • 類型：新增功能（Graph RAG 第二階段）

背景

延續 Graph RAG P1（GraphEdge wiki-link 邊 + 圖檢索融合）。P2 由 LLM 從蒸餾內容抽取「實體—關係—實體」三元組、經人工審核成為受治理的知識圖譜，並把已核可的三元組接進混合檢索加分。沿用蒸餾管線、WikiPage 審核、提示詞四層解析等既有模式。

變更

  1. 資料模型（新表，雙庫 AddGraphExtraction migration）：
  2. GraphNode（實體節點：Name/Type/WikiPageId 錨/Teams，同來源去重）、GraphTriple（節點→關係→節點邊：Relation/Confidence/Status(待審核/已完成/已退回)/審核欄位/Teams）。SubjectNodeId/ObjectNodeId/WikiPageId 為純索引整數無 FK（避免 SQL Server 多重串聯路徑）。
  3. KnowledgeSource 新增 GraphStatus/GraphProgressPercentage/GraphErrorMessage/GraphExtractedAt 狀態機（比照蒸餾/索引）。
  4. 提示詞槽位（四處同步）：LlmPromptKeys.GraphTripleExtract（"圖譜-三元組抽取"）+ LlmPromptsSettings + appsettings.LlmPrompts + LlmPromptDefaults（要求只輸出 JSON 陣列 {subject,subjectType,relation,object,objectType,confidence}）。
  5. 抽取管線（三件套，比照蒸餾）：GraphExtractionEnhancer（LLM + 穩健 JSON 解析 + 降級）、GraphExtractionProcessor（重試/取消/進度/GraphStatus 狀態機；建/去重節點、解析 WikiPage 錨、三元組一律「待審核」）、IGraphExtractionQueue/GraphExtractionQueue（Singleton Channel）、GraphExtractionBackgroundService（RecoverPending/消費/取消）。PipelineNames.GraphExtraction、LlmTokenUsage.OperationGraphExtraction + OperationLabelHelper 標籤。
  6. 觸發：蒸餾完成後自動入列（需 chat LLM）；審核頁「重新抽取」手動觸發。
  7. 重抽保留人工決策：以 (主詞|關係|受詞) 去重、已存在（任何狀態）者跳過，絕不刪除已核可/已退回。
  8. 審核頁（角色權限，比照知識頁審核）：GraphTripleService（查詢/核可/退回/編修/手動重抽觸發/取消）＋ /knowledge-graph-review（GraphReviewPage/GraphReviewView）。權限三處同步：新增頁面權限 角色_知識圖譜審核（沿用動作權 角色_蒸餾審核）、RolePermissionService 知識庫群組、Menu.json（icon hub）；MenuIconTests/PermissionConstantCanaryTests 同步。
  9. 檢索整合：RetrievalService.SearchGraphAsync 除 P1 wiki-link 邊外，再取 已完成 三元組、以兩端節點的 WikiPage 錨當「頁↔頁」邊（無向）併入 seed→1 跳→加分機制，沿用單一 GraphWeight。只有兩端都錨到現行頁的已核可三元組影響檢索。
  10. 待處理背景工作整合：PipelineJobQueryService/PipelineJobCancelService 納入 GraphExtraction（/pipeline-jobs 頁可見/可取消）。
  11. appsettings.json：SystemVersion 1.0.83 → 1.0.84。

安全與相容（leak=0 紅線）

  • 節點/邊帶 Teams（建立時從來源複製）；審核查詢、圖檢索遍歷、加分 chunk 查詢全套 TagStringHelper.BuildTeamAccessPredicate。他隊三元組不得用來加分，即使兩端頁面公開（ApprovedTriple_OtherTeam_DoesNotLeak 測試釘住）。
  • 待審核/已退回三元組不進檢索（PendingTriple_DoesNotBoost 釘住）。GraphWeight=0 仍可整體關閉圖路。
  • P1 的 GraphEdge（wiki-link）與既有 RAG、清洗、蒸餾、評測全部不受影響。

驗證

  • dotnet build 成功；dotnet test 785 全綠（既有 769 + 新增 16：GraphExtractionEnhancerTests 5、GraphExtractionProcessorTests 2、GraphTripleServiceTests 6、RetrievalServiceTests 三元組融合 3）；守護測試（權限/圖示/提示詞/作業別/管線涵蓋）全綠。
  • 手動：對已蒸餾來源自動或按「重新抽取」→ /knowledge-graph-review 列出待審核三元組 → 核可/退回/編修；核可後問跨實體關聯問題，關聯頁更易進出處；/rag-diagnostics 設 GraphWeight=0 回到不含三元組加分。
  • scripts/Test-DocsEncoding.ps1 0 失敗。
