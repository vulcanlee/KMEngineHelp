強化最高風險的逾時點（1.0.34）

  • 日期：2026-07-23
  • 版本：1.0.33 → 1.0.34

摘要

延續逾時盤點，強化三項最容易在「突發網路問題／資料過大」時導致處理逾時或無限阻塞的地方。

內容

1. 非串流 LLM 產生改走串流（解除 120 秒硬上限）

蒸餾、會議紀錄、文件萃取 LLM 產生、技能產生、逐字稿 LLM 產生原本走非串流 CompleteAsync，長內容整段生成易撞 120 秒 HttpClient 逾時。改用 1.0.33 建立的 CompleteStreamingAsync（以 SSE、ResponseHeadersRead 讀取，逾時只界定取得 headers 的時間），與清洗一致。

  • DistillationEnhancer、MeetingMinutesGenerationService、DocumentLlmGenerationService、SkillGenerationProcessor、LlmGenerationService 各一處呼叫改為串流。
  • 圖片解讀（CompleteWithImageAsync）與 Query Rewrite（已有 30 秒 per-call）維持不變。

2. ffmpeg／yt-dlp 加可設定逾時（避免無限阻塞）

VideoTranscoder、MediaChunker、MediaUrlDownloader 原本只吃外部取消權杖、無逾時上限，大檔或慢速網路可無限期阻塞背景管線。新增共用 ProcessRunner：套用逾時、逾時則 Kill 整個程序樹並擲 TimeoutException（沿用 Douyin／MarkItDown 既有範式，讀取輸出與等待同受逾時約束）。

  • 新增設定 OpenAISettings:FfmpegTimeoutSeconds（預設 3600）、OpenAISettings:YtDlpTimeoutSeconds（預設 1800）；值 ≤ 0 表示不套逾時。
  • PipelineRetryHelper.IsTransient 新增 TimeoutException => false：外部程序逾時代表「太久」，不再被重試放大（此改亦讓既有 MarkItDown 600 秒逾時不再重跑 3 次）。

3. 資料庫命令逾時 + SqlServer 連線重試

AddConfiguredDatabase 原本未設 command timeout（EF 預設 30 秒），大查詢／批次寫入易逾時；SqlServer 亦無連線重試。

  • SqlServer 與 Sqlite 兩分支皆加 CommandTimeout，值取自新設定 SystemSettings:DatabaseCommandTimeoutSeconds（預設 120）。
  • SqlServer 加 EnableRetryOnFailure（最多 3 次、間隔 10 秒），網路抖動時自動重試。

實作

  • Business/Services/Transcription/ProcessRunner.cs（新增）；VideoTranscoder.cs、MediaChunker.cs、MediaUrlDownloader.cs（建構式加逾時參數、程序等待套 ProcessRunner）。
  • 建構點串接：TranscriptionProcessor.cs、MediaTranscriptionService.cs。
  • Models/Systems/OpenAISettings.cs、Models/Systems/SystemSettings.cs（新設定）；Web/Extensions/ServiceCollectionExtensions.cs（DB 逾時與重試）；Business/Services/Pipelines/PipelineRetryHelper.cs（逾時不重試）。
  • 五個 LLM 產生服務改呼叫 CompleteStreamingAsync。
  • 測試：PipelineRetryHelperTests 新增 TimeoutException 不重試斷言；既有 LLM 服務測試靠 CompleteStreamingAsync 預設委派維持通過（632 全綠）。

備註

  • 無資料模型變更，不需要資料庫 migration。
  • 本次不含 SignalR ClientTimeoutInterval、IIS 請求 body 上限、Sqlite busy_timeout、ShutdownTimeout、RateLimiter、重試次數設定化等其餘風險項。
