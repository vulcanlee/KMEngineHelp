修正混合檢索關鍵字路徑的候選集無序截斷（1.0.16）

  • 日期：2026/07/19
  • 版本：1.0.15 → 1.0.16
  • 對應文件：知識庫 RAG 設計與執行 §4；嵌入索引與混合檢索 PRD；RAG rerank 是否導入分析

摘要

修正 RetrievalService.SearchKeywordAsync 的召回層缺陷：關鍵字路徑在打分之前就截斷候選集，且截斷時沒有任何排序依據。命中全部查詢詞的高相關 chunk，只要實體 Id 較大就永遠進不了 CandidateTopK，連被打分的機會都沒有。

問題

BuildKeywordPredicate 是 OR 述詞（含任一詞即入選），符合條件的列數往往遠大於 CandidateTopK（預設 50）。修正前：

candidates = candidates.Where(BuildKeywordPredicate(terms));
var rows = await candidates.Take(candidateTopK).ToListAsync(ct);   // ← 無 OrderBy
foreach (var row in rows)
{
    var matched = terms.Count(t => row.ChunkText.Contains(t, StringComparison.OrdinalIgnoreCase));
    if (matched > 0) scores[row.Id] = (row, (double)matched / terms.Count);   // ← 分數在截斷後才算
}

取回哪 50 筆由資料庫回傳順序決定（實務上接近主鍵順序）。這是召回問題不是排序問題：任何下游改善（融合權重調校、未來的 rerank）都救不回從未進入候選集的 chunk。

複現測試 KeywordPath_HighMatchChunk_SurvivesCandidateTruncation 在修正前的實際結果——回傳三筆全是 KeywordScore = 0.333 的雜訊，命中率 1.0 的目標 chunk 完全不在結果中。

設計重點

  • DB 端排序後才截斷：新增 BuildKeywordMatchCountExpression，把 terms 展開成 CASE WHEN ChunkText LIKE '%詞%' THEN 1 ELSE 0 END 的加總（結構比照既有 BuildKeywordPredicate 手工組 Expression tree），OrderByDescending 後再 Take(CandidateTopK)。EF Core 於 Sqlite 與 SQL Server 皆可翻譯，無客戶端評估。
  • 決定性 tie-break：.ThenBy(x => x.Id)。同分 chunk 大量存在時，避免候選集隨 DB 回傳順序漂移導致相同查詢回不同結果。
  • 分數語意不變：DB 端排序鍵僅用於「挑哪些進候選集」，屬近似排名（LIKE 的大小寫／定序語意隨資料庫而異）。最終 KeywordScore = 命中詞數 / 總詞數 仍以記憶體端 OrdinalIgnoreCase 重算，跨兩套 DB 一致。MinScore／RejectThreshold／LowConfidenceThreshold 的既有校準基準因此不受影響。

變更內容

  • 檢索服務（KnowledgeExtraction.Business/Services/Embeddings/RetrievalService.cs）：SearchKeywordAsync 改為排序後截斷；新增私有 BuildKeywordMatchCountExpression；類別註解補說明；LogDebug 補 CandidateTopK 以利 /rag-diagnostics 排查。
  • 測試（RetrievalServiceTests）：新增 KeywordPath_HighMatchChunk_SurvivesCandidateTruncation（先紅後綠，紅燈原因確認為目標 chunk 未進候選集）與 KeywordPath_CandidateSelection_IsDeterministic。全套 570 個測試綠燈。
  • 無模型變更，不需 migration。

影響與後續

  • 本次修正改變了召回基準。RAG rerank 是否導入分析 的觸發條件 2（「召回夠、排序差」）在修正前無法成立，該評測應於 1.0.16 之後重跑，勿沿用舊數據下結論。
  • CandidateTopK 預設值維持 50 未動——排序修好後候選品質已提升，是否需調高待評測數據再定。
  • 未處理（各自獨立、應分開評估）：融合分數的量綱正規化／RRF、MinScore 預設 0.0 使逐筆過濾形同虛設、DualDbVectorStore 全表載入算 cosine（無 ANN）。
