版本瀏覽體驗：主清單只顯示最新版＋版本歷史檢視（0.3.27→0.3.28）

  • 日期：2026-07-11
  • 版本：0.3.27 → 0.3.28
  • 類型：改善（延續素材版本鏈 0.3.21）

需求

素材版本鏈（0.3.21）上線後，主清單把所有版本攤平顯示（舊版標「已被取代」），版本一多即雜亂，且無專屬管道瀏覽同一份檔的歷次版本。決策：主清單只顯示每個版本鏈的最新版，另提供「版本歷史」檢視沿鏈列出 v1…vN；舊版原始資料全部保留、不做保留策略。

（另修正版本欄 razor 模板 v@context.VersionNumber 被 Razor 誤判為 email 而原樣輸出的顯示 bug，改為 v@(context.VersionNumber)。）

變更

商業層

  • 三素材 Service GetAsync(DataRequest) 加 Where(x => x.IsLatest)：主清單只回傳最新版。
  • 三素材 Service 新增 GetVersionHistoryAsync(int id)：載入指定紀錄後套用團隊權控（TagStringHelper.IsTeamAccessible），沿 PreviousVersionId 往回、SupersededById 往前收集整條版本鏈，依 VersionNumber 遞增回傳 AdapterModel 清單；無權限或查無資料回空清單。

UI 層

  • 三 View ActionColumn 新增「版本歷史」按鈕（history，僅 VersionNumber > 1 顯示）。
  • 三 View 各新增一個唯讀 Modal，以表格列出各版本：版本序號＋「最新／已被取代」標記、上傳時間、大小、狀態、下載/檢視連結（音訊＝來源檔＋逐字稿、文件＝Markdown、圖片＝原圖）。舊版下載沿用既有 /{id}/source、/{id}/markdown、/{id}/image API（皆以 id 查詢＋團隊權控、不受 IsLatest 限制，無需改 Controller）。
  • Code-behind 各新增 versionHistoryVisible/versionHistoryTitle/versionHistoryItems 欄位與 OnOpenVersionHistoryAsync/OnVersionHistoryCancel 方法。

測試

  • SourceVersionTests 補 3 筆：GetAsync 只回傳最新版；GetVersionHistoryAsync 回傳整條鏈且依版本序號遞增；非授權團隊取得空清單。

範圍決策（誠實記錄）

  • 不刪除舊版資料列與原始檔（維持現狀），本次不做保留策略／檔案清理。
  • 版本歷史為唯讀檢視；下載能力比照各素材主清單既有能力（文件無原始檔下載端點，故提供 Markdown）。

影響範圍

  • docs/architecture/資料生命週期與維護.md §4.1、§5-D。
  • appsettings.json SystemVersion 0.3.27 → 0.3.28。

驗證

  1. dotnet test --filter SourceVersionTests 綠燈（6 通過）。
  2. 手動：對一筆素材「上傳新版本」→ 主清單只剩最新版一列；點「版本歷史」→ Modal 列出 v1…vN（標記正確），可下載舊版；非管理員僅見有權限的版本鏈。
  3. scripts/Test-DocsEncoding.ps1 全綠。
