變更紀錄

側邊選單新增「僅管理員可見」機制，系統管理群組併入 /system-health 與 /rag-diagnostics（0.3.3→0.3.4）

  • 日期：2026-07-08
  • 版本：0.3.3 → 0.3.4
  • 類型：功能／權限強化

背景

管理員專用頁原本靠頁內 CheckIsAdmin() 守門，但側邊選單沒有「僅管理員可見」機制（選單只依角色權限 CheckAccessPage 過濾，而 IsAdmin 與 RoleList 是兩條獨立軌道，管理員不自動擁有所有權限）。導致：

  • /system-health、/rag-diagnostics 是管理員專用頁卻不在選單（只能記網址）。
  • 既有「系統管理」群組（/myusers、/roleviews，本身也是 CheckIsAdmin 專用頁）以角色權限顯示，出現「非管理員被權限勾選看得到選單、卻在頁面被擋」的不一致。

稽核結論

全站盤點所有 @page 路由後，「管理員專用（CheckIsAdmin）但不在側邊選單」的頁面僅兩個：/system-health、/rag-diagnostics。/myusers、/roleviews 已在「系統管理」群組。

變更

  • SidebarMenuItemModel 新增 AdminOnly 欄位（並在 CloneWith 一併複製，避免 clone 遺失）。
  • SidebarMenuService 過濾抽出純函式 FilterMenuItems(items, isAdmin, checkAccessPage)（可單測）：AdminOnly 項僅管理員可見（略過角色權限 CheckAccessPage），非管理員整項含子樹隱藏。
  • Menu.json：「系統管理」群組與其所有子項標 adminOnly: true，群組 icon 改 admin_panel_settings，新增子項「系統健康監控」(/system-health)、「RAG診斷」(/rag-diagnostics)。
  • 雙層防護：選單隱藏（本次）+ 頁面 CheckIsAdmin（既有，四頁皆具）——非管理員即使直接輸入網址也被擋。

行為變更

  • 「系統管理」群組改為僅管理員可見（原為角色權限控制）。因群組內四頁本來就是 CheckIsAdmin 專用頁，此改動使「選單可見性」與「頁面實際可存取性」一致，並修正先前不一致。
  • 免動 RolePermissionService／MagicObjectHelper（不新增頂層群組、不改順序，無位置索引風險）。

測試

  • 新增 SidebarMenuServiceTests（3）：管理員可見系統管理＋全部 adminOnly 子項（略過角色權限）；非管理員即使 CheckAccessPage 一律 true 仍看不到；一般群組無權限則隱藏。

影響範圍

  • appsettings.json SystemVersion 0.3.3 → 0.3.4。無資料庫變更。
  • 選單有快取，部署／重啟後生效。
  • 同步更新 docs/operations/RAG問題診斷手冊.md（/rag-diagnostics 已入管理員選單）。

驗證

  1. dotnet test --filter SidebarMenuServiceTests 綠燈（3 通過）；dotnet build 成功。
  2. 手動：管理員登入見「系統管理」含四項並可開啟；非管理員看不到該群組；非管理員直達 /system-health、/rag-diagnostics 被擋。
  3. scripts/Test-DocsEncoding.ps1 全綠。
