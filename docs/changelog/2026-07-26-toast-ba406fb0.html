Toast 全站清零並補上自動守門，移除範例死碼（1.0.73→1.0.74）

  • 日期：2026-07-26
  • 版本：1.0.73 → 1.0.74
  • 類型：UX 一致性修正 ＋ 假宣稱更正 ＋ 死碼移除

需求

docs/architecture/開發慣例與限制速查.md 宣稱：

不要用 MessageService……（1.0.24 已全站掃描移除，僅剩未註冊的 RoleViewViewSample 例外）

這句話是假的。 1.0.71 盤點時查出還有 6 個活著的檔案、18 個呼叫點在用 MessageService：

檔案呼叫點影響
Commons/ContentEditDialog.razor9被七個頁面共用，含「已複製到剪貼簿」「已取代 N 處」等高頻 toast
Commons/MarkdownActionBar.razor4複製／PDF 下載提示
Commons/ReportPdfButton.razor1統計報表 PDF 失敗提示
Pages/ChangePassword.razor1變更密碼成功
Pages/Profile.razor1設定 API 密碼成功
Views/TokenUsage/TokenUsageView.razor.cs1Token 用量 PDF 失敗提示

AntDesign 的 message 固定置中頂部、沒有位置選項，所以這些訊息一直跳在畫面正中上方，而全站其他 209 處通知都在右下角。使用者看到的是同一個系統有兩種不一致的提示位置——而且沒人發現。

根因不是有人不遵守慣例，是這條鐵則從來沒有守門。 1.0.24 訂立時只做了一次性 grep 掃描，之後 47 個版本沒有任何機制檢查，於是逐漸回退，文件卻還在宣稱只剩 1 個例外。

變更

一、6 檔清零（18 個呼叫點）

一律改為內嵌 NotificationConfig（1.0.24 明文決定不另建全域 helper），Placement = NotificationPlacement.BottomRight。高頻短確認用 Duration = 3，錯誤沿用預設。

  • ChangePassword／Profile：改用具名標題（「變更密碼成功」／「設定 API 密碼成功」）＋ Duration = 5，與該檔既有的失敗通知對稱。兩檔原本就已注入 NotificationService，只是成功路徑漏用。
  • ContentEditDialog（9 處）與 MarkdownActionBar（4 處）：呼叫點多，各收成本地 Notify(description, type, duration)；跨檔仍逐處內嵌。
  • TokenUsageView：[Inject] MessageService 改為建構式注入 NotificationService，符合速查慣例（AntDesign 服務走建構式、[Inject] 留給框架類）。
  • 順修 AccessDatas/Models/PipelineProgressEvent.cs:14 的過時註解（原寫「對應前端 AntDesign MessageService 的四種 toast」）。

二、刪除範例死碼

刪 Components/Views/Admins/RoleViewViewSample.razor{,.cs,.css}。確認為死碼：無 @page、全 src/ 除自身 partial class 宣告外零引用。

它被 guides/建立一個新 CRUD 操作網頁說明.md 兩處明文點名為「絕對不要當模板」，所以刪除必須連帶改文件，否則讀者會找不到那段警告的對象。而那兩處也宣稱它是「全站唯一還在用 MessageService」——同樣是假的，一併更正。

三、補上自動守門（本批真正的價值）

新增 Tests/ToastConventionTests.cs（範本：LoggingConventionTests），掃 src/ 全部 .cs 與 .razor，出現 MessageService 即紅燈並列出 檔名:行號 與正確寫法。

同時掃 .razor 是必要的：那 6 個回退檔案中有 5 個是把 @inject 寫在 .razor 裡，只掃 .cs 會全部漏掉。

守門本身已驗證有效：刻意在 ReportPdfButton.razor 植入一行 @inject MessageService，測試立刻失敗並精準指出 ReportPdfButton.razor:6，還原後恢復綠燈。

若這次只把速查那句話改對而不加守門，同樣的漂移會第三次發生。這是本批做這件事的理由。

四、更正兩份文件的假宣稱

  • architecture/開發慣例與限制速查.md：刪掉「僅剩未註冊的 RoleViewViewSample 例外」，改為說明 1.0.74 起由測試強制，並記下「為什麼需要自動守門」的完整經過（含 6 檔 18 點的事實），避免日後又有人以為做一次 grep 就夠。
  • guides/建立一個新 CRUD 操作網頁說明.md（2 處）：說明該檔已刪除，並更正「全站唯一」的錯誤說法。

執行順序是刻意的：先改 6 檔 → 刪死碼 → 加測試（此時才會綠）→ 最後才改文件。順序反了就只是把一句假話換成另一句。

測試

708 → 709（+1，全綠）。新增的是掃描式測試，不是行為測試——它保證「沒有人在用被禁的服務」，不保證每個 toast 的位置參數都正確。

影響與相容性

  • 使用者可見：上述 18 處提示的顯示位置由畫面正中頂部改為右下角，與全站一致。訊息文字不變（只有 ChangePassword／Profile 兩處多了標題列，與同頁失敗通知一致）。
  • 刪除的 3 個檔案未註冊路由、零引用，不影響任何功能。
  • 無資料庫 migration、無 API 合約變更。

版本

  • appsettings.json SystemVersion：1.0.73 → 1.0.74。
