Graph RAG P4：跨來源實體合併（1.0.85 → 1.0.86）

  • 日期：2026-07-27
  • 版本：1.0.85 → 1.0.86
  • 類型：行為調整（Graph RAG 第四階段，解除 P3「社群落單一來源」限制）

背景

P2/P3 的 GraphNode 為 per-來源去重、三元組亦同來源，故 P3 社群多半落在單一來源內：兩份不同來源都提到「台積電」時，被視為兩個不同節點、連不起來。P4 以實體名稱正規化把跨來源的同名實體視為同一實體（行為式合併），讓：

  1. 社群偵測跨來源分群（真正解決 P3 限制）。
  2. 檢索三元組路徑跨來源多跳（同名實體連起不同來源的頁）。

與使用者確認的決策：合併準則＝正規化名稱精確比對（trim／大小寫／全半形正規化後相等）；行為式合併、不建表、無 migration；套用範圍＝社群偵測＋檢索都套；合併鍵＝僅用名稱（忽略 Type）。

變更

  1. 新 helper：EntityNameNormalizer.Canonical(name)＝Trim + Normalize(FormKC)（統一全半形與相容字元）+ ToLowerInvariant；null/空白 → 空字串。決定性、無 LLM、成本零。
  2. 社群偵測（GraphCommunityBuilder.RebuildAsync）：LPA 的「頂點」由節點 Id 改為正規化名稱（名稱 ↔ 連續 int 索引）；三元組轉為「正規化名稱邊」（跳過空名與同名自我環）。社群成員＝一組正規化名稱；MemberCount＝去重後實體數；Teams＝所有 canonical 落在群內的節點 Teams 聯集（跨來源自然併入）；relations＝兩端 canonical 皆在群內的三元組（去重）。摘要 LLM 與整批取代不變。
  3. 檢索（RetrievalService.SearchGraphAsync）：三元組兩端由「單一節點錨頁」改為「正規化名稱 → 跨來源頁集合」。先建 pagesByCanon（GraphNode 且 WikiPageId!=0、非管理員套 BuildTeamAccessPredicate(n=>n.Teams)）→ 正規化名稱 → 該名稱的所有 WikiPageId（跨來源）；已核可三元組取兩端名稱與 Teams，僅處理「某端頁集合與種子頁有交集」者（控成本），對每組 (subjPage, objPage) 呼叫既有 AddTripleNeighbor 兩向。P1 GraphEdge（wiki-link）路徑與下游鄰居 chunk 映射/ACL 不變。
  4. appsettings.json：SystemVersion 1.0.85 → 1.0.86。

安全與相容（leak=0 紅線不變）

  • 合併只改「圖的連通性」，不放寬權控：錨頁集合以 node.Teams 過濾、三元組以 triple.Teams、鄰居 chunk 以 VectorEmbedding.Teams——他隊節點/關係不因合併外洩。新增「錨頁節點 ACL」（pagesByCanon 只收使用者可存取的節點錨頁），為既有 chunk 層過濾再加一道防線。
  • 社群 ACL 仍為「Teams 聯集 ⊆ 使用者團隊」（P3）；合併後聯集可能變大（跨來源同名實體的 Teams 併入），是正確且更嚴的結果。
  • 向後相容：當每個名稱只錨一頁（單一來源）時，社群與檢索行為與 P2/P3 完全相同——既有單來源測試不變。
  • 無 schema／migration／新管線／新 UI，純建圖邏輯 + 一個 helper，風險低、可回歸。

已知限制（P5 再處理）

  • 精確名稱合併的取捨：可能把「同名不同物」誤併（如兩來源不相關的「王小明」），也無法併別名（台積電＝TSMC）。這是 GraphRAG 實體解析的基準做法；別名/嵌入式解析與「合併審核」留待未來。
  • 記憶體：檢索需載入（ACL 過濾後的）錨頁節點與已核可三元組名稱；以種子過濾三元組處理量。大圖時可再優化。

驗證

  • dotnet build 成功、無新增警告；dotnet test 806 全綠（既有 795 + 新增 11：EntityNameNormalizerTests 8 個 case、GraphCommunityBuilderTests 跨來源合併 1、RetrievalServiceTests 跨來源多跳 1 + 跨來源越權 leak=0 1）。
  • 重點確認：P2/P3 單來源案例行為不變；跨來源同名實體收斂為單一社群且 Teams 聯集含兩來源；跨來源多跳把另一來源的鄰居頁 chunk 帶進並加分；他隊節點錨頁不進 pagesByCanon（leak=0）。
  • 手動：兩份不同來源、內容含同一實體 → 核可三元組 → 重建社群摘要（社群跨兩來源）→ 全域問答可跨兩來源綜合；一般問答問及該實體時，另一來源相關頁更易進出處。
  • scripts/Test-DocsEncoding.ps1 0 失敗；版本 1.0.86。
