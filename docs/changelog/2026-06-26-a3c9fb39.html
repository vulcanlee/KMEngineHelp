階段三步驟 5：跨來源問答服務 + 知識庫問答頁 + 出處鑽取（0.2.127）

  • 日期：2026/06/26
  • 版本：0.2.126 → 0.2.127
  • 對應設計：階段三：知識庫與 RAG 設計規格 §7–§10；路線圖步驟：strategy/12 §12.2 步驟 5

摘要

階段三最大的一步：把混合檢索接上 LLM 問答與 UI，達成「員工手冊」端到端情境——使用者用自然語言跨整個知識庫提問，得到附出處、受團隊權控的串流答案，並可從出處鑽取回來源成員與原始檔下載。完全沿用既有「知識來源 AI 對話」的服務/頁面慣例與四層提示詞、串流、詳簡、權控機制。

設計重點

  • 跨來源問答服務 KnowledgeBaseChatService：每輪重新取 RecordAccessScope（§8.3）→ IRetrievalService 混合檢索（檢索層即套團隊權控）→ 組附出處 context（Wiki 導引在前、Cleaned 佐證在後，每段前置 【來源：標題｜層別｜錨點】）→ 四層提示詞（新增 知識庫-系統 槽位「查無依據明說、不得臆造」）+ 詳簡 → 委派 IChatConversationClient 串流；記錄結構化稽核軌跡（誰／問句／命中 chunk 與分數）。
  • 知識庫問答頁 /knowledge-base-chat：ChatGPT 風格、多輪、串流（節流重繪）、詳簡切換、停止、每輪複製；每個 AI 回合下方出處面板列出引用 chunk（標題／層別／錨點／片段／分數），可展開來源 → 取成員（KnowledgeSourceService.GetAsync，已權控）→「下載原始檔」走既有受權控端點。
  • 權控（資安關鍵）：越權內容由檢索層過濾，不入 context／答案／出處；下載一律走既有 MediaTranscription/DocumentExtraction/ImageRecognition Controller（內建 IsTeamAccessible），不新造繞過權控的下載。

變更內容

  • 提示詞：LlmPromptKeys/LlmPromptDefaults/LlmPromptsSettings 新增 KnowledgeBaseSystem（知識庫-系統）；appsettings.json LlmPrompts 同步。
  • 服務：KnowledgeBaseChatService（Business/Services/DataAccess/）＋ KnowledgeBaseSourceAdapterModel（出處顯示模型）；DI 註冊 AddScoped<KnowledgeBaseChatService>()。
  • UI：Components/Pages/KnowledgeBase/KnowledgeBaseChatPage.razor＋Components/Views/KnowledgeBase/KnowledgeBaseChatView.razor(.cs/.css)（出處面板與鑽取下載）。
  • 權限三處同步：MagicObjectHelper.角色_知識庫問答；RolePermissionService 群組 2 於知識蒸餾後、審核動作型前插入；Menu.json 清洗與蒸餾群組新增「知識庫問答」(id 35, icon forum, /knowledge-base-chat)；MenuIconTests 允許清單加 forum。
  • 測試：KnowledgeBaseChatServiceTests（context Wiki 在前、出處組裝、越權 0 命中、管理員全得、系統提示詞含「不得臆造」、空 context 退化提示）。全套 351 個測試綠燈。本步驟無模型變更、不需 migration。

後續

依 strategy/12 §12.2，下一步為步驟 6：RAG 評測集與指標（檢索 Precision/Recall/NDCG、出處正確率、越權洩漏測試、延遲/用量），與既有黃金評測頁併呈。
