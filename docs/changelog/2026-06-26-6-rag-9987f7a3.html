階段三步驟 6：RAG 評測集與指標（與黃金評測併呈）（0.2.128）

  • 日期：2026/06/26
  • 版本：0.2.127 → 0.2.128
  • 對應設計：階段三：知識庫與 RAG 設計規格 §11–§12.2；路線圖步驟：strategy/12 §12.2 步驟 6（階段三最後一步）

摘要

替階段三整條 RAG 管線（清洗 → 蒸餾 → 索引 → 混合檢索 → 跨來源問答）補上品質保證層：新增獨立的「RAG 評測」頁，以評測集量化檢索品質與權控合規，與既有「黃金評測」（上游清洗品質）並列於「清洗與蒸餾」選單，形成「清洗品質 → 檢索品質」完整把關鏈。指標採檢索為主、確定性、可離線（不需 LLM 生成即可跑；嵌入未設定時退化為關鍵字檢索仍可評測），完全鏡像黃金評測的縱切與頁面慣例。

設計重點

  • 相關性 ground truth ＝知識來源標題：每筆命中解析其 KnowledgeSourceId → 來源標題，標題 ∈ 樣本「期望命中來源」即視為相關（binary relevance）。以標題（非 chunk Id）標註，對重建索引穩定。
  • 模擬身分評測：每筆樣本帶 EvalIsAdmin/EvalTeams，組成 RecordAccessScope 傳入 IRetrievalService.RetrieveAsync。品質樣本設管理員（看全部）；資安樣本設受限團隊＋只列可見來源，由越權洩漏指標把關。
  • 純函式評測器 RagEvaluator：計算 Precision@k / Recall@k / NDCG@k / MRR / 出處正確率（有期望錨點時以 AnchorRef 命中比例，否則退回來源標題相關比例）/ 越權洩漏（命中中不可見筆數，資安守門應為 0）/ 檢索延遲；仿 CleaningEvaluator 純函式精神，不碰 DB/LLM。
  • 權控（資安關鍵）：越權內容由檢索層（IRetrievalService + TagStringHelper.BuildTeamAccessPredicate）過濾，評測時再以 TagStringHelper.IsTeamAccessible 對每筆命中二次校驗作回歸守門；儀表板「越權洩漏總數」>0 以紅色醒目示警。

  • Migration：AddRagEvalSample 雙資料庫各一套（SQLite AccessDatas＋SQL Server AccessDatas.SqlServerMigrations）。
  • 指標/評測：RagEvaluationModels（RagEvalHit/RagSampleMetrics/RagEvalAggregateReport）＋ RagEvaluator（純函式）於 Business/Services/Embeddings/。
  • 服務：RagEvaluationService（Business/Services/DataAccess/，CRUD＋載入範本種子＋EvaluateOneAsync＋GetAggregateAsync）；DI 註冊 AddScoped<RagEvaluationService>()。
  • 映射：AutoMapping 新增 RagEvalSample ⇄ RagEvalSampleAdapterModel（三標籤欄走 TagStringHelper）；RagEvalSampleAdapterModel（Models/AdapterModel/）。
  • UI：Components/Pages/RagEvaluations/RagEvaluationPage.razor＋Components/Views/RagEvaluations/RagEvaluationView.razor(.cs/.css)（工具列、指標儀表板含越權洩漏示警、表格、編輯/明細 Modal）；路由 /rag-evaluation。
  • 權限三處同步：MagicObjectHelper.角色_RAG評測；RolePermissionService 群組 2 於 角色_知識庫問答 後、角色_知識審核 前插入；Menu.json 清洗與蒸餾群組新增「RAG評測」(id 36, icon query_stats, /rag-evaluation)。
  • 測試：RagEvaluatorTests（P/R/NDCG/MRR/出處/越權＝0 與越權>0 各情形）、RagEvaluationServiceTests（種子、管理員評測指標、受限團隊越權 0 命中、彙總）。本步驟有模型變更，已產雙 migration。

使用備註

  • 「載入種子」載入的是範本樣本（員工手冊健檢福利情境），其「期望命中來源」須改為你實際已索引的知識來源標題才有評測意義。
  • 評測為確定性、不需 LLM；嵌入未設定時走關鍵字檢索路徑仍可量化。生成答案品質（如答案要點涵蓋）屬後續延伸，本步驟聚焦檢索。

後續

階段三步驟 1–6 全部完成。後續 PoC（strategy/12 §11.3）：以 1–2 份真實手冊/SOP 走完整管線並人工檢視答案正確性、出處可追溯、權控正確、遮罩無漏。
