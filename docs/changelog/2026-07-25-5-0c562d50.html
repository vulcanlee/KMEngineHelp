統計報表 5 頁：分析區塊改為垂直排列並放寬間距（1.0.53）

  • 日期：2026-07-25
  • 版本：1.0.52 → 1.0.53
  • 類型：使用體驗修正（版面配置與間距）

問題

/reports/* 底下的 5 個統計報表頁，分析區塊原本以左右兩欄 flex 版面（.report-columns + .report-col）呈現，且同一欄內的第二個區塊只靠 inline style="margin-top:16px;" 隔開。使用者反映這些區塊過於擁擠，且左右兩欄的閱讀動線需要來回跳動。

受影響頁面：Token 用量分析 /reports/token-usage-report、使用者回饋分析 /reports/feedback-report、問答量與使用行為 /reports/qa-activity-report、檢索品質分析 /reports/retrieval-quality-report、內容清點統計 /reports/content-inventory-report。

變更

1. 版面改為單欄垂直堆疊

5 個 View 的分析區塊全部攤平成「一個區塊一個 <section>」，由上而下垂直排列（滿版寬度）。順序依原本畫面「由左至右、由上而下」的閱讀順序：

頁面垂直順序
Token 用量分析統計卡片 → 使用者 Token 用量排名 → 依作業別 → 依模型
使用者回饋分析統計卡片 → 依使用者回饋排名（滿意數） → 每日滿意/不滿意趨勢
問答量與使用行為統計卡片 → 依來源 → 每日問答量/被封鎖趨勢 → 使用者活躍度排名
檢索品質分析統計卡片 → 信心分布 → TopScore 分桶
內容清點統計統計卡片 → 依媒體型別 → 依團隊 → 依狀態 → 依分類

統計卡片列一併納入同一個堆疊成為第一個區塊，讓卡片列到第一個分析區塊的間距與其他區塊一致。所有 <h3 style="margin-top:16px;"> 的 inline style 一併移除，間距改由 CSS 統一控制。

2. 全域 CSS（wwwroot/app.css）

移除只有這 5 頁在用的 .report-columns / .report-col，改為垂直堆疊樣式，沿用儀表板／RAG 診斷頁「留白 + 淡色細分隔線」的既有慣例：

.report-stack {
    margin-bottom: 24px;
}

.report-block {
    margin-bottom: 0;
}

.report-block:not(:first-of-type) {
    margin-top: 28px;
    padding-top: 28px;
    border-top: 1px solid #f0f0f0;
}

:not(:first-of-type) 讓最上方的統計卡片列不會多出一條分隔線。

3. 附帶修正：CRUD 圖示白名單

CrudActionIconTests.AllowedCrudActionIcons 補上 bolt、tune。這兩個圖示是 1.0.49 在 CleaningProfileViewView.razor 新增「低度／中度清洗範本」按鈕時加入的，但當時漏了同步測試白名單，導致該測試自 1.0.49 起持續失敗。兩者皆為合法的 classic Material Icons 名稱。

影響範圍

  • 檔案：wwwroot/app.css、Components/Views/Reports/ 下 5 個 *ReportView.razor、appsettings.json。
  • .report-columns / .report-col 經查證僅這 5 個 View 使用，汰除後無殘留參考，不影響其他頁面。
  • 無 C# 邏輯異動、無資料異動、無資料庫 migration。
  • PDF 匯出不變：各頁 .razor.cs 內組 pdfModel 的程式碼未調整，匯出內容與順序維持原樣。
  • appsettings.json SystemVersion 1.0.52 → 1.0.53。

驗證

  1. dotnet test 通過：632 個測試全數通過（修正白名單前為 631 通過、1 失敗）。
  2. grep -rn "report-columns\|report-col\b" src/ 為 0 筆。
  3. 以管理員逐一開啟 5 個報表頁：各區塊單欄由上而下排列且順序符合上表；區塊之間有明顯留白與一條 #f0f0f0 細線；統計卡片列上方無分隔線；長條圖滿版無破版；視窗縮至窄寬度仍正常。
  4. 任一頁按「匯出 PDF」仍可正常產生。
