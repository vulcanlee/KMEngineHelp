修正 ZIP 批次上傳檔名亂碼（Big5/cp950 解碼）（1.0.32）

  • 日期：2026-07-23
  • 版本：1.0.31 → 1.0.32

摘要

修正「文件萃取」與「圖片清單」以 .zip 批次上傳時，記錄的標題與原始檔名出現亂碼（大量 U+FFFD 替代字元）的問題。

根因

Windows 中文環境用內建壓縮工具產生的 zip，其 entry 檔名以 Big5/cp950 位元組儲存，且未設定 UTF-8 語言旗標（General Purpose Bit Flag bit 11）。兩處批次解壓程式碼建立 ZipArchive 時未指定 entryNameEncoding，.NET 便一律以 UTF-8 解碼；Big5 位元組被判為無效序列而變成 U+FFFD，該亂碼字串再經 entry.Name 寫入 Title 與 OriginalFileName。專案原本亦未具備 cp950 解碼能力。

修正

  • 新增 KnowledgeExtraction.Business/Helpers/ZipEntryEncoding.cs：於 static 建構式註冊

CodePagesEncodingProvider，並提供 cp950（Big5）編碼。

  • DocumentExtractionService.AddBatchFromZipAsync 與 ImageRecognitionService.AddBatchFromZipAsync

建立 ZipArchive 時傳入 entryNameEncoding: ZipEntryEncoding.Cp950。 .NET 對已標 UTF-8 旗標的 entry 仍固定用 UTF-8（忽略此值），未標記者才用 cp950，因此 UTF-8 zip 與 Big5 zip 兩種來源皆正確。

  • KnowledgeExtraction.Business.csproj：新增 System.Text.Encoding.CodePages 套件。
  • 測試：DocumentExtractionBatchZipTests、ImageRecognitionBatchZipTests 各新增一個以 cp950

編碼檔名（不設 UTF-8 旗標）建立 zip 的迴歸測試，斷言解碼後為正確繁中且不含替代字元。

備註

  • 無資料模型變更，不需要資料庫 migration。
  • 既有已亂碼的舊紀錄無法程式還原（解碼時原位元組已遭 U+FFFD 取代而永久消失），

需手動刪除後重新上傳。
