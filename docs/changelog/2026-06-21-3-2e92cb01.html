2026-06-21 方案 3：四層提示詞解析（LlmPromptResolver）

版本：0.2.109 → 0.2.110

承 LLM 提示詞與用量透明化 §7 方案 3。

需求

讓所有 LLM 提示詞可被多層覆蓋、可線上客製、互動更透明，且保留程式預設為最終保險。

變更

新增（Business/Services/Prompts/、Models/Systems/）

  • LlmPromptKeys：槽位鍵常數（清洗五鍵沿用舊名、對話/詳簡/技能/轉錄）。
  • LlmPromptDefaults：集中程式 fallback 預設文字（自 CleaningEnhancer/KnowledgeSourceChatService/SkillPromptDefaults 搬入；SkillPromptDefaults.MetaPrompt 改為 re-export 以免 drift）。
  • LlmPromptsSettings：appsettings LlmPrompts 區段（強型別具名屬性，值留空＝用 fallback）＋ Get(key)。
  • LlmPromptResolver.ResolveAsync(key, perOpOverride, fallback)：四層優先序「單次操作 → DB(同名鍵) → appsettings → fallback」，Debug 記錄採用層級。
  • PromptService.GetEnabledContentByNameAsync(name)：依名稱取啟用提示詞本文（DB 覆蓋層）。

整合（改走 resolver；上層皆空時輸出與 0.2.109 一致）

  • CleaningEnhancer：五步驟改 resolver（單次操作＝清洗設定檔欄位）；移除五段常數與本地字典/helper。
  • KnowledgeSourceChatService：BuildMessages → BuildMessagesAsync，系統提示詞與詳簡指示走 resolver；對話頁改 await。
  • SkillGenerationProcessor：技能 Meta 走 resolver（單次操作＝CustomPromptText）。
  • TranscriptionProcessor：中文轉錄提示詞加 DB「轉錄-提示」覆蓋層，fallback 沿用 OpenAISettings.Prompt。
  • DI：Configure<LlmPromptsSettings>、AddScoped<LlmPromptResolver>；appsettings.json 新增 LlmPrompts 區段（值留空、附說明）。

影響範圍

  • 變更檔：LlmPromptKeys/Defaults/Resolver（新）、LlmPromptsSettings（新）、LlmPromptResolverTests（新）、PromptService、CleaningEnhancer、KnowledgeSourceChatService、KnowledgeSourceChatView.razor.cs、SkillGenerationProcessor、TranscriptionProcessor、SkillPromptDefaults、ServiceCollectionExtensions、appsettings.json、文件。
  • 轉錄維持 json 回應（0.2.109 起）；無資料庫變更、不需 migration（Prompt 表沿用）。
  • 行為不變量：DB 與 appsettings 皆空時＝沿用程式預設，既有產出與測試不變。

驗證

  1. dotnet test 全綠（281 通過，含 5 筆新 LlmPromptResolverTests）。
  2. 「提示詞清單」新增啟用同名鍵 → 對應功能改用；清空→退 appsettings→再退 fallback；對話頁/設定檔等單次輸入蓋過所有層。
  3. scripts/Test-DocsEncoding.ps1 全綠。
