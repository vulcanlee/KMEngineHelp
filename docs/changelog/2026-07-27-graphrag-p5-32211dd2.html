Graph RAG P5：實體別名與合併審核（1.0.86 → 1.0.87）

  • 日期：2026-07-27
  • 版本：1.0.86 → 1.0.87
  • 類型：新增功能（Graph RAG 第五階段，補 P4 精確名合併無法處理的別名）

背景

P4 只以正規化名稱精確比對跨來源合併同名實體，無法合併「別名／同義」——「台積電」與「TSMC」是同一實體卻不同名，社群連不起、檢索多跳斷開。P5 補上人工維護的實體別名與合併審核治理流程：管理員手動建立「別名 → 標準名」對，經審核核可後，別名變體在社群偵測與檢索兩處都視為同一實體（沿用 P4 行為式合併，僅擴大「同一實體」判定）。

與使用者確認的決策：候選來源＝純人工手動建立 + 審核（無 LLM／嵌入／啟發式候選）；UI＝併入現有「知識圖譜審核」頁新增分頁、沿用 角色_知識圖譜審核 頁權（不新增權限常數）；資料模型＝別名 → 標準名（每列一對，核可後以 union-find 傳遞閉包形成合併群組）；套用範圍＝社群偵測＋檢索都套。

變更

  1. 新資料表 GraphEntityAlias（受治理、可審核）：AliasName/CanonicalName/Status(待審核/已完成/已退回)/ReviewedBy/ReviewedAt/ErrorMessage/時間戳。無 FK、無 Teams（全域治理 metadata）。BackendDBContext 加 DbSet；雙庫 AddGraphEntityAlias migration。GraphEntityAliasAdapterModel 含 status 常數，服務端手動投影（不動 AutoMapping）。
  2. 別名解析器 EntityAliasResolver（static、可測）：BuildMap 以 union-find 把已 Canonical 化的別名對聯集成「正規化名稱 → 群組代表」對照（代表取群內序數最小字串，決定性）；Resolve 先 EntityNameNormalizer.Canonical 再查表，無別名者退回自身 canonical。
  3. 三個 canonical 呼叫點套別名解析：GraphCommunityBuilder.RebuildAsync（LPA 頂點）與 RetrievalService.SearchGraphAsync（pagesByCanon 錨頁分組 + 三元組兩端）皆改為「先 Canonical 再 Resolve」，各載入已完成別名建 map。P1 wiki-link 路徑與下游 ACL 不變。
  4. 別名審核服務 GraphEntityAliasService（Scoped，仿 GraphTripleService）：Get/Add/Approve/Reject，守序＝CleanTrackingHelper.Clean → 重讀 → 管理員檢查 → 狀態前置 → 稽核戳 → 存檔。驗證：非空、Canonical(alias)!=Canonical(canonical)、（正規化）重複對擋下。
  5. UI：「知識圖譜審核」頁以 <Tabs> 拆「三元組審核」（原內容）與「實體合併」分頁；後者僅管理員（CheckIsAdmin()）渲染，含新增別名表單、狀態篩選、清單與核可/退回。提示「核可別名後按『重建社群摘要』使社群套用；檢索即時生效」。
  6. appsettings.json：SystemVersion 1.0.86 → 1.0.87。

安全與相容（leak=0 紅線不變）

  • 別名只改「圖的連通性」的「同一實體」判定，不放寬權控：檢索的 pagesByCanon 錨頁節點仍套 BuildTeamAccessPredicate(n=>n.Teams)（他隊別名節點錨頁不得進入）、三元組以 triple.Teams、鄰居 chunk 以 VectorEmbedding.Teams 過濾。別名縱使把某實體連到他隊實體，鄰居 chunk 仍被擋（測試釘住）。
  • 別名為全域管理員治理 metadata：表無 Teams、分頁與動作僅管理員可見可用（比照「重建社群摘要」）。管理員本就見全部資料，故無外洩且免逐列 ACL。
  • 向後相容：無核可別名時 Resolve ≡ Canonical，社群與檢索行為與 P4 完全相同；既有 P2/P3/P4 測試不變。
  • 無新權限常數（沿用 角色_知識圖譜審核）→ 不動 MagicObjectHelper/RolePermissionService/Menu.json 與 canary/alignment/icon 守護測試。無新管線（沿用 P3「重建社群摘要」單例工作，不進 PipelineNames）。

已知限制（未來增量）

  • 純人工別名維護：不自動發現同義詞；候選由管理員判斷。LLM／嵌入式自動候選、別名信心與稽核歷程留待未來。
  • 別名為全域治理，不支援逐團隊別名（若未來需「僅某團隊套用的別名」再擴充 Teams 欄與 ACL）。

驗證

  • dotnet build 成功、無新增警告；dotnet test 822 全綠（既有 806 + 新增 16：EntityAliasResolverTests 4、GraphEntityAliasServiceTests 7、GraphCommunityBuilderTests 別名跨名合併/待審核不生效 2、RetrievalServiceTests 別名跨名多跳/待審核不生效/他隊 leak=0 3）。
  • 重點確認：無別名時 P4 行為不變；核可別名把不同名實體併入同一社群（MemberCount/Teams 聯集正確）與檢索多跳；待審核別名不生效；他隊別名節點錨頁 leak=0。
  • 手動（管理員）：知識圖譜審核頁「實體合併」新增「TSMC → 台積電」→ 核可 → 重建社群摘要 → 兩實體落同一社群；AI 知識問答問及「TSMC」時「台積電」相關頁更易進出處。
  • 雙庫 AddGraphEntityAlias migration 各只建 GraphEntityAlias 一表（無漂移）；scripts/Test-DocsEncoding.ps1 0 失敗；版本 1.0.87。
