修正 YouTube 影片標題亂碼（yt-dlp 輸出 Big5、非 UTF-8）

  • 版本：1.0.29 → 1.0.30
  • 日期：2026/07/22

症狀

「新增音訊轉錄 → 影片連結」貼上 YouTube 網址後，自動帶入的標題出現亂碼：所有 CJK 字元都變成替代字元（U+FFFD，畫面上顯示為菱形問號），英數字則正常。例如原標題「15 分鐘看完 Google Vibe Coding/Agentic Engineering 開發課 Day 1」中的中文全被替換掉，只剩英數字可讀。

根因

改用可攜版獨立 yt-dlp.exe（PyInstaller 打包）後才浮現。直接擷取其 --print "%(title)s" 原始 stdout bytes 確認：

  • 該獨立 exe 在 zh-TW 機器上以 Big5/cp950（Windows ANSI 碼頁） 輸出標題（例：位元組 A4 C0 對應「分」），非 UTF-8。
  • 即使設定 PYTHONIOENCODING=utf-8 或 PYTHONUTF8=1，輸出仍為 Big5（兩者皆被獨立 exe 忽略）。因此 MediaUrlDownloader.RunCaptureAsync 原本設的 PYTHONIOENCODING 對這支 exe 無效。
  • .NET 端以 StandardOutputEncoding=UTF8 讀取 Big5 位元組 → 無效序列 → 全部變成替代字元（U+FFFD）。

（先前 pip 版 yt-dlp.exe 為啟動 python.exe 的薄包裝、會遵守 PYTHONIOENCODING，故無此問題。）

修法

於 MediaUrlDownloader.cs 兩處 yt-dlp 呼叫（標題探測與音訊下載）加入 yt-dlp 自身的 --encoding utf-8 旗標，於 yt-dlp 層強制 UTF-8 輸出，與 Python 環境變數無關。.NET 端維持 StandardOutputEncoding=UTF8 讀取。

驗證後標題正確還原為「15 分鐘看完 Google Vibe Coding/Agentic Engineering 開發課 Day 1」。同時修好下載後顯示檔名（safeTitle 來自同一標題探測）。不影響抖音（Node，已 UTF-8）、ffmpeg、markitdown 路徑。

相關：可攜工具安裝見 IIS 佈署與可攜工具設定、外部工具安裝與路徑設定。
