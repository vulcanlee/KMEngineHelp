清洗設定檔（可重複套用的客製清洗提示詞）（0.2.84）

  • 日期：2026-06-17
  • 版本：0.2.83 → 0.2.84
  • 類型：功能新增

需求

原本清洗的五段提示詞（去重／遮罩／分類／摘要／信心）只能全域客製（提示詞清單啟用 清洗-*），所有知識來源共用同一套。需求是讓不同清洗可套用不同提示詞，且可重複使用。

功能

新增「清洗設定檔（CleaningProfile）」：一組命名的五段提示詞（皆可空，空白＝該步驟用系統內建預設）。

  1. 管理頁 /cleaning-profiles（權限 角色_清洗設定檔，位於「清洗與蒸餾」群組）：CRUD＋啟用/停用，名稱唯一。
  2. 清洗觸發：知識來源「清洗」鈕改為小型對話窗，可選清洗設定檔（含「（預設／全域）」），預設帶入該來源現值；確認後寫回 KnowledgeSource.CleaningProfileId 並排入佇列。
  3. 重試清洗沿用來源已存的設定檔。

提示詞套用優先序

  • 來源有指定設定檔：各步驟「設定檔非空→用設定檔；空→內建預設」，略過全域 清洗-*。
  • 來源未指定（CleaningProfileId 為 null）：維持現行邏輯（全域 清洗-* → 內建預設）。
  • CleaningEnhancer.EnhanceAsync 新增 CleaningPromptSet? overrides 多載；CleaningProcessor 依 source.CleaningProfileId 取啟用設定檔組成 overrides 傳入。黃金評測 EvaluateOneAsync 維持不傳（行為不變）。

資料庫

  • 新表 CleaningProfile；KnowledgeSource 新增 CleaningProfileId(int?, nullable)。
  • 雙 provider migration AddCleaningProfile（Sqlite AccessDatas + SQL Server AccessDatas.SqlServerMigrations）。

影響範圍與相容性

  • 新增：CleaningProfile entity/AdapterModel/Service、CleaningPromptSet、/cleaning-profiles 頁與檢視、AutoMapper 映射、DI 註冊。
  • 修改：KnowledgeSource(+AdapterModel)、BackendDBContext、CleaningEnhancer、CleaningProcessor、KnowledgeSourceService.TriggerCleaningAsync(多載 int? cleaningProfileId)、KnowledgeSourceView、權限三處（MagicObjectHelper/RolePermissionService/Menu.json）。
  • 既有未指定設定檔之知識來源清洗行為不變；其他三處 ContentEditDialog 與黃金評測不受影響。

測試

  • dotnet test 全綠（240 案）。新增清洗設定檔流程後既有 CleaningEnhancer/CleaningProcessor/GoldenSample/KnowledgeSource 測試仍通過。
  • 順帶補：MenuIconTests 允許清單加入 tune（新選單圖示）；CrudActionIconTests 補回先前已在用但未列入的 edit_note、border_color（既有 0.2.74 編修按鈕所用，先前未同步守護清單）。

驗證

  1. /cleaning-profiles 建立/編輯/停用設定檔（五段可空）。
  2. 知識來源「清洗」可選設定檔、預設帶入現值、寫回來源、排入清洗；重試沿用。
  3. 清洗產出反映所選設定檔（空段用預設）；選「預設/全域」同現狀。
