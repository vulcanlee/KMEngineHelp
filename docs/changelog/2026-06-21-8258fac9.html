全系統日誌涵蓋率補強（可診斷化）（0.2.104）

  • 日期：2026-06-21
  • 版本：0.2.103 → 0.2.104
  • 類型：可觀測性強化（日誌）

目的

讓系統出問題時能從日誌還原「當時發生什麼」；平時 Information/Warning/Error，深入除錯時切到 Debug 看到更詳細流程；並讓使用者把日誌交給 AI 分析故障。框架沿用 NLog（ILogger<T>）。

變更

外部整合層（最高診斷價值）

為下列外部呼叫補「開始→成功→失敗」三點式日誌（失敗含 ExitCode／StatusCode／StdErr 或回應前 ~500 字；金鑰未設定 Warning、逾時 Warning）。原本未注入 ILogger 者改建構式注入，手動 new 的 helper 由建立端以 ILoggerFactory.CreateLogger<T>() 串接：

  • OpenAITranscriptionClient（Whisper）、OpenAIChatCompletionClient（文字/視覺/檔案三方法）
  • MediaChunker（ffmpeg 切割與時長探測）、MediaUrlDownloader（yt-dlp）、DouyinAudioDownloader（Node/Playwright 助手）、MarkItDownConverter（含逾時與 TryKill）
  • 串接點：TranscriptionProcessor、DocumentExtractionProcessor、MediaTranscriptionService 新增 ILoggerFactory。

消除「靜默失敗」catch

MediaUrlDownloader.TryPreserveOriginalMedia／GetTitleAsync、MarkItDownConverter.TryKill、DouyinAudioDownloader 逾時 kill、CleaningProcessor／SkillGenerationProcessor 刪舊檔 IOException —— 保留不中斷行為，但一律留下 Warning/Debug 與原因。

權控/權限拒絕可追

  • KnowledgeSourceService：團隊權控、審核權限、狀態不符等拒絕補 Warning；核准/退回成功補 Information（含審核者）。
  • 13 個 Blazor 檢視的「頁面權限檢查失敗」皆補 Warning（先前 6 個已有，補齊另 7 個）。

管線步驟

CleaningEnhancer 補進入、未設 LLM 跳過（Warning）、去重/遮罩/分類/摘要/信心各步驟 Debug。

Blazor circuit 日誌（新增）

新增 ApplicationCircuitHandler，記 circuit 開啟/關閉、連線上線/下線（連線下線 Warning），可追蹤斷線與重連；Program.cs 註冊。

認證

JwtTokenService.ValidateRefreshToken token 類型不符補 Debug（外層 AuthController 已有 Warning）。

已具備、未重複處理

  • API Controllers（Category/Team/Prompt/Project/Meeting/MyTask 等）既有完整三點式日誌（Debug 進入＋Warning＋Information＋Error）；下載端點亦已具 Debug/Warning/Information。
  • 各 DataAccess Service 的 CRUD 例外已 LogError；故檢視層「ShowError 通知使用者」之失敗，其根因多已由 Service/Repository 層日誌記錄，未在檢視層重複記錄。

影響範圍與相容性

  • 純新增日誌與少量建構式參數（ILoggerFactory／ILogger<T>，皆 DI 自動供給），無資料模型變更、無需 migration、無行為改變。
  • 測試：修正 JwtTokenServiceTests 直接 new JwtTokenService 改傳 NullLogger。
  • appsettings.json SystemVersion 0.2.103 → 0.2.104。

文件

  • docs/operations/日誌與設定檔說明.md：新增「§2.1 如何臨時開啟 Debug 詳細日誌」與外部整合/catch 不得靜默原則。
  • docs/architecture/開發慣例與限制速查.md：§1.1 新增「ILogger 使用規範（可診斷化）」。

驗證

  1. dotnet build 0 錯誤；dotnet test 全綠。
  2. scripts/Test-DocsEncoding.ps1 全綠。
  3. 以 Development（Debug）跑轉錄/文件/清洗流程，於日誌可見外部工具參數、起訖、成功/失敗與狀態轉換；故意用錯誤 ffmpeg/markitdown 路徑或缺金鑰，確認失敗有 Error 且含 ExitCode/StdErr/原因；權控拒絕與頁面權限失敗有 Warning；circuit 連線/斷線有日誌。
