修正登入頁輸入框「暗底暗字」不可讀（scoped CSS :root 變數失效）（1.0.27）

  • 日期：2026/07/21
  • 版本：1.0.26 → 1.0.27
  • 類型：錯誤修正（Blazor scoped CSS 選擇器範圍）
  • 觸發來源：登入頁（/Auths/Login，身分核驗）輸入帳號／密碼／驗證碼時，輸入框呈暗底、文字也是暗色，看不清輸入內容；移開焦點後文字仍不清楚。
  • 相關：登入頁科技神秘風重設計

一、問題的本質：:root 被 scoped 改寫後比對不到 <html>

登入頁原設計是「深綠沉浸式暗色主題」：深綠漸層背景 + 暗底輸入框搭配亮色文字（#eafff5）。整頁的設計變數（背景色、文字色、邊框色…）以 :root { --login-*: ... } 定義於 scoped 檔案 Login.razor.css（第 1–19 行）。

Blazor 的 scoped CSS 會把每個選擇器（含 :root）附加元件範圍屬性，改寫為 :root[b-ssch9kskj8]。但 <html> 元素永遠不會帶這個範圍屬性（只有 Login.razor 內渲染的元素才會），因此 :root 選擇器完全比對不到任何元素，所有 --login-* 變數都未定義。

後果：

  • .login-container 的 linear-gradient(..., var(--login-bg-1)...) 因變數無效 → 深綠背景消失，整頁變淡白（只剩用字面 rgba 寫的淡淡光暈）。
  • .form-input 的 color: var(--login-text) 無效 → 文字繼承全域深色 body 文字色。
  • .form-input 的 background: rgba(4,18,11,0.6) 是字面值仍生效 → 灰暗底。
  • 結果：暗底 + 暗字 = 不可讀（回報的 bug）。

二、做法：變數宣告從 :root 移到 .login-container

把 Login.razor.css 第 1–19 行的 --login-* 變數宣告，從 :root 併入頁面最外層 wrapper .login-container（Login.razor:10，包住所有內容）的既有規則區塊。

  • 為何有效：scoped 改寫後變成 .login-container[b-...]，會真正比對到實際渲染的 <div class="login-container">；CSS 變數向下 cascade 到所有子元素（含 .form-input、.brand-panel、.login-card 等）。
  • 已驗證安全：全檔所有 var(--login-*) / var(--fx-*) / var(--mono) 使用點都是 .login-container 的後代，無任何使用點落在 container 之外，故不會有變數遺漏。
  • 另於 .form-input 的文字色加保險 fallback：color: var(--login-text, #eafff5)。

不改動 markup（Login.razor）與任何程式邏輯；純樣式範圍修正，最小改動。

三、成果

  • 整頁回復深綠沉浸式漸層背景。
  • 三個輸入框為暗底 + 亮字（#eafff5）高對比、清楚易讀；focus 時邊框轉青色高亮、文字持續清楚；placeholder 淡綠色可見。
  • 品牌區、驗證碼數字框、登入按鈕漸層等維持原設計外觀。

四、驗證

  • dotnet build 0 錯誤。
  • scoped CSS 重新產生：obj/Debug/net10.0/scopedcss/Components/Auths/Login.razor.rz.scp.css 首行由原 :root[b-ssch9kskj8] 改為 .login-container[b-ssch9kskj8]（已確認）。
  • 實機檢視 /Auths/Login：整頁深綠、三欄輸入暗底亮字清楚可讀。
