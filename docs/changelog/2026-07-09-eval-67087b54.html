變更紀錄

RAG 評測基線快照（EVAL-1）＋查詢期參數化 UI（EVAL-5）（0.3.8→0.3.9）

  • 日期：2026-07-09
  • 版本：0.3.8 → 0.3.9
  • 類型：新增功能（RAG 補強清單）

需求

補齊補強清單兩項互補 P1：EVAL-1（RAG 評測基線）與 EVAL-5（參數化設定 UI）。EVAL-5 提供「可熱套用的調參手段」，EVAL-1 的基線快照提供「量測調參是否變好的尺規」，兩者合成「調參—量測」閉環。

  • EVAL-5 現況缺口：/rag-diagnostics 僅兩段式門檻可熱套用（0.3.3）；TopK／CandidateTopK／融合權重／MinScore 只能改 appsettings 重啟，且 RetrievalService 直接吃 IOptions<SystemSettings> 不走 provider。
  • EVAL-1 現況缺口：/rag-evaluation 頁面與服務已完整，但評測結果只保留最近一次（覆寫 LastMetricsJson），無法凍結基線、無法量測前後差異。

變更

資料層（雙 migration AddEvalParamOverrideAndBaseline）

  • 新增 RetrievalParamOverride（單列覆蓋表：TopK?／CandidateTopK?／VectorWeight?／KeywordWeight?／MinScore?／UpdatedAt／UpdatedBy）——與門檻表 RetrievalSettingOverride 分表，避免兩者「回復預設」互相清除。
  • 新增 RagEvalBaseline（單列基線表：Label／CapturedAt／EvaluatedCount／AggregateJson／ParamsJson／CapturedBy）。
  • Sqlite 與 SqlServer 各一份 migration + 兩 snapshot。

商業層

  • IRetrievalSettingsProvider 擴充查詢期參數：新 record EffectiveRetrievalParams + GetEffectiveParamsAsync／SetParamsAsync／ClearParamsAsync（解析「DB 覆蓋 → appsettings → 預設」；驗證 TopK≥1、CandidateTopK≥TopK、權重與 MinScore ∈ [0,1]）。門檻方法與 RetrievalSettingOverride 保持不動。
  • RetrievalService 改走 provider：由建構式直接吃 IOptions<SystemSettings> 改為每次檢索 GetEffectiveParamsAsync() 即時解析 → TopK／CandidateTopK／權重／MinScore 熱生效（免重啟）。融合、權控、切詞邏輯不動。
  • RagDiagnosticsService：新增 GetEffectiveParamsAsync／ApplyParamsAsync／ResetParamsAsync（委派 provider）。
  • RagEvaluationService：新增 SaveBaselineAsync（upsert 單列，快照當下彙總＋生效參數/門檻）／GetBaselineAsync；注入 IRetrievalSettingsProvider 以擷取參數。
  • 純函式 RagEvalComparer：Compare(current, baseline) 逐指標算 delta 與進步方向（越權洩漏／延遲為「越低越好」）。

UI 層

  • /rag-diagnostics（RagDiagnosticsView）：新增「查詢期檢索參數」區塊——TopK／CandidateTopK／VectorWeight／KeywordWeight／MinScore 輸入 + 套用／回復預設 + 現值與覆蓋狀態；明示切塊參數須重建索引、不納入熱套用。
  • /rag-evaluation（RagEvaluationView）：新增「設為基線」（可命名）與「目前 vs 基線」逐指標 delta 比較面板（進步綠／退步紅）。

測試

  • 更新 RetrievalServiceTests／RagEvaluationServiceTests／KnowledgeBaseChatServiceTests 建構式（RetrievalService 改注入 provider；RagEvaluationService 增 provider 參數）。
  • 新增 RetrievalParamOverrideTests（解析／upsert／清除不影響門檻／驗證 5 例）、RagEvalComparerTests（delta 與方向）、RetrievalServiceTests 熱套用一例、RagEvaluationServiceTests 基線 round-trip／upsert／空樣本擋下。
  • 全測試 461 通過、0 失敗。

範圍決策（誠實記錄）

  • EVAL-5 僅查詢期參數：切塊三參數改動須重建索引才生效，與查詢期熱套用性質不同，本次不納入（維持 appsettings）。
  • EVAL-1 輕量單一基線：僅保留一份基線（upsert 覆寫），非完整 run 歷史。足以量測「調參前後」；多版本歷史/趨勢留待日後（可對應 EVAL-9 觀測性）。
  • 基線數字仍需維運資料工作：程式交付的是「快照＋比較機制」，種子樣本只是範本，正式基線需沉澱代表性問句並實跑。

影響範圍

  • 進度：EVAL-1 ✅、EVAL-5 ✅ 完成。詳見 docs/planning/12-... §〇。
  • 同步更新 docs/guides/檢索品質評測使用指南.md、docs/operations/RAG問題診斷手冊.md、docs/planning/12-RAG系統補強總彙整與優先序.md。
  • appsettings.json SystemVersion 0.3.8 → 0.3.9；需套用雙 migration。

驗證

  1. dotnet build 成功、dotnet test 綠燈（461 通過）。
  2. 手動 EVAL-5：/rag-diagnostics 把 TopK 調小套用 → /rag-evaluation 評測確認回傳數變少（免重啟）→ 回復預設；錯誤輸入被擋。
  3. 手動 EVAL-1：評測全部 → 設為基線 → 調參重跑 → 比較面板顯示 delta。
  4. scripts/Test-DocsEncoding.ps1 全綠。
