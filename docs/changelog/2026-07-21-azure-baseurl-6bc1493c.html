修正切換 Azure OpenAI 端點時 LLM 404（BaseUrl 缺結尾斜線）（1.0.26）

  • 日期：2026/07/21
  • 版本：1.0.25 → 1.0.26
  • 類型：錯誤修正（HttpClient 端點組合）
  • 觸發來源：測試客戶提供的智庫引擎（Azure OpenAI）金鑰與端點時，執行 LLM 檔案解讀出現 HTTP 404 Resource not found。
  • 相關：無

一、問題的本質：/v1 被 .NET 吃掉

客戶端點為 Azure OpenAI 的 v1 介面 https://<資源>.openai.azure.com/openai/v1（結尾無斜線）。

OpenAIChatCompletionClient 等三個 client 皆以相對路徑 chat/completions（見 OpenAIChatCompletionClient.cs:308 等）送出請求，而 BaseAddress 於 Program.cs 啟動時以 new Uri(BaseUrl) 綁定。

.NET 的 new Uri(base, "chat/completions") 合併規則：base 路徑若不以 / 結尾，最後一段會被視為檔名而被覆蓋。因此：

  • 預設 OpenAI https://api.openai.com/v1/（有 /）→ .../v1/chat/completions ✓（所以原本能動）
  • 客戶 Azure .../openai/v1（無 /）→ .../openai/chat/completions，v1 整段被吃掉 → Azure 回 404 Resource not found。

同一個 BaseUrl 由轉錄（OpenAITranscriptionClient）、產生（OpenAIChatCompletionClient）、嵌入（OpenAIEmbeddingClient）三者共用（Program.cs:307/314/321），故三條路徑皆會踩到。

二、做法：BaseAddress 一律正規化為以 / 結尾

於 Program.cs 新增區域函式 EnsureTrailingSlash(string url)，將三處 BaseAddress 設定改為套用它，未以 / 結尾時自動補上。如此任何客戶端點（Azure 或自架、含或不含結尾斜線）都不再因此踩雷。

不改動各 client 的相對路徑寫法，維持最小改動。

三、範圍界線

  • 僅修正端點組合，不改驗證方式：Azure v1 介面接受 Authorization: Bearer <API 金鑰>（現行程式即是此作法）。
  • Azure 以部署名稱(deployment name) 路由；若補斜線後仍 404，需與客戶核對 GenerationModel／QueryRewriteModel／Model／EmbeddingModel 是否對齊該資源實際部署名。此屬設定面，不在本次程式改動內。
  • 客戶金鑰不寫入版控中的 appsettings.json，僅由部署環境設定。

四、驗證

  • dotnet build 0 錯誤。
  • 待實機驗證：部署環境將 OpenAISettings:BaseUrl 設為 Azure 端點（含或不含結尾斜線皆可）→ 重啟 → 重跑原本失敗的 PDF 檔案解讀；日誌不再出現 StatusCode=404，成功時出現 OpenAI chat 用量。Operation=File ...。
