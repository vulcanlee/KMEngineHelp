變更紀錄

續談還原出處與滿意度投票、PDF 補上提問／設定／出處、首頁圖示統一（1.0.98 → 1.0.99）

  • 日期：2026-07-29
  • 版本：1.0.98 → 1.0.99
  • 類型：功能修正（AI 知識問答續談還原）＋ PDF 匯出內容擴充 ＋ 選單圖示調整 ＋ 一處權控補強
  • 無新表、無 migration（出處與查詢模式都存在對話 JSON 全文檔，不是資料庫欄位）

背景

使用者回報三件事：

  1. 從「我的對話」按「繼續對話」續談後，載入回來的歷史回答看不到「出處（N）」區塊，也沒有「滿意／不滿意」按鈕可以重新投票。
  2. 「下載 PDF」產出的 PDF 只有 AI 回答，看不到當初問了什麼。
  3. 側邊選單「首頁」的圖示（analytics）與「知識庫 > AI 知識問答」（forum）不一致——但自 1.0.81 起 /App 已改掛 KnowledgeBaseChatView，兩者其實是同一個問答頁的兩個入口。

根因

出處消失是「資料從來沒存」，不只是 UI 沒接

ChatSessionTurn（對話 JSON 全文檔的一輪）自 1.0.39 建立以來就沒有出處欄位，只有 Index / Timestamp / Question / Answer / Confidence / TopScore / WasBlocked / Settings。ChatSessionService.AppendTurnAsync 也只寫這幾個欄位。所以續談時根本沒有資料可還原——只修 UI 沒有用。

投票列消失是「以訊息實例為鍵」的字典沒有重建

sourcesByMessage／logIdByMessage／feedbackByMessage 三個字典都以 ChatMessage 物件實例為鍵（ChatMessage 是 class、未覆寫 Equals/GetHashCode，即 reference equality）。而 ResumeSession 會先 Clear() 這三個字典，再用全新的 ChatMessage 實例重建訊息串——即使不 Clear，新實例也對不上舊鍵。回饋列的渲染條件正是 logIdByMessage.TryGetValue(msg, …)，因此整列消失。

⚠️ 這是三個症狀的同一個根因，知識來源「AI 對話」頁（KnowledgeSourceChatView）有完全相同的問題。

變更

1. 出處與查詢模式進得了對話 JSON（ChatSessionModels.cs）

  • ChatSessionTurn 新增 List<KnowledgeBaseSourceAdapterModel>? Sources。直接重用既有的出處模型（同專案 Models/AdapterModel/），不另建一份 DTO——續談時讀出來可直接塞回 sourcesByMessage，零轉換、零漂移風險。
  • ChatSettingsSnapshot 新增 string? QueryMode（local／global）。原本快照有「回答詳簡／提示詞／限定來源分類團隊」卻獨缺查詢模式，而查詢模式正是決定「這輪有沒有出處」的那個開關（全域模式走社群摘要，不產生出處）。

⚠️ 兩者都是純 JSON 檔的模型、不是 Entity，因此不需要 migration——對話全文一律存磁碟是 1.0.39 訂下的既有慣例。新欄位對舊檔為 null，向後相容（已由測試釘住）。

2. 寫入端接上出處

  • ChatLogWriteRequest 新增 Sources（知識來源對話／MCP／Web API 不傳＝null，行為不變）。
  • ChatSessionService.AppendTurnAsync 寫入 Sources = req.Sources?.ToList()。
  • KnowledgeBaseChatView.LogTurnAsync 傳 Sources = retrieval?.Sources、快照補 QueryMode = queryMode。

出處的 Snippet 原樣存、不再截斷——它在檢索階段就已截好，再截一次會讓 PDF 與畫面上的出處內容不一致。

3. 續談重建四個附加狀態

新增 ChatLogService.GetSessionTurnFeedbacksAsync(sessionId)：以 LlmChatLog 既有的 SessionId ＋ TurnIndex 反查各輪的 (TurnIndex, LogId, Feedback)。服務端以登入者帳號精確過濾，帳號為空回空清單（fail-closed），比照 ChatSessionService.ReadSessionAsync(requireOwnerAccount) 的本人越權保護。同一輪若有重複列（重試寫入）取 Id 最大者。

兩個檢視的 ResumeSession 由 void 改為 async Task（OnResume 是 EventCallback<ChatSessionFile>，直接接 Task-returning 方法即可），在建立每則 assistant 訊息的當下把四件事填回去：

  • sourcesByMessage ← turn.Sources（→ 出處面板回來了）
  • settingsByMessage ← turn.Settings（新字典，供 PDF 列出查詢設定）
  • logIdByMessage / feedbackByMessage ← 反查結果（→ 投票列回來了，且已投的票會正確高亮，可改可取消）

expandedSourcePanels 維持清空＝預設收合，與新對話一致。

KnowledgeSourceChatView 只做投票重建（該頁本來就沒有出處面板）。

4. PDF 補上提問、查詢設定條件、出處

  • ChatPdfExporter.Generate 改為可選參數多載：Generate(markdown, title, question = null, settingLines = null, sources = null)。現有兩個呼叫端（知識百科、知識來源對話）一行都不用改。
  • 版面由「單一 Markdown 區塊」改為 page.Content().Column(...)（page.Content() 只能呼叫一次），依序輸出：使用者提問 → AI 回覆 → 查詢設定條件 → 出處（N），各區塊皆為「有值才輸出」。
  • 新增 record ChatPdfSource(Layer, Title, Anchor, Score, Snippet)：轉換在 View 端完成，讓共用元件 MarkdownActionBar／ChatPdfExporter 不需要相依知識庫專屬模型。
  • MarkdownActionBar 新增三個可選 [Parameter]：Question / SettingLines / Sources。
  • KnowledgeBaseChatView.razor 的訊息迴圈由 @foreach 改為索引式 @for，才能取得 assistant 訊息對應的前一則使用者提問。⚠️ msg 與 question 必須宣告成迴圈內的區域變數——markup 內多處 lambda（ToggleSourcePanel(msg)、OnFeedbackChangedAsync(msg, …)）會捕捉它們，直接用共享的 i 會全部捕捉到同一個值。
  • 設定條列由 BuildPdfSettingLines 產生：查詢模式／回答詳簡／套用提示詞／系統提示詞／限定知識來源／限定分類／限定團隊。限定來源以 availableSources 解析成名稱輸出，不列裸 Id。
  • PDF 頁首標題由 "AI 回覆" 改為 "AI 知識問答"（PDF 現在不只有回覆）。
  • 中文字型無須任何處理：Noto Sans TC 已於 Program.cs 註冊，新增的中文標題自動套用。

5. 補上 SetFeedbackAsync 的本人守門（既有缺口）

SetFeedbackAsync(int id, …) 原本沒有任何擁有者驗證。過去 logId 只可能來自「本人當輪」，實務上無法被利用；但本次改動讓 logId 改由查詢取得，屬於同一條路徑，必須補上——查詢條件改為 x.Id == id && x.UserAccount == account，找不到就記 LogWarning 後靜默 return（沿用既有行為）。呼叫端只有兩個聊天檢視，/chat-logs 與統計報表只讀不寫，不受影響。

6. 首頁圖示

Datas/Menu.json 第一筆（id 1「首頁」）analytics → forum，與「知識庫 > AI 知識問答」一致。

  • forum 已在 MenuIconTests.AllowedLeafIcons（「首頁」有 url、無 subMenu＝葉節點），不需改白名單；analytics 仍被「統計報表」父群組使用，故保留在清單中。
  • 名稱／順序／url 皆未動 → 不影響 MenuPermissionAlignmentTests 的位置索引，也不動 MagicObjectHelper／RolePermissionService。
  • ⚠️ SidebarMenuService 對 Menu.json 有 ICacheService 快取（key sidebar:menu:raw），改完要重啟才看得到。

7. 其他

  • appsettings.json：SystemVersion 1.0.98 → 1.0.99。
  • 新增 Tests/ChatSessionSourceAndFeedbackTests.cs（7 條）。

刻意不變更

  • 不重構「以訊息實例為鍵」的字典設計：改成穩定 turn id 會波及三個檢視的大量程式碼；本次只要求「重建時把新實例填進字典」即可正確運作。這個脆弱性已在此篇記錄，留待日後有更大範圍改動時一併處理。
  • 不回填舊對話的出處（與使用者確認）：既有 session JSON 沒存出處，續談舊對話時出處面板不出現（投票列會出現，因為 logId 是從 DB 反查）。不在續談時重跑檢索補出處——知識庫已變動時會產出「與當初不同的假出處」，且每次續談都要多跑 N 次檢索。
  • 不改 ChatLogService.BuildFileContent（per-turn .md 稽核檔）：該檔以「送進 LLM 的提示詞」為主，本次需求不涉及。
  • 不改 /chat-logs 管理員頁與統計報表：只讀 Feedback，讀取語意未變。
  • CancelExtractionAsync 式的同輩一致性考量：SetFeedbackAsync 的守門補在服務層而非 UI 層，因為它已成為「可由查詢取得 id」的路徑。
