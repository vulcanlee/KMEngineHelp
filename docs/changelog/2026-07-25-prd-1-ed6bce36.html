找到並修正的問題

1. 規劃但未實作的元件沒有校正紀錄

音訊影片轉錄服務PRD.md §7 的「系統整合點」規劃表列出 MediaTranscriptionRepository，但實作並未採用 —— 轉錄的資料存取直接落在 MediaTranscriptionService，Business/Repositories/ 底下只有 Project／MyTask／Meeting／Category／Team／Prompt／WorkCategory 七個。已在表後加註實作差異，保留原規劃表（那是當初的設計產物，不應改寫）。

2. 技術描述不夠精確

同檔的「以 IHttpClientFactory 建立 HttpClient」——程式實際用的是 typed client AddHttpClient<OpenAITranscriptionClient>（該模式底層即 IHttpClientFactory，但沒有直接引用該介面）。已改為指名實際 API。

3. 狀態列舉缺少「已取消」

音訊影片轉錄服務PRD.md（2 處）與 文件萃取-markitdown-prd.md（2 處）的狀態列舉停在 等待中／處理中／已完成／失敗，實際 *AdapterModel 都已有 StatusCancelled = "已取消"。（圖片清單-prd.md 已正確含此狀態。）

4. 同一份文件自相矛盾

會議AI自動化-prd.md 第 33 行寫會議紀錄產生是「第 8 條管線」，第 42 行寫「第 7 條」。實際 PipelineNames 有 7 個常數（技能管線已於 1.0.45 移除），第 42 行正確。已修正第 33 行。

5. 選單舊名同步

保護式替換 193 處（沿用批次 3 的規則：遮蔽圍欄程式碼、連結網址、行內程式碼、角色_XXX 識別字與複合詞例外）。權限值如 角色_音訊轉錄 = "音訊轉錄" 正確保留未動。

PRD 檔名一律不改 —— 改檔名會牽動全庫 250 處 -prd.md 參照，且 PRD 是以「當初的功能名」建檔的規格基準。

6. 中繼資料標頭

11 份的 現行系統版本 → 1.0.61、最後核對日期 → 2026/07/25（原本多數停在 1.0.11／2026-07-17，落後 49 版）。

方法上的觀察

自動化識別字檢查對 PRD 的價值低於預期：PRD 本來就會提到「當初規劃、後來改掉」的識別字（多數集中在各檔的「現況校正」段落），因此找到的候選多為正確的歷史紀錄而非過期資料。真正的價值在於逐條核對「現況陳述」——本段找到的 4 類問題有 3 類是自動化抓不到的。第 2、3 段將以人工核對為主、自動檢查為輔。
