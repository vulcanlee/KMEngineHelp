Graph RAG P6：LLM 自動別名候選（1.0.87 → 1.0.88）

  • 日期：2026-07-27
  • 版本：1.0.87 → 1.0.88
  • 類型：新增功能（Graph RAG 第六階段，把 P5 的人工別名升級為 LLM 自動建議 + 人工審核）

背景

P5 的實體別名完全靠人工手動建立——管理員得自己想到「台積電＝TSMC」。P6 加 LLM 自動建議（仿 P2「LLM 抽取 → 人工審核」）：管理員按鈕觸發背景工作，LLM 掃描既有實體名、提出「別名 → 標準名」同義候選，寫入 GraphEntityAlias 的待審核佇列，再由管理員於既有「實體合併」分頁核可/退回。降低人工從零發想的負擔，保留人在迴路治理。

與使用者確認的決策：信心分數＝新增 Confidence 欄位儲存；候選範圍＝全庫去重實體名（上限 NameCap=300，超出取出現次數最多者）；執行＝背景單例工作 + 按鈕（仿 P3 重建社群摘要，不進 PipelineNames）。

變更

  1. GraphEntityAlias 加 decimal? Confidence（LLM 自評；人工新增為 null）＋ GraphEntityAliasAdapterModel.Confidence＋服務投影；雙庫 AddGraphEntityAliasConfidence migration。
  2. 新 LLM 提示詞槽位 EntityAliasPropose（圖譜-別名建議）：4 處同步（LlmPromptKeys+AllKeys、LlmPromptsSettings+Get()、appsettings LlmPrompts、LlmPromptDefaults），LlmPromptSlotTests 守。預設提示詞要求 LLM「只用清單內名稱、找同義實體、只輸出合法 JSON 陣列 [{alias,canonical,confidence}]」。
  3. GraphEntityAliasGenerator（Scoped，仿 GraphExtractionEnhancer）：載入去重 canonical 實體名（取出現次數前 NameCap=300）→ CompleteStreamingAsync → 純 ParseAliasCandidates（ExtractJsonArray＋DTO＋批內去重＋NormalizeConfidence）→ 生成端接地過濾（別名與標準名兩側 canonical 皆須為既有實體名，杜絕幻覺）＋自我對/既有非退回對去重 → 批次插入 待審核＋Confidence（單次存檔）。LLM 未設定或實體 <2 → 回 0。
  4. 背景工作三件套（仿 P3，不進 PipelineNames）：IGraphAliasCandidateQueue/GraphAliasCandidateQueue（signal-only）、IGraphAliasBuildState/GraphAliasBuildState、GraphAliasGenerationBackgroundService（OperationContext.Push("EntityAliasPropose",…)、scope 解析 generator、finally 復位旗標）。DI：queue/state Singleton、generator Scoped；Program.cs 加 AddHostedService。
  5. 觸發/狀態：GraphEntityAliasService 注入 queue＋build-state，加 TriggerSuggestionAsync（管理員＋忙碌守門＋樂觀設旗標＋enqueue）與 GetSuggestionStatusAsync（＋record GraphAliasSuggestionStatus，含待審核筆數）。
  6. Token 作業別 OperationEntityAliasPropose + OperationLabelHelper 「實體別名建議」（OperationLabelTests 守）。
  7. UI：「實體合併」分頁（已管理員限定）加狀態列（生成中/上次時間/新增數/待審核數/錯誤）＋「LLM 自動建議別名」按鈕＋「重新整理狀態」（仿重建社群摘要）；別名清單加「信心」欄（null 顯示「—」）。
  8. appsettings.json：SystemVersion 1.0.87 → 1.0.88。

安全與相容（leak=0 紅線不變）

  • 別名候選是全域管理員治理 metadata（無 Teams），生成為管理員觸發、候選一律待審核、不自動核可。核可後的套用仍走 P5 EntityAliasResolver，檢索/社群 ACL 完全不變。
  • 接地保證：LLM 幻覺名（不在實體集合者）被丟棄，核可後必能合併到既有節點。
  • 向後相容：無 LLM 設定或無實體時回 0；P2~P5 與既有功能不受影響；手動別名（P5）原封不動。
  • 不進 PipelineNames（沿用 P3 單例全域工作模型），不牽動 /pipeline-jobs 與健康檢查推導；不新增權限常數（沿用 角色_知識圖譜審核、分頁管理員限定）。

已知限制（未來增量）

  • 候選僅為建議，一律人工核可；信心分數僅輔助排序，不自動門檻丟棄（依使用者決策全部收）。
  • 名稱數超過 NameCap=300 時只看最常出現者（記 log）；本增量以單次（≤cap）LLM 呼叫為主，若名稱清單需分批則跨批同義對可能漏配（留待未來）。

驗證

  • dotnet build 成功、無新增警告；dotnet test 836 全綠（既有 822 + 新增 14：GraphEntityAliasGeneratorTests 純解析 5 + 生成 5、GraphEntityAliasServiceTests 觸發/狀態 4）；守護測試 LlmPromptSlotTests/OperationLabelTests 加常數後自動綠。
  • 重點確認：純解析（合法/圍欄/無效/批內去重/信心正規化）、接地過濾丟棄幻覺名、與既有非退回別名去重、批次插入待審核＋Confidence、LLM 未設定→0、觸發忙碌/管理員守門。
  • 手動（管理員）：實體合併分頁按「LLM 自動建議別名」→ 背景生成 → 待審核候選（含信心）進清單 → 核可 → 重建社群摘要 → 合併生效；Token 用量頁見「實體別名建議」作業。
  • 雙庫 AddGraphEntityAliasConfidence 各只加一欄（無漂移）；scripts/Test-DocsEncoding.ps1 0 失敗；版本 1.0.88。
