作業別中文標籤抽為共用 helper，並統一三處顯示（1.0.67）

  • 日期：2026/07/25
  • 版本：1.0.66 → 1.0.67
  • 類型：重用整理 ＋ 顯示一致性修正
  • 影響範圍：首頁儀表板、Token 用量明細、統計報表「Token 用量統計」（含 PDF 匯出）

一、問題

OperationLabel（LLM 作業常數 → 中文標籤）有兩份逐字相同的 17 分支 switch：

  • Web/Components/Views/Dashboard/DashboardView.razor.cs
  • Web/Components/Views/TokenUsage/TokenUsageView.razor.cs

前者的註解自己就寫著「與 TokenUsageView.OperationLabel 對照一致；日後可抽共用 helper」。1.0.58 的選單改名兩份都得各改一次，是持續漂移來源。

查證時發現的第三處（更嚴重）

統計報表 → Token 用量統計（/reports/token-usage-report）的「依作業別」根本沒套標籤，畫面與 PDF 匯出都直接顯示英文常數：

  • .razor 的 <ReportBarList Items="report.ByOperation" /> —— 該共用元件直接渲染 @item.Label
  • .razor.cs 的 PDF 匯出用 x.Label 原值

資料源 TokenUsageReportService.GroupSumAsync 的 Label = g.Key（raw 常數）。因此同一份「依作業別」統計，首頁儀表板與 Token 用量明細顯示中文、統計報表顯示 KnowledgeBaseChat——使用者在三個頁面看到同一件事的三種不同名字。

二、修正

2.1 新增 Web/Components/Commons/OperationLabelHelper.cs

ToLabel(string operation) 即原本的 17 分支 switch 原樣搬移（保留 _ => operation fallthrough，未知作業仍顯示原值而非空白）。放在 Components/Commons/——該目錄已有 ChatPdfExporter、MarkdownRenderer、InputWatcher 等非元件的靜態輔助類別，三個消費端都在 Web 專案，不引入新的專案相依。

為什麼不放 KnowledgeExtraction.Share：該專案沒有任何 ProjectReference，取用不到 AccessDatas 的 LlmTokenUsage 常數；改用字串字面值會失去常數連結，反而更容易漂移。

2.2 全部 10 個顯示點改用共用 helper

頁面顯示點
首頁儀表板功能熱門度（1 處）
Token 用量明細篩選下拉、依作業分頁、表格欄、明細 Modal、PDF 的兩處與副標題（7 處）
統計報表 Token 用量統計新套用：畫面長條列表、PDF 匯出（2 處）

報表頁的畫面部分，在 code-behind 先產生已標籤化的 LabeledCount 清單再交給 ReportBarList——沒有改動 ReportBarList 元件本身，它被多份報表共用，改它會影響無關的區塊（依模型、信心分布等）。

三、新增 OperationLabelTests（5 個測試）

沿用 1.0.65／1.0.66 建立的模式：用測試強制同步。

  • 每個 LlmTokenUsage.Operation* 常數都有專屬中文標籤——以反射逐一檢查有沒有落入 fallthrough。新增作業常數卻忘了加分支會立刻紅燈，而不是默默在畫面上顯示英文原值。
  • 標籤不重複——兩個作業對到同一個中文名，在報表的分布圖上會看起來像同一件事。
  • 未知作業回傳原值（fallthrough 行為明確化）。
  • SkillGeneration 仍有中文標籤——AI 技能產生器已於 1.0.45 移除，但常數與標籤刻意保留讓歷史用量資料列仍顯示中文。這條刻意寫死，守住「不要順手清掉」這個決定。
