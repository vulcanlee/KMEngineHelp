階段三步驟 2：VectorEmbedding 實體 + 雙 migration + IVectorStore（0.2.124）

  • 日期：2026/06/26
  • 版本：0.2.123 → 0.2.124
  • 對應設計：階段三：知識庫與 RAG 設計規格 §3；路線圖步驟：strategy/12 §12.2 步驟 2

摘要

階段三第二步驟：建立向量的落地與存取層，把步驟 1 的嵌入用戶端產生的 1024 維向量持久化，並提供權控、可排序的近鄰查詢介面，作為步驟 3（索引管線）、步驟 4（混合檢索）的底座。

儲存方案：採規格 §3.1/§13.1 認可的退路 —— 可攜 byte[] 欄位（float32 打包）+ 應用層暴力餘弦，以 IVectorStore 抽象隔離。無原生擴充、無需 SQL Server 2025，雙 provider 走標準 EF migration；日後規模成長可在不動上層下換成 sqlite-vec / 原生 VECTOR / pgvector。

設計重點

  • 實體 VectorEmbedding（依規格 §3.2）：SourceLayer(Wiki/Cleaned)、WikiPageId?、ChunkText(inline)、Embedding(byte[]，1024×float32)、Teams/Categories(分隔字串)、Ordinal、AnchorRef、ContentHash、EmbeddingModel。
  • 刪除政策：KnowledgeSourceId FK Cascade（單一串聯路徑）；WikiPageId FK Restrict —— 因 WikiPage 本身已從 KnowledgeSource Cascade，若再 Cascade 會在 SQL Server 觸發「多重串聯路徑」錯誤；Wiki 頁變更時改由索引管線（步驟 3）顯式清理向量。
  • 權控即過濾：SearchAsync 在查詢層即套 TagStringHelper.BuildTeamAccessPredicate（非管理員只見公開或交集團隊，管理員不限），絕不取回後再濾。
  • provider 無關：byte[] + 應用層餘弦在 SQLite/SQL Server 皆相同；DualDbVectorStore 沿用規格命名，原生索引路徑列為日後替換。

變更內容

  • 實體：KnowledgeExtraction.AccessDatas/Models/VectorEmbedding.cs（仿 WikiPage 風格）。
  • DbContext：BackendDBContext 新增 DbSet<VectorEmbedding> 與 OnModelCreating（Cascade/Restrict 與三個索引：KnowledgeSourceId、WikiPageId、(KnowledgeSourceId, SourceLayer)）。
  • AdapterModel/AutoMapper：VectorEmbeddingAdapterModel（Teams/Categories List+Text、SourceLayer 常數）；AutoMapping 新增 #region VectorEmbedding 雙向 ForMember（標籤走 TagStringHelper）。
  • 向量存取層（KnowledgeExtraction.Business/Services/Embeddings/）：
  • VectorMath：Encode/Decode（Buffer.BlockCopy）、Cosine（純函式）。
  • IVectorStore + VectorQuery(重用 RecordAccessScope)/VectorSearchResult。
  • DualDbVectorStore：UpsertAsync（Id==0 新增否則更新）、SearchAsync（權控過濾 → 解碼 → 餘弦排序 → MinScore → TopK）。
  • DI：ServiceCollectionExtensions 註冊 AddScoped<IVectorStore, DualDbVectorStore>()。
  • 雙 migration：AddVectorEmbedding（SQLite BLOB / SQL Server varbinary(max)，含三索引與 FK 政策），SQLite 與 SqlServerMigrations 各一套。
  • 測試：VectorMathTests（encode/decode round-trip、cosine 同向/正交/反向/零向量/維度不符）；DualDbVectorStoreTests（upsert→search round-trip、TopK、MinScore、SourceLayer 過濾、權控管理員/非管理員/無團隊）。全套 325 個測試綠燈。

後續

依 strategy/12 §12.2，下一步為步驟 3：Chunker + 嵌入索引管線（IEmbeddingIndexQueue/EmbeddingIndexBackgroundService/EmbeddingIndexProcessor，仿 Distillations 三件套），蒸餾完成後自動建索引、增量重建與孤兒清除。
