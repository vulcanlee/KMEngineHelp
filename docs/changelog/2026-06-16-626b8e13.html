內容編修對話窗版面與儲存過期追蹤修正（0.2.75–0.2.76）

  • 日期：2026-06-16
  • 版本：0.2.74 → 0.2.75 → 0.2.76
  • 類型：缺陷修正 / UI

0.2.75 對話窗版面修正

  • ContentEditDialog 改為自帶 content-edit-modal 全域樣式（寬版 90vw、top:3vh、body 內距收斂、底部留白），不再依賴 FormModalHelper。
  • 原因：圖片辨識／影音轉錄／文件萃取三頁未渲染 <FormModalHelper />，沿用 project-view-modal 會退回 AntDesign 預設寬度（約 520px）而出現左右大片留白、兩欄擁擠。
  • 不更動其他 8 頁共用的 project-view-modal。

0.2.76 儲存誤報「尚無可編修內容」修正

  • 症狀：編修對話窗已顯示內容（讀取成功），按儲存卻回報「尚無可編修的生成內容」。
  • 根因：讀取走 AsNoTracking()（讀資料庫最新值），但 Update*ContentAsync 用追蹤查詢；circuit 範圍 DbContext 內的過期追蹤實體（路徑為空）被 EF identity map 回傳 → 路徑誤判為空。
  • 修正：四個 Update*ContentAsync 在追蹤查詢前先 CleanTrackingHelper.Clean<T>(context)，強制由資料庫讀最新值（比照 LlmGenerationService 與速查 §1.2 慣例）。

驗證

  • 三頁開啟編修對話窗為寬版、左右並排、上下留白合宜。
  • 產生內容後開「編修產生結果」加字儲存成功、重開為新內容、原檔被覆寫。
