變更紀錄

蒸餾的輸出截斷偵測，以及讓註記真的看得到（1.0.116 → 1.0.117）

  • 變更日期：2026/07/30
  • 版本：1.0.116 → 1.0.117
  • 性質：程式變更（src/）＋測試＋文件。無模型變更、無新表、無 migration、無新設定鍵。
  • 對應盤點項：後續四項的第二項（原盤點清單的 #1）
  • 編碼：UTF-8（繁體中文，含 BOM）

一、解決什麼

規模守門四項（1.0.112～116）只覆蓋清洗。但蒸餾撞上同一面天花板的機率其實更高：

  • 它同樣是單次呼叫帶整份清洗後全文；
  • 而且它要輸出的是一整個 JSON 陣列（每個概念一個物件，含標題、內容、關聯概念、信心），輸出量往往比去重／遮罩更大。

現況的問題不是沒有處理，而是說錯原因：截斷 → JSON 不完整 → 解析失敗 → 降級成單一 Wiki 頁，但註記寫的是「LLM 回應非預期 JSON 格式」。這句話會把使用者導向去查提示詞或模型設定，而真正該做的是分盒或拆檔。

二、⚠️ 一項要更正的先前判斷

規劃這一項時我寫過「註記會經 DistillationProcessor 寫進 ErrorMessage，畫面看得到」。這句是錯的。

查證：WikiPage.ErrorMessage 確實由 DistillationProcessor 寫入，但 Web/Components/Views/WikiPages/ 三個檔案完全沒有引用這個欄位；KnowledgeSourceView 也只在蒸餾失敗時顯示 DistillationErrorMessage，完成時傳的是 null。

所以既有那句「非預期 JSON 格式」從來沒有出現在任何畫面上。 只改文字等於把一句沒人看得到的話換成另一句沒人看得到的話。這一版因此含兩處極小的曝光改動。

三、看得到什麼

在哪裡顯示
蒸餾當下右下角彈橘色警告 toast（PipelineProgressEvent.LevelWarning，走既有的 PipelineProgressToaster）。⚠️ 只停留數秒且刻意不補播歷史，離開頁面就看不到了
事後查閱Wiki 頁清單 → 該頁「檢視」→ 對話窗上方出現 ⚠️ 處理過程註記：…（與審核者資訊同一列，註記排在前）

兩處都要有，是因為 toast 管「當下知道」、檢視列管「事後查得到」，缺一邊就等於漏訊息。

副作用（好的那種）：1.0.117 之前蒸餾的舊 Wiki 頁，若當時留了註記，現在打開「檢視」就看得到了，不必重跑。

四、三種註記，兩種原因必須分得出來

截斷JSON註記頁數
✅壞「蒸餾的輸出被模型輸出上限截斷，已降級為單一 Wiki 頁；請將此知識來源分盒，或在上傳前把過大的文件拆檔」1（降級）
✅可解析「蒸餾的輸出被模型輸出上限截斷，產出的 Wiki 頁可能不完整（後段概念可能整頁遺失）」照常
❌壞「LLM 回應非預期 JSON 格式，已降級為單一 Wiki 頁，請人工審核。」一字不改1（降級）
❌可解析無註記照常

三句話收成 DistillationEnhancer 上的 public const，讓測試釘住字面——截斷時不可出現「非預期 JSON 格式」，未截斷時那句也不可被新訊息取代。兩種原因的處置完全不同（分盒／拆檔 vs 看提示詞或模型），混用就等於誤導。

第二列值得單獨說：截斷剛好切在某一頁結束處時，JSON 仍可能解析成功。這時已產出的頁照常回傳（不因為註記而丟掉），但缺了幾個概念從頁數本身完全看不出來，所以一定要留話。

五、為什麼截斷不讓蒸餾整筆失敗（與遮罩刻意不同）

被截斷時為什麼
清洗的遮罩整筆失敗截斷的尾段沒經過模型，那部分的個資與機密必然沒被遮到——這是安全問題
蒸餾降級成單頁＋明確註記只是少了幾頁 Wiki，沒有資安風險；整筆失敗會讓使用者連一頁都沒有

六、程式變更

檔案變更
Business/Services/Distillations/DistillationEnhancer.csEnhanceAsync 改用 CompleteStreamingCheckedAsync（P1 已建好的方法）並記 warning log；ParsePages 加第三個帶預設值的參數 truncatedByOutputLimit；三句註記收成 const
Business/Services/Distillations/DistillationProcessor.cs拿到結果後逐筆 progress.Report(note, LevelWarning)
Web/…/WikiPages/WikiPageView.razor.cs抽出 BuildViewNote：ErrorMessage 非空時前置 ⚠️ 處理過程註記： 併入既有備註列

三個刻意的設計選擇

① 第三個參數帶預設值。 ParsePages 是 public static，既有 7 條測試全部呼叫兩參數形式——預設值讓它們一行都不用改。

② 不動 ContentEditDialog。 該共用元件已有 Note 參數（ContentEditDialog.razor:52），被 7 個頁面共用；改它的樣式會擴散到全部。所以只在呼叫端組字串。

③ 不設 KnowledgeSource.DistillationErrorMessage。 完成狀態帶錯誤訊息，會與 KnowledgeSourceView 既有的「失敗才顯示」語意打架。

  • 🔴 反證：未截斷＋壞 JSON → 註記剛好等於 NoteMalformedJson，且不含「截斷」

  • 🔴 反證：未截斷正常多頁 → 2 筆頁、ErrorMessage 全為 null、一則警告事件都沒有
