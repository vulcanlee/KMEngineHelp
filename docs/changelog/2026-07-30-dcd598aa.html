一、為什麼有這一版

規模守門三項（1.0.112～1.0.114）交付後盤點整批工作，查出兩個先前造成的小疏漏，一併修掉。

二、B-4：說明網站漏收了自己的維運文件

問題：建說明網站（1.0.111）時，忘記把同一批交付的 docs/operations/文件說明網站產生與佈署.md 加進 CURATED_SLUGS，也沒有任何角色情境引用它。結果是：

  • 它拿到自動雜湊檔名（doc-xxxxxxxx.html）而不是可讀的英文檔名
  • 只能從「全部文件索引」翻到，角色導覽完全看不到它

這份文件的讀者正是會用到說明網站的人，卻是網站上最難找到的一份。

修正（scripts/help_site_data.py）：

改什麼內容
CURATED_SLUGS新增 "docs/operations/文件說明網站產生與佈署.md": "help-site-build" → 輸出改為 docs/operations/help-site-build.html
SCENARIOS["consultant"] 的「部署到客戶機器」文件清單末尾新增一筆，用途寫「產出並交付客戶要看的說明網站（注意：給客戶一律用對外版）」

放在顧問的部署情境，是因為顧問就是實際會去產這個網站、並把對外版交給客戶的人。

順帶查證但刻意不修：策展目錄內另有 2 份沒有英文 slug 的 md，都在 guides/lab-samples/documents/擴充-純文字/ 底下（虛構的 ERP FAQ 之類）。它們是 Hands-on Lab 的練習素材、不是說明文件，自動 slug 才是正確的。

三、B-5：提示詞檔名錯字

docs/prompts/說明文件的網頁**板**需求.md → 說明文件的網頁**版**需求.md。

以 git mv 改名（git 識別為 R rename，保留檔案歷史）。兩處引用同步更新：

引用處性質為什麼要改
docs/prompts/README.md真正的 Markdown 連結不改會讓 Test-DocLinks.py 紅燈
docs/changelog/2026-07-30-角色導向說明網站產生器.md行內碼裡的路徑文字，不是連結不改不會紅燈，但讀者照著找會找不到檔案

為什麼可以動歷史 changelog：那一處不是對當時事實的陳述，只是「需求來源在哪」的路徑指標。留舊路徑只會讓人找不到檔案。改名這件事已在該處與本篇同時註明（（1.0.115 由「網頁板」更正檔名）），軌跡完整，不是偷偷改掉歷史。

另已確認 scripts/ 下沒有任何腳本寫死這個檔名，改名不影響建置。
