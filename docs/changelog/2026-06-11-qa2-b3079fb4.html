清洗 QA-2：LLM 自評信心分數 + 自動門檻（0.2.62）

  • 日期：2026-06-11
  • 版本：0.2.61 → 0.2.62
  • 對應路線圖：資料清洗開發代辦清單 第四階段 QA-2、設計 strategy/08

摘要

清洗管線新增 QA-2：LLM 對清洗結果自評信心分數，依門檻自動路由—— 高信心自動「已清洗」、低信心轉「待審核」，把人力集中在有疑慮的來源。

內容

  • 資料模型：KnowledgeSource 新增 ConfidenceScore（decimal?，null=未評估）；新增狀態「待審核」

（KnowledgeSourceAdapterModel.StatusReviewPending）。雙 provider migration AddKnowledgeSourceConfidence（可空、免回填）。

  • 設定：SystemSettings.Cleaning.ConfidenceThreshold（預設 0.7，appsettings.json 可調）。
  • CleaningEnhancer：在去重→遮罩→分類→摘要之後新增第 5 步「信心自評」（對遮罩後本文），

可降級；提示詞程式內預設、可由 Prompt 清單同名 清洗-信心 覆寫。新增純函式 ParseConfidence （支援 0.85、85(視為百分比)、夾帶文字取首個數字，超界→null）。

  • CleaningProcessor 路由：寫檔後依信心決定狀態——

未啟用 LLM（Skipped）→ 已清洗（未評估）；信心 null（自評失敗/無法解析）→ 待審核（保守）； 信心 ≥ 門檻 → 已清洗；信心 < 門檻 → 待審核。清洗檔在「待審核」時仍會產出、仍可檢視。

  • UI：知識來源清單新增「信心」欄（百分比，未評估顯示「—」）；「檢視清洗結果」對「待審核」亦開放；

「待審核」可用「清洗」按鈕重新清洗。

  • 測試：CleaningEnhancerTests（信心自評、ParseConfidence、降級、ApiKey 空）與

CleaningProcessorTests（高信心→已清洗、低信心→待審核且檔案產出可讀、遮罩失敗→失敗）；全測試 193 筆綠燈。

  • 不影響既有安全不變量（遮罩失敗仍整筆失敗、Teams 不動、標題不送 LLM）。

未納入（後續 QA-3）

人工審核關卡（待審核 → 核准/退回/校正 → 已清洗）與 ReviewedBy/ReviewedAt 欄位、審核 UI； 黃金評測集（QA-4）以校準門檻。
