統計報表第一階段：LlmTokenUsage／LlmChatLog 新增 Teams 團隊快照＋雙 migration（0.3.36→0.3.37）

  • 日期：2026-07-13
  • 版本：0.3.36 → 0.3.37
  • 類型：新功能（基礎建設，統計報表前置）

需求

規劃中的知識庫統計報表要能「依團隊」統計 Token 用量與聊天回饋，但來源表 LlmTokenUsage、LlmChatLog 只存 UserAccount／UserName，無團隊欄位，無法按團隊切分。本階段新增 Teams 快照欄位並串接寫入路徑，讓升版後新紀錄開始帶團隊；報表頁於後續階段實作。

變更

資料層

  • LlmTokenUsage、LlmChatLog 各新增可空 string? Teams：於紀錄產生當下快照「使用者當時所屬團隊」，採 TagStringHelper.ToStored 的 \n 包夾格式（與 KnowledgeSource.Teams 等一致，供後續 BuildContainsAnyPredicate 過濾）。
  • 雙 provider migration AddTeamsToLlmUsageLogs（SQLite 於 AccessDatas、SQL Server 於 AccessDatas.SqlServerMigrations）：兩份僅對兩表各 AddColumn Teams（nullable），無 rename/drop。

情境與寫入路徑

  • Share/Helpers/OperationContext.cs：OperationInfo 加 Teams、Push(...) 加尾端可選參數 teams；背景作業（清洗/蒸餾/索引/轉錄…）未帶則為 null（向後相容）。
  • TokenUsageRecorder：建立用量列時帶入 OperationContext.Current.Teams。
  • ChatLogService.WriteAsync：以 TagStringHelper.ToStored(user.TeamList) 快照寫入 LlmChatLog.Teams。
  • 兩個聊天進入點 KnowledgeBaseChatView、KnowledgeSourceChatView 於 OperationContext.Push 帶入 CurrentUser.TeamList。

範圍與已知限制（誠實記錄）

  • 團隊快照僅對升版後新紀錄有值；歷史 LlmTokenUsage/LlmChatLog 的 Teams 為 null，統計時歸「未標記團隊」。不回填歷史資料。
  • 背景作業（無使用者情境）的 token 用量 Teams 為 null。
  • 既有 KnowledgeBaseQueryAudit.Teams 為逗號格式（string.Join(",", …)），與本次 \n 格式不同；留待「檢索品質報表」階段處理，本階段不動。
  • 本階段不含報表服務／頁面／選單／PDF（後續階段）。

  • 文件：docs/planning/知識庫統計報表-todo.md（第一階段勾選）。

  2. dotnet test 綠。
  3. 手動：有團隊使用者問答後，LlmChatLog.Teams／對應 LlmTokenUsage.Teams 為 \n團隊\n 格式；背景作業與無團隊使用者為 null。
