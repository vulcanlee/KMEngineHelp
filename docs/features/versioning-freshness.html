功能機制

版本化與時效性

文件目的

說明知識庫中「Wiki 頁版本狀態機（VER-1）」與「向量失效標記／as-of 時點檢索（VER-2）」的機制：知識更新時如何保留歷史、只讓現行版參與問答、以及如何做時間點回溯查詢。此能力自 0.3.14 起完整落地。

相關：知識型態抽象 × 版本化 × 時效性（設計文件）、Wiki 與 Cleaned 的角色差異 §八、知識頁審核與 Wiki 頁管理指南。

1. 為什麼需要版本化與時效性

知識會演進：同一個概念（例如「請假辦法」）可能被多次重蒸餾或線上編修。若每次都覆蓋或刪除舊內容，會遺失歷史、無法回答「上個月的規定是什麼」，也難以稽核。版本化的目標是：

  • 不遺失知識：舊版保留、可回溯。
  • 問答只用最新：預設只讓現行版參與檢索，避免新舊混答。
  • 可時間旅行：能查詢「某個時間點當時的有效知識」（as-of）。

2. 概念鍵與欄位

概念鍵 ＝ (KnowledgeSourceId, Title)：同一來源下、同一標題視為同一個概念；同一概念至多一個現行版（current）。

WikiPage 版本／治理欄位

欄位用途
Version版本序號，核准新版時遞增。
EffectiveStatus版本治理狀態：current（現行）／superseded（已被超越）／null（草稿，尚未核准）。與審核狀態 Status（待審核／已完成／已退回）正交。
EffectiveDate生效時間（核准為現行版時設定）。
ExpiryDate失效時間（被新版超越時設定）。
SupersededByPageId指向超越本頁的新版頁 Id。
PreviousVersionPageId指向前一版頁 Id，構成版本鏈。
Owner知識負責人（治理欄位）。
ChangeSummary本次變更摘要（治理欄位）。
LastReviewedAt最後複審時間（治理欄位）。

VectorEmbedding 時效欄位

欄位用途
IsCurrent此向量是否屬現行版；預設檢索只取 IsCurrent=true。
EffectiveDate向量生效時間（Wiki 層繼承其頁；Cleaned 層為 null）。
ExpiryDate向量失效時間（被超越時設定；null 表示仍有效）。

3. 版本狀態機（核准即超越）

核准一個 Wiki 頁（WikiPageService.ApproveAsync）時：

  1. 將本頁設為 current、設定 EffectiveDate、Version 遞增。
  2. 找出同概念的前一個 current 版，轉為 superseded：設定 ExpiryDate、SupersededByPageId，並將其向量標記 IsCurrent=false（保留、不刪除）。
  3. 新現行版透過重索引建立其向量。

重蒸餾（DistillationProcessor）時不再刪除舊頁：改為建立版本鏈；若新頁自動核准，則超越舊現行版並使其向量失效；審核中的草稿（EffectiveStatus=null）不影響仍在線上的現行版，待核准後才接手。

4. 只索引現行版；舊版保留供回溯

EmbeddingIndexProcessor 只為「Status=已完成 且 EffectiveStatus=current」的 Wiki 頁建索引；superseded 舊版的頁、檔案與向量都保留，但向量 IsCurrent=false，預設不參與問答。Cleaned 層不版本化，只要存在即索引。

5. 事件觸發自動重索引

為縮短「內容已改、索引還舊」的落差，自 0.3.12 起：

  • 線上編修 Wiki 內容（UpdateContentAsync）或核准 Wiki（ApproveAsync）時，會呼叫 WikiPageService.TryEnqueueSourceReindexAsync 自動把來源排入重索引佇列。
  • 有守門：來源須為「已清洗」，且未有進行中的索引作業（避免重複排入）。
  • 底層沿用 EmbeddingIndexQueue → EmbeddingIndexBackgroundService → EmbeddingIndexProcessor（增量、冪等）。

6. as-of 時點檢索

EffectiveVersionFilter.ApplyEffective(asOf) 疊在團隊權控（ACL）之上於 RetrievalService 套用：

  • asOf 為 null：只回傳 IsCurrent=true 的向量（預設行為）。
  • asOf = T：回傳在 T 當時有效的版本，即 EffectiveDate ≤ T 且（ExpiryDate 為 null 或 > T）。
  • Cleaned 層 EffectiveDate=null、永遠納入，不受版本過濾影響。

RetrievalQuery.AsOf 會傳遞到 VectorQuery；診斷頁（RagDiagnosticsService.TryRetrieveAsync）提供 as-of 試檢索，可實際比對「當時 vs 現在」。

7. 使用者介面

  • 版本歷史：Wiki 頁管理與知識百科可查看同概念的版本鏈（GetVersionChainAsync，依 Version 遞減）。
  • 治理編輯：可維護 Owner／ChangeSummary（UpdateGovernanceAsync）。
  • 診斷 as-of 試檢索：/rag-diagnostics 可指定時間點做點檢索試驗。

8. 不變量

  • 權控優先於版本過濾：版本過濾不取代團隊權控；非管理員的越權洩漏必須維持 0。
  • 向後相容：導入時以雙資料庫 migration AddVersioningFields + 回填（既有已完成頁 → current、既有向量 IsCurrent=true）確保既有知識不遺失。
  • 舊版不刪除：superseded 版本保留供 as-of 與稽核。
