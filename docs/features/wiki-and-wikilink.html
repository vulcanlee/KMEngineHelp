功能機制

知識百科與 WikiLink

文件目的

說明 reader（閱讀者）導向的知識百科頁 /knowledge-wiki（DIS-1）與 [[概念]] 可點擊連結（DIS-2）兩項能力：讓使用者像看 Wiki 一樣瀏覽已完成的知識頁、並在頁面間以概念連結互相跳轉。此能力自 0.3.13 起提供。

相關：知識頁審核與 Wiki 頁管理指南、AI 知識問答使用指南、Wiki 與 Cleaned 的角色差異。

1. 知識百科頁 /knowledge-wiki（DIS-1）

有別於「知識頁審核與 Wiki 頁管理」是編輯／審核導向，知識百科頁是閱讀導向：

  • 路由：/knowledge-wiki。
  • 左側：把「已完成」的 Wiki 頁依 Categories 分類分群，並提供三種篩選：
  • 關鍵字：即時比對標題。
  • 分類、團隊：AntDesign 多選下拉（SelectMode.Multiple），永遠顯示。選項取自分類/團隊主檔（CategoryService／TeamService.GetAllEnabledNamesAsync()，與知識頁審核管理頁一致）；篩選比對全部在前端記憶體即時運算，同一篩選內為 OR、關鍵字/分類/團隊三者間為 AND。若選了目前沒有任何頁面使用的團隊，結果清單會為空（預期行為）。
  • 左側清單採前端分頁（每頁 50 筆）：資料一次載入記憶體，僅渲染當前頁項目以避免大量（上萬筆）項目一次渲染造成的效能問題；保留分類分群（同一分類可跨頁切割），清單下方提供分頁器。關鍵字/分類/團隊任一篩選變動會自動回到第 1 頁。
  • 右側：閱讀選定頁的內容（經 Markdown 安全渲染），標題下方提供複製（原始 Markdown）與下載 PDF（詳見 §2.5）。
  • 團隊權控：與全站一致，非管理員只看得到「無團隊（公開）或與自身角色團隊交集」的頁；管理員不受限。清單本身於服務層 team-scoped；團隊下拉為主檔選項，實際可見結果仍受權控。
  • 服務層：WikiPageService.GetBrowseIndexAsync（分類索引，team-scoped、只含已完成頁）。

2. [[概念]] 可點擊連結（DIS-2）

WikiLinkPreprocessor 是一個純函式前處理器，把內文中的 [[概念]] 標記轉為 Markdown 連結後，再交由既有 MarkdownRenderer（Markdig，DisableHtml）渲染：

  • 概念存在（有對應的已完成頁）→ 轉為可點擊連結，跳轉到 /knowledge-wiki?concept=概念。
  • 概念不存在 → 顯示為「標題（待建立）」純文字，不產生死連結。
  • XSS 安全：僅在渲染前做字串前處理，渲染器維持 DisableHtml，不因此開放 HTML 注入。
  • 連結解析：WikiPageService.GetCompletedTitlesAsync（判斷概念是否存在）；?concept= 導覽由 GetByTitleAsync 取頁（皆 team-scoped、只取已完成頁）。

2.1 下游用途：LinkTitles 是知識圖譜的邊（Graph RAG P1，1.0.83）

[[概念]] 除了供閱讀時跳轉，蒸餾時同步存進 WikiPage.LinkTitles（分隔字串）的那份清單，還是 Graph RAG 的邊來源：

  • GraphEdgeService.RebuildForSourceAsync 把 LinkTitles 解析為 GraphEdge 邊表（先比對同來源標題、再比對全域現行頁；解析不到目標頁時 TargetWikiPageId = 0，保留 TargetTitle 備查但不參與遍歷）。此步驟不呼叫 LLM。
  • 觸發時機：蒸餾完成（DistillationProcessor）、Wiki 頁核可或線上編修（WikiPageService）。整批刪除重建、冪等；失敗只記警告、不影響主流程。
  • 用途：檢索時以命中的 Wiki 頁為種子沿邊做多跳擴展（預設 2 跳、可設定），把鄰居頁的 chunk 加分（見 知識庫 RAG 設計與執行 §4.2）。

換言之，多寫一個正確的 [[概念]] 連結，不只是多一個可點擊的字，也是在替知識圖譜補一條可被檢索利用的邊。邊同樣帶 Teams 並於遍歷前過濾，維持零越權洩漏。

2.5 內容複製與下載 PDF（共用元件 MarkdownActionBar）

右側閱讀區與兩個 AI 對談頁（AI 知識問答、知識來源對話）共用同一動作列元件 Components/Commons/MarkdownActionBar.razor：

  • 複製：以 JS interop 呼叫 keChat.copyText 複製原始 Markdown（1.0.38 起改用此法；原本的 navigator.clipboard 在 LAN 純 HTTP 的非安全內容下不存在，會直接失效）。
  • 下載 PDF：後端 ChatPdfExporter.Generate(markdown, title)（QuestPDF + QuestPDF.Markdown，內嵌 Noto Sans TC 繁中字型不亂碼、文字可選取）產生 byte[]，經 DotNetStreamReference 串流由前端 keChat.downloadFileFromStream 觸發下載；檔名為 {前綴}_{時間戳}.pdf（瀏覽頁前綴為「知識百科」，PDF 頁首為該頁標題）。
  • 參數：Content（Markdown 來源）、PdfTitle（PDF 頁首）、FileNamePrefix（檔名前綴）、ShowPdf（是否顯示下載 PDF，使用者訊息僅複製時設 false）。

3. 權限與選單

新增角色權限 角色_知識瀏覽，並依專案慣例於三處同步登記：

  1. src/KnowledgeExtraction/KnowledgeExtraction.Share/Helpers/MagicObjectHelper.cs（角色常數）
  2. RolePermissionService（權限樹）
  3. src/KnowledgeExtraction/KnowledgeExtraction.Web/Datas/Menu.json（選單項，圖示 menu_book）

選單與頁面權限依位置索引對應，三處需一致，否則權限樹會錯位。

4. 與知識頁審核／Wiki 管理的關係

頁面導向對象
知識頁審核 / Wiki 頁管理編輯・審核（觸發蒸餾、核准/退回/編修/刪除、版本治理）知識維護者
知識百科 /knowledge-wiki閱讀・探索（分類瀏覽、概念跳轉）一般閱讀者

知識百科只呈現「已完成」頁；搭配版本化（見 features/版本化與時效性），閱讀者看到的是現行版知識。
