抖音影片自動轉錄整合 — 設計文件

  • 日期：2026-06-04
  • 狀態：已與使用者確認設計，待寫實作計畫
  • 版本基準：系統 0.2.25

Context（為什麼做）

目前抖音影片無法用「音訊轉錄」的「影片連結」來源下載：抖音 web API 需要其 JS 即時計算的簽章（a_bogus／msToken），yt-dlp 算不出，必定回 Fresh cookies (not necessarily logged in) are needed（與 cookie 無關，已實測）。本 session 已做出半自動助手 tools/douyin-audio/get-douyin-audio.mjs：用已登入的 playwright 瀏覽器攔截音訊串流→下載→ffmpeg 轉 mp3，需人工偶爾過驗證。

使用者希望把抖音流程整合進系統自動化：

  1. 新增轉錄記錄時，於「影片網址」欄貼上抖音分享文字，自動帶出標題與乾淨網址到對應欄位。
  2. 下載階段偵測到抖音，自動觸發助手腳本（取代 yt-dlp）。
  3. 下載完成後，沿用與上傳檔相同的「抽音訊→轉錄」流程，使抖音→文字稿自動化。

已確認的決策與限制

  • 自動化模式：直接自動觸發；需驗證時瀏覽器視窗跳出由使用者當場手動過，逾時則該筆標記「失敗」可重試。
  • 標題來源：從分享文字擷取（可手動修改），下載時不覆寫使用者標題。
  • 環境限制：助手需可見瀏覽器與偶爾人工驗證，僅限有桌面的本機（非無頭伺服器）。
  • 併發：持久瀏覽器設定檔有鎖，同時間只能跑一個抖音工作；既有轉錄背景佇列本就循序處理，符合此限制。

Goals / Non-Goals

Goals

  • 貼分享文字即自動帶入標題＋網址。
  • 抖音記錄在背景轉錄時自動以助手下載音訊，後續轉錄全自動。
  • 失敗（逾時／需驗證／無音訊）以既有「失敗 + 錯誤訊息」呈現，可重試。

Non-Goals

  • 不支援無頭伺服器自動跑抖音（架構限制，文件已載明）。
  • 不為抖音另建獨立佇列／worker。
  • 不改動既有分段、OpenAI 轉錄、OpenCC 繁體流程。

架構（採「C# 下載策略切換」）

整合點：TranscriptionProcessor.DownloadFromUrlAsync（src/.../Business/Services/Transcription/TranscriptionProcessor.cs:130），由 ProcessAsync 在 IsUrlSource && MediaRelativePath 為空 時呼叫。依網址選擇下載器，兩者皆回傳 MediaDownloadResult（FullPath, RelativePath, OriginalFileName, ContentType, FileSize），下游不變。

ProcessAsync
  └─ DownloadFromUrlAsync(record)
       ├─ IsDouyin(record.SourceUrl) ? DouyinAudioDownloader : MediaUrlDownloader(yt-dlp)
       │       └─ 回傳 MediaDownloadResult → 寫入 record 欄位
       └─ 既有：分段 → OpenAI 轉錄 → OpenCC 繁體 → 存逐字稿（不變）

元件設計

① ShareTextParser（Part 1，分享文字解析）

  • 位置：KnowledgeExtraction.Business/Helpers/ShareTextParser.cs（與 UrlExtractor 同層）。
  • 介面：
  • string? ExtractUrl(string? text) — 委派既有 UrlExtractor.ExtractFirstUrl。
  • string? ExtractTitle(string? text) — 取第一個 http(s) URL 之前的文字，去除抖音分享前綴雜訊（數字代碼、形如 :8pm 的時間、形如 05/11 的日期、短亂碼 token），回傳清理後標題；無法判定則回傳 null。
  • 範例：4.30 QkC:/ d@a.nD :8pm 05/11 35岁的产品经理都去哪了 # 产品经理 https://v.douyin.com/UkmXQe9ia84/ 复制此链接… → 標題 35岁的产品经理都去哪了 # 产品经理、URL https://v.douyin.com/UkmXQe9ia84/。
  • 啟發式為「最佳努力、可編輯」；擷取失敗不阻擋建立（標題欄維持空白由使用者填）。

② 建立表單自動帶入（Part 1，UI）

  • 檔案：KnowledgeExtraction.Web/Components/Views/MediaTranscriptions/MediaTranscriptionView.razor[.cs]。
  • 行為：來源類型為「影片連結」時，於「影片網址」輸入框變更／貼上後：以 ShareTextParser 解析；將乾淨網址寫回網址欄；若標題欄為空，填入擷取標題（使用者可改）。
  • 伺服器端 MediaTranscriptionService.BeforeAddCheckAsync 既有 URL 清理保留為保險。

③ DouyinAudioDownloader（Part 2，C# 包裝助手）

  • 位置：KnowledgeExtraction.Business/Services/Transcription/DouyinAudioDownloader.cs。
  • 職責：以 NodePath 執行 DouyinHelperScript，傳入網址與指定輸出檔 {MediaUploadPath}/{yyyy}/{guid}.mp3；等待（DouyinTimeoutSeconds）；解析助手輸出取得 mp3 路徑；組 MediaDownloadResult 回傳。
  • IsDouyin(url)：host 屬 v.douyin.com／www.douyin.com／douyin.com／iesdouyin.com。
  • 失敗（exit≠0、逾時、找不到輸出檔）→ 丟 InvalidOperationException（含 stderr 摘要），由既有 catch 標記「失敗」。

④ 助手腳本契約升級

  • 檔案：tools/douyin-audio/get-douyin-audio.mjs。
  • 新增：以 --out <mp3 完整路徑> 旗標接受指定輸出檔（不影響既有「第三參數＝輸出資料夾」的手動用法）；成功時印出一行機器可解析結果：MP3_PATH=<絕對路徑>。
  • 維持人類可讀訊息與既有 exit code（0 成功、2 需驗證/無音訊、3 下載失敗、4 轉檔失敗）。供命令列手動使用者與 C# 整合共用。

⑤ 設定

  • OpenAISettings 新增：
  • NodePath（預設 node，走 PATH）
  • DouyinHelperScript（get-douyin-audio.mjs 的絕對路徑；預設空白。為空時抖音下載直接以明確訊息失敗，提示需設定此路徑——因腳本位於 repo 的 tools/，發布後位置依部署而定，故不預設相對路徑以免誤判）
  • DouyinTimeoutSeconds（預設 150）
  • 對應更新 日誌與設定檔說明.md、外部工具安裝與路徑設定.md、全新機器部署SOP.md（參數表）。

資料流

  1. 使用者貼分享文字 → UI 解析帶入標題＋網址 → 儲存（SourceType=Url、SourceUrl=乾淨網址、Title=擷取標題）。
  2. 背景佇列 → ProcessAsync → DownloadFromUrlAsync：IsDouyin → DouyinAudioDownloader 跑助手（瀏覽器視窗可能跳出）→ 產出 mp3 至 MediaUploadPath/{yyyy}/{guid}.mp3 → 寫入 record.MediaRelativePath/FileSize/...。
  3. 既有分段→OpenAI→OpenCC→存 .txt，記錄標記「已完成」。

錯誤處理

  • 助手 exit≠0／逾時／無輸出檔 → DouyinAudioDownloader 丟例外 → ProcessAsync 既有 catch 寫 ErrorMessage、標記「失敗」、可重試。
  • 需驗證時：瀏覽器視窗跳出，使用者當場手動過；逾時即失敗。
  • 同時間僅一個抖音工作（佇列循序 + 設定檔鎖）。

測試

  • 單元測試：ShareTextParser.ExtractTitle／ExtractUrl 多種分享文字格式（含本文件範例、純網址、無標題、含全形標點）。
  • 整合（手動）：以真實抖音分享文字新增記錄 → 確認標題＋網址自動帶入 → 背景轉錄自動下載（助手視窗）→ 產出繁體逐字稿。
  • 迴歸：YouTube／小紅書「影片連結」仍走 yt-dlp、上傳檔流程不受影響。

部署注意

  • 僅本機（有桌面）可自動跑抖音；無頭伺服器下抖音記錄會逾時失敗（屬已知限制，文件載明）。
  • 需安裝 Node.js 與 @playwright/cli（含 Chromium）並維持抖音登入設定檔（見 外部工具安裝與路徑設定.md §3.3、§8、§9）。
