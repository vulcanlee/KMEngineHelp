知識庫產品調研 prompt

使用 superpower 技能 最近將這套知識庫系統與幾個客戶來介紹，發現大家所要的知識庫並不是只是單純的資料檔案味道系統內，並且做成向量進行檢索這樣簡單的需求，例如其中一個是想要教他們的設計結構標準納入到這個系統內並且能夠進行迭代的修正與更新，但就這樣的需求好像並不是單純的只是把一些文件匯入到系統內，如何把這樣的設計規格與標準需求，要如何整理成可以進行知識庫管理的文件，是否需要特定格式或者是做法，好像就並不是是單純的資料庫Rag解鎖的方式，面對這樣的需求是否還要再設計其他的功能或者頁面來輔助這樣的應用 另外一個客戶是想要將它開發的系統規格與資料庫上面的結構納入到知識庫內，但是這樣的這些資料究竟要如何變成未來真正使用的需求，看樣子客戶好像並不是單純只是要進行搜尋姿勢這樣的應用這麼簡單，從這2個例子來看，應該都是要將企業上的一些知識或者做法，經過體驗產出不同的內容，不過由於每個客戶的需求都不一樣，就算在同一個客戶裡面也存在著不同步有著不同的知識庫應用的需要，另外面對索要匯入的資料，好像並不是單純的一個檔案；這些檔案存在的特殊的意義與格式規範，要如何將這些資料變成未來的應用，也是一個待解決的問題 我這裡需要一個探索與研究，面對到現在這樣的系統，基本上已經完成了rag的設計，因此需要以產品經理的角色來進行這樣的市場分析，面對市面上的各種知識庫的產品，他們究竟存在了哪些功能，還是基本的將檔案匯入到一個大系統可以提供一個檢索以及對話的功能而已，又或者他們在這樣的知識庫系統上面有建議或開發出不同的應用，我需要這方面的調研，提出一些未來這個產品開發的方向以及指南，並且這樣的東西是能夠明確戳中客戶的痛點而且是客戶真正想要這樣的功能，那麼究竟是要在這個系統上增加更多的功能他是開發出更多的系統，而是基於這個知識庫的應用所產生出來的外溢效應，我需要有這樣的分析文件分析文件，讓我可以來進行判讀接下來的下一個步驟與未來的開發方向該如何進行 分析現有這個系統，若要完成上述剛剛提到的2個客戶的應用，是否需要變更系統架構獲得增加更多的畫來應應這樣的處理機制，當然可以有更靈活的做法也是更好的 由於對我而言這是一個完全陌生而且沒有接觸過的系統，我需要能夠進行深度的分析以及調研，整理出一些做法與建議 若有不清楚我的需求或者目的，請反覆與我提問，直到你了解我想要做甚麼事情，這樣這個需求寫入到一個文件檔案內

將這份文件，根據底下的內容，進行進一步的修訂 我覺得客戶應該不是只單純的需要知識庫問答這樣的功能，普通 RAG，它可以視為企業自建知識庫的基礎。做法通常是先將企業文件解析出來，切分成多個小段，再轉為向量存入向量資料庫。當使用者提問時，系統會先從知識庫中檢索相關內容，再把找到的片段交給大模型生成回答。另外，傳統知識庫往往偏向文件檢索或 PDF 問答，但在企業合規場景中，面對國標、法規、企業內部制度等複雜文件時，單純檢索往往不足。企業常因文件數量龐大、標準彼此引用、版本持續更新，而難以及時判斷合規性，進而產生遺漏、錯誤或資訊不透明等問題。所以若可以將 AI Agent 加入之後，是否可以有更多讓客戶想要的功能，這些正好解決客戶的痛點，面對文件多版本的問題是否有更好的解決做法，也就是說，對於運行之後，原始資料的不斷迭代與更新和異動，如何確保知識庫可以使用最新最正確的來源，對於資料安全的要求設計，有沒有甚麼要改善的

面對這句話：企業知識庫的核心從來不只是把文件集中管理，而是如何把分散在不同系統、不同流程與不同載體中的知識重新組織起來。有沒有甚麼建議與想法

面對這句話：該企業級知識庫系統的定位，不是簡單問答工具，而是面向企業合規管理的知識平臺。系統可識別文件狀態、追蹤法規版本、理解表格語意、建立知識路徑，並提供完整的原文溯源與可解析答案，協助企業處理更高複雜度的知識管理需求。分析一下這句話的意義，真的可行嗎？面對各種客戶的不同需求，落地做得到嗎?並且，呈現出來的成果與效果，真的是客戶要的嗎?還只是一個空泛的口號而已，又或者又投入極高的成本，但回收有限
