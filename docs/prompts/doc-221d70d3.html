說明文件的網頁版需求

針對知識庫管理者、導入顧問、知識庫系統銷售人員，將 docs 目錄下的相關文件，建立起許多 html 網頁文件，產生在 C:\Users\vulca\Downloads\KMEngineHelp 目錄內，我的目的是在於這套知識庫系統慢慢變得有些大與複雜，而且有些事情使用的轉準備工作與如何觀察知識問題真實有效、如何整理出最原始資料的內容等等，提供完整的相關說明文件

在這個網頁內，一開始先要選擇角色是甚麼：知識庫管理者、導入顧問、知識庫系統銷售人員(能夠有一個圖片來表示這三種角色)，接著會進入到這個角色需要觀看的相關文件清單或者有哪些類型文件的清單，在這裡這個網頁的使用者，將會針對不同的需求或者情境(要有文字主題與說明這個主題是要提供甚麼樣的內容，為什麼需要來看這些文件，這些文件主要可以解決甚麼樣的問題)，列出有哪些文件可以幫助使用者了解這個系統的功能或特色、如何解決他的問題，接這也許就直接將原先在 docs 內的某個文件，使用 html 格式顯示在網頁上，當開啟這個說明網頁之後，若原始文件內有其他的參考連結(定義在 .md 檔案內)，同樣可以讓使用者點選這個連結來查看到這些網頁版本的文件，若這份說明網頁沒有提供額外參考的文件，可以在這個網頁上加入參考文件連結

整個知識庫說明文件網頁，採用靜態網站模式來產生相關的網頁檔案，整個網頁所有檔案，也許會透過 github page 佈署過去，或者取得原始的所有檔案，可以在本機開啟，透過瀏覽器來觀看這些文件，讓使用者可以透過網頁來直接查看這些說明內容
