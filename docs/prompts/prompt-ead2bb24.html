關於如何設計資料清洗的規範 prompt

這個系統主要是要最終要做出一個環繞於知識庫的應用系統 現在還早期，正在做到 資料匯入 階段，將各種格式檔案，轉換成為文字 底下為規劃的整理流程 資料匯入 → 資料清洗 → 知識蒸餾 → 建立知識庫 → 智慧應用 問題一，對於資料匯入這塊的規劃與實際開發上，現在還有那些地方是不足，並且需要改善的地方，該如何做出修正 問題二，若要開始規劃資料清洗階段，該如何規劃、又有哪些做法可以選擇，因為現在的資料相當的零散與破碎，如何才能夠產出具有高品質與有用的資料或者知識出來，許多蒐集到的資料都是來自於單一的檔案、影片、錄音、圖片檔案，這些資訊是否需要進行群組定義又或者需要進行梳理，形成一個比較完整的資料來源，如何設計出這樣需求的系統出來。又該如何確認這樣的作法是可行的，確認資料的品質性 我需要這樣的分析報告與代辦事項清單文件，方便日後執行與開發出資料清洗的功能，分析已經開發出來的系統程式碼與 docs 下的文件 看看我的想法是否還有那些地方是有問題的，並且反覆迭代向我提問，一起找出具體可行作法，並且產生出相關文件與可以預期的系統功能架構 尋找與建議使用合適的技能來做出更好的計畫
