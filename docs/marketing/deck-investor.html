企業知識庫計畫

把分散資訊，變成可運用的智慧資產

決策投資簡報　|　2026/07/18　|　對應系統版本 1.0.14 KnowledgeExtraction.AI（產品名：智庫引擎）

一句話

將分散的資訊轉換成可搜尋、可理解、可運用的企業智慧資產， 並透過 AI 與外部 Agent 持續創造更大的商業價值。

完整閉環：資料匯入 → 資料清洗 → 知識頁審核 → 建立知識庫 → 附加應用

問題與機會

  • 資訊分散：文件、會議、影音、信件、聊天、系統資料散落各處
  • 會議很多，但結論與待辦沒人記得
  • 人工整理成本高、品質不穩定
  • 關鍵知識依附在「人」身上，人員一走就斷層

機會：AI 讓這些資訊第一次能被自動收斂為可用、可信、可稽核的知識。

願景

  • 員工以自然語言提問，30 秒得到帶出處、帶權限、可稽核的答案
  • 知識留在系統、不在個人腦中，並隨版本演進保留時效
  • 從問答助理，延伸到讓外部 AI Agent 安全查庫、再到自動化工作流

效益：提升效率、降低人力成本、加速知識傳承與決策品質。

我們的起點：不是願景，是已上線的系統

階段現況（1.0.14）
資料匯入✅ 音訊/影片（含 YouTube/抖音）、文件（PDF/Word/PPT/Excel/批次 ZIP）、圖片辨識
資料清洗✅ 去重、個資遮罩、分類/標籤、摘要、信心自評（5 步）、知識頁審核
知識頁審核✅ 互連 Wiki 實體頁、版本化與 as-of 時效、事件觸發自動重索引
建立知識庫✅ 切塊、Embedding、混合檢索、兩段式信心門檻、附出處問答、團隊權控（越權=0）
附加應用✅ AI 知識問答、單一來源 AI 對話、知識百科、MCP 對外 AI Agent 整合

成熟平台（.NET 10 / Blazor Server，600+ 個 C# 檔、約 40 個功能頁），不是從零開始。

平台成熟度：可觀測、可治理、可維運

  • 合規稽核：問答稽核明細、Token 用量歸屬、問答稽核（僅指標、不落內容本文）
  • 經營儀表板：5 支統計報表（用量/滿意度/問答行為/檢索品質/內容清點）＋首頁管理者專區
  • 系統可觀測性：24 項健康檢查，含實呼叫探針驗證大語言模型與嵌入端點是否真的可用
  • 維運工具：資料一致性巡檢、檢索診斷與調校與門檻熱套用、依時間區間打包下載日誌
  • 品質量化：清洗品質評測（上游清洗）＋ 檢索品質評測（下游檢索、含越權洩漏測試）＋ 評測基線

雙路線定位

路線對象價值
內部自用開發團隊自身自己使用、dogfooding 驗證產品
對外商品化其他企業／通路可私有部署、企業級權控與稽核的方案

地端與雲端皆支援（生成與嵌入模型都可地端）：地端是面對「資料不可外流」企業的關鍵賣點與差異化。

旗艦應用（聚焦兩個）

  1. AI 智慧問答／企業知識助理

最通用、最容易展示價值、ROI 易量化；已上線

  1. MCP 對外 AI Agent 整合 → 自動化工作流

讓 Claude／Codex 等 AI Agent 沿用同一套權控與稽核安全查庫；已上線基礎（5 工具），自動化工作流為長期願景

投資報酬（衡量框架）

  • 效率：查找/整理時間 × 人力成本 × 頻次
  • 降本：逐字稿/摘要/分類的人工工時自動化
  • 傳承：降低人員異動造成的重工與斷層
  • 決策：帶出處知識讓決策有據

導入時先選 1–2 高頻情境量測基準值，作為 ROI 證據與對外燈塔案例。

已交付里程碑（節錄 1.0.x）

里程碑內容
MCP Server（1.0.1→1.0.9）5 知識工具＋JWT/API Key 雙認證＋金鑰資料庫化可即時啟停＋呼叫併入稽核與 Token 歸屬
資安與稽核（0.3.x）P0 注入防護＋遮罩不變量、問答稽核持久化、滿意度回饋、PDF 匯出
版本化與時效（0.3.14）版本鏈、as-of 時點查詢、事件觸發自動重索引、一鍵全量重建
統計報表與健康監控（1.0.13）5 支報表＋24 項健康檢查（含 LLM/嵌入實呼叫探針）＋管理者專區
維運工具（1.0.12/1.0.14）日誌下載打包、儀表板管理者視角

近期路線圖（3–6 個月）

核心閉環與商品化基礎皆已上線；近期聚焦商品化包裝與 Agent 自動化。

方向重點狀態
商品化包裝私有部署 SOP、授權/計費機制（規劃中）、導入服務化規劃中
Agent 自動化以 MCP 為基礎，發展跨步驟自動化工作流規劃中
檢索品質rerank（二階重排，評測驅動之 P2）、知識缺口分析評估中

授權/計費保護機制目前為設計規劃（見 docs/strategy/軟體授權保護機制設計.md），尚未實作。

架構方向

  • 知識頁審核 ＋ LLM 知識 Wiki（Karpathy 概念）：萃取真實可用知識，知識複利累積
  • 混合檢索（向量 0.7＋關鍵字 0.3）＋查詢改寫＋兩段式信心門檻（rerank 為評測驅動之 P2，尚未導入）
  • 雙資料庫平台：SQLite／SQL Server 可切換；向量以 Embedding 存取層抽象
  • Embedding/LLM 供應商可切換（雲端/地端，維度鎖定 1024 對稱檢索）
  • 企業必備：檢索層權控、個資遮罩、存取稽核、分散式快取（Memory/Redis） 內建

資源需求與風險

資源：開發人力、雲端用量/算力、（地端）模型與硬體

主要風險：

  • 地端模型品質/算力不確定 → 先雲端驗證
  • 越權外洩 → 檢索層即過濾＋檢索品質評測越權測試（目標 0）
  • 範圍蔓延 → 嚴守近期範圍，願景分期

決議請求

  • 核准近期 3–6 個月路線圖與資源（商品化包裝＋Agent 自動化）
  • 確認供應商策略（雲端先行）、預算上限與合規範圍
  • 選定 1–2 個內部燈塔情境，並拍板授權/計費模式方向

詳見 docs/strategy/ 策略文件集與 軟體授權保護機制設計.md。
