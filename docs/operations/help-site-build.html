這個網站解決的是：docs/ 有 425 份文件，但既有的 README.md 索引是依目錄分類（回答「這份文件是什麼」），沒有任何入口回答「我是誰、我現在的問題該看哪幾份」。

一、怎麼產

python scripts/Build-HelpSite.py --both       # 完整版＋對外版，一次產（建議）
python scripts/Build-HelpSite.py             # 只產完整版
python scripts/Build-HelpSite.py --audience external   # 只產對外版
python scripts/Build-HelpSite.py --out D:\somewhere\Help   # 指定輸出目錄
python scripts/Build-HelpSite.py --check     # 乾跑：只驗證與轉換，不寫檔

預設輸出：

模式位置內容
完整版C:\Users\vulca\Downloads\KMEngineHelp425 份文件全收，對內文件加紅色警示條
對外版C:\Users\vulca\Downloads\KMEngineHelp-external排除對內文件（見 §三）

⚠️ 輸出目錄會先整個刪除再重建（shutil.rmtree），不要把手改的檔案放在裡面。

⚠️ 輸出不進版控（產出物）。要推 GitHub Pages 時用 --out 指到 repo 內的目錄再另行決定是否納管。

三、兩種輸出模式的差別

排除清單定義在 scripts/help_site_data.py：

常數內容
INTERNAL_DIRSdocs/prompts/、docs/planning/、docs/archive/、docs/superpowers/
INTERNAL_FILESdocs/strategy/知識庫導入實施顧問手冊.md
  • 完整版：全收，對內文件的頁首顯示紅色「⚠ 對內文件，不交付客戶」，角色頁的文件清單旁加「對內」標籤。
  • 對外版：這些檔案根本不產生（不是隱藏連結而已——可以用檔案是否存在驗證）。指向它們的連結會變成不可點文字，建站報告會列出斷開的數量（1.0.111 首次產出為 77 個，全部是刻意排除）。

為什麼要兩種：顧問手冊明寫「不直接交付客戶」。靜態網站沒有權限機制，唯一可靠的隔離就是「那個檔案不在資料夾裡」。要給客戶時一律用對外版。

四、內容要改哪裡

想改什麼改哪個檔

角色名稱、說明文字、圖示同檔的 ROLES

⚠️ 不要直接改輸出的 HTML——下次建站會整個覆蓋。Markdown 是唯一來源。

✅ 資料檔的路徑會被逐一驗證：CURATED_SLUGS、SCENARIOS、INTERNAL_FILES 裡任何一條路徑打錯或檔案改名，建站會當場失敗並指出是哪一條，不會產出半殘的網站。

五、連結是怎麼處理的

docs/ 內共約 1959 個 .md 連結、98 個頁內錨點。轉換時分七類：

型別處理
.md（含 #錨點）改寫為站內對應頁，錨點原樣保留
目錄連結（planning/）指向該目錄 README.md 的頁面
.htmldocs/ 內 18 個 .html 全部都是同名 .md 的伴生檔 → 改指向站內那一頁，不複製伴生檔（複製會讓伴生檔內部的兄弟連結全斷，也會讓同一份內容在站內出現兩次）
圖片複製到 assets/img/ 並改寫路徑
指向 docs/ 外的 .md（repo 根 readme.md、tools/…）不可點文字（在 repo 內有效，但不屬於本網站範圍）
.cs／.ps1／.json 等 repo 檔案不可點文字＋滑過顯示原路徑
應用路由（/knowledge-base-chat）不可點文字（那是系統畫面，不是文件）

錨點為什麼會準：標題 id 用 scripts/doc_slug.py 的 GitHub 相容 slug，而 scripts/Test-DocLinks.py 驗證錨點時用的是同一支函式。集中在一處是刻意的——兩邊各自實作的話，會出現「守門說沒問題、產出的頁面卻跳不到」。

六、搜尋的範圍與取捨

索引收：文件標題、用途描述（- 文件用途： 那一行）、各章節標題（H2／H3）。

刻意不做全文搜尋：全文索引會膨脹到 4～5 MB，每一位訪客首次載入都要下載。目前 337 KB 已能做到「打一個詞就跳到具體章節」。找不到時請改用 all-docs.html。

七、佈署

本機使用：直接開 index.html 即可（file://）。所有路徑都是相對路徑，沒有外部請求。

GitHub Pages：

  1. python scripts/Build-HelpSite.py --audience external --out <repo>/<pages 目錄>
  2. 把該目錄推到 Pages 對應的分支／路徑。
  3. ⚠️ 對外發佈一律用對外版（§三）。
  4. ⚠️ 檔名已全部是 ASCII slug，不會有中文 URL 編碼問題。

八、維護紀律

  1. 改了 docs/**/*.md 之後要重跑建站，否則網站是舊的。網站沒有「自動同步」機制。
  2. 跑 python scripts/Test-DocLinks.py 確認 docs 的連結與錨點都還解析得到（硬性失敗必須為 0）。這支腳本補上了 Test-DocsEncoding.ps1 沒管的那一層——編碼檢查不驗連結。
  3. 建站報告要看：「無法解析的文件連結」必須為 0；「對外版排除而斷開的連結」是預期的，但數字暴增時要確認是不是誤把常用文件列進對內清單。
  4. 新增文件之後：若它該進某個角色的情境，記得在 SCENARIOS 加一條；只想讓它可被搜尋與瀏覽的話什麼都不用做（全部 md 都會轉）。
  5. 視覺確認要人工做。腳本能驗連結與標籤結構，驗不出「看起來對不對」。改過 CSS 或版面後請實開 index.html 走一遍：選角色 → 切幾個情境 → 點進文件 → 點文件內的參考連結 → 用搜尋跳到某個章節。

與 Build-OnboardingDocsHtml.py 的關係

scripts/Build-OnboardingDocsHtml.py（1.0.109 起）產生 docs/ 內的 5 份伴生 HTML，與本站台產生器轉換核心重疊。目前刻意保持兩支獨立：那一支有既有輸出與明確目標檔，改它會讓兩件事同時變動。

後續可考慮（尚未決定）：讓 Build-OnboardingDocsHtml.py 改用 doc_slug.py 與站台的轉換器，或評估那 5 份伴生 HTML 是否已被本網站取代。在做這個決定之前，兩支都要各自維護。
