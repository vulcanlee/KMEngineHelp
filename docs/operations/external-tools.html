部署與維運

外部工具安裝與路徑設定

文件目的

本系統的「影音轉逐字稿」與「文件轉文字」功能會以 System.Diagnostics.Process 呼叫數個本機外部命令列工具完成工作。這些工具不隨專案 NuGet 還原一起安裝，必須由部署者於作業系統層級另行安裝，並在 appsettings.json 設定其執行檔位置。

本文件列出：

  1. 系統用到哪些外部工具、各自用途與在程式中的呼叫位置。
  2. 路徑解析規則（設定空白 → 走 PATH；否則用設定的完整路徑）。
  3. 每個工具的安裝方式（Windows）。
  4. 如何找到工具的「真正完整執行路徑」，填回 appsettings.json。
  5. 安裝後的驗證方式與常見錯誤訊息對照。

設定欄位的總表與其他區段，另見 日誌與設定檔說明 第 4.8 節。

1. 外部工具總覽

工具用途用於功能路徑設定

呼叫位置（原始碼）：

  • yt-dlp：MediaUrlDownloader.cs
  • ffmpeg：MediaChunker.cs（時長偵測與分段）、MediaUrlDownloader.cs（以 --ffmpeg-location 指向 ffmpeg 所在目錄）、VideoTranscoder.cs（下載後原始影片轉碼為 H.264/AAC MP4）
  • markitdown：MarkItDownConverter.cs
  • 抖音助手：tools/douyin-audio/get-douyin-audio.mjs（另見同目錄 README）

2. 路徑解析規則

三個工具的解析邏輯一致（見各 Service 建構式）：

// 例：YouTubeDownloader.cs
this.ytDlpPath = string.IsNullOrWhiteSpace(ytDlpPath) ? "yt-dlp" : ytDlpPath;
this.ffmpegPath = string.IsNullOrWhiteSpace(ffmpegPath) ? "ffmpeg" : ffmpegPath;
  • 設定為空白 → 使用預設名稱（yt-dlp / ffmpeg / markitdown），交由作業系統從 PATH 環境變數尋找。
  • 設定為完整路徑 → 直接使用該絕對路徑啟動，不依賴 PATH。

建議：正式部署填完整絕對路徑，避免「在終端機可執行、但服務帳號的 PATH 找不到」的問題（IIS 應用程式集區、Windows 服務常以不同帳號執行，PATH 與登入使用者不同）。

ffmpeg 的特例（YouTubeDownloader.ResolveFfmpegLocation()）：當 FfmpegPath 不是預設值 ffmpeg 時，系統會取其所在目錄透過 --ffmpeg-location "<目錄>" 傳給 yt-dlp。因此 FfmpegPath 請填到 ffmpeg.exe 本身，系統會自動換算目錄。

3. 安裝方式（Windows）

3.0 一鍵安裝與檢測腳本（建議起點）

專案提供兩支 PowerShell 腳本（位於 scripts/），可大幅簡化首次安裝與驗證：

腳本用途
scripts/Install-ExternalTools.ps1自動安裝核心工具（ffmpeg、Python、yt-dlp、markitdown）與抖音鏈（Node.js、@playwright/cli、Chromium）。以 winget/pip/npm 安裝，工具落在使用者 Home 目錄（適合開發機、以互動帳號執行）。
scripts/Test-ExternalTools.ps1檢測平台前置需求（.NET 10 ASP.NET Core Runtime、PowerShell 版本）與各外部工具（含 npm）是否已安裝、可執行（顯示版本訊息），並輸出可貼入 appsettings.json 的路徑片段與環境變數指令。缺 .NET 10 執行時會以阻斷狀態（結束碼 1）提示先安裝；PowerShell 版本過低僅警告。
scripts/Install-PortableTools.ps1可攜版安裝：直接下載到固定目錄（預設 C:\KMEngineTools）並授權給 IIS 身分。IIS／服務帳號情境用此法（避開使用者 Home 目錄存取問題）。詳見 IIS 佈署與可攜工具設定。
scripts/Test-PortableTools.ps1驗證可攜安裝的工具並檢查 IIS 身分 ACL；支援 -InstallDir／-AppSettingsPath／-AppPoolName。

IIS／服務帳號部署請改走可攜安裝：因應用程式集區身分無法存取安裝使用者 Home 目錄，請用 Install-PortableTools.ps1 裝到 C:\KMEngineTools，完整說明見 IIS 佈署與可攜工具設定。

# 1) 安裝（預設全部安裝；僅核心可加 -SkipDouyin）
pwsh -File scripts/Install-ExternalTools.ps1
# 安裝 Python / Node.js 後若提示 SKIPPED，請關閉並重開終端機再執行一次（PATH 需更新）。

# 2) 檢測並取得各工具絕對路徑
pwsh -File scripts/Test-ExternalTools.ps1

腳本依賴 winget（App Installer）。安裝腳本不會自動修改 appsettings.json；請依檢測腳本輸出的片段，手動填入設定（見第 5 節）或以環境變數覆寫。 檢測腳本對每個工具會顯示「版本訊息」：例如 ffmpeg 印出 ffmpeg version ...、yt-dlp 印出版本號、markitdown 印出 markitdown x.y.z，即代表該工具安裝與路徑無誤。

以下各小節為手動安裝步驟與細節（腳本即依此實作；如需逐項操作或排錯時參考）。

3.1 ffmpeg

建議用 WinGet 安裝：

winget install --id Gyan.FFmpeg -e

安裝後 WinGet 會在 C:\Users\<使用者>\AppData\Local\Microsoft\WinGet\Links\ 放一個 ffmpeg.exe 連結（shim），並通常已加入 PATH。

替代方案：至 https://www.gyan.dev/ffmpeg/builds/ 下載 ffmpeg-release-essentials.zip，解壓到固定目錄（如 C:\tools\ffmpeg\），ffmpeg.exe 位於其 bin\ 子目錄。

3.2 yt-dlp 與 markitdown（皆為 Python 套件）

兩者皆透過 Python 的 pip 安裝，需先安裝 Python 3（建議 3.10 以上）。

python -m pip install --upgrade yt-dlp
python -m pip install --upgrade "markitdown[all]"

markitdown[all] 會一併安裝 PDF、Office、圖片等各格式的相依套件，避免轉特定檔案時缺套件而失敗。

安裝後執行檔（.exe 包裝器）會放在 Python 的 Scripts 目錄，例如：

C:\Users\<使用者>\AppData\Local\Python\pythoncore-3.14-64\Scripts\yt-dlp.exe
C:\Users\<使用者>\AppData\Local\Python\pythoncore-3.14-64\Scripts\markitdown.exe

實際目錄依 Python 安裝方式（官方安裝程式、Microsoft Store、pyenv 等）而不同，務必以第 4 節方法查出自己機器上的真實路徑，不要直接照抄。

3.3 抖音助手工具鏈（Node.js + @playwright/cli + Chromium）

僅在需要轉錄抖音影片時才需要（YouTube／小紅書不需要）。

  1. 安裝 Node.js（建議最新 LTS；v22 以上皆可，已驗證 v22、v24）：
   winget install --id OpenJS.NodeJS.LTS -e
  1. 全域安裝 @playwright/cli（內含 playwright-core）：
   npm install -g @playwright/cli

安裝後封裝器位於 C:\Users\<使用者>\AppData\Roaming\npm\playwright-cli.cmd，套件本體在 ...\npm\node_modules\@playwright\cli。

  1. 下載 Playwright 的 Chromium 瀏覽器（助手用它載入抖音頁面）：
   playwright-cli open https://example.com   # 首次執行會自動下載瀏覽器；或用下列指令
   npx playwright install chromium

瀏覽器快取預設在 C:\Users\<使用者>\AppData\Local\ms-playwright\chromium-<版號>\。助手腳本會自動挑用最新一版已安裝的 Chromium，毋須手動指定版號。

助手腳本引用 @playwright/cli 內建的 playwright-core 與 Chromium。位置優先讀環境變數：KMENGINE_PLAYWRIGHT_CORE（playwright-core 路徑）與 PLAYWRIGHT_BROWSERS_PATH（Chromium 快取目錄）；未設定才退回開發機預設（%APPDATA%\npm\... 與 %LOCALAPPDATA%\ms-playwright）。可攜安裝（Install-PortableTools.ps1）會自動設定此兩變數；手動安裝且路徑不同時，設定環境變數或調整 tools/douyin-audio/get-douyin-audio.mjs 頂部變數皆可。

4. 如何找到「真正完整執行路徑」

安裝完成後，用以下 PowerShell 指令查出每個工具的實際絕對路徑，再填回 appsettings.json。

4.1 Get-Command（最推薦）

(Get-Command yt-dlp).Source
(Get-Command ffmpeg).Source
(Get-Command markitdown).Source

各會印出一行完整路徑，例如：

C:\Users\vulca\AppData\Local\Python\pythoncore-3.14-64\Scripts\yt-dlp.exe

4.2 where.exe（會列出 PATH 中所有同名命中）

where.exe yt-dlp
where.exe ffmpeg
where.exe markitdown

若印出多行，代表機器上有多份同名工具；請挑選你要使用的那一份的完整路徑填入設定，以排除版本不一致的風險。

4.3 pip 套件專用：查 Scripts 目錄

針對 yt-dlp / markitdown，也可直接問 pip 安裝到哪：

python -m pip show -f yt-dlp        # Location 欄 + Files 中的 ../../Scripts/yt-dlp.exe
python -c "import sysconfig; print(sysconfig.get_path('scripts'))"

第二行會印出目前 Python 的 Scripts 目錄，yt-dlp.exe 與 markitdown.exe 即在其中。

4.4 反斜線轉義（重要）

appsettings.json 為 JSON 格式，路徑中的反斜線 \ 必須寫成 \\：

"YtDlpPath": "C:\\Users\\vulca\\AppData\\Local\\Python\\pythoncore-3.14-64\\Scripts\\yt-dlp.exe"

5. 填入設定檔

檔案：src/KnowledgeExtraction/KnowledgeExtraction.Web/appsettings.json

{
  "OpenAISettings": {
    // ...其他欄位...
    "FfmpegPath": "C:\\Users\\vulca\\AppData\\Local\\Microsoft\\WinGet\\Links\\ffmpeg.exe",
    "YtDlpPath":  "C:\\Users\\vulca\\AppData\\Local\\Python\\pythoncore-3.14-64\\Scripts\\yt-dlp.exe",
    "YtDlpCookiesFile": "",            // 選用：需要 cookie 的平台用的 cookies.txt 路徑（見第 8 節）
    "YtDlpCookiesFromBrowser": ""      // 選用：或從瀏覽器讀取，例：edge / chrome / firefox
  },
  "MarkItDownSettings": {
    "MarkItDownPath": "C:\\Users\\vulca\\AppData\\Local\\Python\\pythoncore-3.14-64\\Scripts\\markitdown.exe",
    "TimeoutSeconds": 600
  }
}

這些路徑不是機密，可寫入版控的 appsettings.json；但不同機器路徑會不同，建議於各環境的 appsettings.{Environment}.json 或環境變數覆寫。階層鍵改寫為雙底線： OpenAISettings:FfmpegPath → 環境變數 OpenAISettings__FfmpegPath、 MarkItDownSettings:MarkItDownPath → 環境變數 MarkItDownSettings__MarkItDownPath。

6. 驗證

最快方式：執行 pwsh -File scripts/Test-ExternalTools.ps1，一次檢測所有工具並顯示版本訊息與解析路徑（見第 3.0 節）。以下為手動驗證方式。

6.1 在終端機直接驗證工具

& "C:\Users\vulca\AppData\Local\Microsoft\WinGet\Links\ffmpeg.exe" -version
& "C:\Users\vulca\AppData\Local\Python\pythoncore-3.14-64\Scripts\yt-dlp.exe" --version
& "C:\Users\vulca\AppData\Local\Python\pythoncore-3.14-64\Scripts\markitdown.exe" --help

能印出版本／說明即代表路徑正確、工具可執行。

6.2 在系統內驗證

  • ffmpeg / yt-dlp / 抖音助手：到「影音轉逐字稿」頁，分別以本機音檔（驗證 ffmpeg 時長偵測／分段）、影片連結（貼 YouTube 或小紅書網址驗證 yt-dlp 抽音訊）與抖音連結（驗證系統自動呼叫 playwright 助手）各新增一筆，確認背景轉錄成功。抖音仍需互動式桌面與可用的 DouyinHelperScript，見第 8 節。
  • markitdown：到「文件轉文字」頁上傳一個 PDF 或 Word，確認背景萃取產出 Markdown。

7. 常見錯誤訊息對照

錯誤訊息原因處理
無法啟動 yt-dlp，請確認已安裝並設定 OpenAISettings:YtDlpPath。找不到 yt-dlp 執行檔依第 4 節查出路徑填入 YtDlpPath
無法啟動 FFmpeg，請確認已安裝並設定 OpenAISettings:FfmpegPath。找不到 ffmpeg 執行檔填入 FfmpegPath 完整路徑
無法啟動 MarkItDown，請確認已安裝並設定 MarkItDownSettings:MarkItDownPath。找不到 markitdown 執行檔填入 MarkItDownPath 完整路徑

yt-dlp 執行失敗 (ExitCode=...)連結無效、需登入、地區限制等查看訊息附帶的 stderr；更新 yt-dlp 版本

8. 各影片平台下載方式（小紅書／抖音）

本節為實測結論（2026/06）。不同平台對自動化下載的防護差異很大，請依平台選對方式。

8.1 小紅書 — 影片連結來源（yt-dlp，免 cookies）

小紅書可直接用「影片連結」來源：yt-dlp 會自動跟隨 xhslink.com 短連結轉址、辨識平台並抽取音訊，不需要 cookies。直接於「影音轉逐字稿」頁貼上連結（或整段分享文字）即可。

  • 限制：小紅書許多貼文是圖文（無影片），沒有音訊可轉錄，會以失敗呈現。

疑難排解：下載出現 Read timed out (read timeout=20.0) 多半是 DNS 被導錯，非 yt-dlp 問題。 曾實測本機/ISP 的 DNS 把 www.xiaohongshu.com 劫持解析到錯誤位址（如台灣 TANet 140.111.246.32），yt-dlp 連向死位址而卡到 20 秒逾時，錯誤如：

ERROR: [generic] Unable to download webpage: HTTPSConnectionPool(host='www.xiaohongshu.com', port=443): Read timed out. (read timeout=20.0)

排查：比對本機與公用 DNS 的解析結果——

Resolve-DnsName www.xiaohongshu.com                  # 本機 DNS
Resolve-DnsName www.xiaohongshu.com -Server 8.8.8.8  # 公用 DNS（正解應為 ...eo.dnse0.com → 43.170.214.x）

若本機解析到 140.111.x 之類錯誤位址，把執行 App 那台機器的系統/路由器 DNS 改為 8.8.8.8,1.1.1.1（Set-DnsClientServerAddress -InterfaceAlias "<網卡名>" -ServerAddresses 8.8.8.8,1.1.1.1），下載即恢復。此為 DNS／網路問題，與 cookies、yt-dlp 版本無關。

8.2 抖音 — 系統自動觸發 playwright 助手（無法走 yt-dlp）

抖音無法以 yt-dlp 下載。 抖音 web API 需要由其混淆 JS 即時計算的簽章參數（a_bogus／msToken），yt-dlp 算不出，會回報：

ERROR: [Douyin] xxxxxxxx: Fresh cookies (not necessarily logged in) are needed

此訊息與 cookie 無關——實測即使匯入完整登入 cookie（含 ttwid／sessionid）仍是同樣錯誤。因此抖音改採瀏覽器路線：用已登入的真實瀏覽器載入影片頁、攔截實際音訊 CDN 串流並下載。

自 0.2.27 起此流程已整合進系統（建議用法）：於「影音轉逐字稿」→「影片連結」來源貼上抖音連結或整段分享文字即可，系統偵測到抖音網址會自動呼叫助手腳本下載音訊，後續轉錄與一般流程相同，無須手動上傳。

自 0.2.89 起亦會保留原始影片：系統以 --out-video 一併要求助手保留原始 mp4 至 OriginalMediaPath/{yyyy}/{guid}.mp4（合併檔直接存、DASH 分流則以 ffmpeg 合流視訊軌+音訊軌；僅有音訊無視訊時略過）。影片保留屬加值，失敗不影響 mp3 與轉錄。

  • 前提：OpenAISettings:DouyinHelperScript 指向 get-douyin-audio.mjs 絕對路徑、NodePath 指向 Node（設定說明見 日誌與設定檔說明 §4.8）。
  • 下載期間瀏覽器視窗會跳出；若出現驗證頁請當場手動通過；逾時則該筆標記失敗可重試。
  • 僅限有桌面的本機（助手需可見瀏覽器與人工驗證，無頭伺服器不適用，見 §9.1）。

獨立手動執行（選用）

亦可不透過系統、直接用命令列產出 mp3（除錯或未整合環境），再以「檔案上傳」轉錄。詳見 tools/douyin-audio/README.md：

node tools/douyin-audio/get-douyin-audio.mjs "0.05 复制打开抖音 … https://v.douyin.com/xxxxx/ …"

首次會開啟可見瀏覽器；若出現驗證頁，於視窗內手動通過並登入抖音（登入由持久設定檔記住）。

8.3 cookies 設定（選用，給其他需 cookie 的平台）

OpenAISettings 仍提供兩個 cookies 設定，供其他真正靠 cookie 即可下載的平台使用；YouTube／小紅書不需要，抖音則無效（屬簽章問題，非 cookie 問題）。兩者皆設定時以 YtDlpCookiesFile 優先；皆空白則不帶 cookies。

設定項對應 yt-dlp 參數說明
YtDlpCookiesFile--cookies "<檔路徑>"指向 Netscape 格式的 cookies.txt。伺服器部署建議用此法（不依賴本機瀏覽器）。
YtDlpCookiesFromBrowser--cookies-from-browser <瀏覽器>從本機瀏覽器讀取，例：edge、chrome、firefox。注意較新版 Edge／Chrome 採 App-Bound Encryption，yt-dlp 可能無法解密（Failed to decrypt with DPAPI）；Windows 上以 Firefox 較穩。

cookies.txt 含登入憑證，屬機密，請勿進版控；建議以環境變數 OpenAISettings__YtDlpCookiesFile 指定路徑，或放在受保護目錄。

9. 佈署與注意事項

9.1 可否在伺服器（無頭環境）執行

工具／功能伺服器（IIS／服務帳號、無桌面）說明
ffmpeg / yt-dlp（YouTube、小紅書）/ markitdown✅ 可填完整絕對路徑避免 PATH 問題（見第 2 節）。服務帳號需有讀寫 ExternalFileSystem 各目錄的權限。
抖音助手腳本不建議需要互動式桌面 + 可見瀏覽器讓人工通過驗證／登入，無頭服務帳號無法操作；若部署於本機桌面環境，可由系統自動呼叫。

IIS／服務帳號部署：工具若裝在安裝使用者的 Home 目錄，應用程式集區身分會讀不到。請改用可攜安裝把工具集中到 C:\KMEngineTools 並授權集區身分，完整步驟見 IIS 佈署與可攜工具設定。

抖音為半自動、僅限本機桌面：建議用法是在「影音轉逐字稿」頁貼上抖音連結，由系統自動呼叫助手腳本下載音訊與原始影片；若助手需要驗證，使用者需在跳出的瀏覽器中完成。若部署環境無互動式桌面，則改用命令列於有桌面的機器執行助手產出 mp3，再以「檔案上傳」匯入系統。

9.2 抖音助手的狀態與輸出位置

項目路徑（預設，可於腳本參數調整）是否機密／進版控
登入設定檔（持久 Chromium profile）C:\KMEngineTools\cookies\pw-douyin-profile含登入 session，屬機密，勿進版控
產出 mp3C:\temp\KnowledgeExtraction\DouyinAudio否（轉錄完可刪）
  • 這些路徑皆在 repo 之外（登入設定檔於 C:\KMEngineTools\cookies、mp3 於 C:\temp），不會誤入版控。
  • 抖音登入會過期、平台也可能改版；屆時重跑助手、於視窗內重新登入即可（設定檔會更新）。
  • @playwright/cli 互動模式會在當前工作目錄產生 .playwright-cli\ 快照／日誌夾；本 repo 已於 .gitignore 排除，但若在他處執行請自行清理。

9.3 版本相依注意

  • yt-dlp 對小紅書等平台的支援會隨平台改版而變動，建議定期 python -m pip install --upgrade yt-dlp（或 --pre nightly）。抖音助手所用的 yt-dlp/瀏覽器同理需偶爾更新。
  • @playwright/cli 內建的 playwright-core 期望特定版號的 Chromium；升級後若報「Executable doesn't exist at chromium-<新版號>」，執行 npx playwright install chromium 補下載即可（助手腳本會自動挑最新已安裝版）。
