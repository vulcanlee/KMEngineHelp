部署與維運

日誌與設定檔說明

文件目的

整理本專案使用 NLog 寫入日誌的方式、不同層級的使用時機，以及 appsettings.json 各區段的完整說明。

1. 日誌方案：NLog

採 NLog.Web.AspNetCore 6.1.2，於 src/KnowledgeExtraction/KnowledgeExtraction.Web/Program.cs 的 NLog 設定區塊完成設定：

  1. 從 appsettings.json 讀取 NLog.BasePath（預設 C:\temp\Logs）。
  2. 在 BasePath/KnowledgeExtraction.Web/ 下建立日誌目錄。
  3. 設定 NLog Internal Logger 寫入 KnowledgeExtraction.Web-nlog-internal.log。
  4. 將 BasePath 與 LogFilenamePrefix 變數寫入 NLog 設定，供 nlog.config 內 ${var:BasePath} 引用。
  5. builder.Logging.ClearProviders() 清除預設 Provider，由 builder.Host.UseNLog() 接管。

nlog.config 位於 KnowledgeExtraction.Web/ 根目錄，定義具體 Target / Rule。

/system-health 人工巡檢頁會依 NLog.BasePath 與專案命名空間定位今日日誌檔，並在頁尾顯示最後 100 筆原始日誌。此頁僅限管理員使用，但日誌本身仍不應寫入密碼、token 或完整連線字串。

2. 何時使用何種等級

等級使用時機範例
Trace細節最高的逐步追蹤；通常不啟用。內部演算法每一步狀態。
Debug流程關鍵節點、輸入參數、查詢條件。logger.LogDebug("Received task search request. Keyword={Keyword}", request.Keyword);
Information商業流程成功完成、啟動 / 關閉、Seed 完成。logger.LogInformation("Application startup completed.");
Warning找不到資源、業務驗證未通過、可恢復例外。logger.LogWarning("Task get request could not find record. TaskId={TaskId}", id);
Error例外、外部資源失敗、重要流程中斷。logger.LogError(ex, "Failed to search tasks");
Critical系統幾乎無法繼續運作。DB 連線完全失敗、執行階段崩潰。

撰寫原則：

  • 訊息以英文 + 結構化參數（{Name} 佔位）為主，方便日後檢索。
  • 使用者面向訊息（中文）保留在 ApiResult.Message / Notification，不要混入日誌訊息。
  • 例外請使用 logger.LogError(ex, "...") 寫入完整堆疊。
  • 外部整合（OpenAI Whisper/Chat、ffmpeg、yt-dlp、抖音助手、MarkItDown）一律「開始→成功→失敗」三點式，失敗含 ExitCode／StatusCode／StdErr 或回應前 ~500 字；catch 不得靜默，即使吞例外不中斷也要留一筆 Warning/Debug 與原因。
  • 不記 ApiKey／密碼／token，也不記請求/回應內容本文。

2.1 如何臨時開啟 Debug / Trace 詳細日誌（診斷用）

預設等級＝info，由 nlog.config 這一行決定（唯一有效開關；MEL 端 Logging:LogLevel:Default 已設 Trace 放行、把實際等級交給它）：

<logger name="*" ruleName="AppCatchAll" minlevel="info" writeTo="file_async,console_async" />

外部工具參數、各管線步驟、CRUD 進入點等屬 Debug，平時不輸出。需要更細軌跡時，用以下任一種臨時調高，皆免重啟，診斷完切回 Information：

  • (A) 管理員畫面（最方便）：登入管理員 → 側選單「系統管理 → 日誌等級切換」(/log-settings) → 下拉選 Debug／Trace → 套用，立即生效。此為執行期暫時覆蓋；nlog.config 存檔（autoReload）或應用重啟後，會回到檔案預設（info）。
  • (B) 改設定檔（永久預設）：把上面那行的 minlevel 改成 Debug／Trace 存檔——因 autoReload="true"，存檔即生效免重啟；改回 info 即恢復。這會改變「預設」等級（重啟後仍是這個）。
  • 縮小噪音（可選）：若某命名空間太吵，可在 appsettings 用 MEL 把它單獨壓低（MEL 會在進 NLog 前先過濾），例如 "Microsoft.EntityFrameworkCore": "Warning"。
  • 取檔：日誌在 NLog.BasePath 下 KnowledgeExtraction.Web/KnowledgeExtraction.Web-logfile-{日期}.log；管理員亦可用 /system-health 看最後 100 筆。把該檔（已遮去敏感資訊）提供給 AI 即可分析故障點。

2.2 執行環境情境與例外快照（自 0.3.23）

每筆日誌除既有 TraceId（${aspnet-TraceIdentifier}）外，新增三個情境欄位：user=（登入者帳號）、op=（操作名稱）、id=（紀錄 Id）——來自 ILogger.BeginScope（KnowledgeExtraction.Share.Helpers.LogScope）。

  • 請求層：UseHttpRequestLogging 自動把 user＋op=HTTP 附到該請求內所有下游日誌。
  • 背景管線：轉錄/文件/圖片/清洗/蒸餾/索引各服務處理單筆時帶 op=<管線>＋id=<紀錄Id>（含其 Processor/Enhancer 的日誌）。
  • 啟動摘要：啟動時記一行 Information「執行環境摘要。OS=… Framework=… Machine=… Env=… SystemVersion=… DatabaseProvider=… GenerationProvider=…」（RuntimeEnvironmentInfo.StartupSummary），可核對執行環境是否符合預期。
  • 例外快照：未處理例外（API ApiExceptionFilterAttribute、MVC /Error、Blazor LoggingErrorBoundary）除完整堆疊外，另附 RuntimeEnvironmentInfo.Snapshot()（機器/程序/工作集/GC 記憶體/執行緒數），定位當時運作狀態。
  • 情境欄位只放非機敏資訊（帳號/團隊名/操作/Id），仍不記金鑰/密碼/token/請求本文。
  • 新程式碼慣例：對一段有明確「操作＋對象」的流程，於進入點 using var _ = logger.BeginScope(LogScope.Of("Operation", ("RecordId", id)));；空 catch {} 會被 LoggingConventionTests 擋下。

2.3 依時間區間下載日誌（/log-download，自 1.0.12）

管理員可於側選單「系統管理 → 日誌下載」(/log-download) 選定起訖時間（含時分），下載該區間內的應用日誌。

  • 範圍：僅 NLog 應用程式紀錄檔（{NLog.BasePath}/KnowledgeExtraction.Web/KnowledgeExtraction.Web-logfile-*.log，含每日檔與同日 sequence 封存檔）；不含聊天紀錄等其他檔案。
  • 過濾：以每筆日誌開頭的 ${longdate} 時間戳逐筆過濾，只保留落在 [起, 訖]（含端點）的 entry。例外堆疊等多行內容會整筆歸屬其起首時間戳，不被截斷或漏取。
  • 輸出：符合的 entry 依時間合併為單一 .log（application-{起}-{訖}.log），封裝成 zip（logs_{起}-{訖}.zip）由瀏覽器下載。區間內無資料時仍下載一個空日誌檔的 zip。
  • 限制：區間上限 31 天；輸出量過大（未壓縮 > 200MB）會回 400 並提示縮小範圍。
  • 權限（伺服器端把關）：下載端點 GET /api/LogArchive/download?from=…&to=… 以 IRecordAccessScopeProvider.GetAsync().IsAdmin 於伺服器端確認管理員身分，非管理員回 403——不僅靠隱藏 UI 按鈕。日誌本身仍不應寫入密碼、token 或完整連線字串。
  • 元件：LogArchiveService（KnowledgeExtraction.Business/Services/DataAccess，純解析/合併/壓縮邏輯，可單元測試）＋ LogArchiveController（KnowledgeExtraction.Web/Controllers）＋ Blazor 頁 Components/Pages/LogDownload + Components/Views/LogDownload。

3. 全域請求日誌

ApplicationBuilderExtensions.UseHttpRequestLogging 註冊一個自訂 middleware（由 Program.cs 的中介軟體管線呼叫）：

  • 對每筆 HTTP 請求記錄 Method、Path、StatusCode、ElapsedMilliseconds。
  • 例外發生時改寫為 Error，並重新拋出讓上層 ExceptionHandler 處理。

由此可在不額外加程式的情況下取得每個 endpoint 的響應耗時。

3.1 OpenAI chat token 用量記錄（自 0.2.93）

每次呼叫 OpenAI Chat Completions（OpenAIChatCompletionClient）成功後，會記錄一行 Information 級的 token 用量，供成本與用量稽核：

OpenAI chat 用量。Operation=Text Model=gpt-5.4 送出(prompt)=1200 接收(completion)=340 合計(total)=1540
  • 送出(prompt)＝送進模型的 token、接收(completion)＝模型產生的 token、合計(total)＝兩者總和。
  • Operation：Text（純文字，如清洗五步驟、逐字稿/文件 LLM 生成）、Image（圖片辨識）、File（PDF 等檔案解讀）。
  • 一次清洗最多會看到 5 行（去重/遮罩/分類/摘要/信心自評各一），夾在 cleaning queued 與 Cleaning completed 兩行之間。
  • 地端或回應未含 usage 時，記「OpenAI chat 用量不可用（回應未含 usage）」。
  • 僅記 token 數字，不記錄請求/回應內容本文，避免敏感內容入日誌。
  • 自 0.2.109 起：所有 chat 呼叫（含串流 Operation=Stream）與語音轉錄皆額外記 完整明細=…，由 TokenUsageFormatter.Format 遞迴攤平 usage 的所有數值欄位（含 prompt_tokens_details.cached_tokens、*.audio_tokens、completion_tokens_details.reasoning_tokens 等任意子欄位，不需事先列舉）；非串流另含 理解(reasoning)=…。轉錄記為「OpenAI 轉錄用量。Model=… File=… 完整明細=…」（gpt-4o-transcribe 有 usage；whisper-1 記「不可用」）。
  • 自 0.3.30 起（持久化）：token 用量除了寫日誌，也持久化到 LlmTokenUsage 資料表（ITokenUsageRecorder → Channel → TokenUsageWriterBackgroundService 批次寫入），並附業務作業（Cleaning/KnowledgeBaseChat…，由 OperationContext 帶入；背景作業經佇列帶入提交者身分）與模型。管理員可於 /token-usage 依使用者/作業/型別/模型/時間區間查詢，首頁儀表板顯示近 30 天各類 token 全站彙總。仍只存數字、不存內容本文。

4.1 Logging

.NET 預設記錄等級。NLog 啟動後會接管實際輸出，但此區段仍影響 Microsoft.* 等內建類別的 Filter。

4.2 NLog.BasePath

NLog 寫檔的根目錄；專案會在其下建立 KnowledgeExtraction.Web 子目錄。若不存在會被 NLog 自動建立。

4.3 Swagger / Security / Cors

欄位用途
Swagger.EnabledInProductionProduction 是否開啟 Swagger UI；Production 必須明確設定。
Security.ReturnExceptionDetails是否在 API 500 回應填入完整 Exception；未設定時 Development 才會回傳。
Cors.AllowedOrigins允許跨來源呼叫的 origin 清單；空陣列代表不開放。

4.3.1 GoogleOAuthSettings

欄位用途
Enabled是否啟用 Google 第三方登入；false 時不註冊 Google 驗證，登入頁也不顯示按鈕。
ClientId / ClientSecretGoogle OAuth 用戶端憑證；正式環境請用 user-secrets / 環境變數，勿進版控。
DefaultRoleName首次以 Google 登入而自動建立的帳號所套用的預設角色名稱。

完整設定步驟與登入流程詳見 Google OAuth2 第三方登入。

4.3.2 CacheSettings

欄位用途
Provider快取提供者，支援 Memory（預設，單機記憶體）與 Redis（分散式）。空字串會回退為 Memory，未知值在啟動時拋出例外。
RedisConnectionProvider=Redis 時的連線字串（如 localhost:6379）；Redis 時不可留空，Production 會被啟動安全檢查阻擋。
InstanceNameRedis 鍵前綴，用於隔離同一 Redis 實例上的多個應用。
DefaultExpirationMinutes未指定過期時間時套用的預設絕對過期（分鐘）。

呼叫端統一透過 ICacheService（Get/Set/GetOrCreateAsync<T>/Remove，內含 JSON 序列化），切換 provider 不需改任何使用端程式。完整說明見 分散式快取機制。

4.3.3 JwtSettings

欄位用途
Issuer / AudienceJWT 發行者與受眾識別。
SigningKeyJWT 簽章金鑰；正式環境必須用環境變數或部署 secret 覆寫。
AccessTokenMinutesAccess Token 有效分鐘數。
RefreshTokenDaysRefresh Token 有效天數。
ClockSkewMinutesToken 驗證允許的時間偏移。

4.3.4 BootstrapSettings

欄位用途
SupportAccount / SupportName / SupportEmail系統啟動種子資料使用的支援帳號基本資訊。
SupportPassword支援帳號初始密碼；正式環境必須用部署 secret 覆寫或在初始化後立即更換。

4.4 SystemSettings.DatabaseProvider

支援 Sqlite 與 SqlServer。開發預設為 Sqlite；正式環境可改為 SqlServer，並搭配部署 secret 提供 DefaultConnection。

4.5 SystemSettings.ConnectionStrings

欄位用途
DefaultConnectionSQL Server 連線字串；DatabaseProvider=SqlServer 時使用。
SQLiteDefaultConnectionSQLite 範本字串；實際連線字串由 MagicObjectHelper.GetSQLiteConnectionString 結合 DatabasePath 動態產生。

4.6 SystemSettings.SystemInformation

欄位用途
SystemName顯示在 UI 上的系統名稱。
SystemDescription顯示用描述。
SystemVersion唯一版本來源，每次更新必須遞增；格式 Major.Minor.Patch (YYYY/MM/DD)。詳見 維護規範。

4.7 SystemSettings.ExternalFileSystem

欄位用途
DatabasePathSQLite 資料庫檔放置目錄。
DownloadPath對應 /UploadFiles 的靜態資源目錄。
UploadPath通用上傳暫存目錄。
ProjectFilePath專案附件根目錄（依年/月分層）。

4.7.1 SystemSettings.Cleaning

欄位用途
ConfidenceThreshold清洗信心自動門檻（0~1，預設 0.70）。清洗完成後，LLM 自評信心 ≥ 此值自動標「已清洗」，否則（或信心無法解析）轉「待審核」交人工審核（QA-2/QA-3）。
CleanedRatioWarnBelow「清洗後 ÷ 彙整前」的低比值警示門檻（預設 0.30）。比值低於此值即視為可疑（剛好等於不算），會在①清洗對話窗顯示警示、②/data-consistency 的「低比值來源」列出。0 或負數＝停用；需重啟生效。<br>用途：清洗後內容應與彙整前同一量級，比值明顯偏低常代表內容曾被模型輸出上限截斷——1.0.112 起截斷會直接失敗或留註記，但該版之前清洗的資料沒有痕跡，只有比值看得出來。<br>⚠️ 會有誤報：內容本來就高度重複的素材（大量制式表單）合理地會有很低的比值。判準取自 分盒指南 §4.2（正常 0.5～1.0），會隨模型與素材密度變動。
AggregateWarnBytes清洗前彙整量的軟警告門檻（位元組，預設 200000，約 6.6 萬中文字）。超過時「確認清洗」對話窗會顯示提示並要求勾選確認才能送出——是提示，不是阻擋；TriggerCleaningAsync 的行為完全不變。0 或負數＝停用警告；剛好等於門檻不算超過。<br>⚠️ 200000 只是保守起點，不是正確答案：真正的天花板是模型的輸出上限（去重與遮罩要把整份內容重新輸出一遍），換模型就會變。請依 知識來源分盒與規模上限指南 §五 的實測逼近法量出自己環境的數字後改這個值。

此門檻與遮罩召回率、分類 F1、摘要涵蓋率等「可接受門檻」已正式鎖定，見 strategy/05 §五 資料清洗品質門檻鎖定。調整後需重啟生效。

AggregateWarnBytes 同樣需重啟生效（服務啟動時讀入）。有一條測試會斷言 appsettings.json 的這個鍵存在且與程式預設值一致，所以改了程式預設就必須同步改設定檔，否則測試紅燈。

欄位用途
ConfidenceThreshold知識頁審核 Wiki 頁信心自動門檻（0~1，預設 0.70）。蒸餾頁信心 ≥ 此值標「已完成」，否則轉「待審核」由具 蒸餾審核 權限者核准或退回。

4.7.3 SystemSettings.Retrieval

欄位用途
ChunkTargetCharsRAG 索引建立時的 chunk 目標字元數，預設 800；調整後需重建索引才會影響既有向量。
ChunkMaxChars單一 chunk 硬上限，預設 1200；必須大於或等於 ChunkTargetChars。調整後需重建索引。

LowConfidenceThreshold信心不足門檻：最高分介於 RejectThreshold 與此值之間時照答但加註提示，預設 0.30。

知識圖譜（Graph RAG）參數（1.0.83～1.0.96） — 融合分數為 VectorWeight × 向量 + KeywordWeight × 關鍵字 + GraphWeight × 圖分：

欄位預設用途可否熱套用
GraphWeight0.2圖鄰域分數在融合式中的權重。設 0 即完全關閉圖檢索路徑（連圖查詢都不會發出），系統回到 1.0.82 之前的行為。✅ /rag-diagnostics 熱套用，下一次檢索生效
GraphMaxHops2圖鄰域擴展跳數，合法範圍 1～3（讀取時夾住）。設 1 即 1.0.89 之前的單跳行為。✅ 同上
GraphHopDecay0.5跳數衰減：第 h 跳強度 ＝ 種子強度 × decay^(h-1)，故第 1 跳不衰減。範圍 [0,1]。✅ 同上
GraphMaxNodes200單次檢索圖遍歷的鄰居頁節點上限（安全閥，防大圖爆炸）。達上限即停止擴展並記 log。❌ 只讀 appsettings，改了要重啟
GraphGlobalCommunityCap20全域問答一次 map 最多取用的社群數。每個社群一次 LLM 呼叫，直接決定成本。❌ 需重啟
GraphMaxCommunities50社群摘要重建保留的社群數上限（每群一次 LLM；超出者取成員數最大的前 N 群並記 log）。❌ 需重啟
GraphAliasNameCap300LLM 別名建議一次送出的實體名上限（超出者取出現次數最多者）。❌ 需重啟

⚠️ 前三項與後四項的行為不同，不要混在一起記：GraphWeight／GraphMaxHops／GraphHopDecay 有資料庫覆寫路徑（RetrievalParamOverride），可在「系統管理 → 診斷與日誌 → 檢索診斷與調校」（/rag-diagnostics）線上調整並即時生效，因此你在 appsettings 看到的值不一定是當前生效值。後四項是成本／安全閥，沒有 DB 覆寫路徑，該頁也刻意不提供調整入口，只能改 appsettings 並重啟。

⚠️ 後四項讀取時以 Math.Max(1, 值) 夾住：填 0 或負數會退回 1，不會靜默停擺。GraphMaxHops／GraphHopDecay 亦於讀取時夾上下界。

⚠️ GraphMaxHops 預設是 2（1.0.90 起多跳生效）。 這會讓 1.0.89 之前建立的檢索評測基線位移（召回變多）。升級後應重跑一次評測建立新基線；要維持舊行為就設 1。

TopK、CandidateTopK、VectorWeight、KeywordWeight、MinScore 由 IRetrievalService 用於AI 知識問答與 檢索品質評測；檢索層會先套團隊權控，再回傳可見 chunk。RejectThreshold、LowConfidenceThreshold 由 KnowledgeBaseChatService 以「最高分命中」判定AI 知識問答的整體信心（兩段式門檻），預設值僅為起點、須以真實資料校準。調整後需重啟生效。

ChunkTargetChars、ChunkMaxChars、ChunkOverlapChars 由 Chunker 在嵌入索引建立時使用。調整後除了重啟服務，也必須重新蒸餾或重建索引，既有 VectorEmbedding 才會套用新的切塊規則。完整設計見 知識庫 RAG 設計與執行。

台灣繁體保底：OpenAI 轉錄 API 的 language 僅接受 ISO-639-1 兩碼（中文僅 zh，不支援 zh-tw），且 language／prompt 僅為軟性偏好。因此語言為中文時，逐字稿會再經 OpenccNetLib（s2twp）簡轉繁，確保輸出為台灣繁體中文。

影片連結來源：新增記錄時來源類型可選「影片連結」，系統以 yt-dlp -x --audio-format mp3 僅抽取音訊後轉錄，無須上傳檔案。可直接貼整段分享文字（系統會自動抽出網址）；平台辨識交給 yt-dlp（YouTube／小紅書等，均不需 cookies）。抖音例外：偵測到抖音網址時系統會自動以 DouyinHelperScript 所指定的 playwright 助手腳本下載（需設定 NodePath 與 DouyinHelperScript）；未設定或逾時則標記失敗可重試。助手仍可獨立於命令列手動執行，詳見外部工具安裝與路徑設定 第 8 節。

雲端／地端 LLM 切換：GenerationProvider=Local 可讓清洗（去重/遮罩/分類/摘要/信心）、逐字稿/文件 LLM 產生、圖片視覺、知識來源對話、AI 知識問答、知識頁審核改走地端 OpenAI 相容伺服器，資料不出企業環境。地端伺服器須提供 POST {LocalBaseUrl}chat/completions（OpenAI 相容）。注意：圖片視覺解讀走同一聊天 client，地端模型須支援視覺才可用；語音轉錄不在切換範圍（永遠雲端）。

地端範例（Ollama）：

"OpenAISettings": {
  "GenerationProvider": "Local",
  "LocalBaseUrl": "http://localhost:11434/v1/",
  "LocalGenerationModel": "llama3.1",
  "LocalApiKey": "",
  "LocalGenerationTimeoutSeconds": 300
}

未設定聊天/生成 LLM（雲端 ApiKey 空，或地端 LocalBaseUrl／LocalGenerationModel 缺）時，清洗會略過 LLM 增強，僅輸出彙整＋繁體正規化並加註記；其他需要 LLM 的生成/對話/蒸餾功能會顯示設定不足或處理失敗。

嵌入模型切換：EmbeddingProvider 留空時沿用 GenerationProvider；明確設為 Cloud 或 Local 可獨立切換。是否可用由 OpenAISettings.IsEmbeddingConfigured() 判斷：雲端需 ApiKey，地端需 LocalBaseUrl + LocalEmbeddingModel。換模型或維度後需重新建立所有 VectorEmbedding 索引。

註冊位置：OpenAISettings 綁定於 ServiceCollectionExtensions.AddConfiguredOptions，HttpClient 與背景工作於 Program.cs 的 AddHttpClient<OpenAITranscriptionClient> 與 AddHostedService<TranscriptionBackgroundService>。聊天 client AddHttpClient<OpenAIChatCompletionClient> 的 BaseAddress/逾時取自 OpenAISettings.ResolveChatLlm()（依 GenerationProvider）。

依提示詞透過 LLM 產生內容：影音轉逐字稿與文件轉文字頁對「已完成」紀錄提供「依提示詞產生」功能，將使用者選取／調整後的提示詞與內容送往 GenerationModel 指定的 Chat Completions 模型，結果寫入 ExternalFileSystem.GeneratedContentPath 下的年度檔案並回填相對路徑（只保留最新一筆）。對應元件：OpenAIChatCompletionClient（AddHttpClient<OpenAIChatCompletionClient>，逾時取 GenerationTimeoutSeconds）、LlmGenerationService 與 DocumentLlmGenerationService。AI 提示詞由「基礎資料設定 > AI 提示詞」維護。

4.8.1 LlmPrompts（LLM 提示詞平台預設層，自 0.2.110）

LLM 提示詞的「平台預設層」，介於 DB 覆蓋與程式 fallback 之間。每個屬性對應一個槽位鍵；值留空＝沿用程式內建預設（LlmPromptDefaults），不要把預設文字抄一份進來以免分歧（drift）。

四層覆蓋優先序（高→低）：單次操作覆蓋（對話頁輸入／清洗規則設定）→ DB Prompt(同名鍵，於「AI 提示詞」/prompts 線上編輯、免重啟）→ 本區段 LlmPrompts（改值需重啟）→ 程式 fallback LlmPromptDefaults。任一層非空白即採用、否則往下退；LlmPromptResolver 以 Debug 記錄本次採用層級。

屬性／槽位鍵（沿用 LlmPromptKeys）：CleaningDedupe（清洗-去重）、CleaningMask（清洗-遮罩）、CleaningClassify（清洗-分類）、CleaningSummary（清洗-摘要）、CleaningConfidence（清洗-信心）、ChatSystem（對話-系統）、ChatConcise/ChatStandard/ChatDetailed（對話 詳簡三段）、KnowledgeBaseSystem（知識庫-系統）、KnowledgeBaseQueryRewrite（知識庫-查詢改寫）、DistillationGenerate（蒸餾-生成）、GraphTripleExtract（圖譜-三元組抽取）、GraphCommunitySummary（圖譜-社群摘要）、GraphGlobalMap（圖譜-全域map）、GraphGlobalReduce（圖譜-全域reduce）、EntityAliasPropose（圖譜-別名建議）、MeetingMinutes（會議-紀錄生成）、DocumentPdfToMarkdown（文件-PDF轉Markdown）。轉錄提示詞不在此，沿用 OpenAISettings.Prompt，另由 DB「轉錄-提示」覆蓋。

"LlmPrompts": {
  "CleaningDedupe": "", "CleaningMask": "", "CleaningClassify": "",
  "CleaningSummary": "", "CleaningConfidence": "",
  "ChatSystem": "", "ChatConcise": "", "ChatStandard": "", "ChatDetailed": "",
  "KnowledgeBaseSystem": "",
  "KnowledgeBaseQueryRewrite": "",
  "DistillationGenerate": "",
  "GraphTripleExtract": "",
  "GraphCommunitySummary": "",
  "GraphGlobalMap": "",
  "GraphGlobalReduce": "",
  "EntityAliasPropose": "",
  "MeetingMinutes": "",
  "DocumentPdfToMarkdown": ""
}

槽位鍵 MeetingMinutes（DB 對應名稱「會議-紀錄生成」）供上傳會議錄音後產生會議紀錄時使用；DocumentPdfToMarkdown（DB 對應名稱「文件-PDF轉Markdown」）供 PDF 走大語言模型萃取時使用，見 §4.8.2。

五個 Graph*／EntityAliasPropose 槽位鍵（1.0.84～1.0.88）供知識圖譜使用：三元組抽取、社群摘要、全域問答的 map 與 reduce、LLM 別名建議。⚠️ 它們在 DB /prompts 的對應名稱是中文的 圖譜-*（如 圖譜-三元組抽取），不是這裡的英文屬性名——填英文名不會命中（DB 比對是精確相等）。目前共 20 個槽位鍵，完整對照見 LLM 提示詞與用量透明化 §10.1。

註冊位置：LlmPromptsSettings 綁定於 ServiceCollectionExtensions.AddConfiguredOptions；解析器 LlmPromptResolver 為 Scoped。完整說明（槽位鍵對照、操作方式、衝突解析、預設全文）見 LLM 提示詞與用量透明化 §10／§3。

4.8.2 MarkItDownSettings

下表的「預設」指程式內建預設值（MarkItDownSettings.cs 的屬性初始值）。倉庫的 appsettings.json 已覆寫其中數項（工具絕對路徑、PdfUseLlm、PdfLlmModel），實際生效值以 §4 的快照為準。

欄位用途
MarkItDownPathMarkItDown 命令列工具執行檔路徑；預設 markitdown（走 PATH）。文件轉文字背景管線會以此工具將 PDF、Office、文字、HTML、圖片等支援格式轉為 Markdown。
TimeoutSecondsMarkItDown 轉檔逾時秒數，預設 600。逾時或外部行程非 0 結束會將該筆文件轉文字標記為失敗並留下錯誤訊息。
PdfUseLlm上傳檔案為 PDF 時，是否改呼叫大語言模型 API 轉 Markdown（而非用 MarkItDown）。預設 false＝一律走 MarkItDown。
PdfLlmModelPDF 轉換使用的模型名稱；留空＝沿用 OpenAISettings.ResolveChatLlm() 解析出的聊天模型（雲端為 GenerationModel、地端為 LocalGenerationModel）。
PdfLlmTimeoutSecondsPDF 轉換請求逾時秒數，預設 600；0＝沿用聊天模型的逾時。此逾時套在專屬的 PdfMarkdownLlmClient HttpClient 上，不影響對話、清洗等其他 LLM 功能。

安裝與路徑設定見 外部工具安裝與路徑設定。

PDF 走大語言模型萃取（自 1.0.54）

MarkItDown 對 PDF 只做純文字抽取，圖片與圖表會遺失、複雜表格常被壓成無結構文字。開啟 PdfUseLlm 後，PDF 會改以 base64 file 內容送 OpenAI Chat Completions，請模型輸出完整 Markdown（含表格語法，圖片則以 > **[圖片]** 描述段落表達）。

  • 提示詞走 §4.8.1 的解析鏈，槽位鍵為 DocumentPdfToMarkdown /「文件-PDF轉Markdown」，可於「AI 提示詞」/prompts 線上調整、免重啟。

⚠️ 這條路徑實際只有 3 層：DB /prompts > appsettings LlmPrompts > 程式內建 fallback。四層裡的第 1 層「單次操作覆蓋」在 PDF 自動萃取硬傳 null（DocumentExtractionProcessor 呼叫 ResolveAsync 時第 2 引數為 null）——那是背景管線、沒有使用者互動點，所以沒有覆蓋入口。 ⚠️ 在 /prompts 覆蓋時名稱必須逐字完全一致（文件-PDF轉Markdown，含連字號與 Markdown 大小寫，不可多空白）。DB 比對是精確的（x.Name == name），打錯不會有任何錯誤或日誌，只會安靜退回內建預設。1.0.77 起 /prompts 的名稱欄會即時顯示「✅ 對應系統槽位」或「ℹ️ 這是自訂提示詞」並列出可點擊填入的槽位清單，避免這個坑。

  • 失敗自動降級：LLM 只嘗試一次（金鑰未設定、API 錯誤、逾時、模型不支援 file 輸入皆同），失敗即自動改用 MarkItDown 完成轉換。該筆紀錄狀態仍為「已完成」，並在訊息欄留下「AI 解析 PDF 失敗，已自動改用 MarkItDown 轉換：…」。
  • 輸出被截斷也算失敗（1.0.77 起）：回應 choices[0].finish_reason == "length" 代表 PDF 太長、模型輸出撞到上限，Markdown 不完整。此時不採用該結果、走上述降級路徑。先前這種情況會被當成成功——殘缺的 Markdown 直接落檔、狀態「已完成」、無任何提示，之後整條 RAG（切塊／嵌入／問答）都建立在殘缺內容上。

請求刻意不帶 max_tokens（模型預設上限通常大於我們能合理硬設的值，硬設反而更早截斷）；目標是「截斷要被發現」而非「提高上限」。

  • 不設檔案大小上限，超限由 OpenAI API 回報錯誤後走降級路徑。
  • Token 用量記為 Operation=DocumentExtraction、CallType=File，可於 /token-usage 與 Token 用量報表查閱。

5. 環境差異設定

appsettings.Development.json 僅覆寫 Logging：

{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}

未來可在 appsettings.Production.json 內切換 SystemSettings（例如連線字串、外部目錄）以符合不同部署環境。

6. 以環境變數 / User Secrets 覆寫敏感設定（OpenAI 金鑰等）

本專案使用 WebApplication.CreateBuilder(args)（Program.cs），其預設設定來源已包含環境變數 provider，且優先序高於 appsettings.json。因此 OpenAISettings.ApiKey、JWT SigningKey、Google ClientSecret 等機密不應寫入 appsettings.json，而以環境變數或 User Secrets 提供。

6.1 設定來源優先序（後者覆蓋前者）

appsettings.json
→ appsettings.{Environment}.json
→ User Secrets（僅 Development 環境）
→ 環境變數
→ 命令列參數

6.2 階層鍵 → 環境變數命名

設定鍵的冒號 : 在環境變數需改寫為雙底線 __：

設定鍵環境變數名稱
OpenAISettings:ApiKeyOpenAISettings__ApiKey
OpenAISettings:FfmpegPathOpenAISettings__FfmpegPath
OpenAISettings:YtDlpPathOpenAISettings__YtDlpPath
JwtSettings:SigningKeyJwtSettings__SigningKey

appsettings.json 內對應欄位留空即可，由環境變數覆寫。

6.3 Windows 設定方式（擇一）

A. 目前 PowerShell 工作階段（測試用，關閉視窗即失效；須在同一階段啟動 App）

$env:OpenAISettings__ApiKey = "sk-你的金鑰"
dotnet run --project src/KnowledgeExtraction/KnowledgeExtraction.Web

B. 永久寫入使用者環境變數（需重新開啟終端機/IDE 才生效）

setx OpenAISettings__ApiKey "sk-你的金鑰"

C. 開發階段建議：User Secrets（金鑰存於專案外、不進版控；使用冒號 : 而非 __）

cd src/KnowledgeExtraction/KnowledgeExtraction.Web
dotnet user-secrets init        # 若 csproj 尚無 UserSecretsId 才需要
dotnet user-secrets set "OpenAISettings:ApiKey" "sk-你的金鑰"

D. IDE 偵錯（Properties/launchSettings.json，僅供本機開發，勿放正式金鑰）

"environmentVariables": {
  "OpenAISettings__ApiKey": "sk-你的金鑰"
}

6.4 部署環境

正式環境建議透過部署平台的機密管理提供：IIS 應用程式集區環境變數、Windows 服務環境變數、容器 -e OpenAISettings__ApiKey=... 等。

6.5 驗證

啟動後於「影音轉逐字稿」頁上傳音檔；若金鑰未被讀到，OpenAITranscriptionClient 會丟出中文例外「尚未設定 OpenAISettings:ApiKey。」並把該筆轉錄標記為「失敗」。不再出現此訊息即代表覆寫成功。同理，FfmpegPath 亦可用 OpenAISettings__FfmpegPath 指向本機已安裝的 FFmpeg，而不必寫死在版控的 appsettings.json。
