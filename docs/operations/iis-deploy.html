部署與維運

IIS 佈署與可攜工具設定（C:\KMEngineTools）

文件目的

系統的「影音轉逐字稿」與「文件轉文字」會以 System.Diagnostics.Process 呼叫本機外部工具（ffmpeg / yt-dlp / markitdown，以及抖音鏈的 Node.js / Chromium）。

以 scripts/Install-ExternalTools.ps1（winget / pip / npm）安裝時，工具會落在安裝使用者的 Home 目錄下：

  • ffmpeg：%LOCALAPPDATA%\Microsoft\WinGet\Links
  • yt-dlp / markitdown：%LOCALAPPDATA%\Python\...\Scripts
  • @playwright/cli：%APPDATA%\npm
  • Chromium：%LOCALAPPDATA%\ms-playwright

在 IIS 下，Web 以應用程式集區身分（ApplicationPoolIdentity／服務帳號）執行，無法存取安裝使用者 Home 目錄 → 這些工具在使用時會找不到而失敗。

本文件說明另一條路徑：以 scripts/Install-PortableTools.ps1 把工具的可攜版直接下載到固定目錄 C:\KMEngineTools，授權給 IIS 身分，再以絕對路徑填入 appsettings.json。C# 端本就從設定讀路徑、無硬編碼（見 外部工具安裝與路徑設定 §2），故只要路徑對、集區可讀即可運作。

一般（開發機、以互動帳號執行）仍可用 Install-ExternalTools.ps1；本文件專供 IIS／服務帳號 或需要固定可攜目錄的情境。

1. 前置需求（注意事項）

項目需求說明
執行權限系統管理員ACL 授權（icacls）與 Machine 範圍環境變數需要提權；未提權腳本會直接中止。
PowerShell建議 7+5.1 亦可執行，但繁中輸出建議 7+：winget install --id Microsoft.PowerShell -e。
網路需可連外下載來源：ffmpeg=github.com/BtbN（GitHub CDN）、yt-dlp=github.com、Node=nodejs.org、Python=python.org。
winget不需要可攜版直接下載，這是相對 Install-ExternalTools.ps1 的優點。

1.1 要由腳本安裝的 runtime

只有兩個 runtime 由腳本裝可攜版到 C:\KMEngineTools：

runtime為何需要落點
Node.js（zip 可攜版）執行抖音助手 get-douyin-audio.mjsC:\KMEngineTools\node\node.exe
Python 3執行 markitdownC:\KMEngineTools\python\python.exe
  • ffmpeg / yt-dlp 為獨立執行檔，無 runtime 相依（yt-dlp 用免 Python 的獨立 exe）。
  • markitdown 就地安裝到 C:\KMEngineTools\python，不搬移——pip 產生的 .exe 包裝器會內嵌 python 絕對路徑，搬移會失效，故一律就地安裝。

1.2 另需手動處理的前置

  • App 執行環境：IIS 主機需安裝 .NET 10 ASP.NET Core Hosting Bundle（非本腳本範圍），見 全新機器部署 SOP §1。
  • markitdown 相依：markitdown[all] 相依較多，Windows 多有預編譯 wheel 免編譯；極少數套件無 wheel 時需 Microsoft C++ Build Tools，屆時安裝後重跑腳本即可。

2. 目錄佈局

C:\KMEngineTools\
  ffmpeg\bin\ffmpeg.exe               ← FfmpegPath
  yt-dlp\yt-dlp.exe                   ← YtDlpPath（免 Python 獨立 exe）
  node\node.exe                       ← NodePath（抖音鏈）
  python\python.exe
  python\Scripts\markitdown.exe       ← MarkItDownPath
  npm\node_modules\@playwright\cli\node_modules\playwright-core   ← KMENGINE_PLAYWRIGHT_CORE
  ms-playwright\chromium-<版號>\...    ← PLAYWRIGHT_BROWSERS_PATH
  cookies\cookies.txt                 ← （選用）YtDlpCookiesFile

3. 安裝與驗證

# 以系統管理員開啟 PowerShell 7
# 1) 安裝可攜工具到 C:\KMEngineTools（僅核心可加 -SkipDouyin）
pwsh -File scripts/Install-PortableTools.ps1 -InstallDir C:\KMEngineTools

# 2) 驗證工具可運作、且 IIS 身分具讀取/執行權
pwsh -File scripts/Test-PortableTools.ps1 -InstallDir C:\KMEngineTools -AppSettingsPath "C:\apps\KnowledgeExtraction\appsettings.json" -AppPoolName <你的集區名>

Install-PortableTools.ps1 參數：

參數預設用途
-InstallDirC:\KMEngineTools安裝根目錄
-SkipDouyin關略過抖音鏈（Node / @playwright/cli / Chromium）
-Force關即使已存在仍重裝（否則略過已存在者，可重複執行）
-SkipIisAcl關略過對 InstallDir 的 ACL 授權
-IisIdentityIIS_IUSRS要授權的身分；亦可 'IIS AppPool\<集區名>'
-PythonVersion3.12.10Python 版本
-NodeVersion自動最新 LTS指定 Node 版本

安裝腳本不會自動修改 appsettings.json，結尾會印出可貼上的片段。

4. ACL 授權

安裝腳本預設已授權 IIS_IUSRS。若要鎖到特定集區身分（最小權限）：

icacls "C:\KMEngineTools" /grant "IIS AppPool\<集區名>:(OI)(CI)(RX)" /T
  • (OI)(CI) = 套用到子資料夾與檔案；(RX) = 讀取+執行。
  • Test-PortableTools.ps1 -AppPoolName <集區名> 會檢查此授權是否存在。

5. appsettings.json 設定

把安裝／驗證腳本印出的絕對路徑填入（反斜線需寫 \\）：

{
  "OpenAISettings": {
    "FfmpegPath": "C:\\KMEngineTools\\ffmpeg\\bin\\ffmpeg.exe",
    "YtDlpPath": "C:\\KMEngineTools\\yt-dlp\\yt-dlp.exe",
    "NodePath": "C:\\KMEngineTools\\node\\node.exe",
    "DouyinHelperScript": "C:\\...\\tools\\douyin-audio\\get-douyin-audio.mjs",
    "YtDlpCookiesFile": "",
    "YtDlpCookiesFromBrowser": ""
  },
  "MarkItDownSettings": {
    "MarkItDownPath": "C:\\KMEngineTools\\python\\Scripts\\markitdown.exe"
  }
}

亦可改用環境變數覆寫（雙底線階層鍵，Machine 範圍讓 IIS 看得到）：OpenAISettings__FfmpegPath 等。

IIS 下務必填絕對路徑、不要依賴 PATH：應用程式集區的 PATH 與登入使用者不同，留空退回 PATH 多半找不到工具。

5.1 在 IIS 設定環境變數（機密一律走這裡）

正式環境的機密（JWT 簽章金鑰、support 密碼、OpenAI 金鑰、連線字串）不要寫進 appsettings.json——那份檔案在版控裡。IIS 上最可靠的做法是寫在站台目錄的 web.config：

<aspNetCore processPath="dotnet" arguments=".\KnowledgeExtraction.Web.dll"
            stdoutLogEnabled="false" stdoutLogFile=".\logs\stdout"
            hostingModel="inprocess">
  <environmentVariables>
    <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
    <environmentVariable name="JwtSettings__SigningKey" value="<32 字元以上亂數>" />
    <environmentVariable name="BootstrapSettings__SupportPassword" value="<強密碼>" />
    <environmentVariable name="OpenAISettings__ApiKey" value="<OpenAI 金鑰>" />
  </environmentVariables>
</aspNetCore>
  • 階層鍵用雙底線 __，不能寫成 :。
  • 存檔即生效：ASP.NET Core Module 會自動回收應用程式集區，不需重建、不需重部署。
  • <environmentVariables> 必須放在 <aspNetCore> 元素內。

與 setx /M 的差異（這是常見踩雷點）

做法生效方式適用
web.config 的 <environmentVariables>存檔即回收生效IIS 建議優先用這個；設定隨站台走，換機部署好複製
setx NAME "值" /M（Machine 範圍）需重啟 IIS／WAS 服務（有時要重開機）工作處理序才讀得到多站台共用、或不想把值放在站台目錄時

只設 setx /M 卻沒重啟 IIS，是「明明設了卻沒生效」最常見的原因。

權衡：web.config 內的機密會隨站台目錄被備份／複製，請確保該目錄的 ACL 只開給必要帳號。若要更嚴格，改用 Machine 環境變數或密碼保管服務，代價是需要重啟 IIS。

產生強金鑰與強密碼

# 48 字元十六進位金鑰（遠超過 32 字元下限）
-join ((1..48) | ForEach-Object { '0123456789abcdef'[(Get-Random -Maximum 16)] })

# 20 字元強密碼
$c = 'ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz23456789!@#$%^&*'
-join ((1..20) | ForEach-Object { $c[(Get-Random -Maximum $c.Length)] })

support 帳號密碼每次啟動都會依設定值重設，所以改了這裡就等於改了 support 的登入密碼。

6. 應用程式集區設定注意

  • 載入使用者設定檔：進階設定 setProfileEnvironment / 「載入使用者設定檔（Load User Profile）」建議設為 True，讓工具有 %TEMP% 等可用。
  • 媒體/暫存目錄寫入權：App 會寫 C:\temp\KnowledgeExtraction（媒體下載、轉錄輸出、抖音產出與登入設定檔）與 NLog:BasePath；集區身分需對這些路徑有寫入權（ExternalFileSystem:* 詳見 全新機器部署 SOP §7）。
  • 環境變數生效：安裝腳本以 Machine 範圍寫入 PLAYWRIGHT_BROWSERS_PATH、KMENGINE_PLAYWRIGHT_CORE；需重啟應用程式集區或主機服務身分才會讀到。

7. 抖音鏈在 IIS 的限制（重要）

抖音助手 get-douyin-audio.mjs 以 headless: false 開啟可見瀏覽器、需人工登入／通過驗證，並使用持久登入設定檔。IIS 應用程式集區身分無互動桌面，無法真正跑起來。

  • 把抖音鏈裝進 C:\KMEngineTools 只是讓路徑可攜（解除舊版 .mjs 內硬編碼的使用者路徑；改讀 KMENGINE_PLAYWRIGHT_CORE 與 PLAYWRIGHT_BROWSERS_PATH）。
  • 實際抖音下載須於互動桌面工作階段執行：於有桌面的機器（或該機的互動登入 session）跑 node tools/douyin-audio/get-douyin-audio.mjs "<連結>" 產出 mp3，再以「檔案上傳」匯入系統。
  • 若佈署主機無桌面，建議 IIS 的 DouyinHelperScript 可留空——App 會以清楚訊息略過抖音下載，不影響其他功能。

8. yt-dlp cookies 在 IIS 的注意事項

設定對應 yt-dlp 參數IIS 適用性
YtDlpCookiesFile--cookies "<檔>"✅ IIS 請用此法，指向可攜目錄下的 cookies.txt（如 C:\KMEngineTools\cookies\cookies.txt）
YtDlpCookiesFromBrowser--cookies-from-browser <瀏覽器>❌ 不適用：服務身分無瀏覽器設定檔、讀不到互動使用者 Home 的 cookie DB
  • 兩者皆設時 YtDlpCookiesFile 優先；皆空白則不帶 cookies。
  • 公開 YouTube 多半免填；抖音/小紅書、年齡或會員限制才需要（抖音走助手腳本、cookies 對其無效）。
  • 安全性：cookies.txt 含登入 session 憑證 → 限制 ACL、勿進版控、定期更新。

9. 疑難排解

症狀可能原因處理
HTTP 500.30 — ASP.NET Core app failed to start應用程式在啟動階段就結束。常見：JwtSettings:SigningKey 留空或短於 32 字元（選項驗證）、資料庫連線失敗、日誌／檔案目錄無寫入權先看 Windows 事件檢視器 → Windows 記錄 → 應用程式，訊息含例外型別與堆疊。原因對照表與處置見 全新機器部署 SOP §6.4
500.30 但事件紀錄看不出原因未開 stdout 記錄把 web.config 的 stdoutLogEnabled 改為 true、確認 .\logs 目錄存在且集區身分可寫，重現一次後看 logs\stdout_*.log；查完記得關掉（會持續長大）
腳本一開始就中止「需系統管理員」未提權以系統管理員重開 PowerShell
Test-PortableTools.ps1 報 IIS ACL 未找到未授權集區身分依 §4 執行 icacls
App 內轉錄/萃取找不到工具appsettings 未填絕對路徑或集區無讀取權§5 填絕對路徑、§4 授權、重啟集區
markitdown pip 安裝失敗（編譯錯誤）個別套件無 wheel裝 Microsoft C++ Build Tools 後重跑
抖音在 IIS 無反應服務身分無互動桌面（預期限制）見 §7，改於桌面工作階段執行
健康度檢查頁 yt-dlp/markitdown 偶發紅色「版本：無法取得」可攜版 yt-dlp(PyInstaller)/markitdown(Python) 首次冷啟需自解、匯入約數秒，並發探測下超過舊逾時探測逾時已放寬至 15s（1.0.29）；仍偶發可重整頁面（暖啟後即正常）
健康度檢查頁 Node.js 顯示黃色降級舊版硬性期待 v22.x，但安裝抓最新 LTS（如 v24）已放寬為接受 v20+ LTS（1.0.29）；v24 免重裝即轉綠
