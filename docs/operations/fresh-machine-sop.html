部署與維運

全新機器部署 SOP

文件目的

提供一份可照著操作的步驟手冊：在一台全新的 Windows 電腦上，把「智庫引擎」從零安裝到可正常使用。涵蓋執行環境、外部工具、資料庫、appsettings.json 參數與機密設定、啟動、首次登入與功能驗證。

與其他文件的關係（本文件串起流程並交叉引用，細節不重複）：

  • 外部工具安裝細節 → 外部工具安裝與路徑設定
  • IIS／服務帳號的可攜工具安裝 → IIS 佈署與可攜工具設定
  • 各設定項完整說明 → 日誌與設定檔說明
  • 上線前安全稽核 → 正式部署與安全檢查清單
  • 改用 SQL Server → SQL Server 切換說明
  • Google 登入 → Google OAuth2 第三方登入

1. 安裝 .NET 10 執行環境

所有專案目標框架為 net10.0。

  • 僅執行已發布產物：安裝 ASP.NET Core Runtime 10.0（Hosting Bundle，若走 IIS）。
  • 要在本機建置／發布：安裝 .NET SDK 10.0。
winget install --id Microsoft.DotNet.SDK.10 -e        # 開發/建置
# 或僅執行：winget install --id Microsoft.DotNet.AspNetCore.10 -e
dotnet --info                                          # 確認 10.0 已安裝

PowerShell 7+（選配，建議）：程式本身執行不需要 PowerShell，但本專案附的便利／檢測腳本（如 scripts/Test-ExternalTools.ps1、scripts/Install-ExternalTools.ps1）建議以 PowerShell 7 以上執行。Windows 內建為 5.1，建議另裝：winget install --id Microsoft.PowerShell -e，並以 pwsh --version 確認為 7.x。

一鍵檢測：安裝完成後可執行 pwsh -File scripts/Test-ExternalTools.ps1 一次檢查 .NET 10 執行時、PowerShell 版本、ffmpeg/yt-dlp/markitdown 及抖音鏈（Node/npm/playwright）；缺少 .NET 10 執行時會以阻斷狀態（結束碼 1）提示先行安裝。

2. 取得程式

擇一：

  • A. 由原始碼建置（需 SDK）：
  git clone https://github.com/vulcanlee/KnowledgeExtraction.AI.git C:\Vulcan\Github\KnowledgeExtraction.AI
  • B. 發布產物部署（建議正式環境）：在有 SDK 的機器執行
  dotnet publish src/KnowledgeExtraction/KnowledgeExtraction.Web -c Release -o C:\apps\KnowledgeExtraction

將 C:\apps\KnowledgeExtraction 複製到目標機器。

3. 安裝外部工具（依步驟 0 的功能決策）

完整安裝指令與「如何查出工具絕對路徑」見 外部工具安裝與路徑設定。

建議用腳本一鍵安裝與檢測（細節見該文件 §3.0）：

pwsh -File scripts/Install-ExternalTools.ps1   # 安裝（預設全部；僅核心可加 -SkipDouyin）
pwsh -File scripts/Test-ExternalTools.ps1      # 檢測並取得各工具絕對路徑（含版本訊息）

檢測腳本會輸出可貼入 appsettings.json 的路徑片段（步驟 6）。

⚠️ 若以 IIS／服務帳號執行（步驟 0 的「執行身分」）：上述腳本把工具裝在使用者 Home 目錄，應用程式集區身分讀不到。請改用可攜安裝把工具集中到 C:\KMEngineTools 並授權集區：

# 以系統管理員執行
pwsh -File scripts/Install-PortableTools.ps1 -InstallDir C:\KMEngineTools
pwsh -File scripts/Test-PortableTools.ps1 -InstallDir C:\KMEngineTools -AppPoolName <集區名>

完整說明見 IIS 佈署與可攜工具設定。

手動安裝摘要：

功能需要的工具安裝
影音轉逐字稿（檔案、YouTube／小紅書連結）ffmpeg、yt-dlpwinget install Gyan.FFmpeg；python -m pip install --upgrade yt-dlp

安裝後務必查出每支工具的絕對路徑填入 appsettings.json（步驟 6），避免服務帳號 PATH 找不到工具。

4. 安裝資料庫（僅 SQL Server 需要）

  • SQLite（預設）：免安裝。資料庫檔由系統於 SystemSettings:ExternalFileSystem:DatabasePath 下自動建立（BackendDB.db）。
  • SQL Server：安裝 SQL Server（Express 以上）或使用 Azure SQL；建立空資料庫；備妥連線字串。切換步驟與 migration assembly 細節見 SQL Server 切換說明。

啟動時系統會自動套用 EF Core migrations（有 migration 則 Migrate()、否則 EnsureCreated()），無須手動建表。

5. （選用）安裝 Redis

僅當步驟 0 選擇 Redis 快取時。安裝 Redis 伺服器，記下連線字串（如 localhost:6379），於步驟 6 設定。

6. 設定 appsettings 與機密（核心）

設定來源優先序（高→低）：環境變數 → User Secrets（開發） → appsettings.{Environment}.json → appsettings.json。 階層鍵的環境變數寫法：用雙底線，如 OpenAISettings:ApiKey → OpenAISettings__ApiKey。

機密（金鑰、密碼、連線字串）一律不進版控：正式環境用環境變數或部署平台 secret；開發機可用 dotnet user-secrets。

6.2 正式環境設定機密的範例（環境變數）

跑在 IIS 的話，優先用 web.config 的 <environmentVariables>，不要用 setx。 setx /M 寫的是 Machine 範圍變數，IIS 工作處理序要重啟 IIS／WAS 才讀得到——「明明設了卻沒生效」多半是這個原因。 web.config 則是存檔即回收生效、不需重建重部署。完整範例與權衡見 IIS 佈署與可攜工具設定 §5.1：

<aspNetCore processPath="dotnet" arguments=".\KnowledgeExtraction.Web.dll" hostingModel="inprocess">
  <environmentVariables>
    <environmentVariable name="JwtSettings__SigningKey" value="<32 字元以上亂數>" />
    <environmentVariable name="BootstrapSettings__SupportPassword" value="<強密碼>" />
  </environmentVariables>
</aspNetCore>

非 IIS（如以服務或主控台方式執行）可用 Machine 環境變數：

setx ASPNETCORE_ENVIRONMENT "Production" /M
setx JwtSettings__SigningKey "<32 字元以上的亂數字串>" /M
setx BootstrapSettings__SupportPassword "<強密碼>" /M
setx OpenAISettings__ApiKey "<OpenAI 金鑰>" /M
setx SystemSettings__ConnectionStrings__DefaultConnection "<SQL Server 連線字串>" /M
# 用 SQLite 的話，覆寫回 Sqlite：
setx SystemSettings__DatabaseProvider "Sqlite" /M

6.3 開發機設定機密（User Secrets）

cd src/KnowledgeExtraction/KnowledgeExtraction.Web
dotnet user-secrets set "OpenAISettings:ApiKey" "<OpenAI 金鑰>"

6.4 以 Production 啟動失敗（HTTP 500.30）怎麼查

HTTP 500.30 代表應用程式在啟動階段就結束了，IIS 拿不到可服務的處理序。原因不會顯示在瀏覽器上，必須從別處取得。

1.0.68 起沒有「啟動安全檢查」了。先前有一支 StartupSafetyValidator 會在 Production 沿用開發預設金鑰／密碼時中止啟動，因兩度擋住正式部署已移除；1.0.69 連健康檢查的金鑰內容判定也一併移除。

1.0.72 恢復了偵測能力，但改為「只提示、不阻斷」：Production 啟動時若偵測到仍在用開發預設金鑰或 support 預設密碼，會在日誌記一筆 Error（訊息開頭是 Production 安全風險：），且 /system-health 的「身分驗證」項轉黃燈。站台仍會正常啟動。

⚠️ 因此：日誌裡看到 Production 安全風險 這筆 Error，不是 500.30 的原因。 它只是提示你去換金鑰，不會讓處理序結束。查 500.30 請往下看第 1 步。安全性仍須由部署流程確保（見 §6.1、§6.2 與《正式部署與安全檢查清單》的人工核對項）。

第 1 步：看 Windows 事件檢視器（eventvwr → Windows 記錄 → 應用程式）。ASP.NET Core Module 會把啟動期的未處理例外寫在這裡，訊息含例外型別與堆疊。

啟動期失敗多半發生在 NLog 初始化之前或期間，所以 NLog:BasePath 底下的日誌檔可能完全沒有紀錄。別只看日誌檔就下結論。

第 2 步：對照常見原因。

事件訊息關鍵字原因處置
OptionsValidationException: DataAnnotation validation failed for 'JwtSettings' members: 'SigningKey'JwtSettings:SigningKey 留空或短於 32 字元。這是 ASP.NET Core 的選項驗證（ValidateDataAnnotations().ValidateOnStart()），不是已移除的那支安全檢查依 §6.2 設一組 32 字元以上的亂數金鑰
SqliteException ／ SqlException ／ 連線逾時資料庫路徑不存在、無寫入權，或 SQL Server 連線字串錯誤確認 §7 的目錄權限；SQL Server 確認連線字串與網路
UnauthorizedAccessException ／ DirectoryNotFoundExceptionNLog:BasePath 或 ExternalFileSystem:* 目錄不存在／應用程式集區身分無寫入權建立目錄並依 §7 授權
The type initializer for ... threw an exception多半是設定繫結失敗（型別不符、JSON 格式錯）檢查 appsettings.Production.json 是否為合法 JSON

第 3 步（事件紀錄仍看不出原因時）：把 web.config 的 stdoutLogEnabled 改為 true，確認 .\logs 目錄存在且應用程式集區身分可寫，重現一次後看 logs\stdout_*.log。查完務必關掉，該檔會持續長大。

7. 目錄與權限

  • 系統啟動時會自動建立 ExternalFileSystem:* 與 NLog:BasePath 各目錄，無須手動建立。
  • 但需確認執行身分對這些路徑有讀寫權限（IIS 應用程式集區／Windows 服務帳號常與登入使用者不同）。
  • 確認磁碟空間足夠（媒體下載、轉錄輸出、文件轉文字會佔用）。

8. 啟動系統

8.1 開發／驗證

dotnet run --project src/KnowledgeExtraction/KnowledgeExtraction.Web
# 預設網址：https://localhost:7044 （http://localhost:5189）
# 首次本機 HTTPS：dotnet dev-certs https --trust

8.2 正式（已發布產物，Kestrel）

# 已設 ASPNETCORE_ENVIRONMENT=Production（觸發啟動安全檢查、套用 appsettings.Production.json）
$env:ASPNETCORE_URLS = "https://0.0.0.0:7044"
C:\apps\KnowledgeExtraction\KnowledgeExtraction.Web.exe
  • 正式環境會 UseHttpsRedirection() + HSTS；HTTPS 憑證請由反向代理（IIS／Nginx）或 Kestrel 憑證設定提供。
  • 走 IIS 時系統已支援轉發標頭（UseConfiguredForwardedHeaders）；安裝 ASP.NET Core Hosting Bundle。
  • 健康檢查：/health/live、/health/ready；人工巡檢頁 /system-health（僅管理員）。

沒有啟動期的設定安全檢查（1.0.68 起移除，原因見 §6.4）。JwtSettings:SigningKey、BootstrapSettings:SupportPassword、Swagger:EnabledInProduction、CacheSettings:RedisConnection 這幾項沿用不安全值不會被程式擋下，請依 §6.1 的必改清單自行確認。

唯一還會擋啟動的是 ASP.NET Core 對 JwtSettings 的選項驗證（SigningKey 為必填且至少 32 字元）——留空或過短會回 500.30，訊息為 OptionsValidationException。

⚠️ 沒有任何自動偵測：1.0.69 起 /system-health 的「身分驗證」項也不再檢查金鑰內容（只看 Cookie/JWT scheme、Issuer/Audience 是否設定、金鑰長度是否 ≥32）。Production 是否沿用開發預設金鑰，只能靠部署時人工確認。

9. 首次登入

  • 系統首次啟動會自動建立預設管理者帳號（取自 BootstrapSettings）與預設角色「預設角色」。
  • 預設帳號：BootstrapSettings:SupportAccount（預設 support），密碼為 BootstrapSettings:SupportPassword。
  • ⚠️ 目前每次啟動都會以設定值覆寫該帳號密碼；正式環境務必透過 secret 設定強密碼（見步驟 6 與安全檢查清單）。
  • 系統有強制改密碼流程：登入後 AuthenticationStateHelper 若偵測到密碼等於 MagicObjectHelper.NeedChangePassword（123456），會導向 /ChangePassword 強制更換後才能使用其他頁面。注意此流程只認這一個特定值，設成其他弱密碼不會觸發。

10. 功能驗證（逐項確認可用）

  1. 登入：以 support 帳號登入成功。
  2. 資料庫：能正常 CRUD（任一管理頁新增/查詢）。
  3. 影音轉逐字稿 — 檔案：上傳一個音檔，背景轉錄成功、可下載逐字稿。
  4. 影音轉逐字稿 — 連結：貼 YouTube 或小紅書連結，轉錄成功。
  5. 抖音（若需要）：於「影片連結」貼上抖音連結或分享文字 → 送出後系統自動呼叫 playwright 助手下載（瀏覽器視窗跳出，必要時當場手動過驗證）→ 轉錄完成。前提：已設定 OpenAISettings:DouyinHelperScript、本機已登入抖音。（亦可獨立執行 node tools/douyin-audio/get-douyin-audio.mjs "<連結>" 產出 mp3 後改用「檔案上傳」。）
  6. 文件轉文字：上傳 PDF/Word，產出 Markdown。
  7. 健康檢查：/health/ready 回 200。
