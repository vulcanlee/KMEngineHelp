系統介紹：這是一套什麼系統、為你解決什麼？

在開始動手之前，先用幾分鐘認識這套系統——你正在使用的是什麼、它要解決什麼問題、提供哪些功能、最終帶來什麼價值。看完這一節，你就能對「為什麼要用它」一目了然。

這是一套什麼系統

一句話：這是一套「知識萃取與知識庫」系統——把組織裡零散、難用的素材（會議錄音、教學影片、PDF／Office 文件、現場照片），自動煉成「乾淨、去敏、可被自然語言問答、附出處、且受團隊權限控管」的知識資產。

再講清楚一點：你的組織每天都在產生知識——一場客戶會議、一次故障排除、一份系統架構文件、一張錯誤訊息截圖。但這些知識通常散在錄音檔、硬碟、某個人的腦袋裡，找不到、不敢共享、不知道可不可信、也沒有權限邊界。這套系統把「匯入素材 → 聚合主題 → 清洗去敏 → 蒸餾成知識 → 建立索引 → 自然語言問答」整條生產線打通，讓知識從「散落的原料」變成「隨問隨答、可追溯出處、只給該看的人看」的可信知識庫。

這套系統為誰而生

凡是「知識需要被永久保存、需要被快速查詢、且需要權限控管」的團隊都適用，例如：

  • 系統維運／部署團隊：安裝部署 SOP、故障排除經驗、作業系統與硬體問題的解法。
  • 軟體開發團隊：客戶會議紀錄、需求討論、系統架構設計、安裝與操作手冊。
  • 客服、人資、業務等知識密集單位：標準應答、流程規範、合約與高敏感資料。

特別適合「老手經驗難傳承、新人上手慢、敏感資料不敢共享」的組織——讓知識不再綁在某幾個資深員工身上。

它如何確保知識「可信賴」

系統把知識當成生產線一站一站煉，並內建兩道品質把關與兩條安全鐵則：

匯入素材 → 聚合主題 → 清洗(去敏/結構化) → 蒸餾(煉成Wiki) → 索引 → 自然語言問答
                          │                                          │
                  清洗品質評測（量清洗品質）               檢索品質評測（量檢索品質、越權=0）
  • 不變量一・團隊權控：非管理員只看得到「公開（無團隊）」或「與自己團隊有交集」的內容；連問答檢索也即時驗證權限，你無權看的，問答也絕不會吐給你。
  • 不變量二・遮罩失敗＝整筆清洗失敗：寧可重跑，也不讓沒遮乾淨的敏感內容流向下游。安全永遠優先。

它最終帶給你的價值

  • 找得到：散落各處的知識集中可檢索，新人不用再到處問人。
  • 可信任：每個答案附出處、可追溯回原始檔，敢用、能稽核。
  • 不外洩：自動去敏＋團隊權控，敏感資料只給該看的人。
  • 可量測：清洗與檢索品質都能用評測量出來，績效不是口號。
  • 可傳承：知識永久保存，老手的經驗變成全公司的資產。

第 0 章　如何使用本手冊（請先讀這 3 分鐘）

0.1 這份手冊能帶你做到什麼

讀完並照做完本手冊，你會親手完成：

  1. 把系統的基礎資料（團隊、分類、角色、使用者、提示詞、清洗規則設定）依正確順序建好。
  2. 用四條匯入管線（影音轉逐字稿、文件轉文字、圖片解讀，以及會議錄音自動產生 AI 會議紀錄）把素材變成文字。
  3. 把素材聚合成知識來源，跑清洗（去敏、結構化）、蒸餾（煉成 Wiki 頁）、索引。
  4. 用AI 知識問答對整個知識庫提問，得到附出處、且只回你有權看的答案。
  5. 用清洗品質評測與 檢索品質評測量化品質，確認「清洗乾不乾淨、檢索準不準、會不會外洩」。
  6. 親眼看見團隊權控造成的「不同人看到不同資料」，並學會用團隊、分類、關鍵字快速篩選。

0.5 關於「無金鑰替代路徑」

本系統的部分能力需要外部資源才能發揮完整效果：

  • 影音轉逐字稿、圖片解讀：需要 OpenAI API 金鑰（呼叫雲端模型）。
  • 文件轉文字：PDF 走 LLM（出貨設定 PdfUseLlm=true，需金鑰；無金鑰會自動降級成 markitdown、不會失敗）；PDF 以外的格式一律走本機 markitdown、不需金鑰。
  • 文件轉文字：需要本機工具 markitdown（不需金鑰）。
  • 清洗的 LLM 步驟（去重／遮罩／分類／摘要／信心）、蒸餾、問答：需要金鑰。
  • 索引：需要設定好嵌入端點（雲端金鑰或地端模型）。

如果你手邊沒有金鑰，仍然可以把整套流程練習一遍——只是某些步驟的 AI 產出會以「彙整＋繁體化」代替，或需要你手動貼上我們提供的範例結果。凡是會用到金鑰／工具的步驟，本手冊都會同時給你一條 🟢 無金鑰替代路徑。建議第一次先用無金鑰路徑把「操作流程」走熟，日後有金鑰再回來體驗完整 AI 效果。

⚠️ 能力邊界要先講清楚：無金鑰路徑能讓你練習建檔、標籤、權控、聚合與部分狀態操作，但不等於已驗證 LLM 遮罩／摘要、AI 蒸餾、向量嵌入或完整 RAG 問答。需要 AI 或嵌入的驗收項目，若環境未就緒，請標記為「待完整環境補驗」，不要把手動貼上的範例當成系統實際產出。

1.5 績效提升（量化的期望值）

導入後，鼎峰第一系統開發部期望達到（以一般知識管理導入經驗為基準的合理預期）：

  • 找答案的時間：從「半小時翻檔案＋問人」縮短到「1 分鐘問知識庫」，查詢效率提升約 10 倍。
  • 新人上手週期：從 1～2 個月縮短到 2～3 週，約縮短 50%，因為知識不再綁在資深員工身上。
  • 重複犯錯／重複求助：同類問題重複發問下降 60% 以上，因為解法已被永久保存且可被檢索。

2.2 兩個貫穿全程、絕不能違反的不變量

  1. 團隊權控：非管理員只看得到「未指定團隊（公開）」或「與自己角色預設團隊有交集」的紀錄；管理員不受限。這條規則從匯入、知識來源、Wiki 頁一路貫穿到問答出處——你看不到的內容，問答也絕不會檢索到。
  2. 遮罩失敗＝整筆清洗失敗：寧可重跑，也不讓沒遮乾淨的敏感內容流向下游。安全永遠優先。

本手冊的「第 15 章 權控與篩選綜合練習」會讓你用不同帳號登入，親眼驗證第一條不變量。

2.3 大多數產物「只存檔案、不存資料庫」

逐字稿、萃取的 Markdown、清洗結果、Wiki 頁等內容都存在伺服器的檔案系統（例如 C:\temp\KnowledgeExtraction\… 對應子目錄），資料庫只存「相對路徑」與狀態。你操作時不必管檔案在哪，知道「找不到清洗檔時它在檔案系統、不在 DB」即可（這在排錯時有用）。

2.4 幾乎所有重工作都是「背景作業」

三條匯入管線、清洗、蒸餾、索引都是背景任務：你按下去之後可以離開，清單會即時顯示「等待中 → 處理中 → 已完成／失敗」。失敗可重試、處理中可取消，不必重新整理網頁。

10.1 知識百科 /knowledge-wiki（一般讀者怎麼讀蒸餾後的 Wiki）

13.4 👉 動手做（zhang）：三元組審核

  1. 進「知識庫 → 知識圖譜審核」→「三元組審核」分頁（狀態篩選預設「待審核」）。

  3. 故意挑 1 筆明顯錯誤的（例如把不相干的兩個名詞連起來），按「退回」並在理由填「關係不成立，非事實」。
  4. 挑 1 筆關係詞不精確的，按「編修」把「關係」改得更準（例如「提到」改成「相依於」），儲存。

第 16 章　MCP Server：讓外部 AI Agent 查詢知識庫 /mcp

這個畫面做什麼：前 15 章都在「網頁裡」操作知識庫。本章把同一座知識庫對外開放給外部 AI 助手（Claude、Codex 等）。系統提供一個 MCP（Model Context Protocol）端點 /mcp，任何支援 MCP 的 AI 工具連上後，就能把「查詢鼎峰知識庫」當成內建能力。它解決的問題是——讓工程師在自己慣用的 AI 工具裡直接問公司知識，而團隊權控與網頁完全一致：換一個人的憑證，就換成那個人能看的範圍。這正是第 15 章「不同人看到不同資料」在外部 Agent 上的延續。

📌 五個工具：knowledge_ask（問答，含出處）、knowledge_search（檢索片段）、knowledge_list_sources（列出可見來源）、knowledge_get_document（取單一來源全文）、knowledge_ping（連通性檢查）。

🔑 需要金鑰／工具：一個支援 MCP 的用戶端（本章以 Claude Code CLI 示範，Codex 亦可）；一組憑證；且已完成第 11 章（索引）與第 12 章（可問答）——問答/檢索工具需要嵌入索引。

👉 前置：取得憑證（兩種擇一）

  • JWT：呼叫既有登入端點（POST /api/Auth/...，實際路徑見系統管理員）以帳密換取 token，之後帶 Authorization: Bearer <JWT>。到期需重新換發。
  • API Key（M2M 整合）：系統管理員於 /mcp-api-keys（系統管理 → MCP 金鑰管理）網頁新增一把金鑰（自動產生）並對映到某個帳號（例如對映 wang），呼叫端帶專用標頭 X-API-Key: <金鑰>。可即時啟用/停用，撤銷＝停用或刪除該金鑰（存資料庫，1.0.9 起）。

💡 為什麼憑證＝身分：MCP 端點沿用系統既有認證，解析出「你是誰、屬哪些團隊」後，所有查詢都在檢索層套團隊權控——和你在 /knowledge-base-chat 看到的一模一樣。

👉 動手做（用 Claude Code CLI，分三種身分各連一次）

  1. 連通（先確認連得上）：以任一有效憑證新增伺服器並列出工具：
   claude mcp add --transport http dingfeng https://<你的主機>/mcp --header "Authorization: Bearer <JWT>"
   claude mcp list

呼叫 knowledge_ping → 應回 KnowledgeExtraction MCP server is alive.。

  1. 王小明（wang，運維組非管理員）問答：用 wang 的憑證呼叫 knowledge_ask，問「機房 UPS 與備援的巡檢重點？」→ 應得含出處的答案（來自運維組 A 系列來源）。
  2. 李四（lisi，開發組）越權測試：用 lisi 的憑證問同一題運維內容 → 應「查無依據」（confidence: Insufficient、sources: []）；再用 lisi 對某筆運維來源 Id 呼叫 knowledge_get_document → 應回 { "error": "unavailable" }（不洩漏該來源是否存在）。
  3. 管理員（support）對照：用 support 的憑證呼叫 knowledge_list_sources → 應看到全部來源（含業務合約組 B3「客戶A-合約與SLA」）；同一呼叫由 lisi 執行則看不到 B3。

✅ 你會看到：同一個問題／同一個列表工具，wang／lisi／support 得到不同的可見範圍，且與第 15 章網頁驗證的結果完全一致。越權內容永遠不會出現在回傳裡。

🟢 無金鑰（嵌入端點未設定）：knowledge_ask／knowledge_search 需要嵌入，此時無法驗；但仍可完整驗證 knowledge_ping 連通 與 knowledge_list_sources 的權控（列表不需嵌入）——wang 只列運維組＋公開、lisi 列不到 B3、support 全列。問答/檢索類指標標「□ 待補驗」。

⚠️ 常見錯誤：

  • 憑證放錯標頭——JWT 用 Authorization: Bearer、API Key 用 X-API-Key，別互換。
  • 回 401：JWT 過期或無效（重新換發）／API Key 與設定不符。
  • 連得上但問答查無：先確認已完成第 11 章索引、且該憑證對映的帳號團隊正確（用 support 對照同題應答得出）。

✅ 第 16 章通過條件：knowledge_ping 連通；wang 取得運維組答案且附出處，lisi 問同題查無依據、取運維全文回 unavailable，support 於 knowledge_list_sources 看到含 B3 的完整清單——越權洩漏＝0。無金鑰模式下至少 knowledge_ping 通、且 knowledge_list_sources 三帳號權控正確，其餘標「待補驗」。任一越權可見都屬安全失敗。

各家 AI 工具（Codex、Claude Code/Desktop、Cursor、VS Code）的逐步設定、五工具參數與回傳範例、日誌與稽核運維，見《MCP 服務使用說明書》；技術規格見《MCP Server 整合設計與使用指南》。

第 17 章　知識更新練習（文件改版了，知識庫怎麼跟著更新）

真實世界裡，文件會改版——合約續約、SOP 更新、架構調整。這時「原料、清洗結果、蒸餾出的 Wiki、索引」都要跟著更新。本章教你怎麼做。

17.1 情境：客戶 A 的維護合約續約了（B3 改版）

👉 動手做

  1. 更新原料：用 chen（或 zhang／support）到 /document-extraction，找到「客戶A維護合約與SLA」。李四建檔後已因團隊權控失去存取權，不能用 lisi 執行本章。
  2. 做法一（推薦）：對該筆按 「上傳新版本」，上傳改版檔案。系統會建立素材版本鏈——版本欄變成 v2，舊版標示「（已被取代）」，可按「版本歷史」查看各版本與 as-of 時序。這是保留歷史又最語意清楚的做法。
  3. 做法二：重新匯入新版檔案為另一筆新素材（標題加 v2）。較不推薦，因為版本關係不會被系統串起來。
  4. 更新成員：到 /knowledge-sources 的「客戶A-合約與SLA知識」。採做法一（上傳新版本）時，來源會沿著版本鏈指向最新版本，通常確認一下即可；採做法二時，需按「管理成員」把舊素材移除、加入新的 v2 素材。
  5. 重新清洗：對該來源按 「重試清洗」（或「清洗」），重新產出乾淨內容。
  6. 重新蒸餾：清洗完成後按 「蒸餾」🧪（可重蒸餾），Wiki 頁會重煉。
  7. 索引自動更新：蒸餾完成後索引自動重跑，狀態回到「已索引」。
  8. 驗證：到 /knowledge-base-chat 問與合約有關的問題，確認答到的是新版內容、出處指向 v2。

✅ 你會看到：知識庫的答案隨著原料更新而更新，且舊出處可被新出處取代。

💡 設計重點：因為「清洗結果、Wiki 頁只存檔案、DB 存路徑與狀態」，重跑清洗/蒸餾會產生新的檔案版本；索引在蒸餾後自動連動，所以你只要從『更新原料』開始，沿著生產線重跑一次，下游就會全部刷新。 💡 要不要保留舊版？ 視稽核需求。要留歷史就用「新增 v2」；不需要就直接更新同一筆。合約這類高敏感、需稽核的，建議留歷史。

17.2 只是小修，不想全部重跑？

若只是清洗結果的文字要微調（例如補一句話），可用「檢視清洗結果」裡的線上編修直接改存；但要注意：手動改過清洗結果後，若再重跑清洗會被覆蓋。蒸餾頁的 Wiki 也同理可線上編修。小修建議直接編修，大改才從原料重跑。

👉 動手做

  1. 進 /log-download（「系統管理 > 日誌下載」），確認預設區間為「最近一小時」。
  2. 用「快速區間」下拉選「最近30分鐘」（1.0.13 新增），觀察兩個時間欄位自動以現在時間回推帶入；若要涵蓋更早的操作時段，再手動微調起始時間，按「下載」。
  3. 解壓 zip，打開裡面的 .log，確認能找到剛才操作留下的紀錄（依時間排序、例外堆疊完整保留）。

⚠️ 限制：區間上限 31 天；合併後超過 200 MB 會顯示「選取範圍的日誌量過大，請縮小時間區間。」；起始晚於結束或未選時間都會被擋下。日誌每日輪替、保留 30 天。

✅ 你會看到：zip 檔名為 logs_{起}-{訖}.zip（時間各到分）；就算選了沒有日誌的區間，也會下載到空的日誌檔（代表「查過了、真的沒有」）。

19.8 統計報表五頁 /reports/…（觀察式驗收）

這些畫面做什麼：Sidebar 獨立群組「統計報表」五頁管理儀表——Token 用量統計、AI 回答滿意度、問答使用統計、檢索品質統計、內容清點統計。共通操作：進頁即以近 30 天預設區間自動查詢；可用日期＋團隊多選篩選；每頁都有「下載 PDF 報表」。

👉 動手做

  1. 依序開五頁，確認各頁進入後已自動帶出近 30 天資料。
  2. 在「AI 回答滿意度」找到你在第 12 章按過的 👍/👎（滿意率與每日趨勢應有紀錄）。
  3. 在「問答使用統計」確認練習期間的問答筆數，並觀察是否有「被封鎖（查無依據）」筆數。
  4. 在「檢索品質統計」對照 19.4 學到的 topScore 觀念，看平均 TopScore、命中率與 TopScore 分桶。
  5. 在「內容清點統計」用「團隊＝運維」或分類篩選，對照第 6 章匯入的素材筆數（依媒體型別/狀態/團隊/分類）。
  6. 任選一頁按「下載 PDF 報表」，確認取得 統計報表_…_{時間戳}.pdf。

✅ 通過條件：五頁皆有資料且與你的練習操作對得上；PDF 可下載開啟。無金鑰模式下與 AI 相關的數字（token、滿意度）可能為空，記錄為「依環境註記」即可。

19.10 重跑與清理練習資料原則

  • 重跑前先辨識環境：只在全新或專用練習資料庫重建整套資料；共用／正式環境不得用本手冊虛構資料做重置測試。
  • 優先修正單筆：匯入、清洗、蒸餾或索引失敗時，先讀錯誤並只重試該筆，不用批次重跑掩蓋根因。
  • 刪除要沿依賴反向處理：先確認問答／評測證據是否要保留，再處理下游索引、Wiki、來源成員與上游素材；不確定時交由管理員依資料生命週期指南處理。
  • 整庫重置交給安裝人員：資料庫與檔案產物分開保存，不能只刪資料庫或只刪 C:\temp\KnowledgeExtraction。重置前要備份並確認所有使用者已停止操作。

第 20 章　FAQ（常見問答，持續擴充）

依主題分區。遇到問題先用瀏覽器 Ctrl+F 搜尋關鍵字。

A. 安裝、啟動與環境

Q. 我打不開系統網頁怎麼辦？ A. 確認安裝人員已啟動程式、且你用對網址（例如 http://localhost:5080）。本手冊假設系統已安裝啟動；安裝細節見《使用者安裝與操作手冊》。

Q. 執行檔一開就閃退、說缺少框架？ A. 多半是沒裝 .NET 10 ASP.NET Core Runtime。請安裝人員處理。

Q. 啟動說 HTTPS/憑證錯誤？ A. 本機建議只綁 HTTP；要 HTTPS 走憑證或反向代理。屬安裝設定，非操作層面。

Q. 連接埠被占用？ A. 換一個埠啟動（例如 --urls "http://localhost:8081"），由安裝人員調整。

B. 登入與帳號

Q. 一直「驗證碼錯誤」？ A. 驗證碼是隨機 4 位數、每次載入會換。請每次都重看右側的新數字，不要沿用舊的。

Q. 「身分驗證失敗，請重新確認帳號與密碼」？ A. 檢查帳密大小寫。內建管理帳號是 support / 1qaz@WSX；具名帳號用你在第 5.4 節設定的密碼。

Q. 忘記某個具名帳號的密碼？ A. 用 support 登入到 /myusers，編輯該帳號，在密碼欄填新密碼存檔（留空則不變更）。

Q. support 可以拿來日常用嗎？ A. 不建議。它密碼由設定檔控制、每次啟動重設、介面改不了，只適合開機建基礎資料。日常請用具名帳號。

Q. 「記住我」要不要勾？ A. 自己的電腦可勾，保持登入較久；公用電腦請勿勾。

C. 權限、角色與團隊

Q. 登入後左側看不到某些選單？ A. 該角色沒勾那頁權限。用 support 到 /roleviews 編輯角色，補勾權限後請對方重新登入。

Q. 看不到別人/別組輸入的紀錄？ A. 這是正常的團隊權控：非管理員只看得到「公開（無團隊）」或「與自己角色預設團隊有交集」的紀錄。要看到某團隊紀錄，角色的預設團隊就要含該團隊。

Q. 我自己輸入的紀錄，怎麼自己看不到了？ A. 你把它的團隊標成了你無權的團隊（像本手冊的 B3）。輸入者≠有權看。請管理員或有權者協助，或調整該紀錄團隊。

Q. 為什麼張經理不是管理員卻看得到全部？ A. 因為他角色的「預設團隊」同時含三組，與每筆紀錄都有交集。「看得到」靠團隊交集，不一定要管理員。

Q. 管理員（IsAdmin）跟「預設團隊含全部」有何不同？ A. 管理員完全不受權控（連未來新增的團隊也照看）；「預設團隊含全部」只是目前剛好交集到所有現有團隊，未來新團隊的紀錄他不會自動看到。本練習刻意用後者來示範權控。

Q. 改了團隊名稱，舊紀錄就對不上了？ A. 團隊/分類是字串精確比對，命名後別隨意改名。真要改，舊紀錄的標籤也要一起更新。

D. 匯入素材

Q. 沒有 OpenAI 金鑰，還能練嗎？ A. 能。文件轉文字不需金鑰，是無金鑰主力管線。音訊/圖片改走「無金鑰替代路徑」（把逐字稿/解讀文字當文件匯入）。見第 6 章各節 🟢。

Q. 轉錄/影片連結下載一直失敗？ A. 多半缺 ffmpeg/yt-dlp 或沒填路徑/金鑰，或格式/大小超限。請安裝人員補齊，或走無金鑰替代路徑。

Q. 文件轉文字失敗、說格式不支援？ A. 換成畫面顯示的支援副檔名（如 .txt/.docx/.pdf）。

Q. 圖片解讀失敗？ A. 確認有視覺模型金鑰、圖片不超過約 50MB、是常見影像格式；或走無金鑰替代路徑。

Q. 素材標籤（分類/團隊）填錯了怎麼改？ A. 在對應清單頁編輯該筆，重選分類/團隊存檔即可。

E. 知識來源與清洗

Q. 管理成員時，找不到我想加的素材？ A. 三個原因：①素材還沒「已完成」；②素材團隊你無權看；③已加入過。確認後再試。

Q. 清洗後找不到結果檔案？ A. 清洗結果只存檔案不存 DB（預設 C:\temp\KnowledgeExtraction\CleanedSource\{年}\）。直接按「檢視清洗結果」看即可。

Q. 清洗結果沒有遮罩/摘要/分類？ A. 多半沒設金鑰，LLM 步驟被略過（只做彙整＋繁體化）。補金鑰後「重試清洗」。

Q. 選不同清洗規則設定，差在哪？ A. 差在五段提示詞。例如「運維配方」摘要分『問題/原因/解法』、「會議配方」分『決議/待辦/負責人』。可對同一來源重試清洗換配方比較。

Q. 為什麼有的清洗完是「已清洗」、有的是「待審核」？ A. 看信心分數：≥門檻（預設0.70）自動「已清洗」；低於門檻落「待審核」，要人工核准/退回。

Q. 「遮罩失敗＝整筆清洗失敗」是什麼意思？ A. 安全設計。寧可整筆失敗，也不放行沒遮乾淨的敏感內容。先讀錯誤訊息，檢查金鑰、遮罩提示詞與輸入內容，修正根因後再重試；不要只反覆重跑。

Q. 核准/退回按鈕是灰的/沒看到？ A. 需要「知識審核」權限（本練習給知識管理員＝張經理）。用有權帳號操作。

F. 蒸餾、索引

Q. 找不到「蒸餾」按鈕？ A. 蒸餾只對「已清洗」的來源開放。先完成清洗。

Q. 蒸餾完了，問答還是查不到？ A. 多半是索引沒成功（嵌入端點沒設）。看來源的「索引狀態」，失敗的話請安裝人員設好嵌入端點後重跑。

Q. 可以重蒸餾嗎？ A. 可以。重蒸餾後 Wiki 頁重煉、索引自動連動更新。

Q. Wiki 頁的 [[連結]] 是做什麼的？ A. 它把概念頁互相連起來，形成知識網。標題就是連結的比對鍵。

G. AI 知識問答

Q. 問答答非所問、或漏掉內容？ A. 確認對應來源已「清洗→蒸餾→索引」三狀態皆完成；可用 檢索品質評測定位是檢索問題還是內容問題。

Q. 答案會不會洩漏我無權看的內容？ A. 不會。每次查詢即時驗證權限，非管理員檢索不到無權內容（越權應為 0）。

Q. 怎麼讓答案變成步驟/表格格式？ A. 在「套用既有提示詞」選你寫好的「問答-條列步驟」或「問答-表格比較」。提示詞決定回答格式。

Q. 出處怎麼看、怎麼追原始檔？ A. 答案下方附出處，點它可鑽取「知識來源→成員→原始檔」並下載原始檔。

Q. 詳簡切換有什麼用？ A. 簡潔給短答案、詳細給完整說明。依需求切換，套用到下一則訊息。

H. 評測（黃金 / RAG）

Q. 清洗品質評測和 檢索品質評測差在哪？ A. 清洗品質評測量「上游清洗乾不乾淨」；檢索品質評測量「下游檢索找得到/找得準/不外洩」。一前一後形成完整把關鏈。

Q. 指標多少算好？ A. 參考：清洗品質評測遮罩召回 ≥0.98、分類 F1 ≥0.70；檢索品質評測看 P@k/R@k/NDCG/MRR 越高越好，越權洩漏一定要 0。

Q. 「載入種子」是什麼？ A. 一鍵帶入內建範例樣本，方便新手看標準長相再改成自己的。

Q. 建議門檻怎麼真正生效？ A. 改 appsettings.json 的 SystemSettings.Cleaning.ConfidenceThreshold（預設 0.70）。屬設定層，請安裝人員協助。

Q. 檢索品質評測的越權測試怎麼設？ A. 設「評測團隊」為某一組、問另一組才有的內容、不勾模擬管理員；結果越權洩漏應為 0。

I. 資料更新與維運

Q. 文件改版了，知識庫怎麼更新？ A. 從「更新原料」沿生產線重跑：更新素材→管理成員換新版→重試清洗→重蒸餾→索引自動更新→問答驗證。見第 17 章。

Q. 小修清洗結果一定要重跑嗎？ A. 不用。可用「檢視清洗結果」線上編修直接改存；但之後若重跑清洗會被覆蓋。

Q. 各種產物存在哪？ A. 逐字稿、萃取 Markdown、清洗結果、Wiki 都存檔案系統（C:\temp\KnowledgeExtraction\…），DB 只存相對路徑。

Q. 想看詳細錯誤/日誌？ A. 日誌在 C:\temp\Logs\；管理員可開 /system-health 看系統健康與最近紀錄。

Q. 背景作業卡住或想取消？ A. 處理中的匯入/清洗/蒸餾/索引都可「取消」；失敗的可「重試」，不必重整網頁。

J. 知識圖譜與全域問答（第 13 章）

Q. 抽取跑完顯示「已抽取」，但三元組是 0 筆？ A. 幾乎都是該來源的 Wiki 頁還沒核可——抽取讀的是「已完成且現行」的 Wiki 頁。回第 10 章把 Wiki 頁核可，再重抽。

Q. 找不到「抽取／重抽三元組」按鈕？ A. 該來源還不是「已蒸餾」狀態。先完成第 10 章。

Q. 我核可了三元組，但問答結果看起來沒變？ A. 三個原因依序查：①兩端實體必須錨定到現行的 Wiki 頁；②圖分是加分項（權重預設 0.2），原本排名差距大時可能不足以改變順序；③管理員可到「檢索診斷與調校」確認 GraphWeight 的實際生效值不是 0（那一頁的值可覆寫 appsettings，所以看 appsettings 不準）。

Q. 重抽三元組會不會蓋掉我審核過的結果？ A. 不會。 去重鍵是「主詞｜關係｜受詞」，已核可與已退回的判斷原樣保留。素材更新、抽壞了都可以放心重抽。

Q. 全域模式的答案沒有出處面板，是壞了嗎？ A. 不是，設計如此。社群摘要是跨多筆來源歸納後的產物，本來就沒有對應到某一段原文的位置；改為顯示取用社群數。要出處請把查詢模式切回「一般」再問一次具體問題。

Q. 全域模式說「沒有可用社群」？ A. 管理員要先在「知識圖譜審核」頁頂按「重建社群摘要」（13.7）。這是部署後最常漏掉的一步。

Q. 我用 zhang 登入，看不到「實體合併」分頁？ A. 正常。該分頁與「重建社群摘要」按鈕是程式寫死僅管理員，勾任何角色權限都開不出來。用 support 操作。

Q. 我勾了 知識圖譜審核，卻不能核可三元組？ A. 那是兩種不同權限：進頁面要 知識圖譜審核，核可／退回還要 蒸餾審核（或管理員身分）。

Q. 圖譜瀏覽說「查無實體」？ A. 三種可能：名字打錯、那些三元組還在「待審核」、或那些關係屬於你沒權限的團隊。

Q. 按了取消，作業為什麼還在跑？ A. 單次 LLM 呼叫進行中無法中斷，取消只在呼叫之間生效。社群摘要重建是「每群一次 LLM」，要等當前那一群跑完。

K. 其他

Q. 我把資料建錯了，可以全部重來嗎？ A. 可逐筆刪除重建（刪除有確認）。要整庫重置請洽安裝人員（涉及資料庫與檔案）。

# Windows Server 記憶體不足故障排除

## 症狀
服務在凌晨批次作業期間中斷，事件檢視器出現記憶體不足錯誤。

## 排查
1. 用工作管理員/效能監視器觀察記憶體用量曲線。
2. 檢查是否有批次作業同時段疊加。
3. 檢查應用程式是否有記憶體洩漏。

## 解法
1. 將大型批次排程錯開時段。
2. 增加實體記憶體或調整虛擬記憶體。
3. 套用後重新開機，觀察一週。
