操作指南

EF Core Migration 指令備忘

  • 更新日期：2026/07/27
  • 對應系統版本：1.0.90
  • 編碼：UTF-8（繁體中文，含 BOM）

⚠️ 執行前必讀三件事

1. 工作目錄必須是方案目錄，不是 repo 根目錄。 下面所有 --project / --startup-project 都是相對於方案目錄的路徑。repo 根目錄底下只有 docs／scripts／src／tools，沒有 KnowledgeExtraction.AccessDatas 這種資料夾，在根目錄執行一定失敗。

cd src\KnowledgeExtraction     # ← 先切到這裡

（或改用完整相對路徑 --project src/KnowledgeExtraction/KnowledgeExtraction.AccessDatas ...。）

2. 平常不需要手動 Update-Database。 程式啟動時會自動套用 migration（Program.cs 的 dbContext.Database.Migrate()），所以開發時只要產生 migration、重跑程式即可。手動套用只在需要離線升級或產 SQL 腳本時才用。

3. 模型一改就要產「雙 provider」migration。 SQLite 與 SQL Server 各維護一套，缺一套會讓另一個資料庫的 schema 靜默落後。見 §雙 provider。

-Context BackendDBContext 可以省略：全庫只有一個 DbContext（AccessDatas/BackendDBContext.cs）。

兩套指令別混用

Package Manager Console（Visual Studio）dotnet ef CLI（終端機）
新增Add-Migration <Name>dotnet ef migrations add <Name>
套用Update-Databasedotnet ef database update
移除最後一支Remove-Migrationdotnet ef migrations remove
產 SQL 腳本Script-Migrationdotnet ef migrations script

Add-Migration／Update-Database／Remove-Migration／Script-Migration 是 PMC 專用，在一般終端機打會找不到指令。

PMC（Visual Studio 套件管理器主控台）

Add-Migration AddMeetingFields -Project KnowledgeExtraction.AccessDatas -StartupProject KnowledgeExtraction.Web
Update-Database              -Project KnowledgeExtraction.AccessDatas -StartupProject KnowledgeExtraction.Web
Remove-Migration             -Project KnowledgeExtraction.AccessDatas -StartupProject KnowledgeExtraction.Web
Script-Migration             -Project KnowledgeExtraction.AccessDatas -StartupProject KnowledgeExtraction.Web

參數說明：

  • -Context <String> — 要用的 DbContext。只有一個時可省略。
  • -Project <String> — migration 產出的目標專案。
  • -StartupProject <String> — 提供設定與 DI 的啟動專案（本專案固定是 KnowledgeExtraction.Web）。
  • -Args <String> — 傳給應用程式的參數。
  • -Verbose — 顯示詳細輸出。

dotnet ef CLI

cd src\KnowledgeExtraction

dotnet ef migrations add AddMeetingFields --project KnowledgeExtraction.AccessDatas --startup-project KnowledgeExtraction.Web
dotnet ef database update                 --project KnowledgeExtraction.AccessDatas --startup-project KnowledgeExtraction.Web
dotnet ef migrations remove               --project KnowledgeExtraction.AccessDatas --startup-project KnowledgeExtraction.Web
dotnet ef migrations script               --project KnowledgeExtraction.AccessDatas --startup-project KnowledgeExtraction.Web

雙 provider：每次模型變更都要做兩次

cd src\KnowledgeExtraction

# 1) SQLite（預設 provider）
dotnet ef migrations add <Name> --project KnowledgeExtraction.AccessDatas --startup-project KnowledgeExtraction.Web

# 2) SQL Server（用環境變數切 provider）
$env:SystemSettings__DatabaseProvider="SqlServer"
dotnet ef migrations add <Name> --project KnowledgeExtraction.AccessDatas.SqlServerMigrations --startup-project KnowledgeExtraction.Web
Remove-Item Env:\SystemSettings__DatabaseProvider   # 記得清掉，否則後續指令都會走 SqlServer

⚠️ SQL Server 那套的起點與 SQLite 不同，不能用來從零建庫。 目前 SQLite 有 57 支、SQL Server 有 54 支：SQL Server 缺最早的 init／add-some／AddGoogleOAuth，第一支是 20260602065813_AddMediaTranscription。也就是說 SQL Server 那套假設資料庫已有基礎表，直接對空的 SQL Server 資料庫套用會失敗。要新建 SQL Server 環境請先確認基礎 schema 來源。

產生雙 provider migration 的指令見上方「雙 provider」一節。

踩雷點

  • DbSet 名稱 ≠ Entity 名稱：DbSet 是 MyTas／MyTasFile，Entity 是 MyTask／MyTasFile（早期命名遺留）。產生 migration 時要留意別讓 EF 誤判成 rename。
  • 忘記產 SQL Server 那一套：SQLite 跑得好好的，換到 SQL Server 才發現少了欄位。每次模型變更都跑兩次。
  • SystemSettings__DatabaseProvider 環境變數沒清掉：後續所有 dotnet ef 指令都會走 SqlServer 分支，產出錯的 migration。
  • 只有一個 DbContext：所以 -Context BackendDBContext 可省；若哪天新增第二個 context，這個參數就變成必填。
