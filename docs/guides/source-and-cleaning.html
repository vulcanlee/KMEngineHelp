操作指南

知識來源加工與清洗規則設定｜使用教育訓練指南

  • 文件版本：1.2
  • 更新日期：2026/07/26
  • 對應系統版本：1.0.71（系統名稱：智庫引擎）
  • 編碼：UTF-8（繁體中文，含 BOM）

文件目的與適用對象

本文件給第一次使用「知識來源加工」與「清洗規則設定」的使用者。讀完你將能回答：

  • 這兩個功能是做什麼的、在整個知識管理系統裡扮演什麼角色、重不重要。
  • 「管理成員」要怎麼挑要加入的資料來源，有沒有操作依據。
  • 「清洗」的目的是什麼、會得到什麼成果、操作上有什麼建議。
  • 清洗規則設定的五個提示詞欄位（去重／遮罩／分類／摘要／信心自評）各代表什麼、怎麼寫，並透過 5 個實際範例看「清洗後會長成什麼樣」。

想先把整套系統從零跑起來，請看 使用者安裝與操作手冊；三個功能（清洗／設定檔／清洗品質評測）的關係與端到端例子見 從匯入到知識的操作流程。本文聚焦在「知識來源加工」與「清洗規則設定」兩個畫面的深入用法。

1. 一分鐘觀念：它們在系統裡的角色

整個知識管理的主線是四步：匯入 → 檢視 → 清洗 → 評量。

匯入素材              聚合成一包            清洗成知識             把關品質
（音訊/文件/圖片）  →  知識來源(成員)   →  乾淨 Markdown      →  信心門檻＋人工審核＋清洗品質評測
                       〔知識來源加工〕      〔清洗＋清洗規則設定〕
  • 知識來源加工：把多筆「已完成」的零散素材聚合成一個有主題、有團隊歸屬的單位（一個「知識來源」），當成一次清洗的單位。
  • 清洗規則設定：一組可重複使用的清洗「配方」（要怎麼去重／遮罩／分類／摘要／評信心）。

它重要嗎？ 重要，不是可有可無的過場。沒有它，素材只是一堆零散檔案；有了它，素材才會變成「敢用（去敏）、找得到（分類摘要）、可被信賴（信心分數＋人工審核）、可被管理（狀態可視）」的知識資產。

2. 知識來源加工（/knowledge-sources）

這個畫面列出你所有的「知識來源」，並讓你建立、聚合素材、觸發清洗、檢視結果與審核。

列表欄位（共 12 欄）： 標題、描述、分類、團隊、成員數、狀態、進度、信心、蒸餾、索引、更新時間、操作。可用分類／團隊過濾與關鍵字搜尋。

後兩個狀態欄常被忽略，但它們決定了「這筆知識到底能不能被問答查到」：

欄位可能的值
蒸餾待蒸餾（還沒蒸餾過）／等待中／處理中（NN%）／已蒸餾／失敗／已取消
索引待索引／等待中／處理中（NN%）／已索引／失敗／已取消

工具列：新增、重新整理、全量重建索引（見 §2.2），右側是分類過濾／團隊過濾／關鍵字搜尋。

狀態（狀態機）：

狀態意義
草稿已建立、尚未清洗。
等待中 / 處理中已排入清洗佇列／清洗進行中。
已清洗清洗完成且信心達門檻（或無 LLM 直接完成）。
待審核信心未達門檻（或無法評分），需人工核准。
已退回人工審核退回。
失敗 / 已取消清洗失敗或被取消。

2.1 列上動作按鈕與出現條件

這頁的按鈕會依狀態動態出現／消失——「找不到某顆按鈕」幾乎都是狀態不對，而不是權限問題。完整對照：

按鈕什麼時候才看得到
清洗狀態不是「等待中」也不是「處理中」
取消清洗狀態是「等待中」或「處理中」
重試清洗狀態是「失敗」或「已取消」
檢視清洗結果狀態是「已清洗」「待審核」或「已退回」
核准 / 退回狀態是「待審核」且你有「知識審核」權限（或是管理員）
蒸餾狀態是「已清洗」且蒸餾狀態不是「等待中／處理中」
取消蒸餾蒸餾狀態是「等待中」或「處理中」
重試蒸餾蒸餾狀態是「失敗」或「已取消」
清除蒸餾結果蒸餾狀態是「已蒸餾」
建立索引 / 重建索引狀態是「已清洗」且索引狀態不是「等待中／處理中」（已索引過就顯示「重建索引」）
AI 對話（下拉）一直都在。兩個選項：「對清洗後內容對話」（沒有清洗結果時不可點）、「對原始來源對話」（成員數為 0 時不可點）
管理成員 / 修改 / 刪除一直都在

建立索引不需要重新蒸餾。 只要狀態是「已清洗」就能按。常見誤解是「補了嵌入設定後要重跑一次蒸餾」——不用，那會白花一次昂貴的 LLM 費用。

2.2 全量重建索引

工具列的「全量重建索引」會把你可存取的所有「已清洗」來源逐一排入索引佇列。按下後先確認（逐字）：

將對您可存取的所有『已清洗』知識來源逐一排入建立/重建索引（背景處理）。索引為增量更新，內容未變動的來源不會重新嵌入，可安全執行。

執行完會彈出「全量重建索引：略過清單」，顯示「已排入重建：N 筆；略過：M 筆。」與每一筆的略過原因。

因為是增量更新（內容沒變的不會重新嵌入、不會重複計費），這個動作可以安心重複執行。適用時機：換了嵌入模型、改了切塊參數、或懷疑索引不完整。

權限：非管理員只看得到「無團隊（公開）或與自己角色團隊有交集」的知識來源；管理員不受限。

3. 管理成員：要加入哪些資料來源、怎麼選

點某筆知識來源的「管理成員」會開啟成員管理視窗。

「成員」是什麼？ 一筆來自下列四種素材、且狀態為「已完成」的素材（1.0.25 起新增第四型「會議紀錄」）：

成員類型來自畫面
影音轉逐字稿/media-transcription
文件轉文字/document-extraction
圖片解讀/image-recognition
會議紀錄（AI 會議紀錄，1.0.25）/meeting（只列「會議紀錄狀態＝已產生」者；索引的是 AI 會議紀錄，非逐字稿）

你可以在同一個知識來源裡自由混搭這四類，並用上／下移調整順序（清洗時會依此順序合併）。

⚠️ 右側「加入素材」的型別下拉，顯示的是素材本身的名稱：影音轉逐字稿／文件轉文字／圖片解讀／會議紀錄（前三個在 1.0.70 已與選單名對齊）。

挑選輔助：右側「加入素材（僅顯示已完成）」除了型別下拉與「搜尋標題」，還有：

  • 「分類過濾」「團隊過濾」兩個多選下拉
  • 排序下拉：最近更新優先 / 最舊更新優先
  • 「上一頁 / 第 N / M 頁（共 K 筆）/ 下一頁」分頁
  • 已加入的素材會顯示「已加入」而不是「加入」按鈕

左側「已加入成員（依順序）」每列有「上移」「下移」「移除」；沒有成員時顯示「尚無成員」。

系統的硬限制（程式強制）：

  1. 只能加入狀態「已完成」的素材。
  2. 只能加入你有團隊權限的素材。
  3. 不可重複加入同一筆素材。

怎麼挑？操作依據（建議，非程式強制）：

一個知識來源 = 一個主題／一個用途。請把「同一主題、同一用途」的素材放在一起。

原因：清洗會把所有成員合併成一份再做摘要與分類。主題太雜，摘要會失焦、分類會變亂、信心分數也會偏低。

好的分組（建議）不好的分組（避免）
「2026 Q2 產品週會」：放該會議的逐字稿＋會議簡報萃取把「產品週會」「客服退款」「員工合約」全丟進同一筆
「客服－退款流程」：放退款通話逐字稿＋退款 FAQ 文件把不同季度、不同專案的會議混在一包
「A 產品使用手冊」：放手冊各章節文件轉文字主題不相關、只是「剛好都已完成」就全加進來

不確定時，寧可拆成多筆、分主題管理（退款、帳務、物流各一筆），日後查找與維護都更輕鬆。

成員順序（上移／下移）有什麼影響？

左側「已加入成員」可用上移／下移調整每筆成員的位置。這個順序就是「合併順序」：

  • 清洗在開始時，會由上而下、依此順序把所有成員內容合併成一份，再送進 LLM。
  • 影響：
  • 清洗結果 Markdown 的正文段落順序會直接反映此排序（每個成員一段）。
  • 間接影響 LLM 產出：模型常把較前面的內容視為主軸，順序會影響摘要重點、建議分類傾向。建議把最關鍵／最具代表性的素材排在前面。
  • 不影響：哪些成員被納入（所有「已完成」成員都會納入，與順序無關）、團隊權控、是否觸發。
  • 重要：調整順序不會自動重跑。 若該筆已是「已清洗／已完成」，重新排序不會改變已產出的結果；要讓新順序生效，需再按一次「清洗」／「產生」重新執行。

成員異動後該怎麼做？（清洗/蒸餾/索引會過期）

當你新增、移除或重排成員，或在其他頁面編輯了某成員的原始內容後，這筆來源既有的「清洗 → 蒸餾 → 索引」結果就過期了——AI 知識問答仍會用到舊內容。

  • 系統會把該筆標記為「內容已變更，建議重新清洗→蒸餾」（清單頁狀態欄顯示提示）。
  • 成員的原始內容在別的畫面被編修，系統也會自動偵測：四種素材型別（影音轉逐字稿／文件轉文字／圖片解讀／會議紀錄）只要在各自畫面編修過文字內容，系統就會把所有引用它的知識來源標記為過時，你不必自己記得哪些來源受影響。刪除素材時還會順便清掉指向它的孤兒成員。
  • 但有兩種情況刻意不標記（因為不影響聚合內容）：①只改素材的標題／分類／團隊等中介資料；②會議把 AI 產出的摘要／決議事項／與會人員套用到欄位（這三個欄位不進知識來源內容，只有 GeneratedContentRelativePath 指向的會議紀錄 .md 全文才算）。
  • 重跑順序：
  • 按「清洗」重新清洗（完成後提示消失）。
  • 按「蒸餾」重新蒸餾（VER-1，0.3.14：產生新版頁，舊現行版轉「已汰換」保留，不刪舊頁）。
  • 蒸餾完成會自動建立索引（若已設定嵌入端點）；也可手動按「建立索引」。
  • 內容變多或變少都會正確反映：變多→新增新版 Wiki 頁與向量；變少→不再產生的概念其舊版轉「已汰換」保留、向量標為非現行而退出檢索（版本化，非刪除）。不需手動處理（詳見 知識庫 RAG 設計與執行 §2.1）。
  • 每個動作的開始與完成都會有畫面訊息通知；處理中清單會自動刷新狀態。

4. 清洗：目的、成果與產出長相

在知識來源按「清洗」，於對話窗選擇要套用的清洗規則設定（或「預設／全域」），系統就會在背景把這包素材清成一份乾淨知識。

清洗會做什麼（依序）：

  1. 彙整：依成員順序把所有內容合併成一份。
  2. 繁體正規化：把簡體轉成台灣繁體（標題保留原文）。
  3. LLM 五步：去重 → 遮罩 → 分類 → 摘要 → 信心自評。
  4. 產出單一 Markdown 並依信心分數路由狀態。

你會得到什麼（清洗結果的固定結構）：

# {知識來源標題}

## 摘要
（約 100–200 字重點摘要；下一行「關鍵實體：」列出重要的人/組織/產品/主題）

## 建議分類
標籤A、標籤B、標籤C

> 註記：（若某步驟降級或未設金鑰才會出現）

---

（這裡是「去重＋遮罩」後的正文，每個成員以「## 類型：標題」分段）

完成後：

  • 信心 ≥ 門檻（預設 0.70） → 直接「已清洗」。
  • 信心 < 門檻或無法評分 → 「待審核」，由具「知識審核」權限者核准或退回。
  • 「建議分類」會自動併入該知識來源的分類欄位。
  • 隨時可「檢視清洗結果」：預覽、複製、線上編修。清洗結果只存成檔案（在 C:\temp\KnowledgeExtraction\CleanedSource\{年}\），不存資料庫。
  • 未設定 OpenAI 金鑰時：清洗只做「彙整＋繁體化」，跳過去重/遮罩/分類/摘要，並在結果開頭加上這行註記（逐字）：

> 註記：未設定 LLM（OpenAI ApiKey），略過去重/遮罩/分類/摘要，僅輸出彙整與繁體正規化內容。

操作建議：

  • 清洗前先把成員的關鍵字修對（人名、料號、專案代號）——錯字會一路被帶到摘要和分類。
  • 高敏感資料（個資、合約）把信心門檻訂保守，刻意讓多數走人工關卡。

5. 清洗到底在做什麼？（常見疑問直答）

Q：清洗是把所有成員的原始內容全部合併成一個新檔案嗎？ 是。系統會把指定知識來源的所有成員依序合併成一份，輸出成一個 Markdown 檔。

Q：那是直接用原文，還是會重新生成內容？兩者都有，要分清楚：

  • 正文＝原始合併內容經「去重＋遮罩」後的版本——保留原意，只移除重複/雜訊與個資。但「去重」是 LLM 操作，可能輕微改動措辭。
  • 摘要與建議分類＝額外新生成的層疊資訊（獨立區塊），不會取代正文。

Q：那會不會跟原意有差異？怎麼防？ 因為去重/遮罩是 LLM 操作，確實有風險，所以系統設了三道把關：

  1. 信心自評＋信心門檻：分數不夠就不自動放行。
  2. 人工審核（待審核 → 核准／退回）。
  3. 清洗品質評測：用標準答案題庫量「遮罩召回率、必保留詞、分類 F1、摘要涵蓋率」，校準門檻。

此外安全設計是「遮罩失敗＝整筆清洗失敗」——寧可重跑，也不讓沒遮乾淨的內容外流。

Q：AI 知識問答，是用清洗後的內容來回答嗎？ 是。乾淨內容會經「蒸餾」煉成互連 Wiki 頁、再自動建立向量索引；之後即可於 AI 知識問答 /knowledge-base-chat 跨來源自然語言問答、附出處、受團隊權控（RAG／向量檢索／問答已於階段三 0.2.123–0.2.128 實作）。清洗的價值是：產出乾淨、去敏、已分類摘要、可信任的知識資產，並可線上預覽與編修，作為蒸餾、索引與問答的基礎。

6. 清洗規則設定（/cleaning-profiles）：五個提示詞欄位

清洗規則設定是一組「配方」，五段提示詞各對應清洗的一個 LLM 步驟。這五段可以留空——留空就用系統內建預設。下面列出每段的用途、內建預設原文與撰寫建議。

除了五段提示詞，表單還有三個欄位（這三個不是提示詞，語意不同）：

欄位（畫面標籤）必填說明
名稱✅清洗時的下拉選單會顯示它；不可與其他設定檔重複（不分大小寫）。建議用「用途＋策略」命名，例如「客服對話-完整保留」
描述—說明採用什麼策略、適合哪種來源，方便日後自己或同事挑選
啟用狀態—控制它是否出現在「清洗」的選單。停用後不能再被新的清洗選用，但先前已使用它的知識來源仍會記得曾套用它（重試時沿用）。想暫時收起某個設定檔又不想刪除時使用

清單欄位為：名稱、描述、啟用狀態、更新時間（預設依更新時間新到舊）。

套用規則：知識來源若指定了設定檔，每個步驟「設定檔有填→用設定檔；留空→用內建預設」，並略過全域AI 提示詞。若未指定設定檔，則改用「AI 提示詞 /prompts」中名為 清洗-去重/遮罩/分類/摘要/信心 的啟用項，再退回內建預設。

6.1 去重提示詞（DedupePrompt）

  • 用途：移除重複段落與明顯雜訊（重複客套、無意義填充），保留有資訊價值的內容、維持原意。輸出成為正文的基礎。
  • 內建預設：

你是資料清洗助手。請移除以下內容中的重複段落與明顯雜訊（重複客套、無意義填充），保留所有有資訊價值的內容，維持原意與繁體中文。直接輸出清理後的內容，不要任何額外說明或前後綴。

  • 撰寫建議：想保留原話（訪談、法律）→ 要求「只刪完全重複、不要改寫」；想精煉（會議、客服）→ 可放寬。務必加上「維持原意」「直接輸出、不要額外說明」。

6.2 遮罩提示詞（MaskPrompt）

  • 用途：把個資與機密以【已遮罩】取代，其餘原樣保留。這步失敗＝整筆清洗失敗，最關鍵。
  • 內建預設：

你是資安遮罩助手。請將以下內容中的個資與機密（身分證號、電話、Email、地址、金融帳號、密碼、金鑰等）以【已遮罩】取代，其餘內容原樣保留，維持繁體中文。直接輸出遮罩後內容，不要任何額外說明。

  • 撰寫建議：依產業明列要遮的項目（如統一編號、病歷號、合約金額）；同時明列「必須保留」的關鍵詞（如退款規則、條款用語），避免誤遮。

6.3 分類提示詞（ClassifyPrompt）

  • 用途：建議主題標籤，會併入知識來源分類，幫助日後查找。內建預設建議 1–5 個；系統最多保留 10 個標籤，故設定檔可要求更細的分類。
  • 內建預設：

請閱讀以下內容，建議 1-5 個最貼切的主題分類標籤。僅輸出分類名稱、以「、」分隔於同一行，不要其他文字。

  • 撰寫建議：可限定分類詞庫（如「只從：客服、財務、物流、技術 中挑」），分類會更一致；想分得更細可要求涵蓋多個面向（主題、對象、情境、產品／流程），最多保留 10 個。務必維持「以、分隔、單行、不要其他文字」的輸出格式，否則解析會受影響。

6.4 摘要提示詞（SummaryPrompt）

  • 用途：產生重點摘要與關鍵實體列表，放在結果最上方。
  • 內建預設：

請為以下內容寫一段約 100-200 字的繁體中文重點摘要；摘要後另起一行，以「關鍵實體：」開頭列出重要的人/組織/產品/主題（以「、」分隔）。直接輸出，不要額外說明。

  • 撰寫建議：可指定輸出格式讓產出穩定好讀，例如會議要求「分『決議』『待辦』『負責人』三段條列」。

6.5 信心自評提示詞（ConfidencePrompt）

  • 用途：讓模型自評清洗結果整體正確/完整的信心，輸出 0–1 小數。分數會與門檻（預設 0.70）比較決定「已清洗」或「待審核」。
  • 內建預設：

請評估你對上述清洗結果（去重、遮罩、摘要、分類）整體正確與完整的信心，僅輸出 0 到 1 之間的一個小數（例如 0.85），不要任何其他文字。

  • 撰寫建議：高敏感場景可要求「對遮罩有疑慮就給較低分」，把更多結果推向人工審核。務必維持「只輸出一個 0–1 小數」的格式。

6.6 快速上手：三種預設範本按鈕與欄位說明圖示

第一次使用不知道各欄位怎麼填？畫面上有兩個輔助功能：

（一）三顆「預設範本」按鈕（清單頁工具列）

清洗規則設定頁面工具列（新增／重新整理 旁）有三顆範本按鈕。按下後會開啟新增表單並自動帶入該範本的名稱、描述與五段提示詞，你可以先檢視、微調（例如改名、依產業補上要保留的關鍵詞）再按確定儲存。除了快速上手，也能藉此學習提示詞的寫法。

範本保留程度適用情境
最大保留範本最高：幾乎不去重、只遮最高風險機密（密碼／金鑰／完整卡號）、分類 5–10 個怕漏細節、需要完整內容做AI 知識問答的來源
低度清洗範本高：只移除明顯重複與雜訊、僅遮最敏感個資（身分證／金融帳號／密碼／金鑰），姓名、電話、Email、地址等保留想保留大部分內容、又要基本去敏
中度清洗範本中：標準去重、遮罩常見個資但保留姓名、分類適中想要乾淨去敏又不要砍太多的一般來源

三者保留程度由高到低為：最大保留 ＞ 低度清洗 ＞ 中度清洗 ＞（系統全域預設）。也就是說，即使是「中度清洗」，保留的內容也比「未選任何設定檔（預設／全域）」更多——這正是為了解決「清洗後原有內容常常消失」的痛點。範本名稱後綴「（範本）」，儲存前可自行改名；名稱不可與既有設定檔重複。

（二）欄位說明圖示（游標移上顯示用法）

新增／修改表單的每個欄位標籤旁都有一個「?」說明圖示，游標移上去會顯示該欄位的詳細用法：該填什麼、留空會怎樣、清洗後會得到什麼結果。搭配上述範本，第一次使用也能快速理解每個提示詞的作用。

7. 5 個實際清洗規則設定範例（含清洗後會看到什麼）

以下每個範例給「情境 → 五欄位填法 → 清洗後會看到什麼」。留空＝用內建預設，故只列出需要客製的欄位。

範例 1：會議知識（摘要要「決議／待辦／負責人」）

  • 情境：產品週會逐字稿，要快速看到決議與待辦。
  • 設定：摘要提示詞＝「請寫繁體中文摘要，並分『決議』『待辦』『負責人』三段條列；最後一行以『關鍵實體：』列出人/產品/專案。直接輸出。」；其餘留空。
  • 清洗後：## 摘要 直接呈現三段條列（決議／待辦／負責人），## 建議分類 出現如「產品、會議、規劃」，正文為去重遮罩後的逐字稿。信心多半 ≥0.70 自動「已清洗」。

範例 2：客服－退款流程（遮罩客戶個資、保留退款規則）

  • 情境：退款通話逐字稿＋退款 FAQ。
  • 設定：遮罩提示詞＝「將客戶姓名、電話、Email、訂單號、信用卡號以【已遮罩】取代；務必保留退款金額規則、計費條件、處理時效等業務用語。直接輸出。」；分類提示詞＝「只從：客服、財務、物流、退款 中挑 1–3 個。以、分隔單行。」
  • 清洗後：正文中客戶個資變【已遮罩】，但「7 日內全額退款」「運費不退」等規則完整保留；分類落在客服/財務/退款。建議拿一筆相近黃金樣本評測，確認「該遮的遮掉、該留的留住」。

範例 3：HR／合約（高敏感，門檻保守）

  • 情境：合約 PDF＋員工名冊，個資極敏感。
  • 設定：遮罩提示詞＝「強化遮罩：身分證號、統一編號、金融帳號、薪資數字、密碼、住址以【已遮罩】取代；保留合約條款編號與關鍵條款用語。直接輸出。」；信心自評提示詞＝「若對任何個資是否遮乾淨有疑慮，請給較低分。只輸出 0–1 小數。」；並把系統信心門檻訂保守。
  • 清洗後：個資被嚴格遮罩、條款用語保留；信心常 <0.70 自動進「待審核」，由具「知識審核」權限者確認後核准/退回。寧可多走人工關卡。

範例 4：技術文件／FAQ（強去重、技術分類）

  • 情境：多份重疊的產品手冊、FAQ，重複內容多。
  • 設定：去重提示詞＝「積極移除重複說明與重出的步驟，合併同義段落，保留所有設定值、指令、參數與限制，維持原意。直接輸出。」；分類提示詞＝「只從：安裝、設定、疑難排解、API、限制 中挑 1–5 個。以、分隔單行。」
  • 清洗後：正文大幅精簡、重複段落消失，但指令/參數/限制完整；分類偏技術主題；摘要列出關鍵實體（產品名、模組）。適合當成內部知識庫底稿。

範例 5：研究／訪談（輕去重保留原話）

  • 情境：受訪者逐字稿，需保留語氣與原話供引用。
  • 設定：去重提示詞＝「僅移除完全重複的句子與口頭語贅字（嗯、那個…），不要改寫或精簡語句，保留受訪者原話與順序。直接輸出。」；摘要提示詞＝「寫 150 字內主題摘要，並以『關鍵實體：』列出受訪者、機構、議題。直接輸出。」
  • 清洗後：正文幾乎是原話（僅去贅字），可安心引用；上方有研究主題摘要與關鍵實體；分類落在研究主題。

提醒：所有範例都假設已設定 OpenAI 金鑰。未設金鑰時清洗只做彙整＋繁體化，不會有摘要/分類/遮罩。

8. 新手操作步驟（端到端）

  1. 準備素材：到 /media-transcription、/document-extraction 或 /image-recognition（圖片解讀），把素材轉成文字並確認狀態「已完成」。
  2. 建立知識來源：/knowledge-sources →「新增」，填標題、描述，設定分類與團隊。
  3. 管理成員：按「管理成員」，挑同主題的已完成素材加入，調整順序。
  4. （選配）建立清洗規則設定：/cleaning-profiles →「新增」，依第 6、7 節填你需要客製的欄位（其餘留空用預設）。
  5. 清洗：回知識來源按「清洗」，選設定檔（或「預設／全域」）。
  6. 看結果：背景完成後「檢視清洗結果」，預覽摘要/分類/正文，必要時線上編修。
  7. 審核（若為待審核）：具「知識審核」權限者核准或退回（填理由）。
  8. （選配）校準品質：到 /golden-samples 建標準答案題庫並「評測」，依建議調整信心門檻與提示詞。

9. 常見誤用與注意事項

  • 主題混雜：一筆知識來源塞太多不相關素材 → 摘要失焦、分類變亂、信心偏低。分主題拆多筆。
  • 未設 OpenAI 金鑰：清洗只會彙整＋繁體化，沒有去重/遮罩/分類/摘要。需要這些就先填金鑰並重啟。
  • 遮罩失敗＝整筆清洗失敗：這是刻意的安全設計，避免個資外流。失敗請重跑或檢查遮罩提示詞與金鑰。
  • 先修關鍵字再清洗：成員裡的人名/料號/專案代號錯字會一路帶到摘要與分類。
  • 格式要求別省略：分類要「以、分隔、單行」、信心要「只輸出 0–1 小數」，破壞格式會影響解析。
  • 高敏感場景門檻訂保守：刻意讓多數走人工審核，比全自動更安心。
