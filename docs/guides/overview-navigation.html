一、這個系統把什麼變成什麼

一句話：把零散的素材（會議錄音、影片、PDF/Office 文件、圖片）變成「乾淨、去敏、可被自然語言問答、附出處、且受團隊權限控管」的知識資產。

它解決的痛點：資料散在各處、含個資不敢用、找不到、AI 答了卻不知道依據在哪、不同人不該看到不同內容。本系統把這條路一站一站打通，並讓品質可被量測。

二、5 分鐘心智模型（資料怎麼流動）

一句話：匯入素材 → 聚合成知識來源 → 清洗（去重/遮罩/分類/摘要/信心）→ 蒸餾成互連 Wiki → 自動索引 → 跨來源附出處問答；旁支以清洗品質評測量上游清洗品質、檢索品質評測量下游檢索品質（越權＝0）。

完整資料流圖與每一站的逐項說明，見 完整操作手冊 的 §二「整體系統架構與資料流」。

三、功能總覽（依左側選單）

系統左側選單分八大群組：首頁、專案協作、資料匯入、知識庫、系統管理、基礎資料設定、統計報表、登出。其中「首頁」與「登出」是單一畫面，其餘六組有子項。

「系統管理」底下還有三個子分類（要多點一層）：

子分類底下的畫面
權限管理使用者管理、角色管理
系統監控統計儀表板、系統健康監控、待處理背景工作、資料表使用狀況
診斷與日誌檢索診斷與調校、資料一致性巡檢、日誌等級切換、日誌下載
AI 與整合問答稽核明細、完整對話紀錄、Token 用量明細、MCP 金鑰管理

各畫面的路由、職責與彼此的上下游（產出/消費）關係，見 完整操作手冊 的 §三「畫面地圖與彼此關係」；每個畫面對應的深入指南，見下方 §四 導覽地圖。

⚠️ 設定角色權限前先看對照表：「角色管理」的權限樹上，項目名稱刻意保留舊名，跟左側選單看到的名稱不一樣（例如選單「知識百科」＝權限樹「知識瀏覽」）。完整對照見 完整操作手冊 §3.1 選單名 ↔ 權限樹名 對照表。

知識庫群組另有「知識圖譜審核」（/knowledge-graph-review，1.0.84 起）：審核 AI 從已核可 Wiki 頁抽出的「實體—關係—實體」三元組、維護實體別名、瀏覽圖譜鄰域、重建供「全域問答」用的社群摘要。它是 Wiki 頁核可後的下游能力，見 知識圖譜（Graph RAG）使用指南。

對外整合入口：除了畫面操作，系統另提供 MCP Server（端點 /mcp），讓外部 AI Agent（Claude／Codex 等）以標準協定查詢知識庫、沿用同一團隊權控。見 MCP 服務使用說明書。1.0.96 起另有兩支唯讀 REST 端點（/api/v1/KnowledgeGraph/global-ask、.../neighbors）供不講 MCP 協定的系統整合。

五、推薦上手路徑

Day-1（先把一條路走通）

  1. 安裝、啟動、用預設帳號登入 → 安裝手冊。
  2. 建好團隊、分類、角色、你自己的管理員帳號 → 基礎設定指南。
  3. 匯入一份素材（先挑一段乾淨的會議錄音或一份 PDF）→ 資料匯入指南。
  4. 建知識來源、加入剛匯入的成員、標上團隊、按「清洗」→ 檢視清洗結果 → 知識來源加工與清洗規則設定指南。

進階（把知識變成可問答、可信任）

  1. 設定嵌入端點（雲端金鑰或地端 bge-m3）→ 對已清洗來源按「蒸餾」，系統自動建索引 → PoC 指南 §2.1。
  2. 到AI 知識問答提問、檢查出處與權控 → PoC 指南。
  3. 用清洗品質評測 / 檢索品質評測把品質數字化、建立回歸基準 → 檢索品質評測使用指南。

選配（讓 AI 答得出「關聯」與「綜觀」）

  1. 先在「知識頁審核」把 Wiki 頁核可（沒核可就抽不出關係）→ 對該來源按「抽取／重抽三元組」→ 到「知識圖譜審核」核可三元組 → 按「重建社群摘要」→ 回問答頁把查詢模式切到「全域」試問一題綜觀型問題 → 知識圖譜（Graph RAG）使用指南。

六、角色別入口（你是誰、先讀哪些）

  • 操作人員：本頁 → 資料匯入指南 → 知識來源加工與清洗規則設定指南。
  • 系統管理員：本頁 → 安裝手冊 → 基礎設定指南（特別是角色權限與團隊權控）→ 知識圖譜使用指南（實體合併與社群摘要重建僅管理員可做）。
  • 知識庫管理者 / QA：本頁 → PoC 執行與驗收指南 → 檢索品質評測使用指南 → 知識圖譜使用指南（三元組審核是知識維護者的日常工作）。
  • 導入顧問：全部；以 PoC 指南為交付主軸。

七、名詞速覽

本節是共用短版術語表（使用者安裝與操作手冊、完整操作手冊、實作練習手冊 都指向這裡）。想看更白話、附舉例的完整版，見 新手完整操作指南 §十八。

名詞白話解釋
知識來源一個主題單位，聚合多筆匯入素材（成員），是清洗/蒸餾/權控的主體
成員知識來源底下的一筆素材（某段逐字稿/某份文件/某張圖的解讀）
清洗去重、遮罩個資、分類、摘要、信心自評，產出乾淨 Markdown
遮罩把姓名/電話/Email/身分證/帳號等敏感資訊蓋掉
蒸餾把乾淨內容煉成「一概念一頁、互相連結」的 Wiki 頁
chunk（切塊）為了檢索把內容切成的小段落
嵌入把文字轉成向量，讓系統能做語意比對
索引把 chunk 的向量存進向量庫，供檢索
檢索依問句找出最相關的 chunk（向量＋關鍵字混合）
出處答案引用的來源（可鑽取回知識來源 → 成員 → 原始檔）
團隊權控非管理員只看得到「公開或與自己團隊交集」的內容
清洗品質評測量「上游清洗品質」（遮罩召回、分類、摘要…）
檢索品質評測量「下游檢索品質」（找得到/找得準/越權=0/延遲）
實體知識圖譜裡的一個名詞（人／組織／產品／系統／概念），例如「客戶A ERP系統」
三元組「實體—關係—實體」一組，圖譜的最小單位，例如「客戶A ERP系統 — 部署於 → Windows Server 2022」。AI 抽出後須人工核可才會影響檢索
實體別名「別名 → 標準名」對照（如 TSMC → 台積電），核可後變體視為同一實體
社群摘要關係緊密的一群實體，系統替每群寫的一份摘要；「全域問答」就是拿這些摘要來答
跳數從命中的內容沿關係往外走幾步（1～3）。2 跳才找得到「A 透過 B 連到 C」這種關聯
圖分混合檢索的第三路分數（向量＋關鍵字＋圖）；權重是 GraphWeight，設 0 即關閉
