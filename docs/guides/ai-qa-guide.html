AI 知識問答使用指南

一、AI 知識問答在做什麼？（為什麼需要）

一句話：用自然語言對「整個知識庫」提問，得到「附出處、且只包含你有權看的內容」的答案。

它解決的痛點：知識散在多份來源、人工翻找慢、AI 答了卻不知依據在哪、不同人不該看到不同內容。AI 知識問答用混合檢索（向量＋關鍵字）跨來源找出最相關片段，組成參考資料給 LLM 作答，並附上可鑽取回原始檔的出處，全程受團隊權控。

二、開始前的前提

  • 要能跨來源語意問答，知識來源需走完「已清洗 → 已蒸餾 → 已索引」，且已設定嵌入端點。前置見 PoC 指南 §2.1。
  • 若未設定嵌入，新索引無法建立向量；檢索服務仍可用既有資料做關鍵字路徑，但不等於完整的跨來源語意檢索。

三、操作步驟（頁面各控制項）

進入：登入後預設直接落在本頁；亦可從選單「知識庫 → AI 知識問答」(/knowledge-base-chat) 進入。權限樹上要勾的是 知識庫問答（刻意保留的舊名，對照見 完整操作手冊 §3.1）。

標題列的三顆按鈕：

按鈕作用
新對話清空畫面上的問答並開始新的一段對話（sessionId 重置，下次送出時才產生新識別碼，不會留下 0 輪的空對話）。設定面板的所有條件與輸入框草稿都保留。串流中此鈕停用（要中斷請按「停止」）。1.0.105 起
我的對話開啟抽屜列出你自己的歷史對話，可關鍵字搜尋、回看與「繼續對話」。見 §3.1
系統提示詞設定展開/收合下方設定面板；展開後按鈕文字會變成「收合設定」

設定面板（按「系統提示詞設定」展開）：

  • 查詢模式：一般（精準檢索）（預設）/ 全域（社群摘要）。這是兩種性質不同的問答方式，不是效能開關：
  • 一般：走混合檢索（向量＋關鍵字＋圖），適合具體事實、條款、步驟、數字。有出處面板可鑽取回原始檔。
  • 全域：走知識圖譜的社群摘要 map-reduce，適合「整體風險有哪些」「反覆出現的系統性問題是什麼」這類要看過全部才答得出的問題。⚠️ 沒有出處面板、沒有相似度（改顯示取用社群數）、不套用下方的限定來源／分類／團隊篩選，且成本是「每個你有權存取的社群各一次 LLM」。
  • 前置：管理員需先在「知識庫 → 知識圖譜審核」按過「重建社群摘要」；從未重建時系統會回可行動的原因說明，不是空白。詳見 知識圖譜（Graph RAG）使用指南 §六。
  • 回答詳簡：簡潔 / 標準（預設）/ 詳細。
  • 套用既有提示詞：從清單挑一個提示詞帶入系統提示詞欄（仍可編輯）。
  • 系統提示詞：可留空（用內建知識庫助理提示詞），也可自訂；變更後下一則訊息起生效。
  • 限定知識來源 / 限定分類 / 限定團隊（多選）：把檢索範圍縮小到選定的知識來源、分類或團隊；留空＝在你有權限的整個知識庫範圍內問答。此為查詢期篩選，改選即於下一則訊息生效、不需重建索引，且疊加在團隊權控之上（只會縮小、不會讓你看到無權限內容）。適合「多客戶／多系統／多團隊」情境下只問某一套範圍。
  • 知識來源 / 分類篩選 0.3.22 起；團隊篩選 0.3.36 起。
  • 「限定分類」下拉只列出你可存取知識中實際用到的分類；「限定團隊」下拉只列出你可存取的團隊（管理員為全部啟用團隊）。兩者預設皆留空＝全部。

對話：

  • 在底部輸入框打問題 → 「送出」；回答以串流逐字呈現。
  • 串流中可按「停止」中止。每則 AI 回答下方為同一列常駐的動作按鈕：複製 / 下載 PDF / 滿意 / 不滿意。
  • 支援多輪：系統會帶入先前對話作為脈絡；若你問「它有哪些限制？」、「剛剛那個怎麼處理？」這類短問句，系統會先把問題補全成可檢索的查詢，再去找資料。

3.1 我的對話與繼續對話

按標題列的「我的對話」會滑出抽屜（標題就是「我的對話」），列出你自己在本頁的歷史對話：

  • 每列顯示：對話標題（取自首輪提問，過長會截斷）、藍色「N 輪」標籤、時間；知識來源對話還會附上來源標題。
  • 每頁 10 筆；沒有紀錄時顯示「尚無對話紀錄」。
  • 關鍵字搜尋（1.0.105 起）：抽屜最上方有搜尋框，輸入後按 Enter 或「搜尋」即可篩選；比對範圍是對話標題與該段對話各輪的提問文字，不含 AI 回答，所以第 2 輪以後才問到的關鍵字也找得到。按「清除」回到完整清單；換關鍵字會自動回到第 1 頁；關閉再開抽屜時關鍵字會重置。
  • 實作上提問文字另存於 LlmChatSession.QuestionsIndex（各輪提問以換行串接、上限 4000 字），因此搜尋與分頁都由 SQL 完成。本功能上線前的舊對話由啟動時的一次性回填補齊。
  • 點任一列進入詳細頁，可看整段問答，每輪下方有「設定：」摘要當時的條件（詳簡、套用的提示詞、有無自訂系統提示詞、分類、團隊、限定來源幾個）。
  • 詳細頁上方有「← 返回清單」與「繼續對話」。按「繼續對話」會把那段對話載回主畫面，你可以接著問下去。

這個抽屜只看得到你自己的對話（系統會驗證帳號，別人的讀不到）。管理員若要查全部使用者的對話，用「系統管理 → AI 與整合 → 完整對話紀錄」（/chat-sessions）。

3.2 你的回饋去哪裡了

按「滿意」👍／「不滿意」👎 之後（再按同一顆＝取消）：

  • 明細會進「系統管理 → AI 與整合 → 問答稽核明細」（/chat-logs），管理員看得到你問了什麼、系統答了什麼、當時的信心與 topScore。
  • 統計會匯總進「統計報表 → AI 回答滿意度」與「問答使用統計」。

提醒：問答的問句與回覆全文會保留在伺服器的實體檔案（刻意的稽核設計，僅管理員可查閱）。這不是「匿名統計」——填入機密內容前請留意。

四、出處面板：鑽取與下載

⚠️ 本章只適用於「一般（精準檢索）」模式。「全域（社群摘要）」模式沒有出處面板、也沒有相似度，改為顯示取用了幾個社群——社群摘要是跨多筆來源歸納後的產物，本來就沒有對應到某一段原文的位置。要追出處請切回一般模式再問一次具體問題。

每則 AI 回答下方會列出「出處（N）」。出處明細預設收合（查詢後先不展開每一筆內容），標題右側提供「展開／收合」切換按鈕：按「展開」後列出全部出處明細、按鈕變為「收合」；再按即收回。每則回答的出處面板各自獨立收合。

展開後每筆命中包含：

  • 層別標籤：藍色標籤文字是「蒸餾頁」（Wiki，概念導引）、綠色是「清洗內容」（Cleaned，事實佐證）。
  • 來源標題（過長時滑鼠移上看全文）、錨點（如章節/條款）、相似度分數（融合分數，固定三位小數，如「相似度 0.423」，越高越相關）、文字片段（截斷 160 字）。
  • 出處區標頭是「出處（N）」，預設收合，按「展開」/「收合」切換。
  • 鑽取來源：展開後列出該來源的成員（影音轉逐字稿/文件轉文字/圖片解讀）。
  • 下載原始檔：對有權限的成員可下載原始素材（音訊/文件/圖片各自的受權控端點）。

這條鑽取鏈讓答案可一路回溯：命中片段 → 來源 → 成員 → 原始檔，是「答案可信」的關鍵。

五、權控如何運作（資安關鍵）

  • 每一輪問答都會重新取得你的存取範圍（避免身分切換後沿用舊權限）。
  • 多輪短問句的查詢補全只影響檢索文字，不會放寬權限；仍只會檢索你有權看到的公開或團隊資料。
  • 非授權團隊的內容由檢索層直接過濾，不會進入參考資料、答案或出處；出處面板的成員標題也受權控（無權者顯示「（無權限）」）。
  • 找不到依據時，系統會由程式直接回覆「查無相關依據」並不呼叫 LLM、不臆造（見下節「兩段式信心提示」）。
  • 全域（社群摘要）模式的權控更嚴：社群摘要採子集判定——社群涵蓋來源的團隊聯集必須是你的團隊的子集，或該社群完全公開，你才取用得到。理由是一份摘要混了多筆來源的知識，其中任一筆你無權看，整份就不能給。這是全系統唯一採子集判定的地方（其餘紀錄都是交集判定）。
  • 知識圖譜的加分也受權控：他人團隊的三元組即使兩端頁面都是公開的，也不會替你加分——「這兩者之間有關係」本身就是一項知識，歸屬於抽出它的來源所在團隊。多跳遍歷的每一跳都重新驗權限，不能借道無權限節點繞路。

5.1 兩段式信心提示

系統會依檢索到的最相關內容「分數高低」決定回應方式，避免知識庫其實沒有相關內容卻硬答：

  • 查無依據：最相關內容分數仍太低（或完全沒命中）時，回覆固定訊息「您的問題在知識庫中查無相關依據…」，不附出處。請換更精確的問法，或確認該主題是否已納入知識庫。
  • 信心不足：有命中但分數偏低時，仍會回答，但會在回答最前面標示「⚠️ 信心不足：知識庫中僅找到弱相關內容，以下回答僅供參考。」——請務必展開出處核對。
  • 正常回答：分數足夠時正常作答並附出處。

判定門檻不必改設定檔、也不必重啟。 appsettings.json 的 RejectThreshold（0.15）與 LowConfidenceThreshold（0.30）只是預設值；管理員可在「系統管理 → 診斷與日誌 → 檢索診斷與調校」（/rag-diagnostics）手動輸入或「套用建議值」，下一則問答就生效（覆寫存在資料庫）。該頁會顯示「頁面覆蓋中」徽章與覆蓋時間/覆蓋者，也可清除覆寫還原成 appsettings 的值。

同一頁還能熱套用查詢期檢索參數 TopK／CandidateTopK／VectorWeight／KeywordWeight／MinScore（下一次檢索生效）。唯一不能熱套用的是切塊參數（ChunkTargetChars 等）——那個改了必須重建索引才生效。

也就是說：你在 appsettings 看到的值不一定是當前生效值，要確認實際生效值請看 /rag-diagnostics。詳見 知識庫 RAG 設計與執行 §4.1。

六、怎麼問得到好答案（建議）

  • 問具體、單一意圖：一次問一件事；把關鍵詞講清楚（如「入職滿三年的健康檢查福利」優於「福利」）。
  • 多輪追問可自然一點：前一輪已經講清楚主題時，可以問「它的限制？」或「那要怎麼設定？」；系統會嘗試補全檢索查詢。但涉及數字、條款、專案名時，仍建議把關鍵字講出來。
  • 善用詳簡：要點用「簡潔」，要完整說明用「詳細」。
  • 先看出處再採信：展開出處、必要時下載原始檔核對，特別是涉及數字/條款的答案。
  • 答非所問或查無依據時：換更精確的問法，或確認該主題是否已清洗/蒸餾/索引。
  • 用系統提示詞調風格：例如要求「條列、附條款編號、不確定就說不知道」。

七、常見問題（FAQ）

問題說明
問什麼都「查無依據」最常見原因是向量索引從未建立（例如內容在索引功能上線前就蒸餾）。管理員請到「知識來源加工」，對已清洗來源按「建立索引」（不需重蒸餾），完成後即可問答；也可在 /system-health 看「向量索引涵蓋率」。管理員在問答頁查無依據時也會看到診斷提示。若主題確實在庫內卻被誤判，到 /rag-diagnostics 調降 RejectThreshold 並套用即可（免改設定檔、免重啟，下一則問答生效）。
短問句（如只打「RAG」）沒有被自動補全設計使然：查詢改寫只在「有對話歷史」且問句依賴上下文時才啟動，避免把單一關鍵詞亂擴寫。第一句請把問題講完整（如「RAG 是什麼？」）；索引建好後單一關鍵詞通常也能命中。
回答最前面出現「⚠️ 信心不足」表示僅找到弱相關內容、屬正常提醒；請展開出處核對，或換更精確的問法。
出處下載不了你對該成員所屬團隊無權限，或原始素材已不存在。
看不到別人團隊的內容正常，團隊權控；管理員或具該團隊者才看得到。
答案太長／太短調「回答詳簡」。
多輪追問答非所問系統會自動補全短問句，但仍可能判斷錯主題；請把主詞補上，例如「RAG Query Rewrite 的限制是什麼？」。
想換回答風格/語氣在系統提示詞自訂，或套用既有提示詞。
串流跑很久可按「停止」保留已生成部分；或縮小問題範圍。
什麼時候該用「全域」模式問題是「整體風險有哪些」「反覆出現的系統性問題是什麼」這種要看過全部才答得出的類型時。具體條款、數字、步驟一律用「一般」模式——那才有出處可核對。
全域模式沒有出處，是壞了嗎不是，設計如此。社群摘要是跨多筆來源歸納後的產物，沒有對應到某一段原文的位置；改顯示取用社群數。
全域模式說「沒有可用社群」管理員需先到「知識庫 → 知識圖譜審核」按「重建社群摘要」。這是部署後最常漏掉的一步。
問「A 和 C 有什麼關聯」答不出來這需要知識圖譜的多跳能力：確認該來源的 Wiki 頁已核可 → 已抽取三元組 → 三元組已核可（待審核的不算）→ 管理員在 /rag-diagnostics 確認 GraphWeight 生效值不為 0。詳見 知識圖譜使用指南。
