KMEngine Windows Server 2025 安裝與設定手冊

將以 .NET 10、ASP.NET Core、Blazor 開發的 KMEngine 部署到 Windows Server 2025 與 IIS

  • 文件用途：將以 .NET 10、ASP.NET Core、Blazor 開發的 KMEngine 部署到 Windows Server 2025 與 IIS
  • Web 專案目錄：C:\KMEngine
  • 可攜式工具目錄：C:\KMEngineTools
  • 適用作業系統：Windows Server 2025（建議 Desktop Experience、64 位元）
  • 文件版本：1.1（新增 §7.2 正式環境必改項、PDF LLM 設定與排錯、可攜工具腳本、MCP 部署、日誌下載）
  • 更新日期：2026/07/26
  • 對應系統版本：1.0.71
  • 主要讀者：系統管理員、部署人員、維運人員

本手冊以 publish.zip 與 KMEngineTools.zip 為部署來源。正式安裝前，請確認壓縮檔來自可信來源，並保留原始檔與 SHA-256 雜湊值供日後稽核。

目前發佈檔是 framework-dependent deployment，KnowledgeExtraction.Web.runtimeconfig.json 指定：

  • Microsoft.NETCore.App 10.0.0
  • Microsoft.AspNetCore.App 10.0.0
  • Target Framework：net10.0

因此伺服器必須安裝相容的 .NET 10 Runtime；在 IIS 上執行時，還必須安裝 .NET 10 Hosting Bundle，讓 IIS 取得 ASP.NET Core Module V2。

2. 安裝前準備

請準備：

  1. Windows Server 2025 系統管理員帳號。
  2. publish.zip。
  3. KMEngineTools.zip。
  4. OpenAI API Key。
  5. 若要下載 YouTube：可登入 YouTube 的 Microsoft Edge。
  6. 若要下載抖音：可互動登入抖音的桌面工作階段。
  7. 建議建立 C:\Install，把兩個 ZIP 放入此目錄。

檢查檔案並記錄 SHA-256：

Get-FileHash "C:\Install\publish.zip" -Algorithm SHA256
Get-FileHash "C:\Install\KMEngineTools.zip" -Algorithm SHA256

2.1 管理命令列

IIS 角色安裝與 IIS 設定，請使用以系統管理員身分執行的 Windows PowerShell 5.1（powershell.exe）。安裝 PowerShell 7 後，日常維運可使用 pwsh；但 WebAdministration 的 IIS:\ Provider 在 Windows PowerShell 5.1 最直接。

2.2 確認 WinGet

Windows Server 2025 Desktop Experience 內含 WinGet，但第一次登入後可能尚未完成註冊：

winget --version

若找不到 winget，先嘗試：

Add-AppxPackage -RegisterByFamilyName -MainPackage Microsoft.DesktopAppInstaller_8wekyb3d8bbwe

重新開啟 PowerShell 後再檢查。Server Core 不提供完整 Desktop Experience；本專案的抖音／YouTube 互動登入流程建議使用 Desktop Experience。

3. 安裝與設定 IIS

原始需求中的 Web-Server 指令重複，可合併成一個命令。以系統管理員開啟 Windows PowerShell 5.1，執行：

Import-Module ServerManager

Install-WindowsFeature `
  -Name Web-Server,Web-WebSockets,Web-Scripting-Tools `
  -IncludeManagementTools

其中：

  • Web-Server：IIS Web Server。
  • Web-WebSockets：Blazor／SignalR 連線所需。
  • Web-Scripting-Tools：IIS PowerShell 管理工具。
  • -IncludeManagementTools：安裝 IIS Manager。

驗證：

Get-WindowsFeature Web-Server,Web-WebSockets,Web-Scripting-Tools,Web-Mgmt-Console |
  Select-Object Name,InstallState

四項應顯示 Installed。

5. 解壓網站與工具

5.1 建立目錄

New-Item -ItemType Directory -Path "C:\KMEngine" -Force
New-Item -ItemType Directory -Path "C:\KMEngineTools" -Force
New-Item -ItemType Directory -Path "C:\temp\KnowledgeExtraction" -Force
New-Item -ItemType Directory -Path "C:\temp\Logs" -Force

5.2 首次部署：完整解壓所有檔案

下列方式只適用於第一次安裝且 C:\KMEngine 是全新或空白目錄。第一次部署必須把 publish.zip 的所有內容完整解壓，包括 appsettings.json 與 appsettings.Production.json：

Expand-Archive -LiteralPath "C:\Install\publish.zip" `
  -DestinationPath "C:\KMEngine" -Force

Expand-Archive -LiteralPath "C:\Install\KMEngineTools.zip" `
  -DestinationPath "C:\KMEngineTools" -Force

if (-not (Test-Path "C:\KMEngine\appsettings.Production.json")) {
    throw "首次部署缺少 appsettings.Production.json，請檢查 publish.zip。"
}

也可以用 7-Zip：

  1. 把 publish.zip 的全部內容解壓到 C:\KMEngine，不要取消選取任何設定檔。
  2. 把 KMEngineTools.zip 內容解壓到 C:\KMEngineTools。

重要：「完整解壓」只適用於首次部署。日後更新不得直接把新版 ZIP 解壓到 C:\KMEngine，否則可能覆蓋正式環境的 API Key、工具路徑及其他設定。後續更新必須依第 13.1 節及附錄 B 排除 appsettings.Production.json。

6. 設定 IIS Application Pool 與網站

6.1 使用 IIS Manager

  1. 開啟 IIS Manager。
  2. 進入 Application Pools。
  3. 新增 Application Pool：
  4. Name：KMEngineAppPool
  5. .NET CLR version：No Managed Code
  6. Managed pipeline mode：Integrated
  7. 選取 KMEngineAppPool，開啟 Advanced Settings：
  8. Process Model > Idle Time-out (minutes)：從 20 改為 0
  9. General > Enable 32-Bit Applications：維持 False
  10. 選取 Default Web Site，點選 Basic Settings：
  11. Application Pool：KMEngineAppPool
  12. Physical Path：C:\KMEngine
  13. 確認網站已啟動。

6.2 使用腳本完成相同設定

請在系統管理員 Windows PowerShell 5.1 執行：

Import-Module WebAdministration

if (-not (Test-Path "IIS:\AppPools\KMEngineAppPool")) {
    New-WebAppPool -Name "KMEngineAppPool"
}

Set-ItemProperty "IIS:\AppPools\KMEngineAppPool" `
  -Name managedRuntimeVersion -Value ""

Set-ItemProperty "IIS:\AppPools\KMEngineAppPool" `
  -Name processModel.idleTimeout -Value ([TimeSpan]::Zero)

Set-ItemProperty "IIS:\AppPools\KMEngineAppPool" `
  -Name enable32BitAppOnWin64 -Value $false

Set-ItemProperty "IIS:\Sites\Default Web Site" `
  -Name applicationPool -Value "KMEngineAppPool"

Set-ItemProperty "IIS:\Sites\Default Web Site" `
  -Name physicalPath -Value "C:\KMEngine"

6.3 設定檔案權限

網站程式只需要讀取／執行程式與工具；資料與記錄目錄需要修改權限：

icacls "C:\KMEngine" /grant "IIS AppPool\KMEngineAppPool:(OI)(CI)RX" /T
icacls "C:\KMEngineTools" /grant "IIS AppPool\KMEngineAppPool:(OI)(CI)RX" /T
icacls "C:\temp\KnowledgeExtraction" /grant "IIS AppPool\KMEngineAppPool:(OI)(CI)M" /T
icacls "C:\temp\Logs" /grant "IIS AppPool\KMEngineAppPool:(OI)(CI)M" /T

權限不足時，SQLite 可能出現 readonly database，上傳／轉錄也可能出現 Access denied。

7. 設定 appsettings

7.1 應修改哪個檔案

目前發佈套件同時包含 appsettings.json 與 appsettings.Production.json。第一次部署時兩個檔案都必須複製到 C:\KMEngine；正式環境的 API Key、工具路徑、資料目錄及其他環境差異，統一在 C:\KMEngine\appsettings.Production.json 調整。

  • appsettings.json：應用程式共用預設值，可隨新版程式更新。
  • appsettings.Production.json：伺服器專屬正式設定；完成初次設定後視為持久設定，後續發佈不得覆蓋。
  • 如果首次部署後找不到 appsettings.Production.json，請先停止設定與啟動作業，回頭檢查 ZIP 內容及解壓層級，不要直接把 API Key 改寫到不明檔案。

ASP.NET Core 未另行指定環境時，預設為 Production。

7.2 ⚠️ 正式環境必改項（上線前一定要做）

這一節的項目沒有任何程式守門會擋你。 1.0.69 移除了 Production 啟動安全檢查，所以即使你留著出廠的開發預設值，程式也會正常啟動、不會警告。只能靠人工檢查。

設定鍵出廠值為什麼一定要改
JwtSettings.SigningKeyDevelopmentOnly-ChangeThisJwtSigningKey-AtLeast32CharsSigningKeySigningKey...最高風險。這是簽發 JWT 的密鑰，出廠值是公開在原始碼裡的。不改＝任何看過這個專案的人都能自己簽出合法 token 冒充任何使用者（含管理員）。必須換成至少 32 字元的隨機值（有 [MinLength(32)] 驗證）
BootstrapSettings.SupportPassword1qaz@WSX內建 support 管理帳號的密碼。程式每次啟動都會用這個值重設該帳號的密碼雜湊（不是只有第一次），所以「登入後改密碼」沒有用——一定要改設定檔
JwtSettings.Issuer / AudienceKnowledgeExtraction / KnowledgeExtraction.WebApi多系統並存時建議改成本站識別，避免跨站 token 互通
Swagger.EnabledInProductionfalse出廠已是安全值，確認沒有被改成 true
Security.ReturnExceptionDetailsnull出廠已是安全值（不回傳例外細節給用戶端），確認沒被打開
Cors.AllowedOrigins[]出廠是空陣列（不開放跨網域）。若確實需要，逐一列出網域，不要用 *

產生一個安全的 SigningKey：

# 產生 64 字元隨機字串
[Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(48))

把它與密碼一起寫進 C:\KMEngine\appsettings.Production.json：

{
  "JwtSettings": {
    "SigningKey": "（貼上剛才產生的隨機字串）",
    "Issuer": "KMEngine",
    "Audience": "KMEngine.WebApi"
  },
  "BootstrapSettings": {
    "SupportPassword": "（改成強密碼）"
  }
}

更好的做法：把這兩個值放環境變數而不是設定檔，避免它們進到備份與版控。ASP.NET Core 的階層用 __ 對應 :：

[Environment]::SetEnvironmentVariable('JwtSettings__SigningKey', '（隨機值）', 'Machine')
[Environment]::SetEnvironmentVariable('BootstrapSettings__SupportPassword', '（強密碼）', 'Machine')

設完要重啟 IIS（iisreset）讓應用程式集區重新讀取。

改完後，登入系統先建立你自己的管理員帳號日常使用，不要用 support。

7.3 設定 OpenAI API Key

先備份原始設定，再使用 Notepad++ 開啟正式設定檔：

Copy-Item "C:\KMEngine\appsettings.Production.json" `
  "C:\KMEngine\appsettings.Production.json.initial.bak" -Force

& "C:\Program Files\Notepad++\notepad++.exe" `
  "C:\KMEngine\appsettings.Production.json"

找到並依正式環境需求調整：

{
  "OpenAISettings": {
    "ApiKey": "在此填入 OpenAI API Key"
  }
}

注意：

  • 不要把真實 API Key 貼到工單、Email、聊天或記錄檔。
  • JSON 的最後一個屬性不能多一個逗號。
  • 修改完成後先驗證 JSON，再執行 iisreset：
Get-Content "C:\KMEngine\appsettings.Production.json" -Raw `
  | ConvertFrom-Json | Out-Null

iisreset

命令沒有顯示錯誤才表示 JSON 語法可解析；這只驗證格式，不會驗證 API Key 是否有效。

7.4 確認工具路徑

設定檔應包含：

{
  "OpenAISettings": {
    "FfmpegPath": "C:\\KMEngineTools\\ffmpeg\\bin\\ffmpeg.exe",
    "YtDlpPath": "C:\\KMEngineTools\\yt-dlp\\yt-dlp.exe",
    "NodePath": "C:\\KMEngineTools\\node\\node.exe",
    "DouyinHelperScript": "C:\\KMEngineTools\\douyin-audio\\get-douyin-audio.mjs",
    "DouyinTimeoutSeconds": 150
  },
  "MarkItDownSettings": {
    "MarkItDownPath": "C:\\KMEngineTools\\python\\Scripts\\markitdown.exe",
    "TimeoutSeconds": 600,
    "PdfUseLlm": true,
    "PdfLlmModel": "gpt-5.4",
    "PdfLlmTimeoutSeconds": 600
  }
}

目前預設資料位置是 C:\temp\KnowledgeExtraction，記錄位置是 C:\temp\Logs。若改到其他磁碟，請同步修改 ACL。

⚠️ PDF 轉檔預設會呼叫外部 LLM（影響離線與封閉網路環境）

PdfUseLlm 的出貨值是 true，代表「文件轉文字」在處理 PDF 時會把整份 PDF 送到 OpenAI（模型 PdfLlmModel，出貨為 gpt-5.4），而不是用本機的 markitdown。部署時要知道三件事：

  1. PDF 轉檔需要 OpenAISettings.ApiKey 與對外網路，而且會計入 Token 用量。
  2. 失敗不會讓工作失敗：沒有金鑰、被防火牆擋、或逾時（600 秒）時，系統會自動降級改用 markitdown，該筆狀態仍是「已完成」，但錯誤訊息欄會留下

AI 解析 PDF 失敗，已自動改用 MarkItDown 轉換：{原因}。 所以「PDF 轉出來品質不如預期」時，第一件事是去看有沒有這行訊息，而不是先懷疑 markitdown。

  1. 封閉網路 / 不允許文件外送的環境，請明確關閉它：
{
  "MarkItDownSettings": {
    "PdfUseLlm": false
  }
}

（程式屬性的預設值本來就是 false，是本專案的設定檔把它打開的。）PDF 以外的格式一律走本機 markitdown，不受此設定影響。

8.1 快速版本檢查

若手上有原始程式碼（repo），建議直接用專案附的檢測腳本，它會一次檢查所有工具、並驗證 IIS 應用程式集區身分對工具目錄的存取權限（這正是「本機跑得動、部署到 IIS 就轉檔失敗」最常見的原因）：

pwsh -File scripts/Test-PortableTools.ps1 -InstallDir C:\KMEngineTools -AppPoolName KMEngineAppPool

安裝／重建可攜工具目錄也有對應腳本（會把工具集中裝到 C:\KMEngineTools，正好是設定檔的預設路徑）：

pwsh -File scripts/Install-PortableTools.ps1 -InstallDir C:\KMEngineTools

另有 scripts/Install-ExternalTools.ps1／Test-ExternalTools.ps1，但那組是用 winget/pip 裝到使用者家目錄，不適合 IIS（服務帳號讀不到）。伺服器一律用 Portable 版那組。

更詳細的 IIS 與可攜工具設定見 IIS 佈署與可攜工具設定；本機單機安裝見 使用者安裝與操作手冊 §3.5。

若沒有 repo，逐項手動檢查：

& "C:\KMEngineTools\ffmpeg\bin\ffmpeg.exe" -version
& "C:\KMEngineTools\ffmpeg\bin\ffprobe.exe" -version
& "C:\KMEngineTools\yt-dlp\yt-dlp.exe" --version
& "C:\KMEngineTools\node\node.exe" --version
& "C:\KMEngineTools\python\python.exe" --version
& "C:\KMEngineTools\python\Scripts\markitdown.exe" --version

應顯示版本，不應出現 DLL load failed 或 MODULE_NOT_FOUND。

8.2 MarkItDown 測試與排錯

& "C:\KMEngineTools\python\Scripts\markitdown.exe" `
  "C:\Test\sample.pdf" `
  -o "C:\Test\sample.md"

若顯示 Unsupported Windows version (2025server) 但仍完成，通常只是 onnxruntime 的版本辨識警告。

若顯示 ImportError: DLL load failed while importing onnxruntime_pybind11_state，請安裝／修復 Microsoft.VCRedist.2015+.x64。

Couldn't find ffmpeg or avconv 主要影響 MarkItDown 處理音訊／影片；一般 PDF、Word、Excel 不受影響。KMEngine 本身以絕對路徑使用 ffmpeg。

Invoke-WebRequest "http://localhost/" -UseBasicParsing |
  Select-Object StatusCode,StatusDescription

預期為 200，或出現正常登入頁重新導向。

11.4 第一次登入 KMEngine

發佈包固定內建下列管理帳號（不是「若」——appsettings.json 就是這個值）：

  • 帳號：support
  • 密碼：1qaz@WSX

⚠️ support 的密碼由設定檔控制，而且程式每次啟動都會用設定檔的值重設它——所以「登入後改密碼」不會生效，必須改 BootstrapSettings.SupportPassword（見 §7.2）。

上線前務必：①依 §7.2 改掉 SupportPassword 與 JwtSettings.SigningKey；②建立自己的管理員帳號日常使用；③設定 HTTPS、憑證、防火牆與備份。

登入後會直接落在「AI 知識問答」頁（/knowledge-base-chat），不是首頁；剛部署完還沒有任何知識，問什麼都會回「查無相關依據」，這是正常的。

11.5（選用）啟用 MCP 對外服務

若要讓外部 AI Agent（Claude Code／Codex／Cursor 等）直接查詢這座知識庫，系統另提供 MCP Server，端點是 /mcp（與網站同一個站台、同一組認證與安全邊界，不需要另開服務或另開埠）。

部署面要做的事：

  1. 確認 /mcp 從外部可達：它走 HTTP（Streamable HTTP），若前面有反向代理或 WAF，要放行這個路徑並允許串流回應（不要緩衝整個 response）。
  2. 建立 API Key：登入後到「系統管理 → AI 與整合 → MCP 金鑰管理」（/mcp-api-keys）新增，外部 Agent 用 X-API-Key 標頭帶入。金鑰存資料庫、可即時停用。
  3. 也可以用 JWT Bearer（登入取得），但無狀態的 Agent 通常用 API Key 較方便。
  4. 權控自動沿用：MCP 呼叫套用與網頁完全相同的團隊權控——金鑰對應到哪個使用者，就只查得到那個人有權看的內容。
  5. /mcp 已內建套用限流（api 政策），不需另外加。

⚠️ 隱私注意：MCP 的 knowledge_ask 會把問句原文與回傳的參考資料全文寫入實體檔案（C:\temp\KnowledgeExtraction\ChatLog，僅管理員可從 /chat-logs 查閱）。這是刻意的稽核設計，但若你的環境不允許問句落地，導入前必須先確認政策。詳見 MCP 服務使用說明書 §七 Q2。

不需要對外整合時，這一節可整段略過——不建金鑰就沒有外部 Agent 能用 X-API-Key 進來（健康檢查會顯示「MCP Server：0 把啟用金鑰」的黃燈，屬預期狀態、可忽略）。

連線設定步驟與各工具參數見 MCP 服務使用說明書。

13. 更新與備份

13.1 安全更新網站並保留正式設定

禁止事項：後續更新不得再次把 publish.zip 直接解壓到 C:\KMEngine，也不得覆蓋或刪除既有的 appsettings.Production.json。新版 ZIP 內的同名檔只作為設定範例，不自動套用。

更新順序：

  1. 確認 C:\KMEngine\appsettings.Production.json 存在；若不存在，立即停止更新，先從備份還原或由管理員建立並確認設定。
  2. 備份網站、appsettings.Production.json、C:\temp\KnowledgeExtraction，尤其 SQLite 與 Cookie。
  3. 記錄更新前 appsettings.Production.json 的 SHA-256。
  4. 停止 KMEngineAppPool。
  5. 將新版 publish.zip 解壓到新的暫存目錄，確認暫存根目錄可看到 web.config。
  6. 使用 robocopy /E /XF appsettings.Production.json 從暫存目錄複製到 C:\KMEngine。
  7. 不使用 /MIR：它可能刪除正式目錄中只存在於伺服器的檔案。
  8. 再次計算正式設定檔雜湊；必須與更新前完全相同。
  9. 只有複製成功且雜湊相同時，才啟動 App Pool 並執行網站、API、工具測試。

可直接使用附錄 B 的安全更新腳本。該腳本把 robocopy ExitCode 0 到 7 視為成功；8 以上會停止並保留 App Pool 的停止狀態，以便管理員檢查及還原。

13.2 更新 KMEngineTools

  1. 停止轉錄／文件轉文字工作。
  2. 備份 C:\KMEngineTools。
  3. 解壓新版工具包。
  4. 不要刪除或覆蓋 C:\KMEngineTools\cookies（YouTube／抖音登入設定檔存於此；解壓新版工具包時請保留此子目錄，勿覆蓋）。
  5. 重跑工具版本、YouTube 標題與 MarkItDown 測試。

附錄 B：後續網站安全更新腳本

請以系統管理員身分執行。這個腳本不會覆蓋 C:\KMEngine\appsettings.Production.json，也不會使用 /MIR。開始前請把新版網站壓縮檔放到 C:\Install\publish.zip。

Import-Module WebAdministration

$packagePath = "C:\Install\publish.zip"
$siteRoot = "C:\KMEngine"
$productionConfig = Join-Path $siteRoot "appsettings.Production.json"
$timestamp = Get-Date -Format "yyyyMMdd-HHmmss"
$backupRoot = Join-Path "C:\Install\KMEngineBackup" $timestamp
$stagingRoot = Join-Path "C:\Install\KMEngineStaging" $timestamp

if (-not (Test-Path -LiteralPath $packagePath)) {
    throw "找不到更新套件：$packagePath"
}

if (-not (Test-Path -LiteralPath $productionConfig)) {
    throw "正式設定檔不存在，已停止更新。請先還原或建立 appsettings.Production.json。"
}

New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
New-Item -ItemType Directory -Path $stagingRoot -Force | Out-Null

Copy-Item -LiteralPath $productionConfig `
  -Destination (Join-Path $backupRoot "appsettings.Production.json") -Force

$hashBefore = (Get-FileHash -LiteralPath $productionConfig -Algorithm SHA256).Hash
$hashBefore | Set-Content `
  -LiteralPath (Join-Path $backupRoot "appsettings.Production.sha256.txt") `
  -Encoding UTF8

Expand-Archive -LiteralPath $packagePath -DestinationPath $stagingRoot -Force

# 若 ZIP 最外層多一個 publish 目錄，自動選取唯一且含 web.config 的子目錄。
$sourceRoot = $stagingRoot
if (-not (Test-Path -LiteralPath (Join-Path $sourceRoot "web.config"))) {
    $candidates = @(Get-ChildItem -LiteralPath $stagingRoot -Directory | Where-Object {
        Test-Path -LiteralPath (Join-Path $_.FullName "web.config")
    })

    if ($candidates.Count -eq 1) {
        $sourceRoot = $candidates[0].FullName
    } else {
        throw "暫存目錄根層找不到唯一的 web.config，請檢查 ZIP 解壓層級。"
    }
}

$updateSucceeded = $false
Stop-WebAppPool -Name "KMEngineAppPool"

try {
    & robocopy.exe $sourceRoot $siteRoot /E `
      /XF "appsettings.Production.json" /R:2 /W:2
    $robocopyExitCode = $LASTEXITCODE

    if ($robocopyExitCode -gt 7) {
        throw "robocopy 更新失敗，ExitCode=$robocopyExitCode。"
    }

    if (-not (Test-Path -LiteralPath $productionConfig)) {
        throw "更新後找不到 appsettings.Production.json，請從備份還原。"
    }

    $hashAfter = (Get-FileHash -LiteralPath $productionConfig -Algorithm SHA256).Hash
    if ($hashBefore -ne $hashAfter) {
        throw "appsettings.Production.json 雜湊已改變，請從備份還原並停止上線。"
    }

    Get-Content -LiteralPath $productionConfig -Raw `
      | ConvertFrom-Json | Out-Null

    $updateSucceeded = $true
}
finally {
    if ($updateSucceeded) {
        Start-WebAppPool -Name "KMEngineAppPool"
        Write-Host "更新完成，正式設定檔未被覆蓋。" -ForegroundColor Green
        Write-Host "更新前後 SHA-256：$hashBefore"
    } else {
        Write-Warning "更新未完成，KMEngineAppPool 保持停止。請檢查錯誤並使用 $backupRoot 還原。"
    }
}

執行完成後，檢查 C:\temp\Logs、Event Viewer 與 IIS 記錄，並測試首頁、登入、OpenAI API、文件轉文字、YouTube／抖音等實際啟用的功能。暫存與備份目錄請在確認上線穩定後，再依組織的保留政策處理。
