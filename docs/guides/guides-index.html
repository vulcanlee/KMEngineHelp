in-app 說明 vs 本目錄的文件（1.0.101 起）

系統自 1.0.101 起，每一頁的頂欄標題旁都有一個說明圖示，點開是一個近乎滿版的對話窗，內含該頁的六大段說明（功能摘要／頁面在做什麼／按鈕與互動／操作建議與結果／名詞解釋／相關頁面）。內容檔放在 src/KnowledgeExtraction/KnowledgeExtraction.Web/Datas/Help/*.md，索引在同層的 HelpTopics.json（41 條路由、40 份檔案）。

兩者分工是硬性的，不要混寫：

in-app 說明（Datas/Help/）本目錄的指南（docs/guides/）
定位入門、短、操作當下看權威、完整、離線查閱
讀者假設完全不懂知識庫、沒有 IT 背景依各份文件的「主要讀者」而定
可調參數、門檻、公式❌ 一律不寫✅ 完整列出
數學與演算法❌ 不寫✅ 可以寫
篇幅一頁約 150～250 行不限

⚠️ 為什麼 in-app 說明不寫參數：那些值會隨版本與環境改變（有些還可以線上熱調），寫進 in-app 說明必然過時——而過時的參數說明會害人調錯。所以每份 in-app 說明的結尾固定一行指向本目錄的權威文件檔名，需要查參數的人往那裡走。

維護紀律（同時記載於 開發慣例與限制速查）：

  1. 新增 @page 路由時，須在 HelpTopics.json 登記，或列入 PageHelpCatalogTests.RoutesWithoutHelp 並附排除理由（二者皆無會讓測試紅燈）。
  2. 改動頁面控制項時，須同步該頁說明檔的第三段。這一條沒有守門測試，是流程紀律。
  3. 說明檔須 UTF-8 含 BOM、六個 H2 逐字相符且按序（由 PageHelpCatalogTests 共 62 條測試守著）。
  4. 改 .md 檔不必重新編譯，最多 30 分鐘生效（快取逾時）；要立即生效需重啟。
