SQL Server 切換說明

說明本系統如何在 SQLite（預設） 與 SQL Server 之間切換，包含實際操作步驟、設定鍵、migration assembly 邊界與注意事項。

  • 文件用途：說明本系統如何在 SQLite（預設） 與 SQL Server 之間切換，包含實際操作步驟、設定鍵、migration assembly 邊界與注意事項。
  • 主要讀者：開發者、部署與維運人員
  • 文件版本：2.0（由完工 backlog 改寫為操作說明）
  • 更新日期：2026/07/26
  • 對應系統版本：1.0.71
  • 編碼：UTF-8（繁體中文，含 BOM）

相關：migration 指令見 EFCore.md；正式部署見 正式部署與安全檢查清單。

一、怎麼切（3 步）

1. 改 provider

appsettings.json 的 SystemSettings.DatabaseProvider 改成 SqlServer（可接受值：Sqlite／SqlServer）：

"SystemSettings": {
  "DatabaseProvider": "SqlServer",
  ...
}

2. 填連線字串

SystemSettings.ConnectionStrings.DefaultConnection：

"ConnectionStrings": {
  "DefaultConnection": "Server=...;Initial Catalog=BackendDB;..."
}

⚠️ 這個值空白會讓程式啟動就擲 InvalidOperationException（在 AddConfiguredDatabase 裡直接擋下），不是靜默 fallback 回 SQLite。

3. 重啟程式

Provider 是在啟動時決定的（DI 註冊階段），改了設定一定要重啟，沒有熱套用。

啟動後會自動套用 SQL Server 那套 migration（Program.cs 的 Database.Migrate()）。

二、設定鍵一覽

設定鍵說明
SystemSettings.DatabaseProviderSqlite（預設）或 SqlServer
SystemSettings.ConnectionStrings.DefaultConnectionSQL Server 連線字串。provider 為 SqlServer 時必填
SystemSettings.DatabaseCommandTimeoutSeconds指令逾時秒數，預設 120，兩種 provider 都會套用
SystemSettings.ExternalFileSystem.DatabasePathSQLite 實際使用的目錄；SQLite 連線字串是由這個路徑 ＋ BackendDB.db 組出來的

⚠️ SQLiteDefaultConnection 是死設定，改它沒有用

appsettings.json 裡有一個 SystemSettings.ConnectionStrings.SQLiteDefaultConnection（值 Data Source=BackendDB.db），看起來像是 SQLite 的連線字串，但全庫沒有任何地方讀取它（只有宣告，沒有讀取點）。

SQLite 的連線字串實際上是由 ExternalFileSystem.DatabasePath 組出來的（透過 MagicObjectHelper.GetSQLiteConnectionString(...)）。要換 SQLite 的資料庫位置，改 DatabasePath，不是改 SQLiteDefaultConnection。

三、兩種 provider 的行為差異

SQLiteSQL Server
連線字串來源由 ExternalFileSystem.DatabasePath ＋ BackendDB.db 組出直接讀 DefaultConnection
指令逾時套用 DatabaseCommandTimeoutSeconds套用 DatabaseCommandTimeoutSeconds
連線重試無EnableRetryOnFailure(3, 10 秒)（暫時性錯誤自動重試 3 次）
migration assemblyKnowledgeExtraction.AccessDatasKnowledgeExtraction.AccessDatas.SqlServerMigrations

EF Core 的註冊集中在 KnowledgeExtraction.Web/Extensions/ServiceCollectionExtensions.cs 的 AddConfiguredDatabase（早期版本在 Program.cs，已搬移）。SQL Server 的 migration assembly 由 marker 型別自動綁定，不需要手動指定。

四、Migration 邊界（重要）

SQLite 與 SQL Server 各維護一套 migration，模型一改就要產兩支，詳見 EFCore.md。

⚠️ SQL Server 那套不能用來從零建庫。 目前 SQLite 有 49 支、SQL Server 只有 46 支 —— SQL Server 缺最早的 init／add-some／AddGoogleOAuth，第一支是 AddMediaTranscription。它假設資料庫已有基礎表，直接對空的 SQL Server 資料庫套用會失敗。新建 SQL Server 環境前請先確認基礎 schema 從哪裡來。

五、正式環境的連線字串放哪

不要把正式連線字串寫進 appsettings.json 並提交進版控。 改用環境變數或部署平台的 secret：

SystemSettings__ConnectionStrings__DefaultConnection=Server=...;...

（ASP.NET Core 的設定階層用 __ 對應 :。）

現況提醒：appsettings.Production.json 目前只有 OpenAISettings.ApiKey 一個 placeholder，並沒有預留 ConnectionStrings 的空白項。要在該檔管理連線字串的話得自己加，或（建議）一律走環境變數。

六、切換前的相容性風險

SQLite 與 SQL Server 在型別、索引、預設值、定序（collation）與交易行為上都有差異，正式切換前務必做實體資料庫測試：

  • 定序與大小寫：SQLite 的 LIKE 預設不分大小寫、SQL Server 取決於資料庫定序。本系統的標籤欄位（Categories／Teams）用 Contains 做精確成員比對，定序差異可能影響命中。
  • 日期時間精度與 decimal 精度可能不同。
  • 並行與鎖：SQLite 是檔案鎖（寫入序列化），SQL Server 是列/頁鎖；背景管線大量寫入時的行為會不一樣。
  • 目前 integration tests 跑的是 SQLite；SQL Server 需在具備該環境的機器或 CI 上另做實體驗證。
