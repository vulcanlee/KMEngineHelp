讀完你將能：①在一台 Windows 電腦上把系統跑起來；②用預設帳號登入並建立自己的帳號/角色/團隊/分類；③把音訊、文件、圖片匯入並轉成文字；④把多筆素材彙整、清洗成乾淨可用的知識；⑤用清洗品質評測檢查清洗品質；⑥遇到問題時自己排查。

名詞速覽：常用術語（知識來源／成員／清洗／遮罩／蒸餾／嵌入／索引／檢索／出處／團隊權控／清洗品質評測／檢索品質評測）見 系統總覽與使用導覽 的 §七「名詞速覽」。

1. 系統需求與事前準備

  • 作業系統：Windows 10/11（64 位元）。
  • 必裝：.NET 10 ASP.NET Core 執行時（Runtime）。本程式為「相依框架」發佈，沒有內含 .NET 執行時，未安裝會無法啟動。
  • 安裝（擇一）：
  • winget：winget install Microsoft.DotNet.AspNetCore.10
  • 或到微軟官網下載「.NET 10 → ASP.NET Core Runtime（Hosting/Runtime）」安裝。
  • 確認版本：開 PowerShell 執行 dotnet --info，能看到 10.x 的 Microsoft.AspNetCore.App 即可。
  • 一鍵確認：若有 repo，可執行 pwsh -File scripts/Test-ExternalTools.ps1，它會檢測 .NET 10 執行時、PowerShell 版本與所有外部工具；缺 .NET 10 執行時會明確標示「系統將無法執行」並提示安裝指令。
  • 選配：第三方工具與 OpenAI 金鑰（依你要用的功能，見第 3 節對照表）。不裝也能登入與操作系統，但「轉錄／文件轉文字／圖片解讀／LLM 清洗」需要對應元件。
  • 選配（建議）：PowerShell 7+（pwsh）。程式本身不需要 PowerShell；但專案附的便利腳本（一鍵安裝/檢測外部工具 scripts/Install-ExternalTools.ps1、scripts/Test-ExternalTools.ps1，與文件編碼檢查 scripts/Test-DocsEncoding.ps1）建議用 PowerShell 7 以上執行。Windows 內建的是 Windows PowerShell 5.1，建議另裝 7.x 以求一致。
  • 安裝（擇一）：
  • winget：winget install --id Microsoft.PowerShell -e
  • 或到微軟官網下載 PowerShell 7.x 安裝。
  • 確認版本：新開一個 pwsh 視窗執行 pwsh --version（或 $PSVersionTable.PSVersion），看到 7.x 即可。

沒有 OpenAI 金鑰也能用：清洗會只做「彙整＋繁體化」，跳過 LLM 的去重/遮罩/分類/摘要（並標註略過）。

不裝 pwsh 也能照第 2～7 節手動操作系統；只是無法直接使用本手冊中 pwsh -File scripts/... 的便利腳本。

2. 安裝（解壓與設定檔）

  1. 取得壓縮檔（內容為 publish 資料夾）。
  2. 解壓到一個你有完整讀寫權限的目錄，建議用純英文路徑，例如 C:\KnowledgeExtraction\app（避免放在「Program Files」等需要系統管理權限的位置）。
  3. 認識設定檔 appsettings.json（用記事本即可開），重點：
  4. SystemSettings.DatabaseProvider：預設 Sqlite（單機免安裝資料庫，建議維持）。
  5. SystemSettings.ExternalFileSystem.*：各種檔案存放根目錄，預設都在 C:\temp\KnowledgeExtraction\...（資料庫、轉錄、文件、圖片、清洗結果）。第一次啟動會自動建立這些資料夾與資料庫，你不必先手動建立。
  6. NLog:BasePath：記錄檔位置，預設 C:\temp\Logs。
  7. （選配）OpenAISettings:ApiKey：要用轉錄/圖片解讀/LLM 清洗時填入你的金鑰。
  8. （選配）工具路徑 OpenAISettings:FfmpegPath、OpenAISettings:YtDlpPath、MarkItDownSettings:MarkItDownPath：出貨預設值指向 C:\KMEngineTools\...（可攜版的標準位置，見 §3.5）。若你用 winget/pip 裝在使用者家目錄，就要改成你自己的實際路徑（見第 3 節）。

小提醒：若想把資料/記錄改放別的磁碟，改上述路徑即可；改完重新啟動才生效。

3. 第三方工具安裝與檢測（依需求）

功能 ↔ 需要的元件 對照

功能需要的工具需要 OpenAI 金鑰？
影音轉逐字稿（本機檔案）ffmpeg✅
影音轉逐字稿（YouTube 等連結）ffmpeg、yt-dlp✅
抖音（Douyin）影片轉錄Node.js＋@playwright/cli＋Chromium、ffmpeg✅
文件轉文字：PDF（出貨設定走 LLM，失敗才降級 markitdown）✅ 建議填（見下方說明）
文件轉文字：PDF 以外（Word/Excel/PPT/txt…）markitdown❌（本機執行）
圖片解讀（圖片→文字）（無外部工具）✅（視覺模型）
知識清洗的 LLM 強化（去重/遮罩/分類/摘要/信心）（無外部工具）✅（未設則略過 LLM）

關於 PDF 需不需要金鑰（1.0.54 起有變）：本專案的出貨設定（MarkItDownSettings.PdfUseLlm = true）是先把整份 PDF 送給大語言模型轉 Markdown，所以 PDF 會用到金鑰、也會計入 Token 用量；好處是表格與圖表判讀好很多。

沒填金鑰不會壞掉 —— 系統會自動降級改用 markitdown、狀態仍是「已完成」，只是會在該筆留下訊息 AI 解析 PDF 失敗，已自動改用 MarkItDown 轉換：{原因}，品質與 AI 路徑不同。若你就是要純本機、不外送內容，把 PdfUseLlm 設成 false（程式屬性的預設值本來就是 false）。PDF 以外的格式一律走本機 markitdown，完全不需要金鑰。

關於影片連結：YouTube／小紅書用 yt-dlp 即可、不需 Node；唯獨抖音因平台簽章限制（yt-dlp 無法下載）改走瀏覽器助手，故需 Node 工具鏈，且僅限有桌面的本機（下載時需人工通過驗證），無頭伺服器不適用。安裝見下方「抖音轉錄工具鏈」。

安裝指令（PowerShell）

winget install Gyan.FFmpeg            # ffmpeg
winget install Python.Python.3.12     # Python（提供 pip）
# 安裝完 Python 請「關閉再重開」PowerShell 讓 PATH 生效，再執行：
pip install yt-dlp                     # 影片連結下載
pip install "markitdown[all]"          # 文件轉文字

找到工具路徑並填入設定檔

安裝後查出每個工具的實際位置，填回 appsettings.json：

(Get-Command ffmpeg).Source      # → 填 OpenAISettings:FfmpegPath
(Get-Command yt-dlp).Source      # → 填 OpenAISettings:YtDlpPath
(Get-Command markitdown).Source  # → 填 MarkItDownSettings:MarkItDownPath

重要：缺工具不會讓系統開不了機，而是在你「實際使用該功能」時才失敗（例如沒裝 ffmpeg → 第一次轉錄時報錯）。所以裝完務必先檢測。

若你手上有原始程式碼（repo），可用便利腳本一鍵安裝與檢測：pwsh -File scripts/Install-ExternalTools.ps1、pwsh -File scripts/Test-ExternalTools.ps1（後者會印出可直接貼回 appsettings 的路徑）。深入說明見 外部工具安裝與路徑設定。

3.5 可攜版安裝（伺服器／IIS 建議走這條）

上面那組腳本是用 winget／pip 安裝，工具會落在使用者家目錄。這在自己的桌機沒問題，但部署到 IIS 時會出事：IIS 應用程式集區用的是服務帳號，讀不到你的家目錄。

伺服器情境請改用可攜版腳本，它會把所有工具集中安裝到 C:\KMEngineTools（正好是 appsettings.json 的出貨預設路徑，裝完不必改設定）：

# 安裝到 C:\KMEngineTools
pwsh -File scripts/Install-PortableTools.ps1 -InstallDir C:\KMEngineTools

# 檢測，並順便檢查 IIS 應用程式集區身分有沒有讀取權限
pwsh -File scripts/Test-PortableTools.ps1 -InstallDir C:\KMEngineTools -AppPoolName KMEngineAppPool

-AppPoolName 是關鍵：它會檢查該應用程式集區身分對工具目錄的 ACL，這正是「本機跑得動、部署到 IIS 就轉檔失敗」最常見的原因。

完整的 IIS 部署步驟見 IIS 佈署與可攜工具設定 與 Windows Server 2025 安裝與設定手冊。

上述 pwsh -File scripts/... 需先裝 PowerShell 7（見第 1 節「選配（建議）」）。

抖音轉錄工具鏈（Node.js＋playwright＋Chromium）

只在要轉錄「抖音」影片時才需要（YouTube／小紅書不需要）。安裝指令（PowerShell）：

winget install --id OpenJS.NodeJS.LTS -e   # Node.js（建議 LTS，已驗證 v22）
# 安裝完 Node 請「關閉再重開」終端機讓 PATH 生效，再執行：
npm install -g @playwright/cli              # 內含 playwright-core
npx playwright install chromium             # 下載 Playwright 用的 Chromium

檢查是否裝好：

node -v                       # 顯示 Node 版本（如 v22.x）
npm -v                        # 顯示 npm 版本
playwright-cli --version      # 顯示 @playwright/cli 版本

最省事的檢測：執行 pwsh -File scripts/Test-ExternalTools.ps1 會一併檢測 Node／@playwright/cli／Chromium／抖音助手腳本（此鏈缺少只警告、不影響核心工具的檢測結果）。

設定：抖音整合需在 appsettings.json 填 OpenAISettings:NodePath（Node 絕對路徑）與 OpenAISettings:DouyinHelperScript（指向 tools/douyin-audio/get-douyin-audio.mjs）；Test-ExternalTools.ps1 會輸出可直接貼上的片段。

重要：抖音為半自動、僅限本機——下載時會跳出瀏覽器，可能需當場手動通過驗證／登入。不轉錄抖音者完全不需要安裝此鏈。完整說明見 外部工具安裝與路徑設定（§3.3 安裝、§8 抖音下載方式、§9 無頭環境限制）。

4. 啟動系統

在解壓目錄開 PowerShell，執行（本機建議只綁 HTTP）：

.\KnowledgeExtraction.Web.exe --urls "http://localhost:5080"

看到主控台出現「Now listening on: http://localhost:5080」即代表啟動成功。停止系統：在該視窗按 Ctrl + C。

--urls 參數怎麼用

  • 格式：scheme://host:port，多個用分號 ; 串接。
  • host：
  • localhost（或 127.0.0.1）＝只有本機連得到。
  • 0.0.0.0＝所有網卡，同區網其他電腦可用 http://你的電腦IP:5080 連入（需放行 Windows 防火牆對應連接埠）。
  • port：可改成未被占用的埠，例如 --urls "http://localhost:8080"。
  • 範例（區網分享）：--urls "http://0.0.0.0:5080"。

關於 HTTPS（你看到的 5443）

  • 本程式以正式（Production）模式執行，綁 HTTPS 需要有效的伺服器憑證。若直接用 --urls "...;https://0.0.0.0:5443" 而機器上沒有憑證，啟動會失敗。
  • 本機快速上手請只用 HTTP（如上）。需要 HTTPS 時，請改用憑證或在前方架反向代理（IIS/Nginx）負責 HTTPS，作法見 全新機器部署 SOP、正式部署與安全檢查清單。
  • 開機自動啟動、背景常駐等，請見 全新機器部署 SOP。

5. 第一次登入

  1. 開瀏覽器輸入 http://localhost:5080，系統會導向登入頁。
  2. 輸入預設帳號密碼並填寫畫面上的驗證碼：
  3. 帳號：support
  4. 密碼：1qaz@WSX
  5. 可勾「記住我」維持登入。
  6. 登入後會直接落在「AI 知識問答」頁（/knowledge-base-chat），不是首頁。要看統計儀表板請點左側選單的「首頁」。（剛裝好還沒有任何知識，這一頁問什麼都會回「查無相關依據」，這是正常的。）

安全提醒：support 是系統內建管理帳號，密碼由設定檔控制、每次啟動會被重設且不可在介面變更。請先建立你自己的管理員帳號（第 6 節）日常使用；正式環境請於設定檔 BootstrapSettings 調整或停用預設帳號（見 安全檢查清單）。

6. 基礎設定（建議依序完成）

登入後請依序建立基礎資料：團隊 /teams → 知識庫分類 /categories → 專案分類 /work-categories → 角色 /roleviews（勾權限樹＋預設團隊）→ 使用者 /myusers（指派一個角色）。

⚠️ 兩件容易漏的事：①分類有兩份獨立主檔 —— /categories 給知識庫用、/work-categories 給專案／工作／會議用；②權限樹上的項目名稱與選單不一樣（例如選單「知識百科」＝權限樹「知識瀏覽」），設角色前先看 完整操作手冊 §3.1 對照表。

團隊權控觀念（重要）：非管理員只看得到「沒有指定團隊（公開）」或「與自己角色團隊有交集」的紀錄；管理員不受限。要看得到資料，角色的預設團隊需與紀錄團隊相符。

各畫面的完整欄位表與輸入說明見 完整操作手冊 的 §五「基礎設定」；深入的權限樹與團隊權控見 基礎設定指南。

7. 核心流程：匯入 → 檢視 → 清洗 → 評量（簡述）

裝好系統後，日常操作的主軸是四個階段：

  1. 匯入：三條管線把素材轉成文字——影音轉逐字稿 /media-transcription、文件轉文字 /document-extraction、圖片解讀 /image-recognition（背景作業，失敗可重試、處理中可取消）。
  2. 檢視/編修：每筆完成後預覽並可線上編修文字（清洗前先把人名、料號等關鍵字改對，下游品質更佳）。
  3. 清洗：到 知識來源加工 /knowledge-sources 新增來源、加入成員、按「清洗」；依信心分數路由為「已清洗／待審核」，必要時由具「知識審核」權限者人工核准。
  4. 評量：到 清洗品質評測 /golden-samples 量測清洗品質、校準信心門檻。

以上每個畫面的完整欄位表、狀態機與逐步操作，以及後續的蒸餾 → 索引 → AI 知識問答 → 檢索品質評測，見 完整操作手冊 的 §六–§十二。

迷你完整範例

上傳一段會議錄音到 /media-transcription → 完成後得到逐字稿 → 到 /knowledge-sources 新增「2026 產品會議」並加入該逐字稿 → 按「清洗」（選預設）→ 信心 0.83 → 自動「已清洗」→ 開「檢視清洗結果」確認 → 完成一筆乾淨、可檢索的會議知識。

7.5 情境故事：企業這樣用

前面把「匯入 → 檢視 → 清洗 → 評量」一個鍵一個鍵走過一遍，可能還是有點抽象。其實同一套流程，套到不同部門就解不同的痛——差別只在「用哪一組清洗配方」和「把關鬆或緊」。下面用三個常見情境，把你剛學到的步驟對應到真實工作，並看看做完能得到什麼。

以下成效為示意（依素材與設定不同而異），用意是讓你想像導入後的工作樣貌，不是保證數字。

情境一：把每週會議變成查得到的決議（會議知識留存）

主角：PMO 專案經理 Wendy，每週要主持跨工程、業務的產品週會。 她的痛：會議決議和待辦只活在錄音檔和某個人的記憶裡。新人接手就反覆問「上次到底決議什麼？」，老問題重複討論，找一條去年的決定要翻半天。

Wendy 決定讓系統幫她把會議「資產化」。她照著四個階段走：

① 匯入 — 她把這次週會的錄音上傳到 影音轉逐字稿 /media-transcription，按下去就回去忙別的。清單上那筆從「等待中」變「處理中」再變「已完成」，背景就把一個半小時的錄音轉成了逐字稿。

建議： 很長的會議可以先分段上傳（也比較好對照議程）；檔名取得有辨識度，例如「2026Q2-產品週會-0612」。若要直接貼線上會議的錄影連結，記得先裝好 yt-dlp（見 §3）。

② 檢視／編修 — 她打開逐字稿快速掃一遍，把幾個被聽錯的人名、產品代號和料號改正後存回。

建議： 清洗前先把「關鍵字」修對（人名、料號、專案代號），下游的摘要和分類會明顯更準——錯字會一路被帶到最後。

③ 清洗 — 她到 知識來源加工 /knowledge-sources 建一筆「2026 Q2 產品週會」，用「管理成員」把剛剛的逐字稿加進來，按「清洗」並選一個她在 /cleaning-profiles 建好、要求摘要輸出「決議／待辦／負責人」三段的設定檔。系統在背景產出一份乾淨的 Markdown，信心 0.83 ≥ 0.70，自動歸到「已清洗」。

建議： 摘要提示詞可以明確要求格式（例如「請分『決議』『待辦』『負責人』三段條列」），產出就會穩定好讀。若這台機器沒有設定 OpenAI 金鑰，清洗只會做彙整＋繁體化、跳過去重/遮罩/分類/摘要（並標註略過）——會議情境通常希望有摘要，記得先把金鑰填好（§2、§3）。

④ 評量（選用） — Wendy 想知道「這組設定到底準不準」，於是到 清洗品質評測 /golden-samples 放一兩筆標準答案（例如一段含決議與人名的會議片段），按「評測」看摘要涵蓋率、分類 F1，以及系統建議的自動放行門檻。

建議： 清洗品質評測算出的門檻是建議值，要實際生效得改 appsettings.json 的 SystemSettings.Cleaning.ConfidenceThreshold（預設 0.70）。把它當「出貨前抽驗」，定期跑、累積對品質的信心。

成效：原本每次會後要花一兩個小時整理、決議還是散落各處；現在分鐘級就產出一份可檢索的會議知識。新人一句話就查到歷次決議與待辦，知識不再因為某個人離職而斷層。

情境二：讓新進客服也答得又快又準（客服知識庫）

主角：客服組長 Amy。她的痛：客戶問題一直重複，答案卻散在通話錄音和一堆 FAQ 文件裡，新人上線慢、答案還不一致。

Amy 把客服的通話錄音丟進轉錄、把退款 FAQ 文件丟進文件轉文字，快速檢視修正後，在知識來源建一筆「客服－退款流程」，並用一個偏向「遮罩客戶姓名／電話／Email、分類偏客服與財務」的清洗規則設定清洗。為了安心，她拿一筆相近的黃金樣本評測，確認「該遮的（客戶個資）遮掉、該留的（退款、計費規則）留住」。

建議： 客服情境最該盯的指標是遮罩召回率（個資別漏）和必保留詞（關鍵流程詞別被誤刪）。常見問題可以拆成多筆知識來源分主題管理（退款、帳務、物流…），日後查找與維護都更輕鬆。

成效：一個個資已遮、可檢索的客服知識庫。新人遇到客戶問退款，查一下就答得出來，答案還一致。

情境三：高敏感資料，先讓人把關才放行（人資／合約）

主角：人資經理 David，和法務一起整理供應商合約與員工名冊。他的痛：這些檔案含身分證、金融帳號、密碼等高敏資料——不整理不行，整理又怕外洩，而且必須留下可稽核的紀錄。

David 把合約 PDF 和員工名冊匯入、檢視後，建一筆知識來源，套用一個「高敏感遮罩設定檔」（強化遮罩身分證、金融帳號、密碼、統一編號，並要求保留合約關鍵條款用語）。清洗後信心 0.6 < 0.70，系統自動把它放到「待審核」；接著由具「知識審核」權限的同仁開啟，確認個資都遮乾淨、條款完整後核准（或退回並填理由）。

建議： 高敏感場景門檻要訂保守，刻意讓多數結果走人工關卡，比全自動更安心。另外系統的安全設計是「遮罩失敗＝整筆清洗失敗」——寧可重跑，也不讓沒遮乾淨的內容外流。

成效：一份可信任、可稽核、個資合規的知識資產；而且「誰在什麼時候核准的」清清楚楚，責任歸屬明確。

同一流程，怎麼適配不同部門

情境用的清洗配方重點把關方式得到什麼
會議知識（情境一）摘要分「決議／待辦／負責人」信心達標自動放行可檢索的會議決議與待辦
客服知識庫（情境二）遮客戶個資、保留流程詞清洗品質評測確認召回率一致、可查的客服答案
人資／合約（情境三）強化遮罩、門檻保守人工審核核准/退回合規、可稽核的知識資產

一句話總結：同一條流程，換不同配方（清洗規則設定）＋不同把關（信心門檻／人工審核），就能適配不同部門的需求。
