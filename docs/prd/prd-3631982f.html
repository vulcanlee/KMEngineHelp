一、目標與範圍

提供工作任務的 CRUD 管理，讓團隊記錄待辦、狀態、優先度、分類、團隊與附件。本功能補足專案管理中偏任務追蹤的紀錄類型。

本 PRD 範圍包含 /Task 頁面、搜尋、排序、分頁、附件、分類/團隊標籤、所屬專案過濾、子工作（父子一層）與團隊資料權控。非範圍包含看板、衝刺規劃、通知提醒、多層巢狀子工作。

二、使用者與入口

項目說明
路由/Task
選單專案協作 → 工作任務（1.0.17 起；原為「專案管理 → 工作任務」）
權限MagicObjectHelper.角色_工作項目
主要使用者專案成員、管理者

三、畫面與欄位

頁面提供工作任務列表、搜尋、排序、分頁、新增、編輯、刪除與附件操作。欄位以現行 MyTask / MyTas 實作為準，包含標題、描述、狀態、優先度、分類、團隊、時間欄位與附件。「所屬專案」為選填（可不綁定專案；ProjectId 可為空）。下拉清單最前提供「（不指定專案）」選項，編輯時可藉此清除已設定的專案（不依賴 AllowClear 圖示）。

注意命名歷史：Entity 為 MyTask，DbSet 名稱為 MyTas，文件與程式維護時不得誤改成 migration rename。

3.1 所屬專案過濾

工具列新增「專案過濾」多選下拉（與分類/團隊過濾一致：Mode=SelectMode.Multiple＋Values/OnSelectedItemsChanged）。選取一或多個專案時，清單只顯示 ProjectId 屬於所選的工作（DataRequest.ProjectIdFilters）。

3.1.1 共用編輯對話窗與專案入口（0.2.152）

工作任務的編輯表單抽成共用元件 MyTasEditModal（自包含 Modal／驗證／附件上傳／存檔），由本頁與「專案管理」清單的「工作與會議」對話窗共用。從專案對話窗新增/修改工作時，「所屬專案」鎖定為該專案（以唯讀顯示）；子工作編輯仍隱藏所屬專案欄位。父工作日期同步仍由服務端 RecomputeParentDatesAsync 處理。

3.2 子工作（父子一層）

  • MyTask 自我關聯 ParentTaskId（FK→MyTas，Restrict）。主清單只顯示頂層工作（ParentTaskId == null），並顯示「子工作」數欄。
  • 每列「管理子工作」開啟子工作 Modal：以子表格列出子工作，可新增/編修/刪除。子工作編輯視窗不顯示「所屬專案」欄位，沿用父工作的專案、團隊、分類（靜默繼承）。開啟子工作編輯視窗時會暫時隱藏「管理子工作」Modal，使編輯視窗顯示於最前；存檔或取消後還原管理 Modal。
  • 父工作日期同步：有子工作時，父工作 StartDate = 子工作最早 StartDate、EndDate = 子工作最新 EndDate（忽略空值），於子工作新增/編修/刪除時由服務 RecomputeParentDatesAsync 自動重算；父工作日期欄位在有子工作時為唯讀。無子工作時保留既有日期、可手動編輯。
  • 刪除連動：刪除父工作會連帶刪除其子工作（自我參照為 Restrict，由服務手動連帶刪除，含各自附件）。
  • 範圍限制：僅父→子一層，子工作不再開放再加子工作。

3.3 彙總進度（1.0.19）

清單新增「彙總進度」欄，純計算、不落地資料庫：

  • 有子工作 → 所有子工作 CompletionPercentage 的平均（含 0%，四捨五入取整），標示「依子工作自動彙總」
  • 無子工作 → 自身 CompletionPercentage，標示「手動值」

0% 一律計入：CompletionPercentage 是非空 int、預設 0，無法區分「未填」與「真的 0%」；未動過的子工作就是 0% 完成。

CompletionPercentage 欄位本身維持為使用者手動維護的值，不會被彙總結果覆寫。實作以 MyTasAdapterModel.RolledUpProgress／HasChildren（由服務填入）承載，效能上沿用既有 ChildCount 的單次 group-by（直接擴充同一支查詢，未多開查詢）。

此欄不可排序——值是查詢後才在記憶體算出的，資料庫端無從排序。顯示沿用全站文字慣例（@context.X%），未使用 AntDesign Progress。

四、內部系統運作

核心流程為 MyTasViewView → MyTaskService → BackendDBContext；API 路徑則透過 MyTaskController → MyTaskRepository。

  1. 進頁檢查登入與 角色_工作項目。
  2. 讀取分類與團隊選項。
  3. 清單查詢接受搜尋、排序、分頁與標籤篩選。
  4. 服務/Repository 查詢一律套 IRecordAccessScopeProvider 與團隊權控 predicate。
  5. 新增/編輯處理多值標籤轉換與附件寫入。
  6. Update/Delete 前清理 EF tracking，避免長生命週期 DbContext 衝突。

五、LLM / RAG 互動

工作任務本身不呼叫 LLM、不建立 embedding。若後續要納入知識庫，應經由知識來源聚合與清洗流程，而非由工作任務頁直接索引。

六、權控與安全

  • 非管理員只可看見公開或團隊交集工作任務。
  • 單筆讀取、更新、刪除與附件下載皆須套團隊權控。
  • 團隊比對必須精確，避免「團隊」誤中「團隊2」。

七、錯誤與邊界

  • 無權限單筆操作應拒絕或回傳找不到。
  • 附件實體檔遺失時應顯示友善錯誤。
  • DbSet 命名不可隨意修正，避免破壞既有資料庫。

八、驗收與測試

  • 可完成工作任務 CRUD、搜尋、排序與分頁。
  • 標籤儲存與顯示正確。
  • 非管理員看不到無交集團隊資料。
  • 附件下載不可繞過權控。
  • 專案過濾：選取專案後，清單只顯示該專案的頂層工作。
  • 所屬專案可留空仍可儲存（父工作與子工作皆然）。
  • 子工作編輯視窗不顯示所屬專案欄位，且顯示於最前（不被管理子工作 Modal 遮住）。
  • 子工作：新增/編修/刪除子工作後，父工作開始=最早子開始、結束=最新子結束；父工作有子工作時日期欄位唯讀；刪除父工作會連帶刪除子工作；主清單只顯示頂層工作。

十、0.3.34 現況校正

  • 所屬專案為選填且可清除；支援從全站工作頁或專案內共用對話窗新增／編輯。
