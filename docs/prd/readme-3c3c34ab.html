四、PRD 維護規則

  1. 新增選單頁時，PRD、此覆蓋矩陣、Menu.json 與權限樹必須同步。權限樹與 Menu.json 以位置索引對應（SidebarMenuService.ApplyChildPermissionStructure 用 permissionNames[index]），因此三處的順序必須一致；動作型權限（無選單）須排在該群組頁面權限之後。
  2. MagicObjectHelper 的 角色_xxx 常數「值」不得變更。權限以名稱字串存於 RoleView.TabViewJson，改值等同清空所有既有角色的權限，且沒有測試會攔到。常數值刻意保留舊選單名，這是正確的。
  3. adminOnly 群組（系統管理、統計報表）改以管理員身分把關、不進權限樹，權限樹中只保留佔位常數以維持位置對齊。
  4. 新增無頁面核心能力時，仍須指定一份產品能力 PRD，不得只留實作文件。
  5. 現行需求以程式碼、設定與測試為準；文件衝突時校正 PRD 並留下 changelog。
  6. 每份 PRD 必須標示文件版本、狀態、現行系統版本、首次實作版本及最後核對日期。
  7. 未實作內容只能放在獨立「規劃中需求」章節；部分實作須逐項列出完成／未完成。
  8. 文件使用 UTF-8 繁體中文含 BOM；提交前執行 scripts/Test-DocsEncoding.ps1。
