產品需求（PRD）

產品需求文件（PRD）：圖片解讀（ImageRecognition）— 圖片上傳與 LLM 視覺解讀

  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.61
  • 首次實作版本：0.2.45
  • 最後核對日期：2026/07/25
  • 建立日期：2026-06-09
  • 狀態：已實作（系統版本 0.2.45）
  • 編碼：UTF-8（繁體中文）

一、背景與目的

系統已具備檔案上傳→產生文字的成熟模式（影音轉逐字稿、文件轉文字），並已整合 OpenAI（含 GenerationModel 視覺模型）與「AI 提示詞（Prompt）」基礎資料。本功能新增「圖片解讀」頁面，讓使用者上傳圖片並做 CRUD 管理；上傳後可選取 AI 提示詞中的提示詞，請 OpenAI 視覺模型解讀圖片並轉成文字。解讀文字以檔案形式儲存於可設定的目錄，並依「上傳年度」切分子目錄。

本功能為標準 CRUD 頁面，需具備側邊選單項目、Menu.json 設定與角色權限控制，位於「專案管理」子選單。

設計範本

以 ProjectPage 的設計方式為範本，並與「影音轉逐字稿（MediaTranscription）」同構（檔案上傳、年度切分儲存、團隊權控），再加上先前建立的「依提示詞背景產生」對話窗流程；差別在於 LLM 改用視覺解讀，且解讀結果以檔案儲存（仿「文件轉文字」的 MarkdownRelativePath）。

二、需求決策

項目決策

三、功能概述

新增「圖片解讀」管理頁面，提供圖片的上傳、查詢、編輯、刪除（CRUD）。每筆紀錄包含標題、描述、原始檔名、圖片相對路徑、分類、團隊、上傳時間等。上傳後可由操作區「解讀圖片」開啟對話窗、選取提示詞，請 LLM 視覺模型解讀並把文字存成檔案；可由「檢視解讀文字」開啟結果並複製到剪貼簿，也可「檢視原圖」。列表預設依上傳時間由新到舊呈現。

四、使用者流程

  1. 進入「圖片解讀」（路由 /image-recognition）；無權限者不顯示選單、不可進入。
  2. 點「新增」上傳圖片並填標題（必填）、描述、分類、團隊；僅接受允許的圖片格式。
  3. 列表預設依上傳時間新到舊；支援關鍵字搜尋與分類／團隊過濾、分頁。
  4. 點「解讀圖片」開對話窗：選提示詞（本文帶入可編輯文字盒，Enter 換行不送出）→按「解讀」。
  5. 對話窗關閉並提示「正在請 LLM 解讀圖片」；系統在背景以視覺模型解讀，文字寫入 ImageRecognitionTextPath/{上傳年度}/{guid}.txt。
  6. 完成後自動刷新，操作區出現「檢視解讀文字」；開啟唯讀檢視並可「複製到剪貼簿」。重新解讀會覆寫舊結果。
  7. 「檢視原圖」於新分頁開啟原圖（經團隊權控串出）。
  8. 刪除紀錄會一併移除圖片檔與解讀文字檔。

六、設定（appsettings.json）

SystemSettings.ExternalFileSystem 新增兩路徑：

"ImageUploadPath": "C:\\temp\\KnowledgeExtraction\\ImageUpload",
"ImageRecognitionTextPath": "C:\\temp\\KnowledgeExtraction\\ImageRecognition"
  • 兩目錄於 Program.cs 啟動時以 EnsureDirectoryExists 建立。
  • 視覺解讀使用既有 OpenAISettings.GenerationModel／ApiKey／BaseUrl／GenerationTimeoutSeconds，不另開設定。
  • 實作建置時版本 +1（→ 0.2.45）。

七、架構與元件

  • 驗證 ImageFormatValidator（KnowledgeExtraction.Business/Helpers/）：允許 .jpg/.jpeg/.png/.webp/.gif；IsSupported/AllowedExtensionsText。
  • 上傳輸入 ImageRecognitionUploadFileInput（FileName/ContentType/FileSize/Content）。
  • CRUD 服務 ImageRecognitionService（比照 MediaTranscriptionService，含團隊權控）：清單／單筆／新增（驗格式＋年度切分存圖）／更新（白名單，不動解讀欄位）／刪除（含刪實體檔）／GetImageAsync（串原圖）／GetRecognitionTextAsync（讀解讀文字）。
  • 背景解讀服務 ImageRecognitionGenerationService（比照 LlmGenerationService，背景安全：僅依賴 BackendDBContext + OpenAIChatCompletionClient + IOptions<SystemSettings>）：RecognizeAsync(id, prompt, imageBytes, mimeType, ct) 呼叫視覺模型→寫年度切分文字檔→更新 RecognitionTextRelativePath/RecognizedAt。
  • 視覺用戶端：OpenAIChatCompletionClient 新增 CompleteWithImageAsync(prompt, imageBytes, mimeType, ct) 與靜態 BuildImageRequestBody(model, prompt, dataUrl)（chat/completions，content 為 text + image_url(base64 data URL) 陣列）。
  • Controller ImageRecognitionController：GET {id}/image（串原圖）、GET {id}/text（串解讀文字），團隊權控於 service。
  • UI：ImageRecognitionPage + ImageRecognitionView（工具列、表格、上傳/編輯 Modal、解讀對話窗、結果 Modal、檢視原圖）。背景解讀採 IServiceScopeFactory；剪貼簿用 IJSRuntime。
  • DI：AddScoped<ImageRecognitionService>()、AddScoped<ImageRecognitionGenerationService>()；HttpClient 重用既有 OpenAIChatCompletionClient 註冊。

八、OpenAI 視覺請求格式

POST chat/completions：

{ "model": "<GenerationModel>",
  "messages": [ { "role": "user", "content": [
      { "type": "text", "text": "<提示詞>" },
      { "type": "image_url", "image_url": { "url": "data:<mime>;base64,<base64>" } }
  ] } ] }

回應解析 choices[0].message.content。

九、選單與權限（三處同步，位置索引對齊）

  1. MagicObjectHelper：新增 角色_圖片清單 = "圖片清單"（接於 角色_文件萃取 後）。
  2. RolePermissionService.GetRoleListPermissionAllName()：於「專案管理」群組末端加入 角色_圖片清單。
  3. Menu.json：「專案管理」(id 2) subMenu 接於文件轉文字(id 25)後新增 { "id": 26, "name": "圖片清單", "icon": "image", "url": "/image-recognition" }。

既有角色需於角色管理頁重新勾選「圖片解讀」才看得到。

十、測試

  • ImageFormatValidatorTests：支援／不支援副檔名、AllowedExtensionsText。
  • OpenAIChatCompletionClientTests 增 BuildImageRequestBody：content 為陣列且含 text + image_url(data url)、model 正確。
  • 檔案系統與視覺 HTTP 端到端走手動驗收（需設定 OpenAISettings:ApiKey）。

十一、驗收條件

  1. 選單「專案管理 > 圖片解讀」出現，無權限角色看不到、不可進入。
  2. 可上傳允許格式的圖片並 CRUD；列表預設依上傳時間新到舊。
  3. 「檢視原圖」可於新分頁開啟（團隊權控）。
  4. 「解讀圖片」選提示詞→背景解讀→完成後「檢視解讀文字」自動出現；內容可複製。
  5. 解讀文字確實以檔案儲存於 ImageRecognitionTextPath/{上傳年度}/，重新解讀覆寫。
  6. 刪除紀錄會移除圖片檔與解讀文字檔。
  7. 雙 provider migration 皆產生；dotnet build／dotnet test 綠燈；版本升至 0.2.45。

十二、編碼需求

  • 所有新增程式碼與本 PRD 採 UTF-8 繁體中文，不得有亂碼；docs/*.md 須 UTF-8 含 BOM，提交前 scripts/Test-DocsEncoding.ps1 全綠。

十四、變更紀錄

v0.2.56–0.2.58（2026/06/10）：解讀佇列化＋重試＋取消

對應資料清洗前置工作（strategy/08 Part A 的 A1/A2/A3），背景解讀架構調整如下：

  • 佇列化（取代 Task.Run 直呼）：解讀改為 IImageRecognitionQueue（Channel<int>）＋ ImageRecognitionBackgroundService ＋ ImageRecognitionProcessor，與文件轉文字／媒體轉錄管線同構。原 ImageRecognitionGenerationService 移除，邏輯併入 Processor（圖片由 Processor 自磁碟讀取；入列於 UI scope 通過團隊權控）。
  • 狀態機：ImageRecognition 新增 Status（未解讀／等待中／處理中／已完成／失敗／已取消）、ProgressPercentage、ErrorMessage、RecognitionPrompt 欄位（migration AddImageRecognitionStatus，含既有資料回填）。觸發時機維持手動：上傳後為「未解讀」，點「解讀圖片」選提示詞後入列。
  • 自動重試：暫時性錯誤（網路、逾時、IO）自動重試最多 2 次（PipelineRetryHelper）；設定缺漏、檔案不存在、提示詞空白不重試。
  • 手動重試／取消：列表操作區新增 重試（🔁，失敗/已取消且留有提示詞）、取消（⏹️，等待中/處理中）、檢視錯誤訊息（⚠️，失敗）；刪除進行中紀錄會先發出取消（IPipelineCancellationRegistry）。
  • 重啟回復：應用重啟後，「等待中／處理中」紀錄自動重新入列。
  • UI：列表新增「狀態」「進度」欄；解讀中停用解讀按鈕；輪詢改依 Status 判斷。

v2.0（0.3.34 基線校正）

  • 支援 .zip 批次上傳，每個支援圖片建立獨立紀錄；不支援項目回報但不阻斷其他檔案。
  • 解讀文字可線上原地編修、複製與搜尋取代；更新後標記相關知識來源過時。
  • 支援素材版本鏈、版本歷史與現行版顯示；下載、內容讀取及編修全路徑套團隊權控。
  • 上傳 Modal 設 MaskClosable="false"，避免原生檔案選擇返回時誤關閉。
