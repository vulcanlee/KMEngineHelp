一、目標與範圍

讓使用者以自然語言對整個已索引知識庫提問，取得「有依據、有出處、且只包含自己有權看的內容」的串流回答。此功能是清洗、蒸餾、嵌入索引完成後的主要智慧應用入口。

本 PRD 範圍包含 /knowledge-base-chat 頁面、跨來源混合檢索、LLM 串流回答、出處面板與原始檔鑽取。同一檢索服務（KnowledgeBaseChatService.RetrieveAsync）亦由 MCP knowledge_ask 工具複用（沿用同一團隊權控與稽核，1.0.x），對外 AI Agent 的問答見 MCP Server 整合 PRD。非範圍包含索引管線本身、PDF 結構化解析、問答稽核紀錄持久化、回答品質自動評分。

二、使用者與入口

項目說明

進頁時須先通過 AuthenticationStateHelper.Check(...)，再檢查頁面權限。無權限時顯示「你沒有權限存取此頁面」，且不載入問答功能。

三、畫面與操作

  • 設定面板：回答詳簡（簡潔/標準/詳細）、套用既有提示詞、系統提示詞文字區、查詢期範圍篩選（限定知識來源／分類／團隊，多選；留空＝有權限的整個知識庫）。分類下拉只列可存取知識中實際用到的分類、團隊下拉只列可存取團隊；篩選疊加在團隊權控之上、只縮小不擴權。
  • 對話區：顯示 user/assistant 多輪訊息，assistant 逐字串流呈現。
  • 輸入區：輸入問題、送出、串流中可停止。
  • 每則 AI 回答下方動作列（同一列常駐顯示）：複製原始 Markdown、下載 PDF（伺服器端以 QuestPDF 產生、內嵌繁中字型，單則匯出）、滿意 / 不滿意回饋。
  • 每輪回答下方顯示出處清單（來源標題、層別、錨點、片段、分數），預設收合；標題旁「展開／收合」按鈕可切換整份出處明細的顯示，各則回答獨立收合。
  • 出處可展開來源成員，並導向既有下載端點下載原始檔。
  • 多輪模糊問題（如「它怎麼處理」「剛剛那個限制是什麼」）會在檢索前自動補全為可獨立檢索的查詢。

四、內部系統運作

核心流程為 KnowledgeBaseChatView → KnowledgeBaseChatService → KnowledgeBaseQueryRewriteService → IRetrievalService → IChatConversationClient。

  1. 使用者送出問題後，前端先快照既有對話作為 history，再新增本輪 user/assistant 訊息。
  2. KnowledgeBaseQueryRewriteService 依 SystemSettings.Retrieval.QueryRewrite 判斷是否用最近 history 補全檢索 query。
  3. KnowledgeBaseChatService.RetrieveAsync 每輪重新透過 IRecordAccessScopeProvider.GetAsync() 取得目前使用者 scope。
  4. IRetrievalService.RetrieveAsync 對 VectorEmbedding 執行混合檢索：向量檢索與關鍵字檢索並行，再依 Retrieval.VectorWeight / KeywordWeight 融合。
  5. 檢索層即套團隊權控：非管理員只可取得公開或團隊交集 chunk；越權 chunk 不會進入 context 或出處。
  6. 兩段式信心門檻：以最高分命中的融合分數判定 RetrievalConfidence。低於 Retrieval.RejectThreshold（或無命中）為 Insufficient，介於兩門檻為 LowConfidence，達 LowConfidenceThreshold 為 Sufficient。
  7. 命中結果排序時「蒸餾頁 Wiki」優先於「清洗內容 Cleaned」，同層再依分數排序。
  8. 服務組出附出處 context，每段格式包含來源標題、層別與錨點。
  9. 依信心分流：Insufficient 由前端直接回固定訊息、不呼叫 LLM、不附出處；LowConfidence 於回答前加註固定提示後照常呼叫 LLM；Sufficient 正常呼叫。
  10. BuildMessagesAsync 組 system 訊息、歷史對話與本輪原始 user 訊息。
  11. StreamAsync 委派 IChatConversationClient.StreamAsync 以 SSE 串流回傳 LLM 文字。

五、LLM 與提示詞

  • LLM 介面：IChatConversationClient，實作為 OpenAIChatCompletionClient。
  • 提示詞解析：LlmPromptResolver.ResolveAsync 四層優先序：單次操作覆蓋 → DB Prompt → appsettings → LlmPromptDefaults。
  • 知識庫系統提示詞鍵：LlmPromptKeys.KnowledgeBaseSystem（顯示名稱「知識庫-系統」）。
  • 查詢改寫提示詞鍵：LlmPromptKeys.KnowledgeBaseQueryRewrite（顯示名稱「知識庫-查詢改寫」）。
  • Query Rewrite 預設使用 OpenAISettings.QueryRewriteModel = gpt-5.4-mini，地端模式可用 LocalQueryRewriteModel 指定；改寫失敗時預設回退原始 query。
  • 回答詳簡提示詞鍵：簡潔/標準/詳細分別走對應 chat verbosity key。
  • 信心判定為 Insufficient（最高分低於 RejectThreshold 或無命中）時，由前端程式層直接回覆固定訊息「您的問題在知識庫中查無相關依據…」，不呼叫 LLM、不附出處。固定訊息為 KnowledgeBaseChatService.InsufficientMessage。
  • 信心判定為 LowConfidence 時，由程式層在 LLM 回答最前面加上固定提示 KnowledgeBaseChatService.LowConfidencePrefix（⚠️ 信心不足…），仍附出處。兩段訊息均由程式層保證，不依賴 LLM 自律。
  • 門檻 RejectThreshold / LowConfidenceThreshold 預設值僅為起點，須以真實資料校準；稽核日誌已記錄每輪最高分與信心供調整。

六、資料與權控

  • 檢索資料來源為 VectorEmbedding，其 Teams、Categories、SourceLayer、AnchorRef 由清洗/蒸餾/索引流程繼承。
  • 團隊權控在檢索層強制套用，出處鑽取時再透過 KnowledgeSourceService.GetAsync 套一次母來源權控。
  • 原始檔下載沿用既有受權控 API，不新增繞過權控的下載端點。
  • 日誌記錄 query 長度、命中 chunk id、層別與分數，不記錄完整問題與完整參考資料本文。

七、錯誤與邊界

  • 未設定嵌入端點時，索引管線無法建立新的向量索引；檢索服務可退化為關鍵字路徑，但語意品質會下降，且不等於完整跨來源語意檢索。
  • 檢索無命中、或最高分低於 RejectThreshold 時，由程式層直接回覆查無依據、不呼叫 LLM、不附出處。
  • Query Rewrite 只做保守補全；不得新增 history 未出現的事實。改寫結果只影響檢索，不取代使用者原始問題。
  • LLM 串流中斷時，保留已產出片段並顯示中斷訊息。
  • 使用者按停止時，取消 token 會中止串流；若尚未產生內容，顯示「已停止」。

八、驗收與測試

  • 具權限者可進入 /knowledge-base-chat 並完成多輪串流問答。
  • 非授權團隊內容不會進入 context、回答或出處清單。
  • 出處清單可展開來源成員，下載走既有受權控端點。
  • Wiki 命中排序在 Cleaned 命中之前。
  • 多輪短問句可透過 Query Rewrite 命中前文所指主題；清楚完整問題不應額外呼叫改寫。
  • 最高分低於 RejectThreshold（或無命中）時，回覆固定查無依據訊息且不呼叫 LLM、不附出處。
  • 最高分介於 RejectThreshold 與 LowConfidenceThreshold 時，回答最前面出現「⚠️ 信心不足」固定提示且仍附出處。
  • 最高分達 LowConfidenceThreshold 時正常回答。
  • 索引未建立（VectorEmbedding 為空）或嵌入未設定時，管理員在問答查無依據訊息後會看到診斷提示（一般使用者僅看到通用訊息）；管理員可於「知識來源加工」按「建立索引」（不需重蒸餾）建立向量索引。

十、0.3.34 現況校正

  • 支援回答詳簡、套用既有提示詞、自訂系統提示、限定多個知識來源與分類、多輪串流、停止、複製及 PDF 下載。
  • Query Rewrite 先改寫檢索查詢，混合檢索依 Reject／LowConfidence 門檻決定查無依據、低信心或正常回答；調校由檢索診斷與調校 PRD 規範。
  • 每則回答附可鑽取至來源成員與原始檔的出處；所有候選在計分前套團隊權控。
  • 滿意度可新增、改選、取消，並與聊天紀錄、首頁統計及 Token 用量連動。
