MCP Server 整合 PRD

技術設計與 AI Agent 使用範例見 MCP Server 整合設計與使用指南；各家客戶端連線設定與運維見 MCP 服務使用說明書；變更歷程見 MCP Server 實作、MCP 問答聊天紀錄與 Token 歸屬、MCP API Key 資料庫化與網頁管理。

一、產品目標與範圍

以 HTTP（Streamable HTTP）transport 在既有 KnowledgeExtraction.Web 內嵌 MCP Server，讓任何支援 MCP 的外部 AI Agent（Claude Code／Desktop、Codex、Cursor、VS Code 等）把「查詢企業知識庫」當成內建工具直接使用，不需為每個 Agent 客製 API 串接，且全面沿用既有團隊權控、聊天紀錄與 Token 歸屬。

範圍內容
✅ 目標端點 /mcp 暴露 4 個知識查詢工具＋連通診斷；全面套用團隊權控；雙認證；分級日誌與稽核
✅ 目標MCP 問答寫入聊天紀錄並將檢索期 Token 歸屬到呼叫者與作業
✅ 目標API Key 存資料庫，提供管理員網頁 CRUD 與逐把啟用/停用
❌ 非目標寫入型工具（新增／修改知識）、MCP resources／prompts、stdio 本機模式、金鑰簽發/撤銷稽核歷程表

二、使用者與入口

項目說明
對外端點/mcp（Streamable HTTP），套 McpAccess 授權 policy 與 api 限流
金鑰管理頁/mcp-api-keys（系統管理 → AI 與整合 →「MCP 金鑰管理」，僅管理員 CheckIsAdmin()）
主要使用者外部 AI Agent 使用者／整合開發者（呼叫端）；系統管理員（發金鑰、運維）
憑證JWT Bearer（Authorization: Bearer）或 MCP 專用 API Key（X-API-Key）擇一

三、對外工具（tools）

工具用途
knowledge_ping連通診斷，確認端點與認證可用
knowledge_ask自然語言問答，回傳含出處與信心的檢索結果（伺服器端不生成 AI 答案，答案由用戶端 LLM 生成）
knowledge_search混合檢索，回傳最相關的原始內容片段
knowledge_list_sources盤點知識來源（只回 Id/Title/Categories/Teams/Status）
knowledge_get_document取回單一文件完整（已清洗）內容；對不存在／未清洗／無權統一回 unavailable，不洩漏來源存在性

工具全部複用已內建團隊權控的既有服務（KnowledgeBaseChatService、IRetrievalService、KnowledgeSourceService），以 assembly 掃描註冊。

四、認證與團隊權控（資安不變量）

  • /mcp 套具名 policy McpAccess，接受 Bearer（JWT）／Cookie／McpApiKey 任一 scheme。
  • JWT 方案：IJwtTokenService 簽發含 ClaimTypes.Sid 的 token；RecordAccessScopeProvider 由 Sid 反查 MyUser 與角色團隊得到 RecordAccessScope。
  • API Key 方案（1.0.9 起 DB 型）：McpApiKeyAuthenticationHandler 經 McpAccessKeyService.FindEnabledMatchAsync（只認啟用中金鑰、CryptographicOperations.FixedTimeEquals 常數時間比對）驗證後，發帶 ClaimTypes.Sid = UserId 的身分。
  • 兩案皆經 McpIdentityResolver 將身分填入 CurrentUserService，MCP 呼叫沿用與 Blazor／Web API 完全一致的團隊權控：非管理員只能查到無團隊（公開）或與其角色團隊交集的內容，管理員不受限。

五、可觀測性（1.0.8 起）

  • 聊天紀錄：knowledge_ask 每次呼叫寫入 LlmChatLog（Origin=Mcp），可於 /chat-logs 以來源標籤篩選查閱；全文含呼叫端金鑰名稱、問題與回傳 context／出處，並標註「伺服器端未生成答案」。
  • Token 歸屬：以 OperationContext.Push（Operation=McpKnowledgeAsk/McpKnowledgeSearch）將檢索期 Embedding／QueryRewrite Token 歸屬至呼叫者與作業，於 /token-usage 以 MCP 作業標籤查閱。生成答案 Token 在用戶端計量，不在本系統。
  • 分級日誌：4 工具注入 IHttpContextAccessor，日誌情境帶 user=（已認證身分）與 op=；catch 不靜默。

六、API Key 網頁管理（1.0.9 起）

  • 入口 /mcp-api-keys，僅管理員。
  • 功能：新增（自動產生金鑰、可重新產生／複製）、對映使用者下拉、啟用/停用切換（免重啟即時生效）、修改、刪除。
  • 資料表 McpAccessKey（Name/KeyValue/UserId/IsEnabled/CreatedAt/UpdatedAt），模型變更已產雙資料庫 migration（Sqlite 20260717053352 ／ SqlServer 20260717053434）。
  • 金鑰以明文存 DB，僅管理員可於網頁檢視。

七、錯誤與邊界

  • 認證失敗回 401；停用金鑰立即被拒（免重啟）。
  • knowledge_get_document 對無權／不存在／未清洗統一回 unavailable，不洩漏來源存在性。
  • 稽核／紀錄／Token 寫入失敗不得阻斷主要查詢流程，但必須留可診斷日誌。
  • 不記錄金鑰明文、Bearer token 至日誌。

八、驗收條件

  1. 以 JWT 與 API Key 各能通過認證並呼叫五個工具。
  2. 管理員 vs 非管理員呼叫同一問題，回傳內容符合團隊權控差異；非管理員看不到無權來源。
  3. MCP 問答在 /chat-logs 可查、在 /token-usage 以 MCP 作業歸屬正確。
  4. /mcp-api-keys 可新增、啟用/停用、刪除；停用後連線立即 401、重新啟用又通。
  5. 選單三處（Menu.json、RolePermissionService、MagicObjectHelper）與頁面權限同步。
  6. dotnet test 全套通過（含權控不變量、四工具、認證、日誌守則）。

九、規劃中需求

  • 尚未實作：寫入型工具、MCP resources／prompts、stdio 本機模式、金鑰簽發/撤銷稽核歷程表、稽核「來源通道」欄位、稽核對 MCP 補記呼叫者 account（目前以工具日誌 user= 補足）。
