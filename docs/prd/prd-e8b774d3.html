產品需求（PRD）

產品需求文件（PRD）：知識來源加工（KnowledgeSource）— 聚合匯入素材的 CRUD 頁面

  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.62
  • 首次實作版本：0.2.59
  • 最後核對日期：2026/07/25
  • 建立日期：2026-06-11
  • 狀態：已實作（系統版本 0.2.59）
  • 編碼：UTF-8（繁體中文，含 BOM）

一、背景與目的

系統的「資料匯入」階段已成熟：影音轉逐字稿（MediaTranscription）、文件轉文字（DocumentExtraction）、 圖片解讀（ImageRecognition）三條管線各自把檔案轉成可用文字。但這些紀錄彼此無關聯、無歸屬容器， 資料零散，無法以「主題」為單位往後做清洗與蒸餾。

本功能新增「知識來源加工」頁面：把多筆零散的匯入素材聚合成一個有主題、有歸屬、 可後續清洗的單位——知識來源（KnowledgeSource）。它是「資料清洗」階段的第一個入口， 也是後續清洗／蒸餾的處理單位（概念見 strategy/08 資料清洗階段設計與分析）。

本功能為標準 CRUD 頁面，外加「成員聚合」管理；需具備側邊選單項目、Menu.json 設定與角色權限控制， 位於新增的父選單「知識庫」之下。

設計範本

以「文件轉文字（DocumentExtraction）」頁面的設計方式為範本（清單表格、新增／編輯／刪除 Modal、 排序、分頁、團隊權控的 UI 模式），可重用 TagStringHelper（標籤字串⇄List 與權控述詞）、 IRecordAccessScopeProvider（團隊權控）、AntDesign 多選 Select、AutoMapper ForMember。

與文件轉文字的關鍵差異：知識來源不上傳檔案（它聚合既有素材，非產生新檔）， 改為以「成員聚合」管理跨三管線的素材紀錄；本階段不含清洗管線（留待後續）。

二、需求決策

項目決策
位置新增父選單「知識庫」；其下子頁「知識來源加工」，路由 /knowledge-sources
範圍知識來源本體 CRUD ＋ 成員聚合（加入／移除／排序成員）；不含檔案上傳、清洗管線
成員型別可跨型別聚合：MediaTranscription／DocumentExtraction／ImageRecognition
成員可選範圍僅可挑選狀態為「已完成」的匯入紀錄（確保有可用文字）
成員參照方式以 ItemType + ItemId 軟參照（不做硬 FK，沿用本專案務實風格）；一筆素材可被多個來源引用
成員唯一性同一來源內 (ItemType, ItemId) 不可重複
成員排序來源內以 SortOrder 排序，可上下移動
預設排序列表預設依 UpdatedAt（更新時間）由新到舊；次序鍵 Id 遞減
UpdatedAt 更新時機來源欄位編輯、或成員增／刪／重排時更新
團隊權控套用（與文件轉文字一致）：非管理員僅見「無團隊（公開）或與自身團隊交集」的來源
刪除行為刪除來源時級聯刪除成員關聯（KnowledgeSourceItem）；被引用的素材原紀錄保留不動
API本階段不需要 Controller（無下載產物）；CRUD 經 Blazor Service 直接操作

三、功能概述

新增「知識來源加工」頁面，提供知識來源的建立、查詢、編輯、刪除（CRUD）， 以及把既有匯入素材聚合為來源成員的管理。每筆知識來源包含標題、描述、分類、團隊、 成員（跨三管線）、建立／更新時間。列表預設依更新時間由新到舊呈現，支援關鍵字搜尋、 分類／團隊多選過濾與分頁，並全程套用團隊權控。

能力邊界：檔案上傳仍由三條匯入管線負責；知識來源頁已整合清洗／蒸餾／索引觸發、狀態進度、信心、人工審核及清洗結果檢視／編修，細節由各能力 PRD 規範。

四、使用者流程

  1. 進入「知識庫 > 知識來源加工」（路由 /knowledge-sources）；無權限者不顯示選單、不可進入。
  2. 列表預設依更新時間新到舊；支援關鍵字搜尋（標題／描述）與分類／團隊多選過濾、分頁。
  3. 點「新增」開 Modal，填標題（必填）、描述、分類（多選）、團隊（多選）後儲存；新來源可先無成員。
  4. 在某筆來源點「管理成員」開 Modal：
  5. 以型別頁籤（影音轉逐字稿／文件轉文字／圖片解讀／會議紀錄，1.0.25 起共四型）切換，輸入關鍵字搜尋；清單僅列已完成且

使用者有權限的素材紀錄（會議紀錄只列「已產生」者，索引 AI 會議紀錄而非逐字稿），可多選「加入」。

  • 已加入的成員顯示於成員清單，可上移／下移調整 SortOrder、可移除。
  • 重複加入同一素材會被阻擋並提示。
  • 點「編輯」修改來源標題／描述／分類／團隊。
  • 點「刪除」確認後刪除來源；一併刪除其成員關聯，但被引用的素材原紀錄保留。
  • 邊界情況：標題空白擋下並提示；非授權團隊之來源不顯示、不可編輯／刪除／管理成員；

成員素材若被原管線刪除，成員清單顯示為「（來源已不存在）」並可移除。

五、資料模型

5.1 KnowledgeSource（知識來源本體）

新增實體 KnowledgeSource（KnowledgeExtraction.AccessDatas/Models/KnowledgeSource.cs）：

欄位型別說明
Idint主鍵
Titlestring標題（必填、供搜尋）
Descriptionstring?描述
Categoriesstring?分類標籤（分隔字串，TagStringHelper 包夾格式）
Teamsstring?團隊標籤（分隔字串，團隊權控用）
CreatedAtDateTime建立時間
UpdatedAtDateTime更新時間（成員增刪／重排亦更新；清單預設排序鍵）

本階段不含清洗相關欄位（Status／ProgressPercentage／ConfidenceScore／ CleanedContentRelativePath／ReviewedAt／ReviewedBy／ErrorMessage）；依 YAGNI 留待 清洗管線階段再以新 migration 加入。

5.2 KnowledgeSourceItem（成員關聯）

新增實體 KnowledgeSourceItem（KnowledgeExtraction.AccessDatas/Models/KnowledgeSourceItem.cs）：

欄位型別說明
Idint主鍵
KnowledgeSourceIdintFK → KnowledgeSource，Cascade Delete（比照 ProjectFile）
ItemTypestring素材型別：MediaTranscription／DocumentExtraction／ImageRecognition
ItemIdint對應型別的紀錄 Id（軟參照，不做硬 FK）
SortOrderint來源內成員排序
CreatedAtDateTime加入時間
  • 唯一性：(KnowledgeSourceId, ItemType, ItemId) 不可重複（以索引或 Service 層檢查）。
  • DbSet KnowledgeSource、KnowledgeSourceItem 註冊於 BackendDBContext。
  • 雙 provider migration AddKnowledgeSource：Sqlite（KnowledgeExtraction.AccessDatas/Migrations）

與 SQL Server（KnowledgeExtraction.AccessDatas.SqlServerMigrations）各一；表名與 DbSet 一致。

5.3 AdapterModel

  • KnowledgeSourceAdapterModel（KnowledgeExtraction.Models/AdapterModel/）：

Categories/Teams 以 List<string> 呈現，含 CategoriesText/TeamsText（string.Join("、", ...)）顯示用； 含 ItemCount（成員數）供列表欄位。

  • KnowledgeSourceItemAdapterModel：含 Id、ItemType、ItemId、SortOrder，

以及即時解析的 ItemTypeName（型別中文名）與 ItemTitle（向對應 Service 依 ItemId 查現值， 反映素材改名；查不到時標示「（來源已不存在）」）。

  • 實作建置時版本 +1（SystemSettings.SystemInformation.SystemVersion，→ 下一版號），

七、架構與元件（實作時新增／修改）

  • Entity：AccessDatas/Models/KnowledgeSource.cs、KnowledgeSourceItem.cs；

BackendDBContext 加入兩個 DbSet 與 KnowledgeSourceItem 的 Cascade 設定。

  • AdapterModel：Models/AdapterModel/KnowledgeSourceAdapterModel.cs、KnowledgeSourceItemAdapterModel.cs。
  • CRUD 服務 KnowledgeSourceService（Business/Services/DataAccess/，比照 DocumentExtractionService，含團隊權控）：
  • GetAsync(DataRequest)：清單查詢，含關鍵字搜尋（Title／Description）、分類／團隊過濾

（TagStringHelper.BuildContainsAnyPredicate）、團隊權控（IRecordAccessScopeProvider ＋ TagStringHelper.BuildTeamAccessPredicate）、分頁；預設排序 OrderByDescending(UpdatedAt).ThenByDescending(Id)。

  • GetAsync(int id)：單筆查詢（含團隊權控），載入成員並解析 ItemTitle。
  • AddAsync／UpdateAsync（白名單欄位）／DeleteAsync（級聯刪成員關聯）。
  • AddItemAsync(sourceId, itemType, itemId)：檢查重複與權控後新增成員、設定 SortOrder、更新來源 UpdatedAt。
  • RemoveItemAsync(itemId) / ReorderItemAsync(itemId, direction)：移除／上下移動，更新 UpdatedAt。
  • GetSelectableItemsAsync(itemType, search, dataRequest)：查對應管線已完成且經團隊權控的紀錄供挑選。
  • AutoMapper：Business/Models/AutoMapping.cs 新增 KnowledgeSource ⇄ KnowledgeSourceAdapterModel

雙向映射，Categories/Teams 以 ForMember ＋ TagStringHelper.ToList／ToStored 轉換； KnowledgeSourceItem ⇄ KnowledgeSourceItemAdapterModel。

  • DI：於 Program.cs / Extensions/ServiceCollectionExtensions.cs 註冊 AddScoped<KnowledgeSourceService>()。
  • UI：Components/Pages/KnowledgeSources/KnowledgeSourcePage.razor（@page "/knowledge-sources"）

＋ Components/Views/KnowledgeSources/KnowledgeSourceView.razor（含 .razor.cs、.razor.css）。

八、UI（Blazor Server + Ant Design）

  • 工具列：關鍵字搜尋、分類多選過濾、團隊多選過濾、「新增」。
  • 表格欄位：標題、描述、分類（CategoriesText）、團隊（TeamsText）、成員數（ItemCount）、

更新時間（可排序、預設降序）。遠端資料源 RemoteDataSource="true" ＋ OnChange 觸發 ReloadAsync。

  • 操作區：編輯（✏️）、管理成員（🧩）、刪除（🗑️）。
  • 新增／編輯 Modal：標題（必填、DataAnnotationsValidator）、描述、分類（多選）、團隊（多選）。
  • 管理成員 Modal：型別頁籤（影音轉逐字稿／文件轉文字／圖片解讀／會議紀錄，1.0.25 起四型）＋搜尋＋多選「已完成」紀錄加入；

已加入成員清單支援上移／下移／移除；重複加入阻擋提示。

  • 慣例（必守）：
  • Service／AntDesign 服務用建構式注入；AuthenticationStateHelper／NavigationManager 用 [Inject]。
  • 進頁 OnInitializedAsync 呼叫 AuthenticationStateHelper.Check ＋

CheckAccessPage(MagicObjectHelper.角色_知識來源管理清單)。

  • 開編輯前對列資料 Clone()；Update／Delete 前 CleanTrackingHelper.Clean<T>()。
  • 多選用 Mode="SelectMode.Multiple"（列舉）＋ Values／OnSelectedItemsChanged，

不要用 @bind-Values:after。

九、API 端點

本階段無新增 Controller（無下載產物）。CRUD 與成員管理皆經 KnowledgeSourceService 於 Blazor 端完成。

清洗產物目前由服務層讀取並在 Blazor 對話窗檢視／編修；若新增獨立下載 API，仍須比照既有下載端點在服務端套團隊權控。

十二、驗收條件

  1. 選單「知識庫 > 知識來源加工」出現，無權限角色看不到、不可進入。
  2. 可建立／編輯／刪除知識來源；列表預設依更新時間由新到舊。
  3. 可加入／移除／上下移動跨型別成員；只可挑選已完成且有權限的素材；重複成員被阻擋。
  4. 來源欄位編輯或成員增刪／重排後，UpdatedAt 更新且該筆排到清單前面。
  5. 非管理員僅見「無團隊或與自身團隊交集」的來源；越權來源不可編輯／刪除／管理成員。
  6. 刪除來源會級聯刪除成員關聯，但被引用的素材原紀錄保留。
  7. 雙 provider migration（Sqlite ＋ SQL Server）皆產生；dotnet build／dotnet test 綠燈；版本號 +1。
  8. 文件同步：docs/README.md 索引新增本 PRD；資料模型文件（如需）同步。
