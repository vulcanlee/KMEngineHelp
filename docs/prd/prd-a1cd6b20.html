產品需求（PRD）

產品需求文件（PRD）：資料清洗管線與品質保證（QA-1..QA-4）＋清洗品質評測集

  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.62
  • 首次實作版本：0.2.60–0.2.68
  • 最後核對日期：2026/07/25
  • 建立日期：2026-06-12
  • 狀態：已實作（系統版本 0.2.60–0.2.68；本 PRD 為回填整合，散見設計收斂為單一文件）
  • 編碼：UTF-8（繁體中文，含 BOM）

本 PRD 把原本散落於 strategy/08 §Part B（設計藍圖）與 planning/07 第三/四階段（代辦與驗收）的內容，整合成單一功能需求文件。前置的「知識來源」聚合見 知識來源管理 PRD。

一、背景與目的

「知識來源管理」（PRD，v0.2.59）已能把零散的匯入素材（影音轉逐字稿／文件轉文字／圖片識別）聚合成一個有主題、可權控的「知識來源（KnowledgeSource）」。但聚合後的內容仍是原始、破碎、含重複與敏感資訊的素材拼貼，無法直接供下游（蒸餾／檢索）使用。

本功能在知識來源之上加一條資料清洗管線：對一個來源觸發清洗，端到端產出乾淨、彙整、繁體統一、敏感資訊已遮罩、帶建議分類與摘要的「清洗後來源 Markdown」，並以分階段疊加的品質保證（全自動 → 信心門檻 → 人工審核 → 清洗品質評測）確保品質可控、可回歸。

五階段流程定位：資料匯入 →〔資料清洗（本 PRD）〕→ 知識頁審核 → 建立知識庫 → 智慧應用。本 PRD 不含知識頁審核、切塊、Embedding、向量索引。

二、需求決策

項目決策

LLM 未設定IsChatLlmConfigured() 為 false → 整段 LLM 增強略過（Skipped），仍輸出彙整+正規化結果並標「已清洗」

三、功能概述

  1. 清洗管線（QA-1，v0.2.60 / LLM 步驟 v0.2.61）：對一個來源觸發清洗，端到端產出清洗後 Markdown，狀態/進度/錯誤可追蹤、可取消/重試。
  2. 信心分數＋自動門檻（QA-2，v0.2.62）：LLM 自評信心，依門檻路由「已清洗 / 待審核」。
  3. 人工審核關卡（QA-3，v0.2.65）：待審核 → 核准/退回，記錄審核者與時間。
  4. 清洗品質評測集（QA-4，v0.2.66）：人工標註樣本，量化遮罩召回率/分類 P-R-F1/摘要涵蓋率＋門檻掃描與建議門檻。
  5. 門檻鎖定（v0.2.68）：把可接受門檻數值正式決議並記錄為回歸基準。

能力邊界：蒸餾、Embedding／向量索引由獨立 PRD 規範；清洗內容線上編修已實作。遮罩召回率單筆硬閘、LLM 自動歸群及地端語音轉錄仍屬規劃中。

四、使用者流程

  1. 於「知識來源加工」對一筆來源點「清洗」→ 來源入清洗佇列，狀態轉「等待中 → 處理中」，前端 5 秒輪詢進度。
  2. 清洗完成後：
  3. 高信心（≥ 門檻）→ 狀態「已清洗」，可檢視清洗後彙整內容（摘要、建議分類已寫回、敏感資訊已遮罩）。
  4. 低信心 / 信心無法解析 → 狀態「待審核」。
  5. 具「知識審核」權限者於待審核來源點「核准」（→已清洗）或「退回」（填退回理由，→已退回）；系統記錄審核者與時間。
  6. 失敗（如遮罩步驟失敗）→ 狀態「失敗」、顯示錯誤訊息，可手動重試；刪除/取消可中止背景工作（→已取消）。
  7. （品質維運）於「清洗品質評測」頁載入/新增樣本、一鍵載入合成種子、執行評測，檢視彙總指標與「建議門檻 vs 現行門檻」，據此回歸並決定是否調整 prompt 或門檻。

五、清洗管線步驟（實作現況）

CleaningProcessor 對一個來源依序執行（對照 strategy/08 §B-4 的七步設計，實作收斂如下）：

步驟動作實作備註
1. 彙整讀取所有成員 item 的抽取文字（.md/.txt），依 SortOrder 串接由 CleaningProcessor 完成
2. 正規化繁體統一（OpenCC ChineseConverter）純程式，不需 LLM
3. LLM 增強CleaningEnhancer.EnhanceAsync：見下表子步驟LLM 未設定則整段略過（Skipped）
4. 產出將遮罩後本文＋摘要寫成清洗後 Markdown 至 CleanedSourcePath（CleanedContentRelativePath）；建議分類合併寫回來源 Categories—
5. 路由依信心門檻決定 已清洗 或 待審核，更新 Status/Progress/CleanedAt/ConfidenceScore見 §七 QA-2

CleaningEnhancer 子步驟（每步提示詞可由「AI 提示詞」覆寫）：

子步驟行為失敗策略
去重移除重複段落與雜訊，保留資訊價值可降級（失敗則用原文、記 note）
遮罩PII/機密（身分證/電話/Email/地址/金融帳號/密碼/金鑰…）以【已遮罩】取代不吞例外：失敗即整筆清洗失敗
分類建議建議 1–5 個主題分類標籤（ParseCategories，去重取前 5）可降級（失敗則空）
摘要100–200 字繁中摘要 ＋「關鍵實體：」列表可降級（失敗則 null）
信心自評對整體清洗結果自評 0–1（ParseConfidence，支援百分比換算）可降級；失敗/無法解析 → null → 由 Processor 轉待審核

七、品質保證（分階段疊加，QA-1..QA-4）

階段版本機制行為
QA-1v0.2.60–0.2.61全自動清洗（含 LLM 去重/遮罩/分類/摘要）端到端跑通，跑完即「已清洗」
QA-2v0.2.62LLM 自評信心 + 自動門檻信心 ≥ ConfidenceThreshold(0.70) → 已清洗；否則/null → 待審核
QA-3v0.2.65 起人工審核與內容校正待審核 → 核准／退回；動作權限＋團隊權控；記錄 ReviewedBy/ReviewedAt。清洗結果可線上原地編修，但編修不自動改變審核狀態。
QA-4v0.2.66清洗品質評測集CleaningEvaluator（純函式）量化指標＋門檻掃描＋建議門檻；校準供參考，套用改 appsettings

CleaningEvaluator 指標（純函式，相對人工標註）：

  • MaskRecall：(應遮數 − 漏遮數)/應遮數；MustKeepOk：必留詞是否全數保留（二元）。
  • ClassifyPrecision/Recall/F1：建議分類相對 ExpectedCategories（不分大小寫集合比對）。
  • SummaryCoverage：摘要涵蓋 ExpectedSummaryEntities 的比率（啟發式）。
  • 門檻掃描範圍固定 {0.5,0.6,0.7,0.8,0.9}；RecommendThreshold(targetPrecision=0.90)：在達目標精準度的列取最低門檻為建議值。

鎖定的可接受門檻（strategy/05 §五，合規優先；量測非硬閘，作回歸基準）：

指標門檻性質
ConfidenceThreshold0.70強制（已套 appsettings）
targetPrecision0.90校準建議用
MaskRecall≥ 0.98（理想 1.0）合規關鍵
MustKeepOk100%二元
分類 F1≥ 0.70參考
SummaryCoverage≥ 0.60參考（啟發式）

量測 vs 硬閘：實際改變流程的只有「信心門檻 0.70」與「遮罩/必留詞失敗即失敗」；MaskRecall/F1/涵蓋率僅於清洗品質評測量化，低於門檻的把關＝清洗品質評測回歸＋人工審核。

  6. 雙 provider migration 皆產生；dotnet build/dotnet test 綠燈；各版本號 +1。
