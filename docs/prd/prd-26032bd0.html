產品需求（PRD）

資料版本、時效性與一致性生命週期 PRD

  • 文件版本：1.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.62
  • 首次實作版本：0.3.12–0.3.21
  • 最後核對日期：2026/07/25

一、產品目標與範圍

確保素材改版、內容編修或刪除後，知識來源、清洗、Wiki 與索引能辨識現行版本與過時狀態；管理員可在 /data-consistency 找出孤兒關聯及過時來源，依風險選擇單筆或批次修復。

二、版本與現行資料

  • 支援對既有素材「上傳新版本」，建立版本鏈並保留舊檔與歷史。
  • 主清單預設只顯示最新版；舊版標示已被取代，可由版本歷史查閱。
  • 來源成員沿版本鏈解析現行版，避免每次上傳新版本都要人工重新加入。
  • as-of 查詢在指定時間點解析當時有效版本；未指定時使用目前現行版。
  • 版本關係、狀態與實體檔案必須一致，不能只改畫面標籤。

三、時效性傳播

  • 上游逐字稿、Markdown、圖片解讀或生成內容原地編修後，相關知識來源標記過時。
  • 成員版本更新、移除或檔案變更後，下游清洗／蒸餾／索引不得繼續被視為最新。
  • 修復順序為重新清洗 → 蒸餾 → 索引；各階段完成時間用於判斷下游是否追上上游。
  • 單一小修可在對應內容編修，但若重新執行上游處理，人工修改可能被覆蓋，產品必須提示。

四、資料一致性巡檢

  • 入口：系統管理 → 資料一致性巡檢，路由 /data-consistency，僅管理員。
  • 報告至少包含孤兒成員與過時來源的數量、識別資訊、原因及建議動作。
  • 孤兒成員指來源成員關聯的上游素材不存在或不可解析。
  • 過時來源指上游內容／版本晚於下游處理成果，可能讓問答引用舊知識。
  • 提供單筆處置，以及「清除所有孤兒成員」「重新清洗所有過時來源」等批次動作。

五、刪除與檔案生命週期

  • EF 外鍵與實體檔案是兩個生命週期；Service 必須明確處理檔案，不能假設資料列 Cascade 會刪檔。
  • 刪除素材時清除或阻擋相關來源成員，避免留下孤兒。
  • Project／MyTask／Meeting 附件可 Cascade 資料列，但實體檔案仍由服務層刪除。
  • 清洗、Wiki、索引與 LLM 生成產物多為檔案＋相對路徑；重置或備份必須同時涵蓋資料庫與檔案根目錄。

六、權限、安全與成本

  • 巡檢頁及批次修復僅管理員；一般使用者不得取得跨團隊異常清單。
  • 批次重清洗可能呼叫 LLM 並連動蒸餾／索引，執行前需確認範圍、成本及維護時段。
  • 清理孤兒會刪除關聯，執行前應保存報告並確認上游不是暫時不可用。
  • 修復日誌記錄操作者、數量、成功／失敗及錯誤，但不記敏感本文。

七、錯誤與恢復

  • 個別修復失敗不應中斷整份報告；保留每筆結果供重試。
  • 檔案遺失、權限不足、背景作業失敗與嵌入不可用須分類顯示。
  • 批次操作不可默默略過；完成後重新巡檢並顯示剩餘異常。

八、驗收條件

  1. 上傳新版本後主清單顯示新版，版本歷史保留舊版。
  2. 來源成員可解析現行版，as-of 能回到指定時間版本。
  3. 上游編修／改版能標記下游過時，重跑後狀態恢復一致。
  4. 刪除上游不留下不可見孤兒；既有孤兒能被報告及安全清除。
  5. 非管理員不能存取一致性報告或批次動作。
  6. 批次修復留下逐筆結果，失敗可診斷與重試。

九、規劃中需求

  • 尚未實作：跨版本內容差異檢視、自動保留政策、排程巡檢通知、可回復的軟刪除與法遵留存鎖定。
