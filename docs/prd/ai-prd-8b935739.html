知識來源 AI 對話 PRD

定義單一知識來源「AI 對話」頁的需求、LLM 串流、多輪記憶與內容權控

  • 文件用途：定義單一知識來源「AI 對話」頁的需求、LLM 串流、多輪記憶與內容權控
  • 主要讀者：產品、開發、導入顧問

一、目標與範圍

讓使用者針對單一知識來源的清洗後內容或原始彙整內容進行 ChatGPT 風格對話，適合快速理解一份來源、追問細節、產生摘要與檢查內容。此功能是單一來源問答，不等同跨來源 AI 知識問答。

本 PRD 範圍包含 /knowledge-sources/{id}/chat?mode=cleaned|original、內容來源切換、系統提示詞、回答詳簡、多輪串流、複製、下載 PDF 與參考資料檢視。非範圍包含跨來源檢索、向量 RAG、對話紀錄持久化。

二、使用者與入口

項目說明
路由/knowledge-sources/{id}/chat
入口知識來源加工操作欄「AI 對話」
權限沿用 角色_知識來源管理清單
主要使用者知識管理者、審核者、導入顧問

本頁不新增選單節點；使用者必須先能存取該知識來源，且來源內容也會再套團隊權控。

三、畫面與操作

  • 內容來源：清洗後內容或原始來源。
  • 系統提示詞：可手動輸入，或由 AI 提示詞套用後再編輯。
  • 回答詳簡：簡潔、標準、詳細。
  • 對話區：顯示多輪 user/assistant 訊息，assistant 串流更新。
  • 參考資料：可檢視實際送進模型的來源內容。
  • 操作：送出、停止生成、切換內容來源後清空重來。每則 AI 回覆下方動作列（同一列常駐顯示）：複製訊息、下載 PDF（單則匯出）、滿意 / 不滿意回饋。

四、內部系統運作

核心流程為 KnowledgeSourceChatView → KnowledgeSourceChatService → KnowledgeSourceService → IChatConversationClient。

  1. 進頁檢查登入與 角色_知識來源管理清單 權限。
  2. 依 mode 取得內容：清洗後走 GetCleanedContentAsync，原始來源走 GetOriginalContentAsync。
  3. 兩種內容讀取皆由服務層套團隊權控；無權限或無內容時回傳空結果。
  4. 使用者送出訊息時，服務組 system 訊息：系統提示詞、回答詳簡、參考資料。
  5. 服務把前面所有 user/assistant 輪次一併送入 LLM，形成記憶體內多輪記憶。
  6. IChatConversationClient.StreamAsync 以 SSE 逐塊回傳；Blazor 端約 60ms 節流重繪。

五、LLM 與提示詞

  • 串流介面：IChatConversationClient，與單輪 IChatCompletionClient 並存。
  • 使用者可輸入單次 system prompt，或從 PromptService.GetAllEnabledAsync() 選取既有提示詞。
  • 回答詳簡由服務解析為額外 system 指示，不以 max_tokens 硬截斷。
  • 參考資料全文會送入模型，但日誌只記錄長度，不記錄本文。

六、權控與資料安全

  • 頁面權限沿用知識來源管理。
  • 內容讀取必須經 KnowledgeSourceService，不可直接讀檔繞過團隊權控。
  • 對話紀錄只保存在目前 Blazor 元件記憶體，不落 DB。
  • 原始來源可能包含未清洗敏感資訊，畫面以 mode 明確區分，供授權使用者自行判斷。

七、錯誤與邊界

  • 清洗後模式若尚無清洗結果，應提示無可用內容。
  • 原始來源若成員已不存在或無權限，彙整內容可能為空或部分缺漏。
  • 串流中斷時保留已產生內容並顯示錯誤或停止訊息。

八、驗收與測試

  • 有權限者可從知識來源清單開啟 AI 對話。
  • 清洗後與原始來源模式取得的參考資料符合服務層內容。
  • 多輪對話會帶入歷史訊息。
  • 停止生成可取消串流。
  • 無權限使用者不可讀取來源內容。

十、0.3.34 現況校正

  • 可選對清洗後內容或原始來源對話，支援多輪串流、簡潔／標準／詳細、停止、參考資料、複製及 PDF 下載。
  • 每輪寫入 AI 聊天稽核、信心／topScore、滿意／不滿意回饋及 Token 用量；稽核寫入失敗不得阻斷主要回覆。
  • 本能力只讀單一來源且每次重新驗證來源團隊；不需要跨庫索引，與 /knowledge-base-chat 的 RAG 問答不同。
