清洗規則設定（CleaningProfile）PRD

定義「清洗規則設定」功能——可重複套用的客製清洗提示詞集合，供知識來源清洗時選用

  • 文件用途：定義「清洗規則設定」功能——可重複套用的客製清洗提示詞集合，供知識來源清洗時選用
  • 主要讀者：產品與開發團隊
  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.62
  • 首次實作版本：0.2.103
  • 最後核對日期：2026/07/25
  • 建立日期：2026/06/17
  • 編碼：UTF-8（繁體中文，含 BOM）

背景與管線見 資料清洗與品質保證 PRD、知識來源管理 PRD；不變量見 開發慣例與限制速查 §1.8.1。

一、問題與目標

清洗的五段提示詞（去重／遮罩／分類／摘要／信心）原本只能全域客製（「AI 提示詞」啟用 清洗-*），所有知識來源、每次清洗共用同一套，無法針對不同來源用不同策略。

目標：提供命名的「清洗規則設定」，清洗時可選擇套用並記在該知識來源（重試沿用），可重複使用；不影響未指定設定檔的既有行為。

二、資料模型

CleaningProfile（表）：Id、Name(必填、唯一)、Description?、IsEnabled、五段提示詞 DedupePrompt/MaskPrompt/ClassifyPrompt/SummaryPrompt/ConfidencePrompt（皆可空，空白＝該步驟用系統內建預設）、CreatedAt、UpdatedAt。

KnowledgeSource 新增 CleaningProfileId(int?, nullable)：null = 用全域 AI 提示詞／內建預設。

雙 provider migration AddCleaningProfile（Sqlite + SqlServer）。

三、功能

  1. 管理頁 /cleaning-profiles（權限 角色_清洗設定檔，置於「基礎資料設定」群組）：CRUD＋啟用/停用，編輯表單含五段提示詞 TextArea（留空＝用預設）。名稱唯一（忽略大小寫）。
  2. 清洗觸發（知識來源加工「清洗」鈕）：改為小型對話窗，可選清洗規則設定（含「（預設／全域）」），預設帶入該來源目前設定；確認後寫回 CleaningProfileId 並排入佇列。
  3. 重試清洗：沿用來源已存的 CleaningProfileId。

四、提示詞套用優先序

  • 來源有指定設定檔：每段「設定檔非空 → 用設定檔；空 → 內建預設」，略過全域 清洗-*（避免雙重覆寫）。
  • 來源未指定（null）：維持現行邏輯（全域啟用 清洗-* → 內建預設）。
  • 由 CleaningProcessor 依 source.CleaningProfileId 取啟用中的設定檔，組成 CleaningPromptSet 傳入 CleaningEnhancer.EnhanceAsync(rawBody, overrides, ct)。

五、非目標（本版）

  • 清洗品質評測「指定設定檔評測」（驗證某設定檔指標）：後續延伸，本版評測維持全域/預設。
  • 清洗觸發時即時編輯提示詞（不存）。
  • 設定檔不做團隊權控（屬系統層設定，比照 AI 提示詞）。

六、驗收

  • 管理頁可建立/編輯/停用設定檔；清洗可選設定檔並寫回來源；清洗產出反映所選設定檔（空段用預設）；選「預設/全域」行為同現狀；重試沿用同設定檔；未指定設定檔之既有來源行為不變。

七、0.3.34 現況校正

  • 入口 /cleaning-profiles，屬共用基礎資料設定，不套團隊權控；頁面權限仍由角色控制。
  • 設定檔含去重、遮罩、分類、摘要與信心五段；來源指定後，設定檔非空段優先、空段回內建預設，且不再讀全域 清洗-*。
  • 未指定設定檔時才走全域 清洗-* → 內建預設；重試沿用來源記錄的設定檔。
  • 停用設定檔不供新選擇，既有來源關聯需保持可解釋，不得無聲改用另一配方。

八、1.0.49 易用性強化：預設範本按鈕、欄位說明圖示、分類上限

背景：未選任何設定檔（「預設／全域」）時走內建預設，其遮罩範圍廣、去重偏積極，導致知識來源原有內容常在清洗後消失；新使用者也不易掌握如何撰寫不同強度的提示詞。

  1. 三種預設範本按鈕（管理頁工具列）：一鍵開啟新增表單並帶入已填好五段提示詞的範本，供檢視／微調後儲存（不直接寫檔，名稱唯一性仍由 BeforeAddCheckAsync 把關）。保留程度由高到低：
  2. 最大保留（範本）：幾乎不去重、只遮最高風險機密、分類 5–10 個。
  3. 低度清洗（範本）：只移除明顯重複與雜訊、僅遮最敏感個資（身分證／金融帳號／密碼／金鑰），其餘保留。
  4. 中度清洗（範本）：標準去重、遮罩常見個資但保留姓名、分類適中；比全域預設多保留。

範本定義於 CleaningProfilePresets（Web 層工廠，回傳 CleaningProfileAdapterModel）。所有範本遮罩段皆要求「其餘內容原樣輸出」，確保回傳非空（避免遮罩步驟丟例外不寫檔）。

  1. 欄位說明圖示：新增／修改表單每個欄位標籤旁加 Tooltip 說明圖示（LabelTemplate + MaterialIcon），游標移上顯示該欄位用法、留空行為與清洗結果。
  2. 分類上限 5 → 10：CleaningEnhancer.ParseCategories 保留上限由 5 提高為 10（具名常數 MaxCategories），讓「盡量多分類」的範本能分出更多標籤。全域內建預設分類提示詞維持「1-5 個」，故未指定設定檔的既有行為不變。

本次不變更 Entity 欄位，無資料庫 migration；範本僅是既有五段欄位的預設文字。
