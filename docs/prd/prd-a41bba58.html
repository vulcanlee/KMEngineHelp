一、背景與目的

本系統具備影音轉逐字稿、文件轉文字等紀錄，未來需透過 LLM 將這些內容轉換為衍生產出（例如：將錄音文稿轉成會議紀錄、工作待辦清單等）。為此需要一個可集中維護、可重複使用的「提示詞（Prompt）」基礎資料，讓使用者預先建立並管理各種提示詞，供日後透過 LLM 產生相關內容時選用。

本功能為一個標準 CRUD 頁面，需具備側邊選單項目、Menu.json 設定與角色權限控制。

設計範本

本功能 以 ProjectPage 的設計方式為範本，並與程式碼庫中結構最相近的現成功能 「知識庫分類」(CategoryPage / CategoryViewView) 同構，沿用其分層架構（Entity → Repository → Service → Controller → DTO → AdapterModel → Blazor View）。

AI 提示詞與知識庫分類的唯一資料差異：新增一個 「提示詞本文」(Content) 長文字欄位，用以儲存實際要餵給 LLM 的指令文字。

對應現成可重用模式：

  • 名稱唯一性檢查：CategoryRepository.ExistsByNameAsync(name, excludeId) / CategoryService.ValidateNameUniqueAsync（新增與編輯皆呼叫，編輯時排除自身）。
  • 分頁／搜尋／排序：CategoryRepository.GetPagedAsync(request) 與 CategoryService.GetAsync(DataRequest)，預設排序為 OrderByDescending(x => x.UpdatedAt)。
  • 名稱重複回應：Controller 回傳 409 Conflict 與友善訊息。
  • Blazor UI：工具列 + Ant Design Table（遠端資料來源、分頁）+ 新增／編輯 Modal（EditForm + DataAnnotationsValidator）。

三、功能概述

新增「AI 提示詞」管理頁面，提供提示詞項目的新增、查詢、編輯、刪除（CRUD）。每筆提示詞包含名稱、提示詞本文、描述與啟用狀態。提示詞名稱在系統內為唯一值（忽略大小寫並去除頭尾空白後比對）。列表預設依更新時間由新到舊呈現，最近更新的紀錄排在最前面。

0.3.34 現況已將提示詞串接至影音／文件衍生內容、圖片辨識、清洗與問答；本 PRD 同時規範 CRUD 與跨流程選用邊界。

四、使用者流程

  1. 進入「AI 提示詞」頁面（路由 /prompts）；權限不足者不顯示選單、不可進入頁面（顯示「你沒有權限存取此頁面」）。
  2. 列表預設依「更新時間」由新到舊排序，最近更新者在最上方；支援關鍵字搜尋與分頁。
  3. 點「新增」，於 Modal 中輸入名稱（必填）、提示詞本文（必填）、描述（選填），並設定是否啟用（預設啟用）。
  4. 送出時驗證名稱唯一性（忽略大小寫 + 去頭尾空白）：
  5. 名稱重複：拒絕儲存，顯示「提示詞名稱已存在」之類的友善訊息（API 回 409 Conflict）。
  6. 通過：建立紀錄，設定建立時間與更新時間，回到列表。
  7. 點「編輯」載入單筆資料，可修改名稱、提示詞本文、描述、啟用狀態；名稱唯一性同樣須通過（比對時排除自身）。
  8. 點「刪除」出現確認對話框，確認後實體刪除該提示詞。
  9. 任何新增或編輯成功皆更新 UpdatedAt，故該紀錄會回到列表最前方。

六、設定（appsettings.json）

本功能不需新增外部路徑或服務設定，但有一個專屬設定區段 LlmPrompts（繫結至 LlmPromptsSettings）：它是四層提示詞解析（見第十七節）的第三層「平台預設」，位於本清單（DB Prompt）之下、程式內建預設之上。

  • 每個槽位鍵對應一個屬性，值留空＝沿用程式內建預設（LlmPromptDefaults）。
  • 改本區段需重啟；改本管理頁的 DB 紀錄則免重啟即時生效——這是本清單相對於設定檔的主要價值。
  • 依專案規範（CLAUDE.md）：實作完成建置時，SystemSettings.SystemInformation.SystemVersion 版本號 +1（以實作當下版本為基準遞增），並於 commit message 說明版本號變更。

十七、提示詞槽位鍵與四層解析

本清單不是自由文字庫，而是以固定槽位鍵接進各條 LLM 流程。解析器為 LlmPromptResolver.ResolveAsync，優先序由高到低四層，任一層非空白即採用、否則往下退：

  1. 單次操作覆蓋 —— 對話頁輸入、清洗規則設定的 CustomPromptText 等。
  2. DB Prompt 表（即本管理頁，依鍵比對）—— 可線上編輯、免重啟。
  3. appsettings LlmPrompts 區段 —— 平台預設，改檔需重啟。
  4. 程式 fallback（LlmPromptDefaults）—— 最底層保險。

槽位鍵目前共 14 個，涵蓋清洗五步、對話四種語氣、知識庫系統與查詢改寫、知識頁生成、會議紀錄生成、PDF 轉 Markdown。

完整鍵名對照表（中文鍵 ⇄ appsettings 屬性名 ⇄ 用途）以 LLM 提示詞與用量透明化 為權威來源，本 PRD 不重列，以免兩份清單各自漂移。新增槽位時需同步四處：LlmPromptKeys、LlmPromptsSettings.Get、appsettings.json 的 LlmPrompts、LlmPromptDefaults。

轉錄提示詞是例外：它不走本機制，沿用 OpenAISettings.Prompt。
