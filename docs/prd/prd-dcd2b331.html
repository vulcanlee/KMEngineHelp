專案管理 PRD

一、目標與範圍

提供專案資料的 CRUD 管理，讓使用者記錄專案名稱、狀態、優先度、分類、團隊與附件，並作為工作任務與會議管理以外的專案管理基礎資料。

本 PRD 範圍包含 /projects 頁面、搜尋、排序、分頁、附件上傳/移除、分類/團隊標籤與團隊資料權控。非範圍包含甘特圖、任務相依性、專案儀表板。

三、畫面與欄位

頁面提供列表、搜尋、分類/團隊篩選、排序、分頁、新增、編輯、刪除與附件管理。表單欄位以現行 ProjectAdapterModel 為準，包含標題/名稱、描述、狀態、優先度、分類、團隊、時間欄位與附件。

分類與團隊皆為多值標籤，UI 使用 AntDesign 多選 Select，資料層以分隔字串儲存。

三之一、彙總進度（1.0.19）

清單新增「彙總進度」欄，純計算、不落地資料庫：

  • 有工作任務 → 該專案頂層工作（ParentTaskId == null）的 CompletionPercentage 簡單平均（每個頂層工作權重相同），標示「依工作任務自動彙總」
  • 無工作任務 → 專案自身 CompletionPercentage，標示「手動值」

已知界線：取的是頂層工作的自身 CompletionPercentage，不是「頂層工作彙總後的進度」。若某頂層工作有子工作，專案會用它的手動值而非其子工作平均。要做到後者需兩層 group-by，成本與複雜度不成比例，故本階段不做。

實作以 ProjectAdapterModel.RolledUpProgress／HasTasks（由服務填入）承載，ProjectService.GetAsync 新增一次 group-by（每頁一次，不隨列數增長）。此欄不可排序，顯示沿用全站文字慣例。

四、內部系統運作

核心流程為 ProjectViewView → ProjectService → BackendDBContext；API 路徑則透過 ProjectController → ProjectRepository。

  1. 進頁檢查登入與頁面權限。
  2. 讀取啟用中的分類與團隊管理作為多選選項。
  3. ProjectService.GetAsync(DataRequest) 依搜尋、排序、分類/團隊篩選與分頁查詢。
  4. 查詢時透過 IRecordAccessScopeProvider 與 TagStringHelper.BuildTeamAccessPredicate 套團隊權控。
  5. 新增/編輯前端使用 clone 與 EditContext，避免雙向綁定污染來源清單。
  6. Update/Delete 前需清理追蹤，避免 Blazor circuit 範圍 DbContext 追蹤衝突。
  7. 附件由服務層寫入設定的專案檔案目錄，DB 保留附件資料列與相對資訊。

五、LLM / RAG 互動

本功能本身不呼叫 LLM、不產生 embedding、不參與 RAG 索引。若專案附件或內容後續被其他匯入流程引用，應由對應匯入/知識來源流程處理。

六、權控與安全

  • 非管理員只可看見公開或團隊交集專案。
  • 單筆讀取、更新、刪除與下載附件皆須套同一團隊權控。
  • 團隊標籤須用 TagStringHelper 精確比對，不可用模糊字串包含。
  • 附件下載不得直接暴露實體路徑。

七、錯誤與邊界

  • 無權限存取單筆資料時應視為找不到或拒絕，不可回傳內容。
  • 附件檔案不存在時應顯示友善錯誤。
  • 使用者把資料指定到自己無權團隊後，可能看不到該筆；伺服器端仍以權控為準。

八、驗收與測試

  • 有權限者可完成專案新增、編輯、刪除、搜尋與分頁。
  • 分類/團隊篩選為精確成員比對。
  • 非管理員不可讀取無團隊交集專案。
  • 附件新增與移除後，DB 與實體檔案狀態一致。
