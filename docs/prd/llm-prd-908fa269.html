產品需求文件（PRD）：逐字稿依提示詞透過 LLM 產生內容

  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.61
  • 首次實作版本：0.2.44
  • 最後核對日期：2026/07/25
  • 建立日期：2026-06-09
  • 狀態：已實作（系統版本 0.2.44）
  • 編碼：UTF-8（繁體中文）

一、背景與目的

影音轉逐字稿頁（/media-transcription）已能產出逐字稿，但逐字稿本身價值有限——使用者真正需要的是「會議紀錄」「工作待辦清單」等衍生產出。本系統已建立「AI 提示詞（Prompt）」基礎資料，且已整合 OpenAI（用於語音轉錄）。本功能把兩者接起來：在每筆「已完成」轉錄的操作區，讓使用者挑一個提示詞、視需要微調後，請 OpenAI 聊天模型依「提示詞 + 逐字稿」產生內容，結果保存於該筆紀錄，可隨時檢視並複製到剪貼簿。

二、需求決策

項目決策
觸發位置影音轉逐字稿列表操作區，僅在該筆 Status == 已完成 時顯示「依提示詞產生」圖示
提示詞選擇單選可搜尋下拉（AntDesign Select + EnableSearch），來源為「AI 提示詞」中啟用中的項目；選取後將其本文帶入可編輯的多行文字盒
送出內容編輯後提示詞 + "\n\n\n"（剛好三個換行）+ 逐字稿，以單一 user 訊息送往 OpenAI Chat Completions
產生方式背景產生：對話窗立即關閉並提示「正在請 LLM 產生資料」，於獨立 DI scope 執行（離開頁面也不中斷），完成後自動讓「檢視產生結果」圖示出現
結果保存只保留最新一筆（MediaTranscription.GeneratedContent / GeneratedAt），重新產生即覆寫
檢視結果操作區「檢視產生結果」圖示（僅在已有結果時顯示）開啟唯讀對話窗，提供「複製到剪貼簿」按鈕
模型寫於 appsettings.json 的 OpenAISettings.GenerationModel，預設 gpt-5.4；逾時 GenerationTimeoutSeconds（預設 120 秒）。共用既有 ApiKey／BaseUrl
範圍僅影音轉逐字稿頁；不另開設定區段

三、使用者流程

  1. 在影音轉逐字稿列表，找到狀態為「已完成」的紀錄，點操作區「依提示詞產生」（✨）。
  2. 對話窗開啟：上方為提示詞單選下拉（可輸入關鍵字搜尋），選取後其本文帶入下方多行文字盒；使用者可自由調整文字（Enter 為換行，不會送出）。
  3. 按「產生」：對話窗關閉，畫面右下顯示「正在請 LLM 產生資料」。系統在背景把「提示詞 + 三個換行 + 逐字稿」送往 LLM。
  4. 取得回應後寫回該筆紀錄；完成時顯示「LLM 已完成內容產生」並自動刷新列表，操作區出現「檢視產生結果」（📑）圖示。
  5. 點「檢視產生結果」：對話窗唯讀顯示產生內容，按「複製到剪貼簿」可複製全文。
  6. 再次「依提示詞產生」會以新結果覆寫舊結果。

四、資料模型

MediaTranscription 實體新增兩欄位（雙 provider migration AddGeneratedContentToMediaTranscription）：

欄位型別說明
GeneratedContentstring?（TEXT／nvarchar(max)）LLM 產生的最新內容；重新產生即覆寫
GeneratedAtDateTime?產生時間

MediaTranscriptionAdapterModel 對應新增 GeneratedContent、GeneratedAt，並提供唯讀 HasGeneratedContent（供操作區圖示判斷）。

五、架構與元件

  • 設定 OpenAISettings（KnowledgeExtraction.Models/Systems/OpenAISettings.cs）：新增 GenerationModel（預設 gpt-5.4）、GenerationTimeoutSeconds（預設 120）。共用 ApiKey／BaseUrl。
  • 聊天用戶端 OpenAIChatCompletionClient（KnowledgeExtraction.Business/Services/Transcription/）：POST chat/completions，Bearer 驗證，請求僅帶 model 與單一 user 訊息（最小欄位，相容 GPT-5 家族）。靜態方法 BuildRequestBody／ParseContent 便於單元測試。AddHttpClient<OpenAIChatCompletionClient>（逾時取 GenerationTimeoutSeconds）。
  • 產生服務 LlmGenerationService（KnowledgeExtraction.Business/Services/DataAccess/）：static ComposePrompt(editedPrompt, transcript)（三換行規則）；GenerateAsync(id, editedPrompt, transcriptText, ct) 呼叫聊天用戶端並把結果寫回紀錄。僅依賴 DbContext 與聊天用戶端，可於背景獨立 DI scope 安全執行。
  • 逐字稿讀取與權控：逐字稿文字由 UI 執行緒（具登入權控情境）以 MediaTranscriptionService.GetTranscriptAsync(id)（已內建團隊權控）取得後，再傳入背景產生；背景不依賴目前登入使用者情境。
  • View MediaTranscriptionView：操作區兩圖示（✨ 產生／📑 檢視結果）；產生對話窗為純 Modal（非 EditForm，故 Enter 換行）；背景以 IServiceScopeFactory 開新 scope 執行 LlmGenerationService；剪貼簿以 IJSRuntime.InvokeVoidAsync("navigator.clipboard.writeText", ...)。
  • DI：AddScoped<LlmGenerationService>()；AddHttpClient<OpenAIChatCompletionClient>。

六、設定（appsettings.json）

於 OpenAISettings 區段新增：

"GenerationModel": "gpt-5.4",
"GenerationTimeoutSeconds": 120

ApiKey 仍屬機密，以環境變數或 User Secrets 提供（見日誌與設定檔說明 第 6 節）。實作建置時 SystemVersion +1（→ 0.2.44）。

七、測試

  • LlmGenerationServiceTests：ComposePrompt 在提示詞與逐字稿間剛好放三個換行（載入核心規則）。
  • OpenAIChatCompletionClientTests：BuildRequestBody（model 與單一 user 訊息）、ParseContent（取 choices[0].message.content、空 choices 拋例外）。
  • PromptServiceTests：GetAllEnabledAsync 僅回啟用中、依名稱排序、含本文。
  • 聊天 HTTP 與背景持久化的端到端路徑以手動驗收涵蓋（需設定 OpenAISettings:ApiKey）。

八、驗收條件

  1. 僅「已完成」紀錄顯示「依提示詞產生」圖示。
  2. 產生對話窗下拉列出啟用中提示詞，選取後本文帶入文字盒且可編輯；Enter 為換行不送出。
  3. 按「產生」後對話窗關閉並提示「正在請 LLM 產生資料」。
  4. 送往 LLM 的內容為「提示詞 + 三個換行 + 逐字稿」。
  5. 產生完成後自動出現「檢視產生結果」圖示；開啟可見內容並可複製到剪貼簿。
  6. 重新產生覆寫舊結果。
  7. 模型取自 appsettings.json 的 GenerationModel（預設 gpt-5.4）。
  8. dotnet build／dotnet test 綠燈；雙 provider migration 皆已產生；版本升至 0.2.44。

九、風險與邊界

  • 無逐字稿／無權限：GetTranscriptAsync 回 null → 錯誤提示，不送出。
  • 未設 ApiKey：聊天用戶端擲中文例外 → 錯誤提示，不致崩潰。
  • LLM 逾時／錯誤：背景捕捉並提示，不寫入結果；逾時由 GenerationTimeoutSeconds 限制。
  • 逐字稿過長超模型 token 上限：API 回錯誤 → 錯誤提示（未來可分段／摘要）。
  • 離開頁面：背景以獨立 scope 持久化，結果仍會落地，下次載入即可檢視。
  • 剪貼簿：navigator.clipboard 需安全內容（https／localhost）與使用者手勢；失敗則提示手動複製。

十、未來延伸（Out of Scope）

  • 保留多筆產生歷史與比較。
  • 過長逐字稿自動分段／摘要再產生。
  • 將產生結果一鍵建立為「會議紀錄」「工作任務」等紀錄。
  • 提示詞變數樣板（如 {{transcript}} 佔位符）。

十一、0.3.34 現況校正

  • 影音逐字稿與文件轉文字均可依已啟用提示詞產生衍生內容；文件另可在支援時直接送原始圖片／PDF。
  • 產生工作在背景執行；觸發前先完成團隊權控與輸入讀取，背景 scope 不自行推測使用者權限。
  • 產生結果以檔案保存，可檢視、複製、搜尋取代及原地編修；新版本／上游內容改變需重新產生。
