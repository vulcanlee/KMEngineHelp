產品需求（PRD）

AI 可觀測性與成本治理 PRD

  • 文件版本：1.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.63
  • 首次實作版本：0.3.29–0.3.30
  • 最後核對日期：2026/07/25

一、產品目標與範圍

讓管理員可稽核 AI 知識問答與單一來源 AI 對話的實際輸入／回覆、信心與使用者回饋，並依作業、模型、帳號及時間觀察 Token 用量與成本趨勢。涵蓋三個明細頁 /chat-logs（單輪稽核）、/chat-sessions（整段對話，1.0.5x 起）、/token-usage（用量），以及首頁摘要與經營洞察。

二、問答稽核明細

  • 入口：系統管理 → 問答稽核明細，路由 /chat-logs，僅管理員。
  • 記錄每一輪 AI 知識問答、知識來源 AI 對話與 MCP 問答（knowledge_ask，來源標為 MCP，1.0.8 起） 的時間、帳號、姓名、來源、提示詞、回覆、信心、topScore 與滿意度。MCP 問答由外部 AI Agent 觸發，答案由用戶端 LLM 生成，聊天紀錄明確標註「伺服器端未生成答案」。
  • 支援帳號／姓名、日期、來源類型、滿意／不滿意／未回饋篩選。
  • 表格提供摘要欄位；「查看全文」顯示該輪完整提示詞與回覆。
  • 問答使用者可在回答下方給滿意／不滿意，允許改選或取消；變更同步至稽核紀錄與首頁統計。

二之一、完整對話紀錄（Session 級）

  • 入口：系統管理 → AI 與整合 → 完整對話紀錄，路由 /chat-sessions，僅管理員。
  • 與上一節的差異是粒度：問答稽核明細一列 = 一輪問答（稽核用）；本頁一列 = 一整段對話（LlmChatSession），欄位為對話標題（首輪提問摘要）、帳號／姓名、來源出處、知識來源標題、建立時間、最後活動時間與輪數，依最後活動時間遞減排序。
  • 儲存架構比照聊天紀錄：資料列只存中繼資料，對話全文（各輪問答＋當時的提示詞設定條件）存實體 JSON 檔（sessions/{yyyy}/{sessionId}.json），不入資料庫。
  • 支援帳號關鍵字、起訖日期與來源出處篩選；「對話全文」Modal 逐輪展開整段內容。
  • 同一份 session 資料同時供使用者檢視／續談自己的對話；本頁是管理員的跨使用者綜覽視圖。

三、Token 用量

  • 入口：系統管理 → Token 用量，路由 /token-usage，僅管理員。
  • 每次 LLM 呼叫記錄作業／畫面、型別、模型、帳號、輸入、輸出、快取及推理 Token；MCP 問答的檢索期 Token 以專屬作業（McpKnowledgeAsk／McpKnowledgeSearch）歸屬到呼叫者（生成答案 Token 在用戶端計量，不在本系統）。
  • 寫入採背景佇列，避免用量紀錄拖慢主要 AI 回應；寫入失敗需留日誌但不能竄改呼叫結果。
  • 支援依帳號、日期、作業、型別及模型篩選；顯示篩選範圍各類 Token 合計與逐筆詳細。
  • 大數字以 K／M 緊湊顯示，tooltip 提供精確值；首頁顯示最近 30 天總量。
  • 可將目前篩選結果匯出 PDF（依作業別統計＋逐筆明細，含篩選條件字串），共用報表匯出元件 ReportPdfExporter。

四、資料治理與安全

  • 兩頁均僅管理員；服務端驗證不可只靠 adminOnly 選單。
  • 不記錄 API Key、Bearer token、密碼或憑證；錯誤日誌不得輸出秘密。
  • 聊天全文可能含業務資料，只能由管理員依稽核目的存取；匯出或跨系統傳送不在現行範圍。
  • 使用者身份、來源與時間必須可追溯；匿名或缺失身份需明確標示。
  • Token 數據是用量，不等同帳單金額；若未設定價格，不顯示虛構成本。

五、首頁摘要與經營洞察

  • 首頁顯示最近 30 天 AI 回答滿意度及 Token 用量，提供管理者快速觀察。
  • 經營洞察區塊（1.0.5x 起，僅管理員可見）：區間可切換（不固定 30 天），指標涵蓋活躍使用者、問答總量、Token 總量、內容處理量、滿意率、不滿意數、低信心數、被封鎖數、零命中率，以及 Token／問答／內容貢獻的 Top N 排名。由 DashboardService.GetManagementInsightsAsync 聚合，排名區塊與統計報表共用 ReportRankList 元件以確保呈現與口徑一致。
  • 首頁卡片與管理頁使用相同資料來源及日期定義，避免統計口徑不同。
  • 無資料時顯示 0／未有回饋，不拋出錯誤。

六、錯誤與邊界

  • 稽核或 Token 寫入失敗不得讓主要問答失敗，但必須留下可診斷警告／錯誤。
  • 全文檔案遺失時表格仍可查詢，查看全文顯示明確錯誤。
  • 日期範圍與篩選需服務端驗證；大量資料以分頁查詢，不一次載入全部。

七、驗收條件

  1. 問答及單一來源對話各產生可查詢稽核紀錄。
  2. 滿意度可新增、改選、取消，首頁與管理頁統計一致。
  3. LLM 呼叫產生分類正確的 Token 用量，篩選合計等於逐筆資料總和。
  4. 緊湊數字與 tooltip 精確值一致。
  5. 非管理員不能進頁或取得資料，紀錄不包含秘密。
  6. 稽核／用量寫入失敗不阻斷主要 AI 流程且有日誌。

八、規劃中需求

  • 尚未實作：模型價格表與實際金額、預算警示、部門配額、聊天稽核與對話全文的匯出、保留期限自動清除及隱私遮罩工作流。
  • 註：Token 用量頁已支援 PDF 匯出（見第三節），尚未實作的是聊天紀錄與對話全文的匯出。
