系統健康監控 PRD

一、目標與範圍

提供管理員一個可快速判斷系統是否可用的巡檢頁，並保留部署平台可輪詢的 liveness/readiness 端點。此功能用於上線前檢查、故障排除與依賴設定確認。

本 PRD 範圍包含 /system-health 頁、/health/live、/health/ready、健康分數、紅黃綠燈、檢查項目與最後 100 筆日誌，以及同屬日誌診斷的 /log-settings（執行期日誌等級切換）與 /log-download（日誌封存下載）。非範圍包含告警推播、歷史趨勢圖、集中式監控平台。

二、使用者與入口

項目說明
路由/system-health
選單系統管理 → 系統監控 → 系統健康監控（adminOnly）；⚠️ 日誌等級切換 /log-settings 與日誌下載 /log-download 自 1.0.97 起改掛同層的「診斷與日誌」群組（原本三者同群組）
權限僅管理員 CheckIsAdmin()
主要使用者維運人員、系統管理員

三、畫面與檢查項目

頁面分三區：

  • 整體摘要：檢查時間、健康百分比、紅黃綠燈。
  • 檢查項目（共 24 項）：應用程式、API、資料庫、資料庫大小與資料量（1.0.13 新增，資訊型）、日誌、身分驗證、檔案系統、主機資源、安全設定、外部工具（ffmpeg/yt-dlp/markitdown/Node.js/抖音助手）與 OpenAI 設定、轉錄儲存目錄、向量索引涵蓋率，1.0.11 新增的 5 項基礎設施與整合檢查：MCP Server（端點/policy/scheme/啟用金鑰數；0 金鑰為警示）、分散式快取（Memory 正常，Redis 實測連線）、AI 生成/嵌入 Provider 就緒（依 Cloud/Local 分流）、RAG 檢索設定合理性（權重/門檻）、背景管線（七條匯入／處理背景服務是否註冊；預期清單自 1.0.66 起由 PipelineNames 常數反射推導，新增管線自動納入；自 1.0.72 起另涵蓋 2 支無法推導的寫入服務PipelineProgressWriter／TokenUsageWriter），以及 1.0.13 新增的 2 項可用性實呼叫檢查：大語言模型可用性（實呼叫主生成模型、8 秒逾時）、嵌入端點可用性（實嵌入探針文字、回報維度）。
  • 日誌尾端：顯示 NLog 今日日誌最後 100 筆。

四、內部系統運作

核心流程為 SystemHealthPage → ISystemHealthService → HealthLogReader。

  1. 進頁檢查登入與管理員身分。
  2. SystemHealthService.GetReportAsync() 逐項檢查依賴。
  3. 每項檢查回傳狀態、燈號、權重、證據與失敗訊息。
  4. 系統依權重計算整體健康分數。
  5. HealthLogReader 讀取今日 NLog 檔案尾端，提供最近日誌。
  6. /health/live 只檢查程序存活；/health/ready 檢查資料庫可用性。

五、LLM / RAG 互動

1.0.13 起，本功能會在「大語言模型可用性」「嵌入端點可用性」兩項檢查中各實際呼叫一次 LLM 與嵌入端點（極小提示詞/探針文字、8 秒逾時；未設定端點時略過），用量以作業別「健康檢查（HealthCheck）」記錄於 Token 用量。其餘檢查僅讀取設定與環境狀態，間接協助判斷轉錄、清洗、視覺、問答與 RAG 是否具備必要依賴。

六、權限與安全

  • /system-health 僅管理員可看。
  • 頁尾原始日誌可能包含路徑、帳號或例外訊息，部署時必須確保只有可信管理員可進入。
  • 日誌規範仍要求不得寫入密碼、token、完整金鑰或完整敏感內容。
  • 探針端點只回簡短狀態，不提供詳細診斷資料。

七、錯誤與邊界

  • OpenAI ApiKey 未設定應列為紅燈，因多數 AI 功能無法運作。
  • 選用工具未設定可列黃燈，不應讓整站不可用。
  • 日誌檔不存在時頁面仍可顯示健康報表，日誌區顯示無可顯示紀錄。

八、驗收與測試

  • 管理員可進入 /system-health 並看到健康報表。
  • 非管理員看到拒絕訊息。
  • /health/live 與 /health/ready 可供部署平台檢查。
  • ApiKey 空白時 OpenAI 檢查為紅燈。
  • 日誌尾端讀取失敗不影響其他健康項目。

十、現況校正：日誌診斷三件組（1.0.63 核對）

本能力現由三個管理員頁面組成，皆在「系統管理」底下；⚠️ 自 1.0.97 起不再同群組——/system-health 在「系統監控」，/log-settings 與 /log-download 在「診斷與日誌」：

  • /system-health 顯示健康分數、正常／警示／異常、各檢查的權重與佐證，以及最後 100 筆日誌；健康端點另供部署平台使用。
  • /log-settings：管理員可在執行期切換 Trace、Debug、Information、Warning、Error，立即生效且免重啟。
  • /log-download：下載 NLog 封存日誌檔，供離線比對與問題回報；由 LogArchiveController 提供下載端點並套用權控。
  • 執行期切換只暫時覆蓋 NLog AppCatchAll 規則；重啟後回到 nlog.config 預設 Information。深度診斷結束後必須切回，避免日誌量與敏感情境增加。
  • 日誌不得記錄 API Key、密碼或 token；外部呼叫需有開始、成功與失敗三點式診斷資訊。
