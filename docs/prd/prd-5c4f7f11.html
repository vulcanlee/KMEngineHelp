產品需求（PRD）

知識頁審核（Knowledge Distillation）PRD

定義「把已清洗的知識來源蒸餾為精煉、可互連的 Wiki 實體頁」之功能需求與設計

  • 文件用途：定義「把已清洗的知識來源蒸餾為精煉、可互連的 Wiki 實體頁」之功能需求與設計
  • 主要讀者：產品、開發團隊
  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.62
  • 首次實作版本：0.2.117
  • 最後核對日期：2026/07/25
  • 建立日期：2026/06/24
  • 對應版本：0.2.117（已實作）
  • 編碼：UTF-8（繁體中文，含 BOM）

路線圖定位見 strategy/04 §階段二；端到端操作見 從匯入到知識的操作流程 §五。

一、目標與範圍

把已清洗（狀態＝已清洗）的知識來源內容，用 LLM 蒸餾為多個精煉、可推理的 Wiki 實體頁：

  • 一概念一頁（一個來源可產出多頁）。
  • 以 [[wiki-links]] 互連相關概念。
  • 繼承來源的 Teams（權控）與 Categories 標籤。
  • 萃取真實可用知識而非原文搬運。

非目標（後續階段或延伸；其中「向量索引／檢索」已於階段三 0.2.123–0.2.128 實作、「可點擊的跨頁導覽」已於 DIS-2 0.3.13 實作）：每來源客製蒸餾提示詞（DistillationProfile）、Wiki 一致性 lint。

二、流程

知識來源（已清洗） ──按「蒸餾」──► 入蒸餾佇列 ──背景──► 讀清洗後內容 ──LLM──► 多個 Wiki 頁
                                                                              │
                              每頁信心 ≥ 門檻 → 已完成；< 門檻或無法解析 → 待審核 → 核准/退回
  • 蒸餾在清洗之後執行，輸入為已遮罩內容，不再重做遮罩。
  • 重蒸餾＝新版（VER-1，0.3.14；不再刪除舊版）：重新蒸餾同一來源會保留舊版——同概念（來源＋標題）的既有現行版轉為「已汰換（superseded）」並保留（含實體檔與向量，向量標為非現行），新蒸餾內容成為新版，自動核可者即成現行版。
  • 沿用既有管線：佇列 → 背景服務 → 處理器（重試／取消／進度）→ 增強器（LLM）。

三、資料模型

  • 新增實體 WikiPage：KnowledgeSourceId(FK，Cascade)、Title、ContentRelativePath、LinkTitles、Categories、Teams、ConfidenceScore、Status（已完成／待審核／已退回）、ReviewedBy/ReviewedAt、ErrorMessage、時間欄位。
  • KnowledgeSource 新增蒸餾任務追蹤：DistillationStatus（待蒸餾／等待中／處理中／已蒸餾／失敗／已取消）、DistillationProgressPercentage、DistillationErrorMessage、DistilledAt。
  • Wiki 頁內容只存檔案（ExternalFileSystem.WikiOutputPath 下 {年}/{guid}.md），DB 僅存相對路徑。

四、提示詞與設定

  • 提示詞鍵 蒸餾-生成（四層解析：單次操作 → DB AI 提示詞 → appsettings → 程式 fallback）。要求 LLM 回 JSON 陣列：[{title, content, links, confidence}]。
  • SystemSettings.Distillation.ConfidenceThreshold（預設 0.70）。
  • LLM 回應非預期 JSON 時降級為單頁並轉「待審核」，不整筆失敗。

五、權限與權控

  • 新增頁面權限 知識蒸餾、動作權限 蒸餾審核（核准/退回）。
  • 所有 Wiki 頁查詢、檢視、編修、刪除、審核皆套團隊權控（TagStringHelper.BuildTeamAccessPredicate/IsTeamAccessible）：非管理員僅見無團隊或與其團隊交集者。

六、UI

  • 知識來源頁：對「已清洗」來源顯示「蒸餾」按鈕；蒸餾中顯示「取消蒸餾」、失敗/取消顯示「重試蒸餾」；新增「蒸餾」狀態欄與進度，沿用 5 秒輪詢。
  • 「知識頁審核」頁（/knowledge-distillation）：列出 Wiki 頁（標題／來源／分類／團隊／關聯概念／信心／狀態），可檢視/編修（Markdown 預覽）、核准/退回（待審核且具權限）、刪除；支援分類/團隊過濾與搜尋。

七、驗收

  • 已清洗來源可蒸餾出多筆互連 Wiki 頁、正確繼承 Teams/Categories。
  • 信心 < 門檻者為待審核，具 蒸餾審核 權限者可核准/退回。
  • 非管理員看不到無交集團隊的 Wiki 頁。
  • 重蒸餾同來源會保留舊版（轉 superseded）並建立版本鏈，不刪除舊頁；編修可存回檔案。

八、0.3.34 現況校正

  • 蒸餾狀態為待蒸餾 → 等待中 → 處理中 → 已蒸餾／失敗／已取消，支援取消、重試與重啟回復。
  • Wiki 審核狀態與來源蒸餾狀態分開；已完成頁才進入一般讀者的 /knowledge-wiki。
  • 蒸餾完成自動觸發索引；重蒸餾保留舊版並建立版本鏈，索引只應引用現行內容。
  • Wiki 編修原地寫檔並標記索引時效性；分類與團隊繼承來源且全路徑權控。
