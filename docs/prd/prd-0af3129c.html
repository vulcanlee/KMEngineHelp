2. 背景與目標

2.1 背景

系統目前已具備多個 CRUD 模組（專案、工作、會議）與成熟的檔案上傳機制，但缺乏將 「語音內容」轉為「可檢索文字」的能力。知識萃取的核心價值之一，是把會議錄音、訪談、 講座等音訊／影片轉成文字後再進行後續萃取與分析。

2.2 目標

  • 提供一個 CRUD 頁面，讓使用者上傳影片或聲音檔案並管理其轉錄結果。
  • 透過背景工作呼叫 OpenAI 語音轉文字 API，自動產生繁體中文逐字稿。
  • 轉錄文字以檔案形式儲存於檔案系統，依上傳時間的年度切分目錄，儲存根目錄

可於 appsettings.json 設定。

  • 提供即時轉換進度，使用者可隨時查看目前進度與狀態。
  • 完整整合既有的 sidebar 選單（Menu.json）與角色權限控制。

2.3 非目標（YAGNI，本期不做）

  • 不做即時串流（live streaming）轉錄。
  • 不輸出字幕檔（SRT/VTT）與時間軸對位。
  • 不支援繁體中文以外的輸出語言切換。
  • 不做轉錄文字的語意分析／摘要（屬後續萃取模組）。

3. 使用者情境與流程

  1. 具權限的使用者進入「影音轉逐字稿」頁面。
  2. 點擊「新增」，填寫標題等基本欄位並選擇一個音訊／影片檔案上傳。
  3. 系統驗證檔案格式與大小後儲存實體檔，建立一筆轉錄紀錄（狀態：等待中），並將工作

排入背景佇列。

  1. 背景工作依序取出工作：呼叫 OpenAI gpt-4o-transcribe 進行轉錄；若檔案超過 25MB

則先分段切割再逐段轉換並合併。

  1. 轉換期間持續更新資料庫中的狀態與進度百分比。
  2. 使用者於列表頁可看到狀態自「等待中 → 處理中（X%）→ 已完成／失敗」即時變化

（前端輪詢）。

  1. 完成後，使用者可在頁面檢視或下載逐字稿文字檔。

4. 功能需求

4.1 CRUD 頁面（參照 ProjectPage）

設計規格參照既有 ProjectViewView（/projects），採用 Blazor Server + AntDesign：

  • 列表：伺服器端分頁、搜尋（標題／狀態）、欄位排序；顯示標題、原始檔名、檔案大小、

轉換狀態、進度百分比、上傳時間、完成時間等欄位。

  • 新增：EditForm + DataAnnotationsValidator + AntDesign InputFile，單檔上傳。
  • 編輯：可修改基本欄位（標題、備註）；原始媒體檔原則上不可置換（如需重轉列為未來延伸）。
  • 刪除：含刪除確認；連動刪除實體媒體檔與逐字稿檔（cascade）。
  • 檢視／下載：完成後提供逐字稿線上檢視與檔案下載（沿用既有 stream 下載模式）。
  • 權限檢查：頁面 OnInitializedAsync 以 AuthenticationStateHelper.CheckAccessPage(...)

驗證；無權限顯示 你沒有權限存取此頁面。

4.2 檔案格式與大小驗證

  • 允許格式（OpenAI 語音轉文字支援副檔名）：

flac, m4a, mp3, mp4, mpeg, mpga, oga, ogg, wav, webm。

  • 上傳時同時檢查副檔名與 MIME Content-Type，不符即拒絕並提示。
  • 上傳容量沿用既有上限（1GB）作為「上傳」上限；超過 API 25MB 單檔限制者於背景以分段

處理（見 4.3）。

4.3 背景轉換工作

  • 佇列架構：採用 System.Threading.Channels 的 Channel<T> 作為工作佇列，搭配

BackgroundService（IHostedService）長駐消費，輕量且無額外套件相依。

  • 轉換模型：gpt-4o-transcribe（最新、辨識準確度最高）。
  • 繁體中文：呼叫時指定 language=zh，並於 prompt 加入繁體中文提示語，使輸出

偏向繁體中文；必要時於後處理進行簡轉繁修整。

  • 大檔分段：當單檔（或轉檔後）超過 25MB API 限制，或音訊長度超過模型單次請求上限

（gpt-4o-transcribe 為 1400 秒，預設以 MaxChunkDurationSeconds=1200 留餘裕）時，依時間自動 切割，逐段送出轉錄後再依序合併文字。實際段數取「大小」與「時長」所需段數的較大者。

  • 媒體切割需透過外部工具 FFmpeg 完成（詳見第 10 節相依與風險）。
  • API 金鑰與連線：以 typed client（AddHttpClient<OpenAITranscriptionClient>，即 IHttpClientFactory 模式）建立 HttpClient 呼叫 OpenAI；金鑰由

appsettings.json 的 OpenAISettings 提供。

  • 失敗處理：呼叫失敗記錄錯誤訊息並標記狀態為「失敗」；允許之重試策略於實作時定義。

4.4 進度追蹤

  • 採用資料庫狀態欄位 + 前端輪詢（符合現有 CRUD／AntDesign 模式）。
  • 狀態列舉：等待中、處理中、已完成、失敗、已取消（已取消 為後續加入，見 MediaTranscriptionAdapterModel 的 Status* 常數）。
  • 處理中時記錄進度百分比（分段轉錄時以已完成片段／總片段估算）。
  • 前端列表頁定時輪詢（重新查詢）以更新狀態與百分比；失敗時顯示錯誤訊息。

4.5 逐字稿儲存

  • 轉錄輸出以純文字檔形式儲存於檔案系統，不存入資料庫大型欄位。
  • 儲存根目錄由 appsettings.json 指定（見第 8 節）。
  • 於根目錄下依上傳時間的年度切分目錄：{root}/{yyyy}/{guid}.txt。

（與既有附件「年／月」慣例一致，但本案依需求改為僅年度切分。）

  • 資料庫僅記錄逐字稿檔案的相對路徑、檔名與必要中繼資料。

5. 非功能需求

  • 安全：OpenAI API Key 不得進版控（沿用機密金鑰管理慣例）；API 端點需 JWT 授權，

頁面需角色權限控管。

  • 效能：背景轉換不得阻塞 Web 請求；佇列具背壓控制；大檔分段避免一次載入過多記憶體。
  • 可靠度：轉換失敗可重試或重新觸發；狀態與錯誤訊息可追蹤；實體檔與逐字稿檔生命週期

與資料列一致（刪除連動）。

  • 本地化：所有介面文字與逐字稿輸出採 UTF-8 繁體中文，且不得有亂碼。

10. 相依與風險

  • FFmpeg 相依：大檔依時間分段切割需 FFmpeg。需確認部署環境可安裝、授權合規，並於

缺失時提供明確錯誤。此為本案最主要的外部相依風險。

  • 模型輸出限制：gpt-4o-transcribe 僅支援 json／text 輸出，**不提供逐字／分段

時間戳記**（僅 whisper-1 的 verbose_json 具備）。若未來需字幕／時間軸，須改用 whisper-1。

  • API 25MB 與時長限制及成本：gpt-4o-transcribe 除 25MB 檔案上限外，另有單次請求 1400 秒音訊長度上限；兩者皆會觸發分段。長音檔分段數多，轉錄耗時與費用隨之上升；需控管併發與成本。
  • 簡繁轉換：模型偶可能輸出簡體中文。本案以「強化繁體 prompt ＋ OpenCC（OpenccNetLib 的 s2twp）後處理」雙重保底，於語言為中文時將輸出強制轉為台灣繁體（見 §13）。
  • 背景工作持久性：Channel 佇列為記憶體內佇列，行程重啟會遺失未完成工作；可透過啟動時

掃描「等待中／處理中」紀錄重新入列補救（實作時定義）。

11. 驗收條件／成功標準

  1. 可上傳合法格式音訊／影片檔；不合法格式或超限即被正確攔截並提示。
  2. 背景工作能將檔案轉成繁體中文逐字稿檔，並存於指定根目錄下、依上傳年度切分的子目錄。
  3. 前端可見轉換狀態與進度由 等待中 → 處理中（0→100%）→ 已完成；失敗時顯示錯誤訊息。
  4. 完成後可線上檢視並下載逐字稿。
  5. >25MB 檔案能自動分段轉換並合併出完整逐字稿。
  6. 選單與角色權限正確控管（無權限者看不到選單／無法進入頁面與呼叫 API）。
  7. 所有文字 UTF-8 繁體中文且無亂碼。

12. 未來延伸（Out of Scope）

  • 既有紀錄的批次重轉／重新觸發轉錄。
  • 字幕檔（SRT/VTT）與時間軸輸出（需改 whisper-1）。
  • 多語言輸出與自動語言偵測。
  • 即時串流轉錄。
  • 轉錄文字的摘要／關鍵字／知識萃取串接。

13. v1.1 功能擴充（YouTube 來源、語言選擇、台灣繁體保底）

版本 0.2.18（2026/06/03）新增。本節之內容補充並覆寫上方 §2.3 與 §12 中關於「語言切換」之非目標描述。

13.1 YouTube 連結來源

本節為 v1.1 當時設計（僅 YouTube）。v1.2（§14）已將其一般化為通用「影片連結」來源並支援分享文字自動抽取與 cookies，下方「僅 YouTube」「網域須含 youtube.com」等限制以 §14 為準。

  • 新增記錄時可選「來源類型」：檔案上傳 或 YouTube 連結。
  • 選擇 YouTube 時改輸入影片網址，無須上傳檔案；建立記錄當下不下載、不寫檔，僅儲存網址（狀態：等待中）。
  • 背景處理器於轉錄前，以 yt-dlp -x --audio-format mp3 -k（搭配 --ffmpeg-location）抽取音訊轉為 mp3 存入 MediaUploadPath 的 {yyyy}/{guid}.mp3（供轉錄），補齊檔案欄位後接回既有的分段／轉錄流程；-k 同時保留 yt-dlp 下載的完整原始影片，搬移至 OriginalMediaPath 的 {yyyy}/{guid}.ext 永久保存（寫回 OriginalMediaRelativePath，供未來知識管理回看原始畫面）。原始影片搬移失敗不影響 mp3 與轉錄主流程。
  • yt-dlp 下載的影片標題作為 OriginalFileName（供逐字稿下載命名）。
  • 網址驗證：須為 http(s) 且網域含 youtube.com 或 youtu.be。

13.2 逐筆轉錄語言選擇

  • 新增記錄時提供「轉錄語言」下拉：繁體中文 / English / 自動偵測，逐筆指定並存入 Language 欄位（zh / en / auto）。
  • 語言對應規則（集中於 TranscriptionProcessor.ResolveLanguageOptions）：

13.3 台灣繁體保底（OpenCC）

  • 經查證，OpenAI 轉錄 API 的 language 僅接受 ISO-639-1 兩碼（中文僅 zh，不支援 zh-tw），且 language／prompt 僅為軟性偏好，無法保證輸出繁體。
  • 因此，當語言為中文時，於逐字稿合併後以 OpenccNetLib（s2twp） 進行簡轉繁（含用詞轉換，如「软件→軟體」），確保輸出為台灣繁體中文。
  • OpenccNetLib 為執行緒安全，註冊為 Singleton（ChineseConverter）重用，字典檔隨建置輸出至 dicts/。

14. v1.2 功能擴充（通用影片連結來源 + 分享文字抽取 + cookies）

版本 0.2.21（2026/06/03）新增；0.2.22（2026/06/04）依實測修訂各平台下載方式。將 §13.1 的「YouTube 連結來源」一般化為通用「影片連結」，平台辨識交給 yt-dlp（支援 1000+ 站台）。各平台實際下載方式（小紅書免 cookies、抖音須用 playwright 助手）見 §14.3。

14.1 通用影片連結來源

  • UI「來源類型」由「YouTube 連結」改為「影片連結」；新建記錄的 SourceType 寫入 Url。
  • 移除 YouTube 網域白名單：網址驗證只確認是合法 http(s) 絕對網址（MediaTranscriptionService.IsLikelyMediaUrl），平台辨識交給 yt-dlp（YouTube／小紅書／TikTok／B 站等；抖音例外，見 §14.3）。
  • 下載器 YouTubeDownloader → 更名 MediaUrlDownloader（結果型別 MediaDownloadResult）；服務 AddYouTubeAsync → AddUrlSourceAsync；處理器 DownloadYouTubeAsync → DownloadFromUrlAsync。
  • 相容舊資料：MediaTranscriptionAdapterModel.IsUrlSource(...) 同時認 Url（新）與 YouTube（舊），舊記錄無須遷移。

14.2 分享文字自動抽取網址

  • 新增 UrlExtractor.ExtractFirstUrl(text)（KnowledgeExtraction.Business/Helpers）：以 regex https?://[^\s]+ 抽出第一個網址並去除結尾標點。
  • 使用者可直接貼整段分享文字，例如抖音：「6.69 ... https://v.douyin.com/xxxx/ 复制此链接...」，系統自動抽出 https://v.douyin.com/xxxx/，於 BeforeAddCheckAsync 抽取後寫回乾淨網址再儲存。

14.3 各平台下載方式（實測 2026/06）

  • 小紅書：以「影片連結」來源直接可用，yt-dlp 自動跟隨 xhslink 短連結並抽音訊，不需 cookies。
  • 抖音：yt-dlp 無法下載（web API 需 JS 即時簽章 a_bogus／msToken，回報 Fresh cookies needed；此問題與 cookie 無關，實測帶完整登入 cookie 仍失敗）。自 0.2.27 起系統整合 playwright 助手 tools/douyin-audio/get-douyin-audio.mjs：於「影片連結」貼上抖音連結，系統偵測到抖音即自動以登入瀏覽器攔截音訊串流→下載→沿用既有轉錄流程（不需手動上傳）。需設定 OpenAISettings:DouyinHelperScript／NodePath，僅限有桌面的本機；亦可獨立用命令列手動執行該助手後改以「檔案上傳」。
  • OpenAISettings 的 YtDlpCookiesFile／YtDlpCookiesFromBrowser 保留供其他需 cookie 的平台使用（YouTube／小紅書不需要、抖音無效）；兩者皆設定時以檔案優先，套用於「取標題探測」與「下載」兩條 yt-dlp 命令。詳見外部工具安裝與路徑設定 第 8 節。

14.4 限制與失敗呈現

  • 抖音助手依賴一個已登入的瀏覽器設定檔，登入過期或平台改版時需重新登入；media 網址有時效，腳本會即時下載。
  • 小紅書圖文（無影片）無音訊可轉錄；其他平台下載仍可能因改版而失敗。
  • 影片連結來源下載失敗時（含 stderr）由 TranscriptionProcessor 既有 catch 寫入記錄 ErrorMessage 並標記「失敗」，使用者可於清單看到原因。

14.5 前置需求

  • 需安裝 yt-dlp 與 FFmpeg，並於 OpenAISettings:YtDlpPath／FfmpegPath 指定路徑；缺失時轉錄該筆會以明確錯誤訊息標記為「失敗」。

15. 0.3.34 現況校正

  • 狀態已包含已取消，支援自動暫時性重試、手動重試、取消及應用重啟回復；URL 來源保留原始影片並在需要時轉碼 H.264／AAC。
  • 完成後可下載來源檔案／逐字稿、線上編修逐字稿、搜尋取代、依提示詞產生及編修衍生內容。
  • 逐字稿與衍生內容原地編修需套團隊權控，並讓相關知識來源標記過時。
  • 素材支援上傳新版本與版本歷史；主清單預設現行版。
