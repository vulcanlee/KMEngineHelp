會議管理 PRD

定義「會議管理」管理頁的需求、資料欄位、附件與團隊權控

  • 文件用途：定義「會議管理」管理頁的需求、資料欄位、附件與團隊權控
  • 主要讀者：產品、開發、導入顧問
  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.61
  • 首次實作版本：既有腳手架；專案對話窗完成於 0.2.152
  • 最後核對日期：2026/07/25
  • 建立日期：2026/06/28
  • 對應版本：0.2.152（所屬專案改為選填可清除；共用編輯元件＋專案對話窗入口）
  • 編碼：UTF-8（繁體中文，含 BOM）

一、目標與範圍

提供會議紀錄的 CRUD 管理，讓使用者保存會議主題、內容、時間、分類、團隊與附件。此功能與影音轉逐字稿不同：本頁管理人工建立或整理後的會議管理，不負責語音轉文字。

本 PRD 範圍包含 /meeting 頁面、搜尋、排序、分頁、附件、分類/團隊標籤與團隊資料權控。非範圍包含會議排程、行事曆同步、語音轉錄。

二、使用者與入口

項目說明
路由/meeting
選單專案協作 → 會議管理（1.0.17 起；原為「專案管理 → 會議管理」）
權限MagicObjectHelper.角色_會議項目
主要使用者專案成員、管理者、會議管理維護者

三、畫面與欄位

頁面提供會議管理列表、搜尋、排序、分頁、新增、編輯、刪除與附件操作。欄位以現行 Meeting 實作為準，包含標題、內容/描述、會議時間、分類、團隊、建立/更新時間與附件。「所屬專案」為選填（ProjectId 可為空）：新增時不自動帶入專案、可不選；下拉清單最前提供「（不指定專案）」選項，編輯時可藉此清除已設定的專案。若有指定，才驗證該專案是否存在。

三之零、1.0.19 新增欄位

五個人工填寫欄位（表單可填；會議形式、主持人、地點另上清單）：

欄位型別說明
MeetingModestring?會議形式：實體／線上／混合（MeetingAdapterModel.MeetingModeOptions），有填才驗證
Locationstring?地點，或線上會議連結
Hoststring?主持人
Recorderstring?紀錄人
Decisionsstring?決議事項

五個階段四（會議 AI 自動化）預留欄位（本階段不上表單、不上清單、不進 API）：

欄位型別說明
SourceTranscriptionIdint?來源轉錄紀錄 Id。軟參照、不做硬 FK
GeneratedContentRelativePathstring?AI 產生的會議紀錄 Markdown 相對路徑（內容只存檔案）
GeneratedAtDateTime?AI 產生時間
MinutesStatusstring?未產生／轉錄中／轉錄完成／排隊中／產生中／已產生／失敗／已取消（MinutesStatusOptions；後兩者 1.0.78 新增——「排隊中」原本與「轉錄完成」共用同一個值而分不出來，取消則原本被寫成「失敗」）
PendingActionItemsJsonstring?AI 待辦草稿 JSON 陣列

全部可空，既有資料不受影響。雙 provider migration AddMeetingFields（SQLite 20260720035447／SQL Server 20260720035519）。

SourceTranscriptionId 為何不做 FK：本專案指向 MediaTranscription 的既有做法都是軟參照（KnowledgeSourceItem 與版本鏈皆然）；且 BackendDBContext 的全域刪除政策是 Restrict，做成硬 FK 會導致「有會議掛著的轉錄紀錄刪不掉」。代價是可能出現孤兒 Id，讀取端須容忍。又因 MediaTranscription 有版本鏈，此 Id 釘的是特定版本而非最新版。

UpdateAsync 的刻意設計：MeetingService.UpdateAsync 為逐欄複製。五個人工欄位已補入；五個 AI 欄位刻意不複製——它們由階段四背景管線維護，若一併複製，使用者改個標題存檔就會把 AI 產出清空。由 MeetingFieldPersistenceTests 守護。

三之一、共用編輯對話窗與專案入口（0.2.152）

會議的編輯表單抽成共用元件 MeetingEditModal（自包含 Modal／驗證／附件上傳／存檔），由本頁與「專案管理」清單的「工作與會議」對話窗共用。從專案對話窗新增/修改會議時，「所屬專案」鎖定為該專案。為支援依專案載入關聯會議，MeetingService.GetAsync 新增 ProjectIdFilters 過濾（團隊權控不變）。

四、內部系統運作

核心流程為 MeetingViewView → MeetingService → BackendDBContext；API 路徑則透過 MeetingController → MeetingRepository。

  1. 進頁檢查登入與 角色_會議項目。
  2. 載入分類與團隊多選資料。
  3. 清單查詢套搜尋、排序、分頁與標籤篩選。
  4. 查詢、單筆、更新、刪除與下載都套團隊權控。
  5. 表單編輯以 clone 隔離來源列表。
  6. 附件寫入會議檔案目錄，資料列與檔案需保持一致。

五、LLM / RAG 互動

本頁不直接呼叫 LLM。若會議管理來自影音轉逐字稿或要進入知識庫，應透過影音轉逐字稿、知識來源聚合與清洗管線處理。

六、權控與安全

  • 非管理員只可見公開或團隊交集會議管理。
  • 下載附件不可繞過母紀錄團隊權控。
  • 分類與團隊多值欄位一律透過 TagStringHelper 轉換與精確比對。

七、錯誤與邊界

  • 附件缺檔時回報可理解錯誤。
  • 無權限者直接以 id 存取單筆或附件時不可洩漏資料。
  • 刪除資料時應同步處理附件實體檔案。

八、驗收與測試

  • 可完成會議管理 CRUD、搜尋、排序與分頁。
  • 分類/團隊篩選正確。
  • 非管理員無法看到其他團隊會議。
  • 附件下載受權控。
  • 新增會議不選專案可直接儲存；編輯時選「（不指定專案）」可清除專案，重新開啟確認已清空。

十、0.3.34 現況校正

  • 所屬專案為選填且可清除；支援從會議頁或專案內共用對話窗新增／編輯。
  • 人工會議管理與影音轉錄是不同產品能力；如需逐字稿，先走轉錄再整理為會議內容。
  • 清單／單筆／附件下載／更新／刪除全路徑套團隊權控，實體附件由服務層處理。
