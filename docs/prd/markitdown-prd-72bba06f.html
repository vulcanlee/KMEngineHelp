產品需求（PRD）

產品需求文件（PRD）：文件轉文字（MarkItDown 轉 Markdown）

  • 文件版本：2.0
  • 文件狀態：已實作
  • 現行系統版本：1.0.61
  • 首次實作版本：0.2.16
  • 最後核對日期：2026/07/25
  • 建立日期：2026-06-03
  • 狀態：已實作（系統版本 0.2.16）
  • 編碼：UTF-8（繁體中文）

一、背景與目的

本系統需新增一個「文件轉文字」功能：讓使用者上傳檔案，透過安裝在本機的 MarkItDown 執行檔，將 Office、PDF、圖片、HTML 等 各式檔案轉換為 Markdown 文字內容。轉換以背景工作非同步執行，UI 需即時顯示轉換進度與狀態 （完成或失敗）；轉換結果以檔案方式儲存於可設定的輸出目錄，並以上傳年度切分子目錄。

本功能為一個 CRUD 頁面，需具備側邊選單項目、Menu.json 設定與角色權限控制。

設計範本

程式碼庫已有與本需求高度對應的現成功能 「影音轉逐字稿」(MediaTranscription)，其架構正是本需求所需：

  • 上傳檔案 → 依年度切分目錄儲存
  • System.Threading.Channels 背景佇列 + BackgroundService + Processor
  • 以 System.Diagnostics.Process 呼叫本機執行檔（ffmpeg，路徑由 appsettings.json 設定）
  • 資料表存 Status、ProgressPercentage、ErrorMessage
  • UI 每 5 秒輪詢顯示進度
  • 結果以 UTF-8（無 BOM）文字檔輸出至依年度切分的目錄

因此本功能 以「影音轉逐字稿」為主要架構範本，CRUD 介面設計參考 ProjectPage / MediaTranscriptionView。

三、功能概述

新增「文件轉文字」功能：使用者上傳單一檔案，系統透過本機安裝的 MarkItDown 執行檔，於背景將檔案 轉換為 Markdown 文字內容。轉換結果以 .md 檔案儲存於可設定的輸出目錄（依上傳年度切分子目錄）， 使用者可於 UI 查看即時轉換狀態與進度，完成後可線上預覽內容或下載 .md 檔案。

MarkItDown 支援格式（依官方說明）：PDF、Word、Excel、PowerPoint、圖片（含 EXIF/OCR）、 音訊（含轉錄）、HTML、CSV/JSON/XML、ZIP（遞迴）、EPub 等。自 0.2.92 起，本系統限制上傳於 DocumentFormatValidator.AllowedExtensions 允許清單（含 .txt、.pdf、Office、CSV/JSON/XML/HTML/Markdown/YAML、 EPub/ZIP、常見圖片；.yaml／.yml 自 1.0.93 起納入），前端以 <InputFile accept> 預檢、後端於 BeforeAddCheckAsync 再驗證，不在清單者 回「不支援的檔案格式，僅接受：…」並擋下；清單內檔案交 MarkItDown 處理，個別無法處理者標記為「失敗」。 允許清單顯示於上傳表單，讓使用者明確知道可上傳哪些格式。

四、使用者流程

  1. 進入「文件轉文字」頁面（路由 /document-extraction）；權限不足者不顯示選單、不可進入。
  2. 點「新增」，於 Modal 中輸入標題、（可選）描述，並選擇單一檔案上傳。
  3. 送出後：檔案存至上傳目錄，建立一筆狀態為「等待中」的紀錄，並加入背景佇列。
  4. 背景服務取出工作 → 狀態轉「處理中」→ 呼叫 MarkItDown 執行檔轉換：
  5. 成功：狀態「已完成」、進度 100%、產生 .md 輸出檔。
  6. 失敗：狀態「失敗」、記錄錯誤訊息。
  7. 列表每 5 秒自動輪詢，更新狀態與進度（當有「等待中／處理中」紀錄時）。
  8. 完成的紀錄可「預覽」（Modal 顯示 Markdown 內容）與「下載」（.md 檔）。
  9. 可編輯標題／描述（中繼資料）、可刪除（連同上傳檔與輸出檔一併清除）。

六、設定（appsettings.json）

  1. 於 SystemSettings.ExternalFileSystem（KnowledgeExtraction.Models/Systems/SystemSettings.cs）新增：
  2. DocumentExtractionUploadPath：上傳原始檔儲存根目錄。
  3. MarkdownFilePath：轉換輸出 .md 的根目錄（可設定的輸出目錄），其下依上傳年度切分子目錄。
  4. 新增設定區段 MarkItDownSettings（對應強型別 Options 類別，比照 OpenAISettings 註冊）：
  5. MarkItDownPath：MarkItDown 執行檔路徑或指令（預設 "markitdown"）。
  6. TimeoutSeconds：轉換逾時秒數（預設 600）。
  7. Program.cs 比照現有 EnsureDirectoryExists 確保新目錄存在。
  8. 依專案規範（CLAUDE.md）：實作完成建置時，SystemSettings.SystemInformation.SystemVersion 版本號 +1，

並於 commit message 說明版本號變更。

設定範例：

"SystemSettings": {
  "ExternalFileSystem": {
    "DocumentExtractionUploadPath": "C:\\temp\\KnowledgeExtraction\\DocumentExtractionUpload",
    "MarkdownFilePath": "C:\\temp\\KnowledgeExtraction\\Markdown"
  }
},
"MarkItDownSettings": {
  "MarkItDownPath": "markitdown",
  "TimeoutSeconds": 600
}

十一、編碼需求

  • 所有輸出 Markdown 檔以 UTF-8（無 BOM） 寫入

（比照 TranscriptionProcessor 使用 new UTF8Encoding(false)）。

  • 預覽讀取、下載皆以 UTF-8 處理，確保繁體中文無亂碼。
  • 以 markitdown -o 直接輸出檔案，避免擷取 stdout 時受 Windows 主控台 codepage 影響而產生亂碼。

十二、驗收條件

  1. 選單出現「文件轉文字」，無權限角色看不到、無法進入頁面。
  2. 上傳檔案後產生「等待中」紀錄並進入背景佇列。
  3. 背景轉換期間狀態為「處理中」，完成轉「已完成」、進度 100%；失敗轉「失敗」並顯示錯誤訊息。
  4. 完成紀錄可線上預覽 Markdown 內容，且可下載 .md，內容為繁體中文 UTF-8 無亂碼。
  5. 輸出檔位於 MarkdownFilePath/<上傳年度>/ 目錄下。
  6. 刪除紀錄會一併移除上傳檔與輸出檔。
  7. appsettings.json 版本號於實作建置時 +1，相關文件同步更新。

十二之一、依提示詞產生衍生內容（0.2.77 新增）

在文件轉文字既有「上傳 → MarkItDown 轉 Markdown → 檢視/下載」之上，新增「依提示詞產生」：以提示詞請 LLM 為該筆文件產生衍生內容（如摘要、重點、改寫），結果落地保存並可線上編修。

  • 產生來源（對話窗可選）：
  • 萃取文字（Markdown）：以已轉出的 Markdown 文字 ＋ 提示詞送 LLM（OpenAIChatCompletionClient.CompleteAsync）。
  • 送原始檔案到 LLM：把原始上傳檔 ＋ 提示詞送 LLM，讓模型看到原始外觀。僅支援圖片與 PDF——圖片走視覺解讀（CompleteWithImageAsync）、PDF 以 base64 file 夾帶（CompleteWithFileAsync）。其餘型別（Word/Excel/PPT/HTML 等）此選項停用，由 DocumentExtractionService.IsLlmFileSupported 判斷；原始檔另有 20MB 上限（MaxLlmSourceFileSize）。
  • 儲存與檢視：結果落 ExternalFileSystem.GeneratedContentPath（{yyyy}/{guid}.md，只保留最新一筆），路徑寫回 DocumentExtraction.GeneratedContentRelativePath／GeneratedAt（新增欄位，雙 migration AddDocumentGeneratedContent）。可由操作區「檢視/編修產生結果」以共用 ContentEditDialog 檢視與編修並存回原檔。
  • 背景產生與權控：產生為背景作業（Task.Run + 獨立 DI scope，由 DocumentLlmGenerationService 執行）。團隊權控與輸入讀取一律在 UI 執行緒先完成（背景 scope 無使用者驗證情境），再把已授權資料傳入背景產生。
  • 限制：PDF 能否成功取決於所設定 GenerationModel 是否支援 file 輸入；不支援時 API 回非 2xx 並以通知呈現，可改用「萃取文字」模式。內容預覽採 Markdig（DisableHtml() 防 XSS）。

列表顯示：文件轉文字清單預設依「上傳時間」遞減排序（最新在前，0.2.78）。

十二之二、批次上傳壓縮檔（.zip）自動建立記錄（0.2.161 新增）

在既有「單檔上傳」之外，新增一個獨立入口「批次上傳壓縮檔」：使用者上傳一個 .zip，系統解壓後為裡面每個支援的檔案各建立一筆記錄並各自排入既有背景佇列。現行「.zip 當單一文件交給 MarkItDown」的單檔行為維持不變（兩者並存）。

  • 入口與 UI：DocumentExtractionView 工具列新增「批次上傳壓縮檔」按鈕（Icon drive_folder_upload），開啟獨立 Modal：選共用「分類／團隊」＋ <InputFile accept=".zip">。送出後以「批次匯入結果」視窗顯示成功筆數與略過／失敗清單。
  • 每筆記錄：標題取自檔名（去副檔名，Path.GetFileNameWithoutExtension）；共用的分類／團隊套用到本次所有記錄；ContentType 由副檔名推得（讓圖片／PDF 仍可用「送原始檔案」模式送 LLM）。
  • 解壓規則：子資料夾遞迴取出、忽略資料夾結構（僅用 entry.Name）；不支援副檔名的檔案與嵌套 .zip 一律略過並列入結果清單。
  • 安全上限（防 zip bomb）：單一 zip 可匯入檔案數上限 500（MaxBatchFileCount）、解壓後總量上限 2 GB（MaxBatchUncompressedBytes），超過即整批拒絕、不建立任何記錄；壓縮檔損毀無法讀取時同樣整批拒絕並提示。
  • 實作：DocumentExtractionService.AddBatchFromZipAsync(zipStream, categories, teams, ...)，以 System.IO.Compression.ZipArchive（.NET 內建，無需 NuGet）走訪 entries，對每個支援 entry 複用既有 AddAsync（存檔＋建記錄＋queue.EnqueueAsync）。結果型別 BatchZipImportResult（SuccessCount / Skipped / Failed / RejectedWholeBatch / RejectReason）。不改資料模型、不需 migration。
