使用者管理 PRD

定義「使用者管理」頁的需求、帳號狀態、角色指派與安全限制

一、目標與範圍

讓管理員建立、查詢、編輯與停用使用者，並指派角色、管理 Google OAuth 自動建立的待審核帳號。此功能是系統權限與資料可見性的管理入口之一。

本 PRD 範圍包含 /myusers 頁面、使用者 CRUD、角色指派、帳號啟用狀態、Google 待審核帳號的啟用處理與密碼處理。非範圍包含自助註冊、細粒度密碼政策、裝置管理。

二、使用者與入口

項目說明

主要使用者系統管理員

三、畫面與欄位

頁面提供搜尋、排序、分頁、新增、編輯、刪除/維護使用者。清單欄位為帳號、名稱、Email、角色、狀態、管理員、建立與更新時間；編輯 Modal 為帳號、密碼、名稱、Email、角色、啟用、管理員。

OAuthProvider 與 GoogleId 存在於資料模型（供 Google 登入比對），但畫面未呈現（見第十節）。

Google OAuth 首次登入建立的使用者預設停用，管理員需在本頁啟用並指派角色後，使用者才能進入系統。

四、內部系統運作

核心流程為 MyUserView → MyUserService → BackendDBContext。

  1. 進頁檢查登入，並要求 AuthenticationStateHelper.CheckIsAdmin()。
  2. 清單透過 MyUserService.GetAsync(DataRequest) 查詢、排序與分頁。
  3. 新增/編輯時載入角色清單供指派。
  4. 密碼以 salt + SHA 雜湊儲存，不保存明碼。
  5. Google 帳號可沒有本地密碼；需要 API JWT 時由使用者在 /Profile 設定 API 密碼。
  6. 預設開發帳號 support 有額外限制，不應由一般畫面任意變更敏感密碼狀態。

五、LLM / RAG 互動

本功能不呼叫 LLM、不使用 embedding。它間接影響 RAG/問答可見範圍：使用者角色的預設團隊會在登入時載入為 CurrentUser.TeamList，供團隊權控使用。

六、權限與安全

  • 僅管理員可進入與操作。
  • 使用者停用後，登入檢查應導向登出或拒絕。
  • 角色指派會決定頁面權限與預設團隊。
  • 不得在日誌或畫面顯示密碼、salt、token。

七、錯誤與邊界

  • 角色不存在或停用時，使用者登入應失敗或被導出。
  • Google 自動建立帳號若未啟用，應導向待審核頁，不建立登入 Cookie。
  • 帳號重複時應拒絕新增。

八、驗收與測試

  • 非管理員不可進入 /myusers。
  • 管理員可新增、編輯、搜尋與分頁使用者。
  • 停用使用者不可通過登入檢查。
  • Google 待審核帳號啟用後可正常登入。

十、現況校正（1.0.63 核對）

  • Google OAuth 首次建立帳號預設停用並進待審核；管理員啟用並指派角色後才能使用系統。
  • 角色無停用機制（RoleView 只有名稱、權限 JSON、預設團隊與時間欄位），因此第七節的「角色停用」情境不存在；實務上的等價情境是角色被刪除或使用者未指派角色，此時登入檢查會拒絕或導出。
  • OAuthProvider／GoogleId 僅供登入比對，清單與編輯 Modal 皆未顯示；若要在畫面呈現 Google 綁定狀態，屬尚未實作的後續強化。
  • IsAdmin 代表完全不受團隊資料權控，必須與一般角色的預設團隊分開呈現及驗收。
  • 編輯密碼欄留空代表不變更；停用帳號不得繼續登入。support 為設定檔管理帳號，不作日常具名稽核使用者。
