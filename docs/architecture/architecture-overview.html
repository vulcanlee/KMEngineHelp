系統架構

架構總覽

文件目的

說明本專案的整體分層、各專案職責、依賴方向、啟動流程，以及 DI 容器中註冊的主要服務，協助新進開發者快速建立心智模型。

1. 解決方案組成

方案檔：src/KnowledgeExtraction/KnowledgeExtraction.slnx（採新版 .slnx 格式）。共 8 個專案，採典型的分層架構：

專案主要職責依賴方向
KnowledgeExtraction.WebBlazor Server 宿主、Razor 元件、Web API、登入、本地化、靜態資源依賴所有其他專案
KnowledgeExtraction.Business商業邏輯：Service、Repository、AutoMapper Profile、Helper→ AccessDatas、Models、Dtos、Share
KnowledgeExtraction.AccessDatasEF Core DbContext、Entity、Migration→ 無外部專案相依
KnowledgeExtraction.AccessDatas.SqlServerMigrationsSQL Server 專用 EF Core migration assembly→ AccessDatas
KnowledgeExtraction.ModelsAdapterModel、System 設定模型、共用領域模型→ 無外部專案相依
KnowledgeExtraction.DtosAPI 對外 DTO：ApiResult<T>、PagedResult<T>、模組 DTO→ 無外部專案相依
KnowledgeExtraction.Share跨層共用 Helper、Extension（純工具）→ 無外部專案相依

依賴方向永遠由「上層」指向「下層」，不可反向引用。Web 不應跳過 Business 直接操作 BackendDBContext，但 Web 內的 API Controller 為了輕量化，使用 Repository（仍位於 Business 專案）。

2. 啟動流程（KnowledgeExtraction.Web/Program.cs）

啟動主檔位於 src/KnowledgeExtraction/KnowledgeExtraction.Web/Program.cs。整體流程：

  1. 建立 WebApplicationBuilder（Program.cs 開頭的 WebApplication.CreateBuilder）。
  2. NLog 設定（Program.cs 的 NLog 設定區塊）：
  3. 從 NLog:BasePath 讀取根目錄，於其下建立 KnowledgeExtraction.Web 子目錄。
  4. 清除預設 logger provider，改由 UseNLog() 接管。
  5. 立即建構服務取得 ILogger<Program> 寫入啟動日誌。
  6. 核心服務註冊（Program.cs 的核心服務註冊，含 AddRazorComponents）：
  7. AddRazorComponents().AddInteractiveServerComponents()：Blazor Server 互動式渲染。
  8. AddControllers()、AddSwaggerGen()：傳統 Web API + Swagger。
  9. AddLocalization()、AddAntDesign()：在地化與 AntDesign。
  10. RequestLocalizationOptions：支援 zh-TW / en-US，採 AcceptLanguageHeaderRequestCultureProvider。
  11. LocaleProvider.SetLocale("zh-TW", AntDesignLocaleFactory.Create("zh-TW"))：套用本地化字串。
  12. 認證（Program.cs 的 AddAuthentication 區塊）：
  13. Cookie 政策：CheckConsentNeeded = true、MinimumSameSitePolicy = None。
  14. AddAuthentication(MagicObjectHelper.CookieScheme).AddCookie(...)：登入 / 登出 / 拒絕路徑均指向 /Auths/Login 系列。
  15. AddAuthorization()。
  16. AutoMapper（Program.cs 的 AutoMapper 註冊）：載入 AutoMapping Profile，可選擇套用 LicenseKey。
  17. 強型別設定（ServiceCollectionExtensions.AddConfiguredOptions）：將 SystemSettings section 綁定為 IOptions<SystemSettings>。
  18. 外部目錄準備（Program.cs 的 EnsureDirectoryExists 呼叫序列）：依 SystemSettings.ExternalFileSystem 各路徑呼叫 EnsureDirectoryExists，缺少時自動建立。
  19. EF Core（Program.cs 的 AddDbContext 區塊）：透過 SystemSettings.DatabaseProvider 切換 Sqlite / SqlServer；SQLite 連線字串由 DatabasePath 動態產生，SQL Server 使用 DefaultConnection 與獨立 migration assembly。
  20. 客製服務（ServiceCollectionExtensions.AddApplicationServices）：所有 Service / Repository 一律 Scoped 生命週期。
  21. 資料庫初始化（Program.cs 的資料庫初始化與種子區塊）：
  22. 若有 Migration 則 Database.Migrate()，否則 EnsureCreated()。
  23. Seed 預設 RoleView（MagicObjectHelper.預設角色）並寫入完整權限 JSON。
  24. Seed 預設 MyUser（MagicObjectHelper.開發者帳號），密碼以 SHA + Salt 存放，標記為 IsAdmin。
  25. 中介軟體管線（Program.cs 的中介軟體管線設定）：
  26. 自訂 middleware 紀錄每筆 HTTP 請求耗時與例外。
  27. UseForwardedHeaders、UseStatusCodePagesWithReExecute("/not-found")、UseHttpsRedirection、UseRequestLocalization、UseCors、UseRateLimiter、UseAntiforgery。
  28. MapStaticAssets、UseStaticFiles 將 DownloadPath 對應為 /UploadFiles。
  29. UseAuthentication → UseAuthorization。
  30. MapControllers、MapHealthChecks("/health/live")、MapHealthChecks("/health/ready")、MapRazorComponents<App>().AddInteractiveServerRenderMode()。
  31. /system-health 由 Razor 元件提供人工巡檢頁，需 Cookie 登入且管理員限定。

非 Scoped 例外：八條非同步管線的佇列為 Singleton（I*Queue → *Queue，內含 Channel<int>），對應的 *BackgroundService 以 HostedService 註冊（見 §4.3）；IPipelineCancellationRegistry 與檢索熱路徑快取 IGraphRetrievalCache 亦為 Singleton。 圖譜的兩條全域作業刻意不進 PipelineNames：社群摘要重建與 LLM 別名建議是全域單例（非 per-record），以 GraphJobState.JobType 識別與持久化，但仍重用 IPipelineCancellationRegistry 取得取消權杖，因此同樣可在 /pipeline-jobs 觀測與取消。 Repository 用於 Web API（Controllers/），Service 用於 Razor 元件 / Page；兩者目前並存。 分類/團隊標籤與「團隊資料權控」相關共用元件：TagStringHelper、TeamJsonHelper（KnowledgeExtraction.Business/Helpers）、IRecordAccessScopeProvider；權控規則見 認證授權與權限機制。 LLM 互動與提示詞：知識來源「AI 對話」為獨立全頁、多輪、SSE 串流（KnowledgeSourceChatService + IChatConversationClient，僅記憶體保存）；所有提示詞統一走 LlmPromptResolver 四層解析（單次操作 → DB Prompt(同名鍵) → appsettings LlmPrompts → 程式 fallback LlmPromptDefaults）；所有 LLM 呼叫（chat 文字/視覺/檔案/串流＋語音轉錄）皆記完整 token 用量（TokenUsageFormatter）。詳見 LLM 提示詞與用量透明化。

4. 請求生命週期

4.1 Razor 元件請求（Blazor Server）

Browser ─► UseAuthentication ─► UseAuthorization ─► MapRazorComponents
                                                         │
                                                         ▼
                                         Layout.razor + Page.razor
                                                         │
                                                         ▼
                                       View 元件 ──► Service ──► DbContext

AuthenticationStateHelper.Check(...) 會在進入受保護頁面時讀取 ClaimsPrincipal、由 Sid 對應到 MyUser，檢查使用者狀態、強制改密碼需求與角色權限資料。檢查結果會以 AuthenticationCheckResult 回傳；Layout、NavMenu 或 Page 會依 Succeeded、Unauthenticated、InvalidUser、RequiresPasswordChange 決定是否繼續載入、停止載入或交由 Helper 導向登出與 /ChangePassword。

4.2 Web API 請求

Browser ─► UseRateLimiter ─► UseAuthentication ─► UseAuthorization ─► MapControllers
                                                         │
                                                         ▼
                                       Controller ──► Repository ──► DbContext
                                                         │
                                                         ▼
                                       回傳 ApiResult<T> 或 PagedResult<T>

詳見 Web API 設計慣例。

API Controller 目前同時支援 /api/{controller} 與 /api/v1/{controller}；新用戶端應優先使用 /api/v1/...。

4.3 非同步管線（佇列式背景處理）

長時間工作（轉錄、萃取、視覺解讀、清洗、蒸餾、嵌入索引、會議紀錄產生、三元組抽取）一律採同構的三層佇列模式，避免阻塞 UI：

觸發(Page/Service) ─► I*Queue(Singleton, Channel<int>) ─► *BackgroundService(HostedService)
                                                                  │ 出列、建立 DI scope
                                                                  ▼
                                              *Processor(Scoped) ──► 更新 Status/Progress/Error ──► DbContext
管線佇列背景服務處理器
影音轉逐字稿ITranscriptionQueueTranscriptionBackgroundServiceTranscriptionProcessor
文件轉文字IDocumentExtractionQueueDocumentExtractionBackgroundServiceDocumentExtractionProcessor
圖片識別IImageRecognitionQueueImageRecognitionBackgroundServiceImageRecognitionProcessor
資料清洗ICleaningQueueCleaningBackgroundServiceCleaningProcessor（＋CleaningEnhancer 做 LLM 去重/遮罩/分類/摘要/信心自評）
知識頁審核IDistillationQueueDistillationBackgroundServiceDistillationProcessor（＋DistillationEnhancer 產生多頁 Wiki）
嵌入索引IEmbeddingIndexQueueEmbeddingIndexBackgroundServiceEmbeddingIndexProcessor（清洗內容/Wiki 切塊、嵌入、寫入 VectorEmbedding）
會議紀錄產生IMeetingMinutesQueueMeetingMinutesBackgroundServiceMeetingMinutesProcessor（轉錄完成後由 TranscriptionProcessor 入列，LLM 產生 AI 會議紀錄，1.0.20）
三元組抽取IGraphExtractionQueueGraphExtractionBackgroundServiceGraphExtractionProcessor（＋GraphExtractionEnhancer 從現行 Wiki 頁抽「實體—關係—實體」，1.0.84）
  • 自動重試：Processor 套 PipelineRetryHelper（暫時性錯誤自動重試），另有 UI 手動重試與重啟後自動重新入列。
  • 取消：各背景服務經 IPipelineCancellationRegistry 取得 linked token，刪除/取消可中止對應工作並標記「已取消」。
  • 清洗門檻：清洗完成依 SystemSettings.Cleaning.ConfidenceThreshold(0.70) 路由為「已清洗」或「待審核」（QA-2），待審核者進人工審核關卡（QA-3）；品質以清洗品質評測集回歸（QA-4，門檻見 strategy/05 §五）。
  • 蒸餾與索引：知識頁審核完成後產生 WikiPage 並在嵌入設定完整時自動入列重建索引；問答與 檢索品質評測皆透過 IRetrievalService 混合檢索並套團隊權控。
  • 圖檢索（Graph RAG，1.0.83～1.0.96）：RetrievalService.SearchGraphAsync 是混合檢索的第三路——以向量∪關鍵字命中的 Wiki 頁為種子，沿 GraphEdge 與已核可三元組做多跳 BFS，融合權重為 SystemSettings.Retrieval.GraphWeight（設 0 即完全關閉此路）。三元組一律先「待審核」、經人工核可才生效；社群摘要另供「全域問答」map-reduce 使用。設計見 知識庫 RAG 設計與執行 §4.2–§4.4，操作見 知識圖譜使用指南。

詳細慣例與不變量見 開發慣例與限制速查。

5. 程式碼分層慣例

慣例說明
命名對齊XxxPage / XxxView / XxxService / XxxRepository / XxxAdapterModel / XxxDto
